# GXR 色彩配方研究协议

目标是让 Ricoh GXR 保存和调用更多用户色彩配方。当前首版集中 A12 50mm，目标为16个列表选择的独立配方，并同时保留配方 JPEG 与 DNG RAW，详情见 A12_50_SCOPE.md。用户已在 2026-10-12 授权按此目标开始本地固件开发。授权覆盖研究、下载公开资料、项目内工具安装、本地源码和机器码构建、静态分析及桌面验证；本阶段没有相机访问，不刷写或写入相机配置、校准数据。

## 证据要求

- 构建、研究和复审简报先读 `docs/FIELD_FACTS.md`，列相关事实 ID、版本与阶段。现场与模型冲突时先对账，在解释前保留模型覆盖缺口；新增现场结论追加至事实表，不能改写旧行来消除反例。
- 技术事实优先使用 Ricoh 官方手册、官方固件、项目源代码与可重跑结果。论坛只能提供线索。
- 每项结论标明：官方文档已确认、上游报告、静态分析已确认、推断、待验证。
- 记录来源 URL、日期、仓库 commit、文件 SHA-256、固件文件名和分析命令。代码定位使用文件路径及行号，二进制定位同时记录文件偏移和运行地址；没有映射证据时不把二者混用。
- 区分 Image Settings 的 Setting 1/2、My Settings、机身保存槽、SD 卡保存槽和完整色彩配方。不得把新增菜单项当成持久化功能已经实现。
- 首版先给出 GXR 机身与 A12 50mm 的证据，其他模块留作后续兼容研究。模块未确认时不宣称通用。
- 中文语言解锁能证明的范围是其实际修改路径。它不能独自证明存在空闲 RAM、可用代码空间、可扩展设置结构或安全恢复能力。
- 禁止上传官方二进制、私人照片、序列号、个人配置、凭据。禁止运行下载的相机固件、未知安装脚本或相机刷写工具。允许执行本项目编写的宿主参考程序及汇编器、链接器，用于离线验证；宿主测试不证明相机行为。工具安装先读入口与依赖，使用项目内目录。
- 遵守用户的 Codex 原生 CUA、T3 浏览器、Playwright pin 和 Apple Container 政策。无需浏览器交互时可使用只读 web 搜索和公开 API。

## 风险分级与现场节奏（2026-11-12 起，采纳 Fable 5.2 顾问意见）

按回退难度把候选分四级。L1：只读观察 DAT。L2：只换 DAT、改变行为。L3：刷机身。L4：刷单元。

- L1/L2 上卡 B 试用的门槛：写入只落在本次请求持有的缓冲和自身状态区；身份与库绑定正确；换回原文件即可回退；没有 P0。其余遗留问题列进现场单，不阻断卡 B 试用。
- 升为卡 A 日常版另需：卡 B 现场通过；不存在可达性已证的 P0/P1；机主点头。L3/L4 保留原有全部纪律。
- **L2N：DAT 在内存里临时改原生指令**（机主 2026-11-16 同意，`decisions.tsv` 的 `owner-1116-l2n-body-plan`）。回退同 L2（关机或换回原文件即还原，不落盘）。额外纪律：先只上实验卡；经 Sol max 复审并在卡 A 现场通过的 L2N 组，可以随日常版上日常卡（机主 2026-11-17 把刷机和换卡的安排交给 root，`decisions.tsv` 的 `l2n-daily-allowed`；241 已经这样带着 Z1a–Z5 在卡 A 日常用）；每一处写前逐字节比对旧字节，不符整组不写并记诊断；只在第一次待机、没有拍摄进行时写一次，关中断写、同步缓存、读回核对；"已写"以读回为准；只改有静态证据的原生函数，不碰开机路径、resident 窗口，不从原生代码直接跳进 DAT；补丁表放 DAT 第 3 段；必须有"同卡关掉这组补丁"的对照。
- 按后果定级。P0：丢照片、损坏 DNG、开机失败或要刷机恢复。P1：照片像素错，或设置丢失后无法恢复。P2：标签、显示或提示错，可以靠操作恢复。只在故障注入下出现的问题另标"可达性未证"，不能直接写成实机缺陷。
- 只有准备上卡的候选才领新代数。复审循环里的修订沿用同一代数，加修订号 rN，例如 g188 r2。
- 待实机的试验最多同时挂 3 项，登记在 `docs/FIELD_QUEUE.md`。每项放行后 48 小时内执行或明确作废，不再悬着。
- 每次现场至少回答一个会改变架构的问题。只有相机能回答的问题，先设计只读观察；数据尽量随照片文件带回。
- 同一问题连续两轮卡住（两次复审拒绝，或两次研究结论"未定"），请 Fable 5.2 high 当顾问或尝试解决。这项授权到机主叫停为止。日常版本见 `docs/DAILY.md`。

## 并行写入边界

主代理负责 docs/RESEARCH_PROTOCOL.md、README.md、decisions.tsv、sources/、tools/、scripts/、artifacts/ 和汇总报告。worker 仅写各自的 research/<任务名>/，可只读其余目录。不得更改他人的文件、全局工具配置或 Git 状态。来源读取和写入边界有冲突时先报告。

## 每份 worker 报告

先写结论，再给证据表、可实施路径、未知项和最小下一步实验。每个事实引用支持它的直接来源。若编写分析脚本，必须执行并记录输出。报告不得声称已经实现新增配方，也不得把桌面工具测试当成相机验证。

最终验收应包含：16个配方的列表选择、编辑、保存、重启保留、覆盖/删除、SD 卡缺失或损坏行为、同一次拍摄得到带配方的 JPEG 与完整 DNG、与现有 Setting 1/2 及 My Settings 的一致性。研究报告列出这些验收，不在无真机证据时宣称通过。
