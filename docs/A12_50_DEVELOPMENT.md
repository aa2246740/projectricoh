# A12 50mm 固件开发与真机配合

日期：2026-10-12。目标为 16 个独立命名配方、列表选择、编辑和保存，同次拍摄保留有配方效果的 JPEG 与原厂 DNG。用户已授权开始本地固件开发；相机尚不在身边，当前不写相机或存储卡。

用户已确认相机使用最新版；当前研究输入为官方 1.51。版本照片不再作为静态研究的前置条件，机身和 50mm 的实际版本页留到候选核对时记录。

## 官方恢复有条件

如果相机仍能进入升级确认画面、读取卡文件并完成写入，才有机会使用官方文件恢复。是否允许同版本重刷、回滚后参数是否一致，需要在用户的机身和模块验证。

主程序故障可能使菜单、卡读取、升级确认或机身模块通信失效。官方更新手册描述正常 SD 卡升级，不提供任意坏固件的恢复保证。只有确认了独立于被修改程序的入口，并验证必要输入、写入范围和失败行为，才能把它称作救援流程。

来源为 [Ricoh 官方升级手册](https://www.ricoh-imaging.co.jp/english/r_dc/download/firmware/docs/gxr_fwup_en.pdf)。上游中文补丁项目报告可在 1.51 上再次升级，但这是[上游补丁的正常更新说明](https://github.com/minakam1/ricoh-gxr-chinese-language-patch)，不是本项目相机的回滚或坏固件恢复实证。

固件中的 `Boot & Monitor`、`Backup prog blk`、`card version up`、`reboot` 等文本已在机身和50mm模块的主程序/监控文件再次定位；候选见 `artifacts/development/environment-and-recovery-strings.json`。这些是维修结构线索，不能证明普通用户能进入，不能证明主程序损坏后入口仍可用。

## 现有电脑环境

当前宿主为 macOS arm64，已核验 Python 3.14.7、Apple Clang 21.0.0、GNU Make 3.81 和项目内 GNU Binutils 2.43 M32R objdump。官方 GXR 1.51 输入和 SHA-256 已保存在本地；前面的记录完整性、映射和反汇编可以复跑。

本轮已补充项目内 M32R 汇编器、链接器、objcopy 和 GNU GCC 13.4.0 C 交叉编译器，并实现配方记录核心。宿主 Clang 测试运行在 Mac 上；同一份核心也已编译成32位大端 M32R 可重定位对象，代码段1220字节、只读数据8字节、无外部未定义符号。对象仍有指向只读数据的重定位，不能把单独的 `.text.bin` 当完整载荷。

根代理已独立重编译，目标对象与 worker 逐字节相同。编译与汇编向量证明工具能生成该指令集代码；GNU调用ABI、固件代码放置、平台回调和hook仍未验证，目标代码没有执行。逐函数 `.su` 报告不包括嵌套调用、回调或中断总栈。证据在 [根目标编译核验](../artifacts/development/m32r-c-root-check/verification.json)与 [M32R 汇编报告](../research/tooling_m32r_asm/REPORT.md)。

目前不需要新增电脑、Windows 环境或容器。Ghidra、完整硬件模拟器和原厂源码/SDK 均未作为已可用能力；缺失的原厂符号、字段和调用关系需要继续恢复。

## 相机上实际由谁做什么

官方升级介质是 SD 卡。通过 USB 连接相机或使用读卡器，都可以把更新文件复制到卡根目录；最终由相机按键进入升级确认并开始写入。

当前没有已验证的 USB 遥控协议，代理不能通过普通 USB 连接自动按相机按钮或触发快门。上游发现的私有 USB 接口和维修脚本需要另外验证；本阶段不依赖它们。

真机阶段的实际分工是：

1. 用户提供 A12 50mm 组合的版本信息，按短步骤在原厂菜单改一项颜色并保存设置，再取出卡。
2. 代理在电脑上读取、差分和检查设置文件，准备实验与验收记录。直接访问卡是否可用，取决于当前挂载及应用权限；也可把需要的文件复制到项目的 `captures/` 后处理。
3. 用户按相机按钮拍摄 JPEG/DNG 样本，代理分析文件。颜色字段采样完成后，继续实现菜单和参数加载。
4. 未来刷写仍需用户在相机上完成按键确认；可刷构建、输入版本、写入目标和恢复路径必须先具体核验。本轮没有更新包或真机刷写。

相机带来时准备机身、A12 50mm、满电电池、已备份的研究用 SD 卡和读卡器即可开始原厂采样。USB 线可作文件复制方式，读卡器也能完成这部分。不要求先拆机或购买烧录器；若后续只能通过内部接口恢复，再根据已确认的接口、电平和设备要求决定。

## 本轮开发产物边界

离线核心已通过16条记录互不覆盖、读取/替换/删除、损坏或截断拒绝加载、错误不改输出、短写/读回失败等行为检查。严格Clang和ASan/UBSan各249项断言通过；Python独立核对18项记录和CRC，实际宿主文件完成写出和新实例重读。根复跑与GPT-6.1独立复核均通过，见 [核心说明](../firmware/recipe_core/README.md)与 [复核记录](../research/review/RECIPE_CORE_REVIEW.md)。

记录使用新格式和合成字节，不冒充原厂 `.IFO`，不提供未校准的胶片预设。该核心没有相机画质或曝光状态指针，仍不能据此宣称将来的相机适配器已保护RAW。

新菜单、原厂颜色字段、模块参数调用、代码空间与完整调用 ABI 仍缺证据。本轮不会把宿主测试、M32R工具验证或原厂包重新打包称为新增配方固件完成。
