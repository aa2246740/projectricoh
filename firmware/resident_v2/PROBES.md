# 常驻 v2 的探针映射

八项探针覆盖 IROM、lease、启动、通知、按键、刷新与 WB。它们是运行在常驻层服务上的引擎设计，本次没有生成探针引擎或卡文件。探针代码只写自有 RAM 和当前菜单字形，不写 S、T、深层行、IROM、卡、更新标记，不主动重置 SD、单元或段装载器。

新编号按本任务的问题排列；旧 engine_lifecycle 的 P1/P2/P3/P4 分别对应这里的 P2/P3/P4/P5。共同的安全边界以 [RESIDENT_SPEC.md](RESIDENT_SPEC.md) 为准。

## 1. 共用显示与执行合同

复用 [Stage2k P0 的菜单行](../stage2k_p0/module.c) 方式：有界 ASCII 经 resident UI_TEXT 转为原生 glyph，写稳定 UI lease。显示使用 06/07/08 三行，不通过旧 `rfw_select(8)` 触发；缺探针、加载失败、忙或返回后都不得落到普通配方应用。入口返回 PASS/CONSUMED 要由 adapter 正确翻译。

示例使用短 ASCII，详细值可逐页查看，不截断后伪报成功。

```text
06 H01 A01
07 DOK COK
08 RUN V03
```

H 为 heap epoch、A 为本次唯一分配次数、V 为人工触发复查次数。其它探针使用 `IROM OK`、`SD E03`、`KEY 025`、`UNOBSERVED`、`ROWS ?` 等。原始错误保留 native_result、阶段、sequence 和代次，不能只显示 AB。

每一步由人工操作后的菜单重开或明确选择触发。无后台任务、周期计时、sleep 或轮询。环被覆盖时显示 dropped 和序号缺口；不得把缺记录当“没有通知”。每次重新取得 S 和 native view，不保留旧 RfwCache 或临时消息指针。

进入堆代码前由 resident 检查 root、完整 lease 区间、代次、元数据和 canary，再验证数据/代码 CRC；返回后重新比对。旧 lease 无效时不读、不调用、不 free。独立事件轨迹还必须证明破坏性 heap/段操作不在卡代码在途时覆盖其代码；返回后的代次检查无法挽救已经发生的覆盖。

## 2. 问题到探针的对应

| 探针 | 只读操作与常驻观察点 | 显示与接受证据 | 停止与恢复边界 |
|---|---|---|---|
| P1 插卡时读 IROM | STORAGE open/read/close 固定 IROM 对象，核对精确长度、EOF、CRC；比较 DCF 当前媒体、卡状态和所用 fd；对照插卡前后。 | `IROM OK`、实际读长、close 状态、源卷；由用户观察原厂拍摄仍到预期媒体，回放/复制菜单正常。读取不调用切记录媒体 API。 | 任一 native 错误保留并退原厂；不修复、格式化或改全局媒体值。只证明被测启动/任务路径。 |
| P2 主堆跨生命周期 | 一次 lease，先小块再独立 32 KiB 档，首中尾 nonce/canary、全块数据/代码 CRC；观察 H16 和 root/lease。已证安全时用短返回桩检查取指。 | 菜单、其它菜单、P/A/S/M、两种回放、MY、显示关闭、真睡眠、自动关机、USB 分项记录；A 始终为1，同址同 lease，D/C/返回值均正确。不能用熄屏代替睡眠。 | `H LOST/ROOT NEW/DATA BAD/CODE BAD` 分开显示；任一失配停本次会话，不重新分配一个相似块冒充保持，不 free 旧指针。完整关机使 RAM 状态失效。 |
| P3 启动与段重载 | H15/H17/H18 只观察自然调用；独立 lease 中保存 nonce 与段0 root nonce，loader pre 在原调用栈暂存见证指针，post 仅在栈/heap 仍可信时重新发布。 | `BOOT n`、`SEG n`、请求段号、pre/post sequence、root 与见证一致性。root 与见证都丢失显示 UNOBSERVED。覆盖 bootstrap/Monitor 的盲区须如实记录。 | 不主动调用 loader/trap。存在在途堆代码时不主动实验重载。不能扫描主堆找回见证或重造同 nonce；缺通知即覆盖未通过。 |
| P4 SD 通知 | H22 入口/出口、SD_ID 返回的完整16 B缓存；观察不同卡、同卡重插、启动、休眠和原生 I/O 恢复。 | 显示 sd_epoch、init pre/post 原返回、ID摘要；底层比较全部16 B。初始化期间有效性必须关闭；同卡重插也要有 epoch 证据。 | 不创建文件、不 reset SD。只作废运输事务，保留 IROM/RAM 引擎与单元恢复记录。原生关机导致记录丢失为 UNOBSERVED。 |
| P5 单元通知 | H19 ready store、H20 receive pre/post、H21 power；只读缓存与完整 name8/version、rx_seq。 | 分别对三单元、同名重连、失败接收记录计数，证明旧绑定再使用之前已有通知，失败缓存不得沿用有效标志。 | 不主动 RPC、不调用 power，不向新单元写旧 stock/T/邻接字节。没有原生支持的装卸流程就不新增带电能力；原生未返回菜单为 UNOBSERVED。 |
| P6 物理键和视图 | H10、H06、H11/H12/H13/H14；复制受审消息头，记录 event、来源、按压/释放/重复、活动、状态、part/tag/top/count 和 view epoch。空面板只改自有草稿与 native view。 | 逐个按 Fn1/Fn2、上下、拨杆左右/压入、MENU/OK、半/全按；核实0x25/0x22以及其它别名。九行显示六参数、Default、Back和标题，确认返回0不重建。 | 退出前先撤自有输入；原栈仍属本面板才恢复完整8 B记录，否则只撤资格。不触及 S 和原七项 setter，不开长按重复，不用延时猜释放。 |
| P7 深层写后取景刷新 | 只读消费引擎 apply 阶段、RPC8 wrapper 读回和 H37 preview pre/post；与人工记录的取景视频/原生显示对应。 | 分清 W回包、整组行验证、S发布、preview请求成功、模块完成和真正画面变化，显示 `ROWS OK / REQ OK / FRAME ?`。记录关联序号，不能把入队当下一帧完成。 | 只读探针自己不产生写入，不能独立关闭此问题。必须由另行授权的产品引擎/写入驱动产生一次已知变化；无驱动时结论 UNKNOWN，不能伪造“已刷新”。 |
| P8 WB 两轴 | 只读 S快照、原厂 WB补偿页、preview 事件，观察原厂 UI 已获授权的 A-B/G-M 改动；探针不写 S。 | 确认两个地址分别对应何轴、正负方向、raw1..17与signed+9、WB模式使能和MY后重取S；显示 `AB +/-n`、`GM +/-n` 与字段读数。 | 只读阶段不改变设置；若使用人工原厂改动，结束后由原厂 UI 恢复原值。正式引擎写入、取消回滚和取景效果另验。不能仅凭 WB0/1 推断轴顺序。 |

P1 读取的对象须在后续获授权环境中预先存在，探针不创建“为了读而写”的文件。文件失效或不存在可以证明 fallback，不能证明 IROM 读取成功。

## 3. 读写能力分阶段开放

第一阶段仅 resident 记录、来源读取与短菜单执行。先证 P3 的自然调用路径和 P2 的分配保持，再扩大执行大小或跨睡眠调用。不能一开始同时打开全部生命周期与写能力。

第二阶段运行 P4/P5/P6 的只读通知和空面板。挂入每个候选位置后仍默认走原厂；若缺事件、出现未覆盖重置或视图留存引用，停止对应能力，不把“代码一直持有”当正确性。

第三阶段只有另行授权并完成写入实现后，才用产品驱动验证 P7/P8 的实际应用。新版建议 ±5、约2倍强度需要新算法的单调/端点/灰点/溢出和真实画面证据；旧4500/3125主机结果没有覆盖它。

文件 create/write/rename/delete、A/B读回、卡 OK确认、原厂格式化停用和重装另需写操作验收。只读探针不能关闭这些项目；不设计拔电实验来声称 FAT/NAND 原子性。

## 4. 共同恢复边界

- 加载前失败撤候选并回原厂七项 UI，不保留 Stage2l 八项默认配方。
- RAM 探针失配后停用该会话，不去 free 或执行未知 lease。code有效而unit绑定失效时只撤绑定，不释放代码。
- root/UI恢复由 resident 独立执行，不调用已经无效的 engine.abort；撤回成功不表示深层数据恢复成功。
- 只读探针没有新增 S/T/文件写入；删除卡送货只控制后续加载，不能卸载 RAM 或撤掉已刷入的常驻 hook。
- 常驻代码本身出错仍可能需要官方机身更新回退；已验证的普通更新回退不扩大为任意坏 MAIN 的救砖保证。
