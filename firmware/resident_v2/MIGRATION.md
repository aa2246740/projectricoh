# Stage2l 到 resident v2 的一次机身升级

目前不能执行升级：这里只交规格、量测骨架和证据，没有 v2 机身映像、更新包、上卡文件或可用的六参数引擎。下列步骤供后续实现通过刷机前清单后使用。

## 1. 起点与已验证退路

用户确认当前相机机身为 Stage2l，完整 SHA-256 为 `efe6587190e845b1c28364c02a6b8bde14e046e7c7411393a4c9892124b6bfd7`，50mm 单元为官方1.51；28mm和MOUNT按各自完整身份/pin选择。这个值也与既有主机包 manifest 一致。

用户已在这台相机验证过官方1.51 `ilaunch3` 经卡更新的回退。只读官方来源为 `artifacts/firmware/gxr-1.51/`，机身 `ilaunch3` SHA-256 为 `da1980e9d6f3996ede4953b8311cf0ce2abeb4bb300b6ee60a38f38e29a3cdf7`。本任务没有重新执行设备回退，官方文件没有改动。

历史确认的恢复状态不需要再要求用户重复操作。若未来升级前又进入过T1，需按当时已验证的04/恢复流程确认实际状态；不能把本次规格或MAIN重刷当T恢复。

## 2. 后续实现的准备

1. 实现并关闭 [RESIDENT_SPEC.md](RESIDENT_SPEC.md) 的刷机前清单。最终严格链接必须同时容纳全部服务、fallback、post桩、恢复和root；当前7632 B骨架不是这个证明。
2. 冻结审查后的resident来源、所有hook及原窗口、最终机身映像、服务ABI ID、三个外部map/stock pin、可读release清单和完整哈希。build ID按排除自身ID及容器checksum字段的可复核规则计算；最终映像完整SHA另外记录。量测ID不能发布。
3. 在原位置保留现有Stage2l包、表和回退材料。旧 `DEEPTBL0/1.DAT`、旧bank不会自动成为v2容器；由独立引擎移植任务保留01–06语义、16槽与三模块绑定，测试槽07/08不自动提升为日用配方。
4. 新引擎纯init完成新版data v2六参数和两空位、默认建议±5及新版算法验收。引擎暂缺时，首刷只能是明确获准的探针阶段，配方功能暂不具备，不能叫日用迁移完成。
5. 在主机核验照片/设置备份及官方回退文件，按已验证原厂流程准备足够电源。后续制作/写卡/刷机另需明确授权；本次没有做这些动作。

## 3. 一次机身升级后的运行

1. 在获准设备操作后，用原厂卡更新流程从Stage2l直接刷最终resident v2机身，只刷这一次机身常驻层。保留原厂更新窗口和已验证回退入口，不顺带刷三个单元。
2. 首次以全部产品写能力关闭的配置验证缺文件/坏文件/错ID时完整原厂七项、Fn2、details和拍摄路径。不要用“payload能启动”替代fallback验证。
3. 根据探针协议先读/保持/通知/按键，再在另行批准的写阶段验证刷新、WB和存储。每个探针通过后只开放对应能力；无需为不同探针改写机身，探针作为兼容引擎送货。
4. 正式配方引擎就绪后，用户只拷入一次`GXRCE.DAT`。首次正常打开配方菜单时自动选择并安装IROM A/B，最后把送货改为`GXRCE.OK`。只有正式副本与送货确认都复核成功才报“已安装”。
5. 用户在三单元分别确认16配方位、面板六参数、Default、确认保存、取消不写、MY/回放/关机恢复，以及Stage2l失败传播和颗粒门。

若探针发现一个未覆盖且必须新增机身hook的通知，这次常驻层不能称最终版；记录覆盖失败，回到实现与审查。一次刷机是满足冻结入口和覆盖门后的目标，不是无条件保证。

## 4. 停用与重新安装

正常安装已确认后，卡上仅有OK而没有送货DAT。用户备份内置照片后，在原厂菜单格式化内置存储，再完整关机重启；IROM容器及微调消失，OK不再自动导入，走原厂。不另增加“卸载扩展”菜单或用户改名步骤。

若卡写保护或改名失败，安装未确认，仍可能存在DAT。UI必须明确显示此状态，不能承诺此时格式化可持续停用。不得让“写入IROM成功”掩盖送货确认失败。

重新安装时再拷DAT即可，无有效IROM时允许相同generation。IROM被原厂单元更新清空时也走同一重建路径；微调备份是否迁回须按完整身份校验。

## 5. 回退

1. 正常可操作时先结束当前配方会话，验证控制及被改行恢复。不能把关掉UI等同于恢复ISP。
2. 关机后使用已验证的官方1.51机身`ilaunch3`及其原厂配套材料，经卡更新回退。不要混入单元固件或新骨架ELF。
3. 完整重启核对原厂菜单、Fn2、拍摄/回放和固件版本；v2的IROM缓存及卡OK/DAT是否保留不能靠MAIN更新猜测。官方固件不提供v2服务，容器不再执行。
4. MAIN-only回退不保证清掉持久T或修复部分写入；这部分沿已验证的单元恢复流程另处理。普通更新退路已经实机验证，不保证任意坏MAIN、断电或硬件故障都能从同一入口恢复。
