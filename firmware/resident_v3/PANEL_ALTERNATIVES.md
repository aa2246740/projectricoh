# H10 删除后的面板接法

建议先选 A。当前交付先禁止产品 Fn2 打开面板，两种接法都没有偷偷接进最终 ELF。

| 方案 | 用户操作 | 需要的接点 | 代价 |
| --- | --- | --- | --- |
| A，沿用原生列表导航。 | Fn2 打开操作列表，上下选动作，确认一次就改一档。 | H06 打开，H08 读取已确认行号，再调用 `panel_event`。 | 面板从九行改成十四行，每个参数各有加、减两行，最后是恢复默认和返回。白平衡行继续禁用。 |
| B，保留九行和完整方向键。 | Fn2 打开，上下选参数，左右改值，确认或取消。 | 继续静态追踪 H06 或 H08 所在函数中的局部分派，只对 type 5、part 2、tag 33 的自有 state 接按键。 | 要新增一个更窄的执行点，重新证明设置、回放和更新界面不可达，并审查覆盖字和中间入口。 |

A 不依赖 H10 的全局事件流，也不需要猜测 PRESS、RELEASE、REPEAT。H08 只有原生确认动作，能转换成一次明确的 PRESS。行号零至十一分别对应六个参数的减、加，十二是默认，十三是返回。原生上下移动继续改变列表游标，不直接改参数。

实现 A 时，H06 调用 `panel_open`；H08 在十四行面板中将行号转换为面板命令，再调用 `panel_event`。十六行配方列表继续走 `apply_step`。关闭面板后重新发布配方列表。独立 UI 快照支持不超过十六行，无需把引擎地址交给原生回调。

B 不能仅凭函数名定安全。必须沿调用和分支条件证明新点只在自有拍摄界面执行。当前只确认 H06 的原生活动门和 H08 的 Image 活动门与 Stage2l 一致，没有证明它们所在函数的所有按键路径都可直接复用。

当前 H10 的静态证据见 [调用上下文](local/h10-context.txt) 和 [扫描结果](local/h10-review.json)。`0x202B120C` 在 `0x202B1100` 的通用事件循环中，调用点为 `0x202AF5D8`。hook 前没有 type 5、part 2、tag 33 限制。中间半字地址未发现引用，但“只在拍摄和 ADJ 执行”没有得到证明，因此本版删除。
