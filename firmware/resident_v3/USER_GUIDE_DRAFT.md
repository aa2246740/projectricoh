# v3 刷机后探针步骤草稿

这份步骤只供最终机身映像通过独立审查、由你决定刷机后使用。本任务没有生成机身映像，也没有操作相机。映像由 `firmware/image_v2` 另行负责。

1. 先不放引擎文件，打开拍摄界面的图像设定。前提是 IROM 两个位置也没有旧引擎，不能只拿掉卡上的文件就当作缺文件测试。应看到原厂七项，能正常退出、拍照、回放和关机。遇到异常先停下，把现象记清楚。

2. 先用 LIFE，之后再用 NOTICE 和 VIEW。每次只选一份，把对应的 `GXRCE.DAT` 放在卡根目录。三个探针只读引擎和设置，不安装 IROM，也不发配方写入。每次换探针先关机重开，避免仍在运行内存中的上一份程序。

3. 打开同一个图像设定菜单。每页有十六行，把整页拍清楚，别漏底下一行。解码程序能检查抄录是否完整，但不会代替你判断相机是否正常。记下当时装的单元，以及刚才做过的操作。

4. 用 LIFE 看首次进入时的会话、主块、代码自检和额外内存见证。Fn2 可以往后翻页。第十三行重新取样，第十四和十五行读 IROM 两个副本，第十六行记标记。第六至八页分别保留三次内存档位测量，第十五至十七页显示对应的原生返回结果。读到了 IROM 文件但没有可信参考值时，只记为读到了，不能记成校验通过。

5. 退出菜单，回放一次，再回来取样。之后可以分别试休眠唤醒和正常关机重开，每次只改一个条件。代码和主块仍有效时，见证应该保持；自检失败后，旧引擎不会继续运行。下一次进入会重新加载，也可能因为文件无效而回到原厂七项。记录完整页面，不要只记地址相同或计数增加。

6. 用 NOTICE 看当前 SD ID、单元名称、版本和入口自检。它不再观察 SD、链路或单元通知。换单元后的新会话应显示新身份，旧会话的变化次数不要求增加。相同型号、相同版本的重新连接，仅凭这套自检分辨不出来。

7. 用 VIEW 看当前 S 中的两个白平衡偏移值。拍下首次进入，再做一次正常的 MY 召回后重新进入。它只观察原始值，还不能确认哪一项是 AB、哪一项是 GM，也不能证明下一帧已经刷新。

8. 三种官方 1.51 单元分别跑一遍。先记录默认流程，再记录回放、唤醒和换单元后的重新进入。系统路径 hook 已经删除，探针不会在这些动作发生时主动报通知。

9. 最后再评估 base 和 huzi 产品容器。它们首次进入会尝试原有的 IROM 安装流程，和三个只读探针不同。本版保留十六项列表和配方应用，Fn2 暂不打开微调面板。方向调节、面板确认与取消，等 H10 的替代接法确定后再验。

抄录页面后，在主机解码，不需要连接相机：

```sh
/usr/bin/python3 -I -B firmware/resident_v3/containers/probes/decode.py 页面抄录.txt
```

LIFE 第五页和 NOTICE 第六页现在显示入口自检，不再显示旧的段装载通知。NOTICE 的按键消息页、VIEW 的帧完成与预览见证没有接入，显示未知是预期结果。
