# resident v3.5 停在链接余量

没有新的 ilaunch3，也没有 gen 116。resident 按现有 200 字节门槛链接失败。断言没有改。`firmware/resident_v34c` 和官方文件没有写。

## 两条根因

OK 成功之后，`rv_ui_abort` 清掉 `ui_restore[0]`。下一次 H07（离开 ADJ 的 MENU，或 Fn2 之后的 OK）在 `owned()` 的 `!ui_restore[0]` 上失败。旧指令在 VMA `0x200529d8` 是 `bra 0x200527d4`（`ff ff ff 7f`），不写 `f[1]`。trampoline 落到原生续体 `0x202871dc`。原生 setter 用游标字节 `0x2022f726` 查 `0x2037f492` 的 `00 09 01 0a 03 06 04 05`，把 `S+0x36e` 写成原生模式。现场 01 变成 Vivid（9）、02 变成 Standard（1），和这张表的第 1、2 项一致。同样会掉进去的还有：发布之后 `RV_CHECK_UI` 退休，以及 `inflight` 时嵌套的 H07。

28mm 第一次 H01 时，`rpc_ready`（`0x2009359c`，只读 BSS `0x200d7fd8`）还是 0。旧 `rv_load` 在 `0x20053560` 先置 `RF_ATTEMPTED`，init 失败后再退休。同一次开机不再试。

## 已经从旧代码里拿回来的字节

它只在 root 全是 `0xFF` 且 `0x2022f5ac>7` 且名字指针不是 `0x2022d610` 时运行。官方 `ilaunch3` 在文件偏移 `0x1e47ac`（VMA `0x2022f5ac`）的计数字节是 7，前一个字是 `0x2022d610`。八行列表只有我们自己的发布会写，而发布发生在 `rv_reset` 已经换掉 `0xFF` root 之后。所以这份映像的冷启动到不了这个块。删掉之后 `rv_hook_observe` 从 `0x3d4` 收到 `0x380`，净省 84 字节。剩下的 52 字节被新的调用点用掉了。

`-fomit-frame-pointer` 和单独对 hooks/loader 用 `-Oz` 都是 0 字节。把 `rv_ui_abort` 里重复的 `0x2022` 收成一个基址，生成代码仍是 `0x134`。LTO 没链过：出现对 `memcpy` 的截断重定位，并且 root 段断言失败。

## 现在的尺寸

| 项 | 旧 | 新 | 差 |
|---|---:|---:|---:|
| `rv_hook_observe` | 0x3d4 | 0x380 | -84 |
| `owned` / `own_fail` | 0x110 | 0x138 | +40 |
| `note` | 0 | 0x54 | +84 |
| 跳转表 `CSWTCH` | 0 | 12 | +12 |
| `rv_load` | 0x628 | 0x650 | +40 |
| `rpc_ready` 桥 | 0 | 12 | +12 |
| 代码末尾 | `0x20054628` | `0x20054690` | +104 |

门槛是 `__resident_code_end <= 0x20054638`（root `0x20054700` 前留 200 字节）。新末尾 `0x20054690` 超出 88 字节。若放行，空余是 `0x20054700-0x20054690=112` 字节。断言保持 200，链接失败，没有 ELF。

源码里的行为已经写上，只是放不进窗口：`RF_PUBLISHED`（flags 的 `0x80`）在进入 `RV_READY` 时置上，退休不清除。本开机发布过之后，H06/H07/H08 的提前返回写 `diag_early`，并把 `f[1]` 设成 `rv_skip_06`、`rv_close_07` 或 `rv_skip_08`。没发布过（含 `RV_DISABLED_UNTIL_REBOOT` 且从未 READY，以及 root 还不是我们的）仍落回原生续体。`rv_load` 在 `rpc_ready()==0` 或 `0x2040f804==0` 时返回 `RV_STALE`，不置 `RF_ATTEMPTED`，状态留在 `RV_FACTORY`。

`diag_early` 在 root 偏移 232（原来的 `grain_settings`）。低 8 位是 hook，8–15 是门 1–5，16–23 是 `rv_check` 原因，24–31 是 `owned()` 失败子项（1 magic … 5 `ui_restore[0]` … 12 top state）。

H06 的原生续体从 `0x202be250` 进入 `0x2026877c`，安全出口仍是 `0x202be6a8`（函数自己的收尾）。H08 的续体从 `0x202bb96c` 用游标 `0x2022f726` 做原生提交，安全出口仍是 `0x202bcf58`。这两处不能改走 `rv_close_07`：那个出口直接 `jmp lr`，会跳过 Fn2/滚动函数对外层寄存器的弹出。

## 凑满 88 字节的做法

1. 去掉 `owned()` 的 12 档子项，退回原来的 0/1 返回。省 40。还差 48。
2. 在 1 的基础上，屏蔽只做 H07。`note` 里三路指针和 12 字节跳转表可以收成只装 `rv_close_07`。按指令粗算能再省大约 26，合计大约 66，还差大约 22。这组没有重新链接。
3. 在 2 的基础上，把 `rpc_ready` 的 12 字节桥和 `rv_load` 里多出来的 40 字节收成一段大约 24 字节的调用。再省大约 28，合计大约 94，能压进门槛，余量大约 6 字节。同样没有重新链接，不能当成已经放进去。
4. 把断言从 200 改成 112，让 `0x20054690` 通过。这一步按任务不能做。

没有第二块能证明是死代码、并且够 88 字节的旧路径。所以停在这里，没有做容器 gen 116，也没有做机身包。

恢复方式不变：卡 A 的 Stage2l，挂 50mm，用「+ 和回放」进恢复。若以后有新机身，刷的时候先挂着 50mm；换镜头之后如果卡住，挂着那个镜头再刷一次，然后回到 50mm 再查一次。

## 这一轮链进去了

断言没改。`__resident_code_end` 是 `0x20054634`，门槛 `0x20054638`，还剩 4 字节。payload 7880 字节。root `0x20054700` 之前还有 204 字节，其中 200 是规定余量。

P1 和 P2 放进去了。P3 放进去了，但只记 hook、门 1–5 和 `rv_check` 原因，H05 不写这条记录。P4 和 P5 没放。4 字节装不下 owned 位图，也装不下 H06/H08 的安全出口。

`owned()` 回到 0/1，地址 `0x20053eb0`，长度 `0x110`。`early` 在 `0x20053fc0`，长度 `0x4a`。它先核对 magic 和 version，再把 `diag_early`（root 偏移 232）写成 `hook | gate<<8 | reason<<16`。本开机进过 `RV_READY`（`RF_PUBLISHED`，flags 的 `0x80`，退休不清除）并且 hook 是 7 时，把帧上的 `f[1]` 写成 `rv_close_07`（`0x20052bf4`）。没进过 READY，或者 root 不是我们的，不写 `f[1]`，原生 setter 继续跑。

`rv_load` 在 `0x200534b4`，长度 `0x650`。`0x200534f8` 起直接读 BSS `0x200d7fd8` 和 `0x2040f804`，相与为 0 就从 `0x20053af4` 返回 `RV_STALE`（`ldi r11,#-5`），不置 `RF_ATTEMPTED`，状态留在 `RV_FACTORY`。12 字节的 `rpc_ready` 桥删了。按映像段基址 `0x2004ae00`，`0x200534f8` 的文件偏移是 `0x86f8`。

宿主 ASan/UBSan：`PASS_HOST checks=143062`。冷启动那块 136 字节修复没有加回去。`F02_root_ff_with_ui` 现在期望 H01 重新装入，不再改写残留的 view。
