# 一次少换文件地记完八项探针

先用 LIFE 记生命周期，再换 NOTICE 记通知和按键，最后换 VIEW 记 WB 和刷新。总共三种引擎、两次换文件。现在交付的是离线代码段，容器还没打包；下面的按键流程要等常驻层和 data v2 接线完成后才能用。本轮没有操作相机。

## 先认这 16 行

行名是 `L00 01010003` 这样的 12 个字符。L 是 LIFE，N 是 NOTICE，V 是 VIEW。前面相机自己的 01..16 行号不用抄，抄字母开头的整行就行。每页 16 行都要拍到或抄到，可分几张照片。拍照前后不要重新采样；解码器会查缺行和整页 CRC。

用上下键选行，再按 MENU/OK 确认。这个映射由 adapter 接线，必须确认列表选择已经被探针消费，不能落到普通配方应用。

- 选 01 看总览，02 看十二个代次。
- 选 03..06 看本引擎的四页数据。
- NOTICE/VIEW 选 07..12 看最近最多 16 条事件，每页最多三条，顺序是旧到新。
- LIFE 的 06、07、08 分别是首次菜单、回放后、睡醒后的容量页；09..12 先看前四页事件，再按 Fn2 看余下两页事件。继续按 Fn2 可看三页容量原始错误，最后循环回总览。
- 选 13 重新采样一次。开页本身也会采样，翻数据页不会。
- LIFE 的 14、15 分别读已有 IROM A、B。文件不存在就记错误，不创建文件。
- 选 16 把人工标记号加一。每个动作前加一次，另外在纸上记“标记 3 = 回放键进入”。

容量页每个时机只测一次。06 页在开机首次进菜单时自动生成；回放后先选 07、再选 13，睡眠唤醒后先选 08、再选 13。不要在还没回放或睡醒时提前触发。重复选 13 不会把已经测过的容量覆盖掉。未执行的时机保持未测，不从屏幕黑过猜睡眠。

一旦回到原厂界面或出现 lease、CRC 错误，就结束这一轮。不要重新加载一个块再算作原块保持。完整关机后是新会话，之前的 RAM 记录不会保留。

## 先用 LIFE，合并 P1、P2、P3

1. 保持当前单元和卡，开机后首次进探针列表。记下 01、02、04、05、06 五页。04 页是见证块，默认 256 B，分配次数应该一直是 1；05 页是启动/段装载观察。06 页已经按 64、48、40、32、16 KiB 各试一次，成功后立即释放，只显示最大成功档位。05 页的重新发布见证当前仍是 UNKNOWN，零次计数不等于没有重载。
2. 选 14 读 IROM A，记 03 页。已有 B 时也可选 15。只有可信参考长度、CRC、EOF、关闭都匹配才是匹配；没有参考的完整读取会明说“无参考”。回到原厂页看记录媒体有没有改变，再打开回放和复制菜单看看能否正常退出，不执行复制，也不用拍照造证据。
3. 每次做下面一个动作，回来选 13，再记 01、02、04、05 和事件页。顺序用“关列表重开 → 打开另一原厂菜单再返回 → P/A/S/M 各转一遍 → 用回放键进回放再回拍摄 → 用另一条原厂回放入口再返回 → MY 召回”。第一次从回放回来时，先选 07、再选 13，拍下容量页；之后的回放不覆盖它。没有找到第二条原厂回放入口就记未测，不用猜键。
4. 先做一次单纯显示关闭，再恢复。另做一次真正睡眠/唤醒。不要为了探针改节能设置；看现有原厂阈值，等那个时间再多 10 秒。真正唤醒后先选 08、再选 13，拍下容量页。只看到黑屏、不能确认真正睡眠时，就写“熄屏，睡眠未确认”，不要测睡醒那一项。
5. 退出菜单后按原厂流程连接和退出 USB，再回来采样。若原厂流程导致重启，记“新会话/未观测”，不能算旧堆保持。自动关机后重开也按新会话单独记。

256 B 这轮经过审查后，再用同一个 LIFE 代码、`witness_bytes=32768` 的接线配置开一个全新会话，重复上面路径。不是在同一会话中分配第二块。它不新增一次代码引擎切换。

P3 只看日常动作自然触发的启动和 loader 事件。不要主动重载段、调用 trap 或模拟睡眠命令。

三次容量页里，五个档位的分配和释放都有结果，另三页保留 native 错误。最大成功档位是“至少这档申请成功且已经释放”，不是精确剩余空间。64 KiB 成功也不表示只剩 64 KiB。容量块本身不填数据、不读内容、不验 canary。三次都完成、session 和 boot/heap 一致时，解码器才列出三次最大档位中的最小值。

计划的 48 KiB 文件还要加实际 BSS、loader 同块开销，并保留探针运行条件差异。容量测试时 LIFE 和同一个 256 B 见证已常驻；换成 32 KiB 见证是另一组条件，不能混进前一组。最终文件长度限制、完整装载和实际产品路径仍要验证，不能仅凭容量页宣布容器可用。

要用这个结果给三个单元定统一预算，就在三个单元各自的新会话里取同一组三时机结果，并在抄录旁写清单元。不要把一个单元的成功当成另外两个已经测过。

## 再用 NOTICE，合并 P4、P5、P6

1. 先记 01、02、03、04、06。03 页带完整 16 B 卡 ID，04 页带完整 name8、版本和接收序号。相同 ID 或相同名字不等于同一连接，代次必须一起看。
2. 沿用 LIFE 的回放、MY、睡眠和 USB 操作，不必重复完整 P/A/S/M。每个动作后采一次，立刻拍 07..12。事件环只有 16 项；有 dropped 或 gaps 就记“记录缺口”，不能写“没有通知”。
3. 卡和单元只按原厂支持的流程装卸。默认先完整关机再换，三个单元各从新会话记录一次身份。没有获准的原生带电流程，就不做带电拔卡或拔单元。关机丢失记录时，P4/P5 的连续通知覆盖填“未观测”。同卡重插、同名单元重连也不能仅凭重新显示身份算通过。
4. 在不会拍照的原厂菜单里，一次只按一个键：Fn1、Fn2、上、下、ADJ 左、ADJ 右、ADJ 压入、MENU/OK、半按快门。每次写清“按下/松开”，回列表采样，记 05、06 和事件页。原厂动作若实际改变设置，就跳过并记录未测。全按会拍照并写卡，本轮跳过，写“全按未测”。不要长按。

05 页显示最后一次已复制输入的逻辑事件、来源、阶段和视图值，06 页显示字段有效位。解码器不会预先把 `0x25` 或 `0x22` 命名成某个物理键。Fn2 的九行空面板还没有 native 验收，这轮只能记原始路径和 RAM 草稿，不能填面板通过。

## 最后用 VIEW，合并 P7、P8 的只读部分

先采一次，记 01、02、03、04、05。03 页是 `S+0x6DD`、`S+0x6DE` 的两个 raw 值和各自减 9 的值；它们还没有 AB/GM 轴名。做一次原厂 MY 召回，再采一次，检查重新取得的 S 值。04 页记 H37 的请求入口/返回和另行接入的 apply 阶段，05 页明确写入驱动为关闭、画面完成为 UNKNOWN。

默认不改 WB、不应用深层配方、不额外请求刷新。没有写入驱动时，P7 填 UNKNOWN；两个 WB 字段没有变化时，P8 的轴方向也填 UNKNOWN。

以下只给另行批准的阶段留步骤，不属于默认操作。

- P7 由另一份获批驱动产生一次已知深层变化，探针只拍阶段和 H37 记录。人工同步记录取景视频，分别核对行读回、S 发布、请求返回和真实画面变化。H37 post 不能替代视频证据。
- P8 先用原厂界面记原值，再按原厂标示的 AB 正一格、恢复、AB 负一格、恢复、GM 正一格、恢复、GM 负一格、恢复。每次离开原厂补偿页后采样、记 03 页，把屏幕写的轴名和方向一起抄下。只有单一 raw 字段按预期变化，才能建立地址/轴/正负绑定；结束用原厂界面恢复原值。还需另外验证 WB 模式使能条件。

## 把抄录还原成结果

把抄录或照片已有的 OCR 文字存进本任务 `local/`。脚本只读文字，不识别图片，也不访问相机或卡。

```sh
cd /Volumes/Workspace/Projects/T3-Runtime/projects/projectricoh
python3 -I -B firmware/probes_v2/decode.py firmware/probes_v2/local/notes.txt
```

它会输出页号、采样计数、session、原始字和字段。`verified=true` 只说明抄录 CRC 正确。多个完整页面可以接在同一个文字文件里；每页从 `L00/N00/V00` 开始。页面必须先完整抄完再翻页。

OCR 把数字认成 O/I/L 时，可以显式加 `--ocr`。脚本会列出修正，仍然校验 CRC。`--partial` 只用于查看缺行文字，结果会保留 `verified=false`，不能拿它判通过。
