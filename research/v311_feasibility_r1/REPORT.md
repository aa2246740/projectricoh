现有存储天花板可以从架构上打破；满足“每种满配、库大小随卡扩展”的最短完整路线是卡上数据仓库、分页索引和只读按需缓存，先关闭读卡门的证据缺口，再加载当前配方与当前 LUT。扩大 DAT 或一次性把整库搬进大 RAM 都不能单独满足这个目标。

### A1. 107,612 B 是经验门槛，三个窗口要分别算

```text
主请求 = 1,228 B 会话 + 6,144 B 私有状态 + 256 B UI 容量
       + align4(DAT + BSS)
       = 7,628 + align4(DAT + BSS)

历史日用主请求：108,124 B
本轮沿用的工程上限：108,124 − 512 = 107,612 B
因此，DAT + BSS 的当前工程预算是 99,984 B。
```

512 B 是项目主动保留的余量；108,124 B 来自 g137 日用，不是已经测出物理 RAM 恰好到这里用完。去掉余量最多取回 512 B，连一份 552 B 都不够，不能解决根本问题。

### A2. “满配”按解压结果定义

### A3. 最短完整路线：只读卡库，固定缓存，库数量不进入 BSS

1. Studio 输出纯数据库，保存每个配方的完整逐单元状态。先支持当前 552 B，格式为 840 B 扩展与 LUT 引用留版本位；不执行库中的代码。原厂 04、单元校准身份和必要恢复数据始终可用。
2. 索引分块、分页。RAM 只保存当前八行需要的名字/ID及少量预取项。稳定配方 ID 不绑定全库数组下标，避免旧 u8 索引、固定 48 条和逐条分配再次形成天花板。文件大小、FAT 目录及整数范围仍受明确支持合同限制，不能称字面上的无限。
3. 用户请求一个未缓存配方时，提交有身份的只读作业。读取到候选缓冲，核对卡/模块代次、长度、CRC、数据版本和全部语义后才发布。失败保留此前完整配方；没有可确认基线时保持明确的未应用状态。
4. 缓存采用当前项与候选项。颜色应用继续走现有完整写入、回读、补偿及 DIRTY/GUARD 流程。浏览、读卡、应用是三个阶段；冷缓存等待必须可见，不把未读完的内容预览出去。
5. LUT 在选择配方时预读并解压，拍摄前固定表身份与地址。拍摄期间不读卡、不换表，不拿 JPEG 写卡阶段去换 LUT 平面。

这条路线不要求先解决机内保存。电脑管理卡上胶片，相机只消费数据；“在相机上编辑后保存回库”留在另一条写桥任务。

现有研究还不够批准第 3 步。g147 的反例已经说明：高层打开数归零、甚至取得文件系统锁后，原生关闭尾部仍可能未完成；一次读打开会引起别的文件的脏 FAT 缓存写回。[读卡门 G1–G6](../diag147/READ_GATE_NOTE.md)、[关闭交接反例](../review_diag147_r3/REVIEW.md)。因此，最短路线是缩小到只读桥后补证，不能把函数名字叫 read 当作只读证明。

最先补的主机证据为：全部脏状态/写者与锁的普查；关闭交接应拒绝而完整关闭应放行的成对反例；照片、回放、目录和格式化路径；USB/换卡/模块代次；迟到完成的内存寿命。现场只补真实 FAT32、任务时序与正常照片，不故意拔卡、耗尽句柄或制造写失败。

建议把“仅效果”的图像区候选缩到 512 KiB，用于数据，不把半格的 12 MiB 一起带入此次范围。这个档位已有 v4 设计起点，但仍需在当前 v3.10 基线上重做归属证明。

## B. 机内真 3D LUT

### B1. 算法有路线，正式时延未知

使用现有 H40 主 JPEG 编码前入口。它位于主图包装器之前、底层压缩重试之外；H41 可观察包装器后的状态。当前 g157 只透传并观察，不做像素处理。已有入口不等于已证明可安全写全帧，产品还需要逐张配方/表身份和退休协议。

| 表格式 | 17³ | 33³ |
| --- | ---: | ---: |
| 三通道 Q8.8，6 B/节点 | 29,478 B | 215,622 B |
| 4 B 对齐后的数据 | 29,480 B | 215,624 B |
| 如另走普通堆分配，含基本块头 | 29,492 B | 215,636 B |
| 三通道 u8，3 B/节点 | 14,739 B | 107,811 B |

u8 是不同精度方案，不能当作 Q8.8 无损压缩。坐标表另加 1,024 B。单张 12MP 有 6,106,112 对像素，完整 YCC 主图为 24,424,448 B。原地 CPU LUT 无需另复制整帧；33³ 增大的是表，不会把每对四面体顶点数乘 7.3。

当前 g157 直接追加一份 17³ 表，会把 test 主请求推到至少 136,336 B，尚未加内核和 scratch；这条做法不采用。33³ 单表也超过现有文件/映像和单 lease 合同。正式产品用卡上按需表与外部数据缓存，精简测速 DAT 则可先把一份 identity 17³ 内嵌，不依赖新读卡桥。

| 既有估算 | 数字及适用前提 |
| --- | --- |
| cpu_speed_r1 的 17³ / 33³ 全图 | 约 12–70 秒 / 12–117 秒；假设 150–230 MHz、70%–100% CPU 份额及指定访存成本。 |
| look_ceiling_r1 的后台 17³ | 约 28–74 秒；假设手写内核每对 200–260 条、123M 指令/秒、70% 效率、后台份额 25%–50%。 |
| 本轮结论 | 没有新增相机秒数。上述区间不是上界、保底性能或可接受性的结论；缓存、同步、编码和存储另计。 |

### B2. 最小新探针：算完但不把结果写回照片

先做一份绑定当前 v3.10 的精简 DAT，不修改机身。当前 H40 已存在，这一步不占那 92 B resident 余量。不要在 g157 test 仅剩的 92 B 代码窗口里硬加内核，也不要复用旧版不可上卡的 CPU 探针。

探针内嵌完整 identity 17³ 表，关闭 identity 特判和跳过像素的快路。H40 对实际主图逐对运行完整四面体算法，输出写入 DAT 自有行缓冲并消费校验值；不写主图、K 描述符、RAW、DNG 预览、T、设置或文件。用访问白名单验证这一点。H41 只记返回状态和时间，不在拍摄回调绘制菜单。

| 次序 | 探针动作 | 真正能回答的问题 |
| --- | --- | --- |
| L0 | 用手机做两次约 30 秒参考区间，保留实际秒数和原始 tick；测空包装与私有向量正确性。 | 时间单位、量化和计算有没有被优化掉；不测 MHz。 |
| L1 | 不运行 LUT，普通单张命中 H40/H41，记录实际几何、外层调用者、状态和堆/栈观察。 | 当前机身/单元的真实拍摄是否进入已支持路径。未知几何直接透传。 |
| L2 | 单次 arm，从少量行逐步扩大影子运算，完整表一直驻留。 | 检查预算、看门狗/调度反应和额外停留；未走完全帧只报实测子量或下界。 |
| L3 | 获准后运行一整帧，OFF/ON 配对至少三对，保留每次 start/end、像素对数、校验值及编码状态。 | 本探针每张实际多花几秒、样本离散和失败情况。第一次加载时间单列。 |

```text
实测影子内核秒数 = (kernel_end − kernel_start) × 外部校准的秒/tick
编码阶段增量     = T(H40 到 H41，ON) − T(H40 到 H41，OFF)
```

差值按无符号回绕规则处理。只有已走完全帧、完成状态有效、表哈希和处理对数正确的样本才进入“每张实测”。保留最小、中位和最大值，不挑最快一次。H41 不是照片文件全部落盘完成点；总保存等待另用手机录像或另经审查的完成观察点记录，不能把 H41 时间叫完整写卡时间。

影子探针保证不主动改变颜色，测的是实际主图读取、查表和私有输出带来的停留。它没有测到向 JPEG DMA 交付修改后主图的全部成本。正式 LUT 仍须验证：输入 DMA 到 CPU 的有效性、CPU 到编码器的可见性、色度字节/范围、原帧独占和取消。不能靠原地写“相同字节”绕过这些门；也不能承诺先前已经裁切的信息会被 LUT 恢复。

对较长处理的安全停留时间目前未知。逐批检查是软退出，不是硬实时上界。若预算不足或相机返回异常，保持下界/失败结论；不拿私有小块外推冒充整张已测。

## C. 第二次 ISP

### C1. F034 硬件与派生通路存在，主 JPEG 回接仍 OPEN

| 命题 | 当前证据 |
| --- | --- |
| 机身有 type23/26/28 的 F034 writer | 静态确认实际写硬件，不能称为只有只读回助手。 |
| 原生内存输入转换会 build/apply 颜色配置 | 已确认请求 18 的原生小图/缩放用途；默认矩阵和曲线为中性配置。 |
| 只有小 JPEG 会调用配置入口 | 已被核验推翻：有 29 个已识别调用点，包含条件回放路径和以主图为输入的派生转换。 |
| 主图作为输入，所以主 JPEG 已经处理两次 | 不成立。派生结果进入另一缓冲；现有晚编码路径仍取原主图。 |
| 全尺寸 1:1、各颜色级有效、原地转换、DMA/锁与最终 JPEG 输出 | OPEN。不能从相同驱动描述符推出这些合同。 |
| 这就是硬件 3D LUT，或最多只能仿射+曲线 | 两种定论都没有证据。现有表不是三轴体素 3D LUT，完整可用函数族还需测试。 |

依据为[硬件核验 K4](../hw_mining_r1/validation/VALIDATION.md)，与两遍颜色模型分别看待。该模型中的 L4+L1 约 1,392 B、L4+L4 约 1,680 B 仅是参数状态；真正大的资源是图像缓冲与引擎所有权。

### C2. 最短探针分成“会运行”和“进入保存文件”两次判定

1. 先补原生转换锁、输入格式、完成/错误出口、配置恢复及输出消费者的静态合同。以原厂 VGA/派生流程做只读 RAM 追踪，记录 request、apply、提交/完成、输入输出几何和 H40 编码源。需要补观察入口时，纳入 v3.11 的默认关闭小跳板；不能在单通道 H40 内再次递归调用 DAT。
2. 在已取得引擎所有权的原生任务上下文中，用两个自有 128×128 YCC 缓冲运行 1:1。源为灰阶/颜色条，目标带保护边界；先完全沿用原厂中性配置，再只改单个已解释的系数或输出偏置。源/目标原始数据共 65,536 B，不能额外从拥挤的 g157 堆临时申请。可用精简探针已有分配中的 BSS，或已取得归属的数据区。
3. 对照输入输出、实际写入范围、canary、配置回读、返回值和时间。中性配置可能有重采样和量化误差，不预设逐字节 identity。一次单变量改变并可恢复，只证明该小缓冲的颜色级生效。
4. 在主图格式、CPU/DMA 交接和别名门通过后，借 H40 把这个 ISP 输出中的一个 MCU 对齐小块复制到主 JPEG 的预定角落。保持其余像素和编码几何，做 A→B→A，检查保存的主 JPEG 分量、位置及恢复。这是最短的最终文件见证；LCD 或 DNG 缩略图变化都不算。它仍只证明小块接通，不证明全帧第二次处理。
5. 再验证完整低分辨率主图，最后才上 12MP。优先研究有边界一致性证明的条带输出；不能假定整帧原地处理，也不能默认缩放比 1:1 或任意条带都受支持。

单独的私有小图调用，在现有 H40 和审清的原生 wrapper 足够时可以仅换 DAT；额外的原厂调用追踪、资源仲裁或产品计划入口才要求改 resident/机身。现在尚未找到可以免除所有权验证的“直接调用即可”合同。

若全尺寸不能原地或分条带，额外输出至少要 24,424,448 B，有既有对齐时约 24,430,080 B。512 KiB 的库/LUT 区不够；旧半格缓冲也不够。此时须单独重审大图像区和连拍容量，不能让 v3.11 因为“参数只多 1.6 KB”就默认可交付。

错误在写主图之前可放弃并继续原厂编码；写过主图之后必须完成本张或使本张 JPEG 明确失败。不能留下半幅变色却报告成功。私有转换也必须证明异步完成后的释放与配置恢复，不能用一次正常返回代替。

### C3. 亮部与暗部可以期待什么

如果第二遍能使用独立通道曲线与有效混色，就能把第一遍完成的结果再作非线性变换，增加暗暖亮冷、高光去饱和、肩部颜色和中性轴分色的表达力。实际级次、RGB/YCC 坐标、旁路和裁切必须先测，不能直接把电脑 L4→L4 套进硬件。

只要求线性地“暗部偏一种颜色、亮部偏另一种”时，完整 C100 的亮度到色度项及偏移已是更短候选；其像素语义同样需单字段探针。任意影调区间独立选色和中间调保护则需要非线性或三维映射。C120 若最终确认为随亮度乘色度，可调分段饱和度；它不会把零色度的灰阶凭空染色，且其自变量目前仍 OPEN。

第二遍不能恢复第一遍已裁掉的颜色信息。现有模型也没有显示所有胶片都受益，因此先测通路、响应和代价，再决定是否做新的逐配方拟合。

这些是未实施的工程估算，不能当交付日期；审查、现场等待与失败返工另计。复用后，诊断、数据架构、只读卡库和两项探针约需数周，不能承诺一个小补丁就完成全部功能。

同一 v3.11 设计应统一：首错诊断、数据区归属/代次、配方与表身份、拍摄前计划、H40/H41、计时与内存回执。新探针默认关闭、逐项 arm。resident 原因页、卡库读入和图像处理各有独立停止条件，F034 尚未放行不应阻止诊断交付。

不纳入这版的默认日用承诺：机内写库、每张必跑完整 3D LUT、完整 33³ 实测、12MP 第二次 ISP、半格的 12 MiB 缓冲。它们分别等待自己的证据，不为了共用一次刷机而先写入未闭合的路径。是否所有入口都能在一次机身更新内定案仍 OPEN；目前只有 LUT 影子测速已具备无需新增 H40 的路线。

### D2. resident 诊断必须覆盖 DAT 尚未运行的阶段

首次失败在退役前锁存，保留阶段、具体原因和“不合格位”；后续通用 STALE 不覆盖首错。至少区分：未开始/暂未就绪、卡和 IROM 的打开/完整读取/EOF、文件身份和 CRC、分配、纯初始化、UI 发布、运行期退役、颜色护栏。

最小记录保存在固定 resident 所有的区域；可复用既有诊断/事件空间，但不得占 pins、颜色护栏或未知原厂 RAM。renderer 和原因入口不能依赖 DAT、扩展成功装载或文件日志。安全待机再提示，详情页仍为八行，未知菜单对象只记录不绘制。DAT 缺失应显示未知代数，而非伪装成正在运行 g157。

已有单 IROM、仅卡布局可多腾窗口，但会改变回退承诺；作为明确设计取舍，不能悄悄删掉 IROM 回退来挤原因页。该页是否装得下由最终链接证明。

### D3. 机主现场最少动作

所有制卡、备份、坏文件样本、摘要和结果分析由后续实施任务准备；本轮没有准备这些包。先只用测试卡，以下是未来按门槛逐次执行的最小配合。

1. 保持当前 MOUNT，先跑仅换 DAT 的 LUT 会话。拍一张版本/状态页，做两次约 30 秒校时；按提示通过小量准入后，完成三对 OFF/ON 单张共六张，手机录像保留等待时间，最后拍结果页。未准入全帧就交当前阶段结果，不强求六张都跑完整遍历。
2. v3.11 通过实现与恢复审查后，再安排一次机身更新，沿用项目已核对的 50mm 和刷回步骤。分别以缺 DAT、匹配 DAT 冷启，拍首错页与正常页；损坏/不匹配样本不在相机上现改。回退测试要排除 IROM 实际仍加载了另一份 DAT。
3. 在测试库里选首页与末页的两个完整胶片，做 A→B→A，保存结果码和三张照片；覆盖一次正常关机再开。其它单元各补一次冷启、选库与原厂 04 对照，不要求重拍整套胶片库。
4. F034 私有小图可以由探针自动完成，只需拍结果页；已获准的小块 JPEG 阶段再拍三张 A→B→A。证明影调分区独立控制还需分别扰动暗部和亮部，不能仅凭这三张通路照片宣布达成。
5. 结束后由实施者恢复稳定 DAT/机身来源并核对。出现异常保留第一张错误页和原文件；不在存图中拔卡、换模块、强断电或格式化原卡来试错。

仅 LUT 会话可在新机身之前独立完成；F034 原厂追踪可合并到之后同一轮正常单张，不为每个计数单独要求机主拍照。上面的最少动作验证研究价值与基本通路，不替代长期日用、USB、取消、连拍和三单元的完整验收。
