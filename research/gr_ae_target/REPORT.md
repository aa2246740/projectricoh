# GR III / GR IV 的 AE 目标与 Standard 中灰

2026-10-21。结论：已找到两代相机的 AE 参考值、统计域、四种测光的入口，并闭合了照片中 AEInfo 的保存路径；尚未把积分统计单位完整换成 DNG 的线性 u。因此，本轮不能给出已证实的“零补偿点测灰卡应输出多少码”，也不能据此给 GXR 配方增加曝光平移。

静态确认：GR III 2.10 的线性参考值为 **550.8179931640625**；普通彩色 GR IV 1.11 为 **566.333984375**。这两个数既不是 JPEG 码值，也不是反射率百分数。它们对应的比较域分别是 `log2(Y)-9 = 0.105431877469` 和 `0.145509294946 EV`。6 张曝光程序标记为 P/A/S 的历史照片，其最终测光量与参考值加内部 EC 的残差绝对值最多为 0.084960 EV；其中一张曝光模式标签冲突，严格的自动曝光一致性样本为 5 张。

未知：积分统计与全分辨率 DNG 之间的工厂校准、读出缩放及 LV/拍摄增益关系。最终 `u_m`、相对 Standard 118 的 EV、Standard JPEG 预测在 [metrics.json](metrics.json) 中均为 `null`。下文的条件计算不取代这三个未知量。

## 2. 参考值与统计量是什么

### 2.1 从曝光服务到 AE 比较值

| 项目 | GR III 2.10 | GR IV 1.11，彩色 |
|---|---|---|
| 曝光计算上层入口 | `0x53472520` | `0x5366c520` |
| 参考值函数 | `0x5346d768` | `0x53667938` |
| 线性参考值 T | 550.8179931640625 | 566.333984375 |
| 常数来源 | double，`0x5346d858` | float32 的 `431 × float32(1.314)`；`0x53667a4c`、`0x53667a54` |
| log 参考值 | 0.105431877469 EV | 0.145509294946 EV |
| 算法总入口 | `0x5347d490` | `0x53677350` |

静态确认：曝光服务比较的是所选算法输出与 `log2(T)-9+EC`。III 在 `0x534729dc..0x53472abc` 形成差值，再进入 `0x5346d950` 的曝光值换算。P/A/S 下游如何分配光圈、快门和感光度，不改变这里找到的统计域参考值。

IV 的 `478` 是另一个产品分支。`SystemConfig_GetProjectType` 位于 `0x538e7fd0`；产品描述符 `0x53fe5180` 的类型字节为 4，名称指针指向 `0x53fe2b08` 的 `GR IV Monochrome`。类型 2、3 分别关联 GR IV、GR IV HDF。单色分支也把 AE 权重改为只取 G。故 **478 属于 Monochrome 校准，不是高光重点测光的目标**。

### 2.2 进入算法的是传感器积分统计的 log 网格

静态确认：III 的预处理入口是 `0x53471158`。经校正后的 R/G/B 统计位于 integration 对象的 `+0x14018`、`+0x18018`、`+0x20018`。在 `0x534714d8..0x534714e8`，AE 线性量为：

```text
GR III: Y = floor((247 R_AE + 179 G_AE) / 256)
GR IV : Y = floor((182 R_AE + 223 G_AE) / 256)
L = log2_approx(Y) - 9
```

IV 的对应预处理入口是 `0x5366b0b8`，系数形成位置为 `0x5366b6e0..0x5366b6f8`。两代彩色 AE 的 B 系数都是零。III 另有用于 RGB 可视化的增益和字节 gamma LUT；它不在这条 AE Y 链里，也不能当作 Standard JPEG 阶调。

III 的 log helper `0x536a3cb0` 使用 `0x53d5ac08` 的 Q8 查表。输入 1、2、4、128 分别对应 0、256、512、1792；网格在 `0x534715d8..0x53471608` 除以 256 后减 9。保存的 log 值分辨率为 1/256 EV，底层 log 近似另有量化。因此这里的“平均亮度”是空间加权的 **log 统计**，不是白平衡后 RAW 的算术平均，更不是 JPEG YUV。

在 AE 之前，III 的 `0x536c2a30`，关联 `src/WaveDetectCorrect.cpp`，已经处理：

1. 扣除每格对应的黑位乘样本数，再除以每格有效样本数。
2. 从运行时 Adjust 对象取得工厂 `AwbGain`，R/B 路径使用校准值与固定除数 14104 / 25389。
3. 施加 Q13 空间增益，除数为 8192；后面还有 AE 专用的 64×64 空间表，单位为表值除以 32。

关键窗口为 `0x536c34f8..0x536c3698`，RTTI 为 `0x53d13dc8`，其名称指针关联 `7AwbGain`。这不是 DNG 的最终 AsShotNeutral。`WhiteBalanceFactory.cpp` 的 `GetWhiteBalanceAdjustGain`，`0x53709628`，也读取该运行时对象的两组四通道字段：`+4..+10` 和 `+12..+18`。本轮没有证明这些校准在 DNG 生成链里怎样保留或相消。

### 2.3 点测、中央重点、多分区与高光重点

| 内部模式 | III 入口 | IV 入口 | 已确认的作用 |
|---|---|---|---|
| 0，多分区 | `0x5347ce40` | `0x53676a10` | 多个 log 区域统计，加场景亮度相关修正和限制。 |
| 1，中央重点 | `0x5347b428` | `0x53675e68` | 中央权重图对 log 网格加权。 |
| 2，点测 | `0x5347c4d8` | `0x53675938` | 窄区域的 log 平均，可受 AF/区域设置影响。 |
| 3，高光重点 | `0x5347d1f0` | `0x53676f20` | 亮区统计与多个窗口的最大值混合，并设下限。 |

III 的默认中心点测区域为 64×64 网格的 `[28,36)×[28,36)`，即 8×8。crop 枚举 1、2 时分别缩成 6×6、4×4；AF 联动和区域设置可能改位置。中央重点默认从 `0x53c544bc` 读取 16×16 权重，再扩成 64×64；展开后的权重总和 38528，中央权重 32，边缘为零。完整权重表只保存在 local。

静态确认：四种模式共用曝光服务参考值；这不意味着它们会给同一场景相同曝光。III 多分区的修正函数 `0x5347b5f0`、`0x5347b690` 使用 `x=b+5`：

```text
c(x) = 1.5                  x <= 2
       (5-x)/2              2 < x <= 5
       0                    5 < x <= 12
       -(x-12)/8            12 < x <= 16
       -0.5                 x > 16
```

这里 b 是算法输入，不能未经换算就叫作绝对场景 BV。对默认 crop、无 AF/人脸/区域混合、正值均匀 log 网格 `L`，代码可化成：

```text
M_multi = L + 0.85 c + 0.15 max(c,0) - d
d0 = clamp(0.5 - 0.2 max(c,0), 0, 0.5)
d  = d0                    x <= 12
     d0 (16-x)/4           12 < x <= 16
     0                     x > 16
```

推断，来自静态流程的代数化：取 `b=3`，有 `c=0,d=0.5`，所以多分区要使均匀网格到达 `T×sqrt(2)`，比点测多曝光 0.5 EV。相同条件下中央重点与点测相同。该代数没有运行固件，且不能外推到一般场景或直接套给 IV。

III 高光重点先取全画面、中央 80%、中央 50% 窗口的最大值，再混合亮区均值；其候选含 `0.3×(亮区均值−1)+0.7×(三个最大值的均值−2)`，最终还受 `全局均值+c` 下限约束。均匀网格时下限使输出为 `L+c`；在上述 `b=3` 条件下与点测相同，不能只看前面的减 1 / 减 2 就声称固定少曝或多曝 1.7 EV。

### 2.4 EC、ISO、其他增益与 SOS

III `0x53471220..0x53471238` 把 CommonXv 编码换成内部 EV：

```text
EC = (64 - CommonXv_code) / 8
```

同一个 getter `0x534919cc` 在 `0x53483c08..0x53483c10` 写入 AEInfo 第 6 字节。R0000097 的编码 69 对应 −0.625 EV，不能用 EXIF 显示的 −0.7 代替内部值。

III `0x5346d950` 的积分参数换算包含：

```text
Tv = log2(1000000 / integration_time_us)
Sv = 5 + log2(integration_gain / runtime_reference_gain)
```

积分时间、增益分别来自记录 `+0x9c`、`+0x98`；参考增益来自输入对象 `+0x94`。常数 5 是该 APEX Sv 计算的基准。静态路径还包含输入字节 A9 引起的 Sv 加 1 EV，以及参考值减 1 EV；后者排除内部程序 12、23。另有 AA 标志的 2 EV 项、光圈及运行分支项。**A9/AA 的物理含义和拍摄时序未闭合，本报告不把它们直接命名为 DR 或 ND。**

现有照片中 SensitivityType/SOS 的既有读取结果能说明标签记录了什么；它没有提供 AE 统计到 Standard 118 的校准方程。找到 `ExtractExifStandardOutputSensitivity` 的 III 入口 `0x535d9d38` 也只闭合元数据提取，不能把 SOS 标签或 Sv 的常数 5 当作“点测必出 118”的证明。

## 4. 转成 raw-linear u：方程已写出，校准量还缺

沿用 [gr4_modes](../gr4_modes/REPORT.md) 的约定，`c` 为扣黑位、除白位范围后的相机 RGB，`n` 为 AsShotNeutral：

```text
u0 = (cR/nR + 2cG/nG + cB/nB) / 4
u  = 2^BE × u0
u_c = u × g(r), 且 g(0)=1
```

对于中性、均匀目标，`c_i=n_i×u0`。令 `D=WhiteLevel−BlackLevel`，并把读出缩放、工厂归一化、LV/拍摄曝光与增益比例、点测区域的空间增益合入 `kR,kG`：

```text
R_AE = kR × D × nR × u0
G_AE = kG × D × nG × u0

u_m = 256 × T × 2^BE × 2^EC
      / [D × (wR kR nR + wG kG nG)]

delta_EV = log2(u_m / u_118)
J_Standard = F_Standard(u_m)
```

此式针对普通点测、额外标志偏置为零、不过饱和且忽略整数/log 量化的条件；非零偏置还要加入对应 EV 项。对有限点测窗，k 应代表相应的 log 平均有效增益。多分区还要加入第 2.3 节的算法偏置。`F_Standard` 和 `u_118` 沿用已测曲线，不是本轮新恢复的完整 ISP 渲染器。

静态确认给出了 T、w、256、EC 的方程；**未确认的 kR/kG 正是不能跳过的一段**。DNG MakerNote `0x0200` 的黑位和 `0x0201` 的最终 WB 增益不能代替工厂 AwbGain。bastibe 的最终增益为 `[22240,8192,8192,13888]`，与其 AsShotNeutral 倒数一致；这没有告诉我们 LV 的工厂校准和拍摄读出比例。

| 演示所用常数 | III，bastibe 白平衡 | IV，投稿 A 白平衡 |
|---|---:|---:|
| nR / nG | 0.368345323741 / 1 | 0.449122807018 / 1 |
| D | 16253 | 16253 |
| BE | −0.5059661865234375 | −0.5059661865234375 |
| u_118 | 0.08577678165824383 | 0.08532165829083668 |
| 条件 u_m | 0.090516940207 | 0.082451409162 |
| 条件 delta_EV | +0.077601 | −0.049368 |
| 条件 Standard 码值 | 121.052 | 115.738 |

同样的“除以 4”代理用于 5 张现有 RAW 的 64×64 全图 log 统计，与 AEInfo 的差值分别约为 0.497、0.279、0.583、0.488、1.290 EV。套用既有 JPEG 径向补偿后仍为 0.275、−0.046、0.258、0.163、0.965 EV。帧顺序为 bastibe、B Standard、A 黑白、A 正片、A 负片。它说明该简化没有通过跨场景一致性检查；不能把全部残差归因于某一个工厂增益或 DR 项。

### 4.2 同一张色卡的条件拟合

枚举 III 预处理引用的 34 张 64×64 空间表，再给 R 相对尺度 0.25–4.0 的 257 个候选值。每个模型用一个全局 LV/拍摄尺度拟合 bastibe 的中央重点 log，再检查整图 log 是否在 0.03 EV 内；留下 248 个模型。

在这些额外假设下，条件点测结果为 `u=0.0786140..0.0818034`，相对 III 118 点为 `−0.125801..−0.068426 EV`，Standard 约 `112.453..115.031`。这些范围 **不是置信区间、不是已证实的上下界，也不是独立验证**：同一帧既用于拟合又用于筛选，且假设 2.10 的空间表适用于 1.60，DNG 与 LV 网格几何一致，剩余差异可用一个全局尺度及 R 相对尺度表示。

它与 D4 的 114.84 接近，不足以确认点测灰卡也会出 114.84。先前的 144 / 107 两个 BaselineExposure 假说，也没有被这次未闭合的 RAW 桥选中或排除。

### 4.3 新找到的 DNG 积分网格

静态确认：III 的 DNG 私有 tag `0x0405` 保存 73,740 字节。读入函数 `0x535ecbc8..0x535ecd98` 把其中 `0x2004`、`0x6004`、`0xa004` 的三组 4096 个 u32 复制回前述 R/G/B 积分缓冲区；`0xe004` 保存每格样本数。bastibe 的头部为 64×62，有效 3968 格，每格计数 1504。完整数组只保存在 local。

对这份已保存网格，不再另加空间校正时，按 III 系数算出的整图 log 均值为 0.783778，中央重点为 0.019749；它们分别比 AEInfo 对应值低 0.091222、0.109158 EV。网格的采集时刻和后续改写链未闭合，不能直接把差值命名为曝光补偿。

进一步按每格 47×32 个半分辨率 RAW 样本做几何拟合，R/G/B 的拟合斜率约为 0.3249 / 0.3333 / 0.3285，同时仍有约 73 / 204 / 126 个积分单位的 RMS 残差。格大小、对齐和仿射参数都在同一帧上推定，这没有通过精确的 RAW 对照，也没有提供最终 kR/kG。这份网格与读入路径是后续继续追校准链的具体入口，不能当成闭合后的新灰点。

## 5. 置信度、准确缺口与后续入口

| 结论 | 证据等级与置信度 |
|---|---|
| 两代彩色 AE 参考值、log 单位、R/G 系数。 | 静态确认，高；常数、调用和算术链可逐地址复核。 |
| IV 的 478 属于 Monochrome。 | 静态确认，高；产品类型与名称描述符闭合。 |
| AEInfo 布局与 34 帧测光枚举一致。 | 静态确认，高；写出链和原始记录相符。 |
| 现有 P/A/S 标签记录支持参考值。 | 观测一致性，中高；5 张标签一致，另 1 张冲突，没有合格点测灰卡。 |
| 均匀场景下多分区可能比点测多给 0.5 EV。 | 静态代数推断，中高；限 III 和明确的输入/分支条件。 |
| 点测目标在 DNG u 与 Standard JPEG 中的位置。 | 未知；121/116 和 112–115 都只是在额外假设下的数。 |

还缺的具体连接是：**WaveDetect 原始积分及硬件读出 → 工厂校准后的 AE R/G → 同次拍摄全分辨率 DNG 的 cR/cG**。要在静态线上闭合，需要继续追到：

1. 积分原始值的位深、每格计数、黑位与模拟/数字增益来源，明确 LV 与拍摄模式的比例。
2. `0x536c2a30` 读取的工厂 AwbGain 两组字段，在 DNG RAW、AsShotNeutral 和相关硬件增益中的保留或相消关系；相关通用 getter 是 `0x53709628`。
3. 运行参考增益 `input+0x94` 的生产者，以及 A9/AA 标志、tag `0x0405` 网格和 AEInfo 各自的保存时序。

若运行工厂数据确实是不可消去的独立量，就需要恢复该校准数据及对应读出状态，才能只靠固件和现有文件给出数值。另一条能直接闭合结论的证据是一组设置可核实的零 EC、中心点测均匀灰卡 DNG 与默认 Standard JPEG；本轮没有该数据，也没有接触设备。

因此本轮没有为 GXR 生成新的曝光位移、曲线或 DAT。GXR 已知的 `u_m≈0.1025`、Stock JPEG≈137，与这次 AE 统计常数不在同一单位里，不能直接相减。

## 6. 交付与复核

公开交付只有本报告、[metrics.json](metrics.json) 和 `.gitignore`。私有 [local/](local/) 保留输入镜像、ZIP、Target.DNG、照片统计快照、64×64 网格、校准线索、带 VMA 的反汇编窗口和复现脚本，不依赖 `/tmp` 保留结果。

从仓库根目录复核本轮已保存的证据与数值：

```sh
python3 -I research/gr_ae_target/local/verify.py
python3 -I research/gr_ae_target/local/spatial.py
python3 -I research/gr_ae_target/local/derive.py
```

`verify.py` 核对输入 SHA-256、两组载荷零和、反汇编机器字与镜像、参考常数、产品描述符、AEInfo 复制、照片记录与公开数值，以及 local 忽略规则。`spatial.py` 是条件模型枚举；`derive.py` 由冻结证据生成 metrics，最终 RAW 锚保持 null。首次输入获取脚本 `prepare.py` 按既有清单重建官方包，网络下载不是离线复核前提。

逐文件 SHA-256 在 [local/SHA256SUMS](local/SHA256SUMS)，复核结果在 [local/verification.json](local/verification.json)。这些检查验证静态证据和计算，没有代替相机、SD 或 GXR 配方的真机验收。
