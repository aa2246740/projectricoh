# 午间实拍复核 r2

完整配方比较已恢复：03 HC BW、M9 STD、HNCS HiCon 最接近现行预测，06 F-CN 偏离最大；本批没有真人皮肤、蓝物体或树叶实拍，不能关闭这三项实物验收。

绑定 g156 test DAT SHA-256 `0f4f26d4cd3669915b41ce8e38260a61c60c590e2c581cb72e93f52a2ac631f7`。最终值全部来自冻结的 Python `Model.predict(..., quantize=False)` 参考链，03 明确丢弃色度，使用实际 MOUNT 原生 03 记录。没有重拟合或改 DAT。

输入为 84 对 DNG 与 JPG，168 文件逐一通过原 SHA256SUMS。实际有 74 张标准屏幕页、1 张额外非网格屏幕画面、9 张笔记本前色卡照。所有照片 EXIF 为 M 档、ISO 200、1/20 秒、日光 WB；光圈记为 0，f/5.6 只能保留为机主口述。照片不能证明机身固件版本或实际装载 DAT 的哈希。

本报告衡量相机 JPEG 与现行预测的一致程度，不衡量配方与胶片、HNCS 或场景真实颜色的接近程度。每块 04 JPEG 反演后，以逐通道 RAW_WB 比值校正输入。主测中央 40%，另验 30% 和 50%。sRGB 经 Bradford 转 D50 Lab，DE00 使用 kL=kC=kH=1。ΔL、ΔC、色相均为实拍减预测，正 ΔL 更亮、正 ΔC 更艳，正角沿 Lab 逆时针。

## 首轮失败与修复

首轮有 14 帧提取失败，main 因屏幕失败将全部未手动确认设置标为 order_untrusted；analyse 在预测前逐帧 continue，所以 identity 中只有空 scores 和 unknown，比较行数为 0。它不是“所有配方响应都无法识别”。固定每八张分组还忽略 R8051974 的额外画面、计划外 03 HC BW，以及 Kodachrome25 与 HiCon 的实际先后。

r2 用逐帧 manifest 固定设置、页码和组号，保留响应冲突判定。页角文字能独立识别黑白帧，不再被彩色图案阈值否决；R8051999、2001、2003、2005 已恢复。加入实际 MOUNT 03 参考记录，确认 manifest 与自动识页的冲突会留痕，正式 manifest 不再被程序生成的草稿覆盖。R8051974 不是网格图，作为已解释的排除项。

小色卡还触发了旧屏幕取样器的大于 300 像素断言。新增实体专用门要求至少 128 总像素、每 CFA 颜色至少 32 样本，4×4 子区 CFA 不得为空；保留屏幕原门。合成回归保留故意错配帧并成功报冲突，九条参考记录另写链式计算得到相同 RGB。实体九帧独立复提取与最终帧 JSON 的全部字段逐值相同，忽略对象键顺序。

## 对 g157 的建议

1. 保留 M9 STD、HNCS HiCon、原生 03 HC BW 的 g156 记录；本批没有证据要求为它们改曲线。Kodachrome25 整体接近，但蓝色低彩度尾部仍需保留为留出。
2. 优先查 MOUNT 的 05 F-CC、06 F-CN 蓝青高彩度响应，再查 LowSat 和 Vision3 的相同色域。先修预测链或建立受输入范围和色相限制的校准，保留这次未参与拟合的页面作留出，不把整幅曝光或统一 RGB 倍率写成补偿。
3. 本批没有定义新的合格门，也没有证明任何新记录优于 g156。保持 round3_mount 的“g157 无新增合格 MOUNT 候选”结论；不要用本批配方识别正确或屏幕低误差推翻既有逐场景、量化和历史残差门。
4. 肤色 R+ Cb、蓝色 B+ Cr 的单通道缺口继续 OPEN。需要同会话独立扰动与 04 参照，以及真正的皮肤、蓝物和树叶照片；本批完整配方与印刷卡不能给这两处机制结案。

## OPEN

- 缺真人皮肤、蓝物体、树叶及口述的额外两张室内照片。实际实体部分只有九张卡片，不能还原未交付照片。
- 除 T1、V1 外，屏幕页缺独立尾 04；六张初始 04 页没有独立响应校验，未过余量门的配方帧留在逐帧清单。
- 屏幕是 P3-D65 预设的机主陈述，没有光谱或亮度校准；不以 CSS Lab 当屏幕实色。卡片未认证且离焦、尺寸较小，真实物体的光谱迁移未测。
- MOUNT 仍使用迁移参考模型，逐块 04 反演和 RAW 比值是条件建模。未知中间漂移、JPG 色度量化和多字段耦合不由本批关闭。
- 机身 v3.10、f/5.6、机内实际加载 g156 的哈希没有独立设备证据。本轮没有访问相机、SD 卡或网络，没有安装依赖、commit 或 push。
