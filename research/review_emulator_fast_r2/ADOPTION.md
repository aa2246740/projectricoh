切换方式

先关闭 REVIEW.md 中的 P1，再冻结新的源码、CPU 库、传输扩展和全部文件输入，重跑反例与整机工作负载。默认入口应指向完整的 `tools/gxr_emulator_fast/fix_r1/launch.py`，保留候选目录层级。不要把候选文件直接覆盖到父目录。当前候选依赖该层级计算项目根，也绑定具体构建路径。

以下命令只说明显式选用候选的方法。本轮只读复审没有改默认入口。

```sh
GXR_FAST_MODEL_FIXES='' GXR_EMULATOR_BATCH=1 \
  nice -n 10 /usr/bin/python3 -I -B tools/gxr_emulator_fast/fix_r1/launch.py \
  --backend native CALLER.py ARGUMENTS
```

参考复核在新进程中运行，使用相同文件字节、设置、按键序列、模型修正和独立可写虚拟介质。

```sh
GXR_FAST_MODEL_FIXES='' GXR_EMULATOR_BATCH=1 \

```

`launch.py` 当前会把不足 15 的 nice 值调为 15；本轮验证脚本直接导入候选，实际 nice 为 10。四项模型修正默认全关，需要时显式填写 `nand-word,preview-link,sd-long-response,nand-read-tail` 的子集，两边保持一致。修正后的模拟结果仍属于相应模型假设。

如果以后调整目录层级，应一并核对所有项目根、资源路径、构建参数和动态库身份，再重新验收。源码或库改变后，旧快照不能沿用。

参考执行范围

- 调度链缺层、顺序改变、未知方法或覆盖层、未审定的观察回调和调试扩展，使用参考后端。候选能自动处理一部分情况，但本轮发现 StepHook 调度方法和模块常量的变化仍可能被接受。
- 跨运行保留可变容器引用或共享容器关系的调用方，使用参考执行。普通保留引用已能触发回退；共享 tuple 内的可变对象仍有遗漏。修改引用关系的任务也必须重新验收。
- 超出原生设备算术范围的大整数和整数子类使用参考执行。字符串等不符合活动字段类型的值不得交给原生推进，先在参考侧确认错误。
- 逐步调试及需要完整调试记录的任务使用参考后端。未知 Python 回调可能形成混合执行，不能只凭原生模式的环境变量声明全程 C。

记录实际模块路径、库和源码 SHA256、模型修正、原生指令数、总执行步数、Python 总线回调、HLE 回调及 batch_stats。原生比例用实际原生指令数除以实际执行步数。保留一份面板记录引用就可能让现有调用方整段回到参考执行；观察记录中的共享 args 也会触发回退。提速必须按调用方实测。

结果复核

当前候选用于结论的结果均须在参考后端复核。关闭 P1 后，FAIL、OPEN、DeviceBoundary、fault、超时、未达到业务目标的预算耗尽和无法解释的停点仍须强制参考复核。保留第一次失败，区分固件行为、共同模型边界和后端差异。同一失败终点不能算作业务流程成功。

快照复用

- 所有实际文件输入用 `pathlib.Path` 传入 Inputs，包括机身、DAT、单元 ROM、设置、NAND、SD 种子、驱动和模型源码。普通字符串只作为配置值，不会读取其所指文件。
- 每个任务、后端、模型配置和构建使用独立的缓存目录及独立介质。由新建实例加载，核对输入键、压缩与展开内容、完整 SD、NAND 和整机状态。首次复用须与同后端冷启动及连续推进逐点比较。
- 模型修正、模块常量、函数、默认值、闭包、Python 版本或架构变化后，建立新身份与新快照。当前键没有覆盖所有运行期变化，不能把键相同当成行为相同。
- 当前快照不能用于含共享可变对象关系的状态。原生和参考的快照恢复都可能拆开共享关系，且值哈希不变。此类任务先关闭快照复用，从冷启动参考执行。不得靠修改元数据接受旧快照。
- 正式运行不使用来源不明或仅供调试的续跑。长流程按检查点拆成预计不足 30 分钟的段，每段保留输入身份和完整比较结果。

任务切换

使用新 Python 进程，不在已经导入另一后端、另一套模型或旧目录模块的进程中改环境变量。先确认实际模块路径，再运行目标任务。保留旧入口作为回退方案；不要共享其他任务的可写虚拟 SD、快照缓存、日志或临时目录。并行任务的目录只读。

本说明只覆盖宿主模拟器。成功完整恢复、存储卡、实卡 FAT32、真实 SD、刷写与断电、相机 RTOS/LCD、物理按键和拍摄均不在本轮验收内。
