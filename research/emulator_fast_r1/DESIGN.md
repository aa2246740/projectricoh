# 原生执行与状态边界

调用方继续使用 `Machine`、`Backend.run()`、`snapshot()` 和原有回执字段。`GXR_FAST_BACKEND=native` 选择原生执行，`reference` 选择副本中的 Python 设备参考路径。已有批量目录保持只读。

CPU 继续使用 GNU M32R 的解码和指令语义。`scalar_semantics.inc` 从冻结的 GNU `sem.c` 生成，普通内存直接访问共享 backing。每条指令比较缓存中的原始字节，执行代码被写入后会重新解码。

原生机器持有全部设备状态，MMIO 分派、设备推进和截止步调度都在 C 中。`wire.py` 与 `value.c` 传输带类型的状态，保留 dict、Counter、list、tuple、deque、bytes、bytearray、set、整数等差别。Python 只在 run 的边界导入或导出状态。未知的调用方回调属于显式 HLE 边界，必须计数和计时；不能静默省略。

虚拟 SD 文件由 Python 在调用方声明的目录中打开，原生侧只接收文件描述符。固件、下载包和真实介质路径不传给原生写入逻辑。NAND 为内存中的稀疏页。快照包含 NAND 和 SD 差异，并以所有运行输入和模拟器源码、库的 SHA-256 绑定身份。

考虑过两种组织方式。直接逐个移植成 C 结构体可以减少动态字段访问，但每增加一个模型字段都需要维护独立序列化和恢复逻辑。采用保留原状态类型的 C 值容器，可以直接比较完整模型状态；高频 CPU、时钟和 IRQ 使用固定结构，低频设备用该容器。后续剖析决定是否需要将更多字段固定化。

所有 C 执行都必须经过与参考模型的分段对照，才进入端到端计时。性能、模型等价、恢复完成、快照续跑和串并行一致分别判定。
