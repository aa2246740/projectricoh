# 严格原生合同

本轮只给已登记的 GXR 固件流程提供原生执行。未登记的 Python 定义和可变状态操作在进入 C 前报错，调用方显式选择参考后端。不会把拒绝改成自动回退。

## 调用方式

```python
from native_input_run import run
run(args)  # 按键、Flow、观察、检查点及结果格式与 input_run 对照
```

已有 input_run 使用参考后端。底层 Machine、Panel、Observer 与设备工厂属于登记表，CPU 的内存和寄存器接口保持明确的输入边界。设备、面板和观察状态从构造完成起只允许读取只读副本；按键与初始化由登记的控制接口处理。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| registry.py / NATIVE_REGISTRY.json | 冻结全部参与源文件，列出模型组合、调度链、函数定义及模块命名空间。按精确登记验证，拒绝未知定义。 |
| ownership.py | 原生对象的所有者、内部访问域、复制的只读视图与明确的写入错误。参考执行保留 Python 所有权。 |
| native_controls.py | 登记的按键、单元和设置输入、观察与停止声明。外部函数不能仅复制标记获准执行。 |
| native_machine.py | 根据登记表绑定固定 C ABI；严格运行没有自动回退或未知 Python 指令执行。旧自动路径仅由显式 auto 选项进入。 |
| native_input_run.py | 使用原生控制与 C 中的 Panel、Observer、Flow 累积记录，结束时导出副本。 |
| snapshots.py | 身份含所有模型文件全文哈希、覆盖层和登记表；拒绝无法表示的 Python 共享/循环状态，恢复前验证。 |

## 两种实现的取舍

继续扩大原有资格判断会继续承诺任意 Python 行为和对象关系，需要在每次同步保留调用方别名。该方案延续第二轮反例的前提，舍弃。

采用冻结登记表与 C 所有权。登记表在独立的干净进程中从最终源码生成；运行期只做精确匹配、输入类型与范围检查。只读副本没有实时引用语义。调用方需要可变设备引用、未知包装或自定义调度时，用参考后端。

## 必须证明的行为

两轮反例必须保持相同结果或在推进、恢复前明确拒绝。真实冷启动、菜单、GPIO/SD、BOOT_RUN、H52、恢复确认页及 native_input_run 必须与参考逐点全状态相同，并记录实际原生指令数。MAIN 与完整驱动各三对交替计时。源码与库冻结后从头验收，不复用中断运行。
