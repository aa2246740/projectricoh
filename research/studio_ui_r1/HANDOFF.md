## 2. 哪些交互必须实时（拖动时每一帧都要跟上）

| 交互 | 画面怎么变 | 帧内要做的事 | 什么时候存盘 |
| --- | --- | --- | --- |
| 拖调整滑块、曲线控制点 | canvas 立即重画 | 只改 GPU uniform 或曲线 LUT 纹理，**不发网络请求** | 松手后防抖 300ms，再 `PUT /edit` |
| 拖配方强度和配方旋钮 | 同上 | 同上（配方表已经在显存里） | 松手 |
| 点配方格、Looks、我的配方 | 立即换效果，不转圈 | 换 3D LUT 纹理（预先加载或用缓存） | 立即 |
| 悬停配方格（可选，LR 的做法） | 画面临时预览这个配方，移开恢复 | 换纹理 | 不存 |
| 拉直刻度盘、拉直 / 垂直 / 水平 / 畸变滑块 | 画面跟着转或变形；裁剪框实时收进有效区域 | 改几何 uniform；有效区域在前端算（`geom.js` 已经有） | 松手 |
| 拖裁剪框、角把手 | 框和尺寸读数（`3600 × 2400`）跟手 | 只动 DOM 覆盖层，不重画照片 | 松手 |
| 边框、时间戳的选项 | 画面立即更新 | 边框和时间戳画在照片 canvas 外面的覆盖层上（2D canvas 或 DOM），不重画照片本体 | 立即 |
| 按住空格 / 按 `\` | 立即换成原图 | 切 shader 旁路，或者显示已经缓存的原图纹理 | — |
| `Y` 左右对比、拖分隔线 | 分隔线跟手 | shader 里按 x 坐标分两半；不要放两个 canvas | — |
| 背景色点 | 立即 | 改一个 CSS 变量 | 存在本机浏览器 |
| 胶片条和图库滚动 | 60fps | 虚拟列表；缩略图懒加载 | — |

拖动中的数值显示（滑块旁的数值、气泡、裁剪尺寸）用 `textContent` 直接改，不要重建节点。

## 3. 避免整块重画（只更新变化的部分）

现在的代码是 `view.replaceChildren(...)` 加上 `panel()` 整块重建。拖动一个滑块会重建整个面板，再向后端要一张新 JPEG，这就是"转圈 + 整块刷新"的来源。建议这样拆：

1. **四个区域各管各的。** 顶栏、画面、右侧面板、胶片条各自是独立的组件，只订阅自己关心的状态：
   - 画面订阅 `edit` 和 `viewMode`；
   - 面板订阅当前标签和 `edit`；
   - 胶片条订阅照片列表和当前照片；
   - 顶栏订阅照片元数据、撤销栈和存储卡状态。
2. **控件建一次，之后只改值。**
   - 面板第一次打开时建好所有控件，之后 `edit` 变化只调各控件的 `setValue()`；
   - 切换标签只切 `hidden`，不销毁，所以滑块位置、折叠状态都还在；
   - 换照片只更新值和可用状态，不重建面板。
3. **画面是一块固定的 canvas。** 换照片换纹理；改参数改 uniform；改窗口大小只改 canvas 尺寸。
   - 不要用 `<img src=blob>` 来回换图，那样每次都要解码、都会闪。
   - 换照片时先显示缩略图纹理，高清纹理到了再无缝替换，不出现空白和转圈。
4. **覆盖层和照片分开。** 裁剪框、参考线、边框、时间戳、"原图"标签、对比分隔线都在 canvas 上面的覆盖层里。改这些不碰照片 canvas。
5. **缩略图实时渲染要节流。** 配方格和边框卡片的缩略图按需渲染：
   - 首选：在同一个 GPU 上下文里把小纹理渲染到离屏 canvas，再 `toDataURL` 或 `ImageBitmap`；
   - 不行就用后端 `size=thumb`，但要缓存；
   - 换照片时先保留旧图，新图到了再换，不清空。
6. **列表做差量更新。** 图库网格和胶片条按照片 id 复用节点（keyed），新导入的照片插进去并淡入，不整表重画。
7. **撤销栈只存差量**（参数快照），撤销时走第 2 条的 `setValue()` 路径，不重建。
8. **定时器收敛。** 现在有 0.8 秒、1 秒、3 秒、15 秒几个 `setInterval`。
   - 存储卡状态改成"变化时才更新存储卡状态这一处"；
   - 导入进度只更新圆环的 `stroke-dasharray` 和计数文字。

## 4. 拍摄配方：数据和显示

### 4.1 需要后端提供的字段（建议，待编排者定合同）

```json
"shot_recipe": {
  "source": "camera" | "inferred" | "unknown",
  "kind": "builtin" | "look" | "user" | null,
  "slot": 5,                 // 内置配方编号；Looks 用 id
  "name": "05 富士 CC",      // 显示名，后端格式化好
  "confidence": 0.83,        // 只有 inferred 才有；0–1
  "candidates": [{"name": "06 富士 CN", "confidence": 0.61}],  // inferred 时的其他候选
  "knobs": {"contrast": 1, "saturation": -1},                    // 机内微调；没有记录就是 null（不是全 0）
  "evidence": "exif" | "card_log" | "fit"                        // 只给"详细信息"折叠区，不放主界面
}
```

- 照片列表接口（图库、胶片条）只需要 `source`、`name`、`confidence`。完整对象只在 `/meta` 或信息面板里取。
- 筛选和分组：
  - `GET /api/photos?shot_recipe=<name>&source=camera|inferred`；
  - 侧栏计数用 `GET /api/shot-recipes`，返回 `[{name, camera, inferred}]`。
- **和电脑编辑分开**：`shot_recipe` 是只读的拍摄事实，`edit.recipe` / `edit.lut` 是电脑上的编辑。字段名、显示位置、颜色都分开（第 4.2 节）。

### 4.2 显示规则

| 位置 | 相机记录 | 推断 | 未知 |
| --- | --- | --- | --- |
| 图库角标 | `📷 05 富士 CC`（实底） | `≈ 02 GR 负片`（虚线框）；可信度 < 60% 时不显示 | 不显示 |
| 胶片条角标 | `📷 05` | `≈ 02` | 不显示 |
| 编辑页顶栏 | `📷 05 富士 CC · 相机记录` | `📷 ≈ 02 GR 负片 · 推断 83%`（虚线框） | `📷 拍摄配方未知` |
| 配方面板顶部 | "拍摄配方 05 富士 CC [相机记录]"，对应的配方格带相机标记 | 同左，标签是"推断" | "拍摄配方 未知" |
| 信息面板 | 名称 + 来源 + 机内微调（8 项，0 值变灰） | 再加"其他候选" | "未知" |
| 侧栏筛选 | 每个配方一行，计数含两种来源；最后一行"未知" | | |
| 按拍摄配方分组 | 组标题写"相机记录 N · 推断 M"；顶部用分段控件筛"全部 / 相机记录 / 推断" | | |
| 两张比较 | 每张下面写拍摄配方、机内微调、电脑编辑 | | |
| 视图选项 | 角标开关：拍摄配方 / 文件类型 / HDR / 已调整；推断门槛 | | |

- Looks 没有编号，显示名字；我的配方显示名字。如果以后机内能装我的配方，也走同一套规则。
- 可信度显示整数百分比。门槛 60% 是设计建议，要等推断算法的实际校准结果再定。

## 5. 跨平台实现要点

- **快捷键**：
  - 用 `e.metaKey`（Mac）或 `e.ctrlKey`（Windows）判断主修饰键，平台用 `navigator.userAgentData?.platform ?? navigator.platform` 判断；
  - 提示气泡、快捷键表、菜单里的键帽都从同一张表生成（设计稿里是 `sc()` 和 `KEYS`）。
- **不要占用的键**：
  - 浏览器保留键：⌘/Ctrl + W、T、N、Q、L，Ctrl+Shift+I/J，F11、F12；
  - Ctrl+E 在 Windows 版 Chrome 里是"搜索"，要 `preventDefault()`。本轮没有在 Windows 上实测能不能拦住，实现时要在 Chrome 和 Edge 上各确认一次。
- **滚动条**：给 `.panel-body`、`.sidebar`、`.grid` 加 `scrollbar-gutter: stable`，用 `::-webkit-scrollbar` 画统一的 10px 灰色滚动条（见 `.win` 规则；正式实现对所有平台生效即可）。
- **原生控件**：下拉、日期选择、颜色选择全部自己画，不用原生 `<select>` 和 `<input type=date>`。
- **字体**：令牌里的字体栈已经覆盖两个平台。Windows 上要实测一次面板标签宽度（微软雅黑比苹方宽）。
- **文案**："推出 / 弹出"和"在访达中显示 / 在文件资源管理器中显示"要按平台选，等编排者确认。
- **路径显示**：Windows 用反斜杠，`%USERPROFILE%` 显示成真实路径。

## 6. 落地顺序建议

1. 令牌和基础组件（按钮、滑块、分段、开关、下拉、对话框、提示条）：纯 CSS 和 JS，不改接口。
2. 布局：新顶栏（合并横幅和底部状态栏）、视图工具栏、胶片条、工具标签。"导出"标签改成对话框。
3. 接实时预览引擎：画面换成 canvas，按第 3 节拆分刷新。
4. 拍摄配方：先做"未知"和"相机记录"两种状态的显示；推断等算法就绪后再接。
5. 比较视图、左右对比、视图选项、Windows 细节。

每一步都对照 `screenshots/` 做截图比对，并重跑 `tools/audit_targets.py` 和 `tools/contrast.py` 的检查口径。

## 7. 需要编排者拍板的设计选择

1. **"导出"从标签改为对话框，右侧面板加"信息"标签。** 功能都还在，⌘E 不变。
2. **胶片条只放在画面下方**，不跨到右侧面板下面。
3. **快捷键**：裁剪仍用 C、参考线仍用 G，不改成 LR 的 R / O。
4. **新增的交互**：
   - `\` 切换原图、`Y` 左右对比、`Z` 适合 / 100%、`C` 比较两张；
   - 画面背景三选一；
   - 图库缩略图大小；
   - 视图选项。
5. **HDR 角标**：本轮按任务要求画了，但现有数据里没有"这张有 HDR"的字段。可能的含义有两种：
   - 上次导出用了 HDR；
   - 这张能导出 HDR（有 RAW）。

   第二种和"有 RAW"重复，建议用第一种，或者干脆不要这个角标。
6. **推断门槛 60%**，以及推断角标的样子：虚线框 + `≈`。
