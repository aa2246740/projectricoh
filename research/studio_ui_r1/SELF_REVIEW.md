## 1. 对照 Lightroom / Capture One / Snapseed / 苹果"照片"

| 方面 | 参照的做法 | 本设计 | 一致 / 有意不同 | 理由 |
| --- | --- | --- | --- | --- |
| 整体配色 | LR、C1 深灰界面，照片周围中性灰 | 全部 R=G=B 中性灰，画面背景比面板亮一档；可切 18% 灰或黑 | 一致 | 看颜色的前提。LR 右键画面背景换色，这里改成视图工具栏上三个色点，点一下就能换 |
| 画面背景 18% 灰 | C1 和 LR 都能设中灰 | `#767676`（L\* ≈ 50） | 一致 | 判断曝光和色偏时用 |
| 工具位置 | 苹果"照片"、Snapseed 工具在右侧；LR 右侧面板；C1 左侧工具 | 右侧 340px 面板，顶部 6 个图标 + 文字标签 | 一致（苹果 / LR） | 机主最熟悉 iPhone 照片；文字标签对很少修图的人更友好 |
| 调整面板分组 | 苹果：光效 / 颜色 / 黑白；LR：基本 | 光效（曝光、对比度、高光、阴影、黑点、暗角）、颜色（饱和度、自然饱和度、色温、色调）、曲线 | 基本一致 | 用苹果的组名。"暗角"在苹果里单独一组，这里只有一个滑块，放进光效里，免得单独一组只有一行 |
| 滑块 | LR、C1：标签 \| 轨道 \| 数值，一行；双击标签复位；点数值输入 | 一样的一行布局，中心零点，拖动时有数值气泡 | 一致 + 增强 | 数值气泡是苹果 / Snapseed 的做法，拖动时眼睛不用离开滑块 |
| 改动提示 | LR：数值变白；苹果：滑块变黄 | 标签和数值从灰变白；工具标签右上角小蓝点 | 一致（LR） | 不在界面上加彩色，保护看颜色 |
| 配方选择 | 苹果滤镜：一排实时缩略图；LR 预设：列表，悬停在导航器预览 | 4 列实时缩略图平铺：内置配方 → Looks → 我的配方，一层到底 | 一致（苹果）+ 按要求平铺 | 机主说"二级麻烦"；缩略图就是效果，不用读名字 |
| 拍摄配方 | LR、C1 只显示相机型号和曝光参数，不认胶片模拟；富士用户靠第三方插件看 FilmMode | 缩略图角标、胶片条、顶栏、信息面板、侧栏筛选、按拍摄配方分组、两张并排比较，全部显示 | 有意超出 | 机主的原话：好多色彩本来就接近，还没标识，想做测试都分不清。这是本工作室独有的需求 |
| 裁剪 | 苹果：画面下方拉直刻度盘，右侧比例；LR：R 键、O 换参考线、X 横竖 | 拉直刻度盘放在画面下方（苹果）+ 面板里的精确滑块；X 横竖（LR） | 一致 | 两种习惯都照顾到 |
| 裁剪快捷键 | LR 用 R | 沿用现有的 C；R 是"配方" | 有意不同 | 保留机主已经在用的键位；LR 的 R 在这里没有意义 |
| 参考线切换 | LR 用 O 循环、⇧O 转方向 | 沿用现有的 G 循环、O 转螺旋方向 | 有意不同 | 不改已有习惯。如果编排者愿意对齐 LR，改一行键位表就行 |
| 原图对比 | 苹果按住；LR 按 \ 切换、Y 左右 | 按住空格看原图（COPY 规定）；\ 切换；Y 左右对比，中间分隔线可拖 | 一致 + 新增 | 三种习惯都能用。LR 里空格是放大，这里不跟 |
| 缩放 | LR：Z、"适合 / 100%" | 视图工具栏右侧"适合 / 100%"，Z 切换 | 一致 | 看锐度和噪点需要 100% |
| 两张比较 | LR 图库 C 键"比较视图" | 选两张按 C，左右并排，每张下方写拍摄配方、机内微调、电脑编辑 | 一致 + 增强 | 满足"对比两张照片时并排显示各自的拍摄配方" |
| 胶片条 | LR 底部全宽；C1 可选 | 只放在画面下方，不跨到右侧面板下面 | 有意不同 | 面板多 92px 高度，配方面板不用滚动就能看到更多 |
| 导出 | LR 对话框；苹果菜单 | 对话框（⌘E），顶栏常驻一个主按钮 | 一致（LR） | 原来的"导出"标签挪成对话框，右侧面板只放编辑工具 |
| 撤销 / 复原 | 苹果：编辑页顶部有"复原"；LR：左下角"复位" | 顶栏左侧：撤销、重做、复原 | 一致（苹果） | 和"照片"返回放在一起，位置固定，不会随标签变 |
| 进度 | LR：左上角细进度条；苹果：侧栏里的小圆环 | 存储卡状态变成圆环 + 计数，点开看详情 | 一致（苹果） | 解决原来那条突兀的绿线 |
| 图标 | LR、C1 用自家图标；苹果用 SF Symbols | Lucide（ISC） | 有意不同 | 开源许可，Windows 上也能用 |
| 浅色模式 | 苹果跟随系统；LR、C1 只有深色 | 只有深色，不跟随系统 | 一致（LR / C1） | 旧界面跟随系统变成浅灰，看颜色不准（机主截图就是这个状态） |
| Windows | LR、C1 两个平台外观一致，只有修饰键不同 | 同一套像素；修饰键、字体、"推出 / 弹出"按平台变 | 一致 | 机主新要求 |

## 4. 可点元素 ≥ 28 px

检查：`python3 -I tools/audit_targets.py`。

- 方法：给每张设计稿注入测量脚本，用无界面 Chrome 在 1728 × 1117 下读出所有可见可点元素的实际尺寸。
- 统计的元素：按钮、链接、输入框、`role=button/switch/slider`、下拉、配方格、边框卡片、图库格子、胶片条缩略图、侧栏行、菜单行、存储卡状态。
- 结果：**19 张图，共 935 个元素，小于 28 px 的 0 个。**

第一版的审计发现了这些问题，已经全部改掉：

| 问题 | 改法 |
| --- | --- |
| 滑块数值框 22px | 改成 28px |
| 滑块轨道 16px | 可点高度改成 28px；滑块整体改成 LR 式一行布局 |
| 分段控件每段 24px | 改成 28px，用透明边框让选中块看起来仍是 24px |
| 画面背景色点 24px | 改成 28px |
| 图库勾选圈 20px | 外层改成 28px |
| 裁剪角把手 22px | 改成 28px |
| 图标按钮按下时缩到 98%，只剩 27px | 图标按钮按下时不再缩放 |

审计不统计的两处，靠实现保证：

- 裁剪框四条边中间的把手，视觉是 28 × 3，靠伪元素把可拖区域扩到 28px。
- 拉直刻度盘是 420 × 44 的整块拖动区。

## 6. 已知局限

- 设计稿里配方和 LUT 的效果是 **CSS 滤镜示意**，不是真实渲染；缩略图色调只表示"会变"。
- 拍摄配方的数据（哪张是相机记录、哪张是推断、可信度多少、机内微调值）是**示意数据**，不代表这些照片的真实拍摄配方。
- Windows 那张图是在 Mac 上用 Chrome 截的，本机没有 Segoe UI 和微软雅黑，所以字形仍然是苹方。截图展示的是：
  - Windows 的快捷键写法和平台叫法；
  - 常显的滚动条；
  - 1920 × 1080、100% 缩放下的布局。

  字体退路已写进令牌。上线前要在 Windows 实机上看一次微软雅黑下的宽度：雅黑比苹方略宽，面板标签留了余量。
- 时间戳的数码管字体用的是仓库里的 DSEG7（OFL）。边框上的 RICOH 标志用仓库里的 Wikimedia 公有领域 SVG，商标说明见 `studio/src/gxr_studio/assets/SOURCES.md`。
