# diag v3（generation 133）：记录每次打开菜单

目的：查清楚为什么拍完照后第一次推 ADJ 会出现原厂菜单。

## 和 v21 的区别

- 每次进入 `ig_menu` 时，在出口之前把进入时的原生列表状态和退出点记成一条记录，最多保留三条。
- 新增 `G`、`I`、`J` 三页，显示本次打开之前的三次尝试；打开时冻结，切页时不变。DISP 顺序为 `G I J A B C D F H`，打开时先显示 `G`。
- 堆页不再因哨兵状态字节判 BAD：原生初始化 `0x2005BF00` 从不写 base+4，分配和释放也不读它；真机上这里是开机残留值。`OK` 行第 7、8 列显示该字节。
- 新增读取都是固定原生地址；视图槽只在数组等于 `0x205A279C` 且 count 为 1..2 时读取。只写自己的 BSS，不增加服务调用。

## G/I/J 页

| 行 | 内容 |
| --- | --- |
| 1 | 页字母、该次打开序号（4 位）、空格、结果 |
| 2 | 首个失败服务返回码低 16 位（4）、root flags（2）、root state（2） |
| 3 | `*(u32*)0x2022F5A8` 列表名表 |
| 4 | `0x2022F5AC` 行数、`0x2022F71C` 种类、视图 count、栈顶 tag（各 2） |
| 5 | `ui_restore[6]` |
| 6 | `ui_restore[0]` |
| 7 | `0x205D9BF8` 低 16 位（4）、`0x205D9C00` 低 8 位（2）、`0x205A280F`（2） |
| 8 | 栈顶 state 字（count 不在 1..2 时显示数组地址） |

结果：`K` 成功；`D` seed 失败；`1`/`2`/`5` render 内所有权检查失败；`3`/`4` UI_TEXT 失败；`6` UI_LIST 失败；`O` 发布后不再拥有；`P` 采样或二次渲染失败。没有记录说明 resident 没有调用本 DAT（门禁在 DAT 之前）。

## 验证

- 构建：`/usr/bin/python3 -I -B firmware/engine_diag_v3/build_diag.py` → DAT `934d48a3…`，23,028 B，BSS 26,684 B（比 v21 多 312 B，全部在结构末尾，前段偏移不变）。
- 模拟器（固定机身 50720c80 + 真实 resident）：`research/diag_dat_v3/artifact_v3.py`，50mm、28mm、MOUNT 各两次打开、每次 10 个页面事件，全部通过；第二次打开的 G 页为 `0001 K`，H 页为 `OK`。
- 未跑旧版 14 组回归；改动只在显示和记录路径。
