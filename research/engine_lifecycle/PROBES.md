# 生命周期只读探针设计

本文是后续设计，没有源码实现、构建物、P 文件、卡包或上机结果。本任务没有操作相机、卡或其他挂载卷。

## 共用机制与边界

沿用已验证 2k-p0 的 `/ATA1/P` 读取、CRC、主堆分配、A/B 取指检查和菜单字形显示。历史依据是 `decisions.tsv:295` 的 `2026-10-21T16:55:55Z` 用户手报；旧 `firmware/stage2k_p0/local/build/build.json` 的 `camera_executed=false` 是先前离线构建快照，不能覆盖后来的实机记录。

原 P0 每次模块返回后都会走 `p0_free`，因此仅替换 P 文件不能测试长期持有。后续探针必须有新的常驻保留/复查桩。它还必须改掉原 P0 的缺文件分支：现有 `.Loff/.Lbusy` 返回原 cache，会恢复原 `rfw_select` 的选择行为；只读探针的 08 在缺文件、错误、忙及成功时均不得落到配方应用。这个差异需在未来构建时单独审查。

这里的“只读”指不写相机设置、S、T、ISP 行、内部文件、卡文件或更新标志。允许写原生分配给探针的 RAM、常驻探针状态和当前菜单的字形缓冲，并沿用已验证的 cache 同步。只读原生 RAM 缓存，不读取可能带清状态副作用的未知 MMIO，不额外发 RPC 8、42 或断电命令。

所有检查由人工操作后的菜单重开/选择触发，不设后台任务、定时轮询或持续日志。菜单视图每次重新取得，不能持有旧 `RfwCache *` 或 MY 召回前的 S 指针。

常驻状态至少记录 `boot_seen`、`heap_epoch`、`link_epoch`、`unit_rx_seq`、`sd_init_epoch`、指针/长度及其反码、已知初始 CRC、每种原因的粘滞位、`inflight`。实际占用和 hook ABI 尚未链接验证；这不是给旧 284 B P0 窗口直接加代码的方案。

检查顺序固定为：

1. 在常驻代码里检查 root、代次、整个分配区间、元数据区间和本会话 lease。
2. 代次不符就只画常驻错误文字，不读旧块、不调用旧块、不 free 旧块。
3. 仍有效时检查数据和代码 CRC，再沿用 P0 同步并调用独立返回桩。
4. 每次从堆返回常驻代码后重新核对代次。期间有事件时，禁止发布“保持成功”。

不能用第 4 步补救执行中代码已经被重建的堆覆盖。事件 trace 必须另证破坏性重置与 `inflight` 不交错；否则这个时刻的堆执行测试停用，只测常驻观察值。

## P1：一个分配跨菜单、模式、回放和休眠

第一次选探针时只分配一次。最小实例用约 256 B 私有数据加 P 模块代码，后续容量验收再请求 32 KiB 数据块。写入本会话 magic、递增 nonce、长度/反码、首中尾 canary 和全块 CRC；不在每次重开时重写。内存不足直接显示失败并回原厂。

同时记录原生分配头 `p-12` 的字段。静态显示分配态为 next=0、`+4` 标志=1，`+8` 是包含头部的占用长度。分配器可能吞掉不足以再拆块的尾部，因此不能要求长度恰好等于请求对齐后再加 12。检查头、范围和 canary 只能辅助观察，不能替代 heap epoch。

建议三行显示如下，具体字符数沿用已知字形函数约束。

```text
06 H1 B1 A1
07 D=OK C=OK
08 RUN OK V3
```

H 是 heap 代次，B 是启动入口计数，A 是本次开机的探针分配次数；V 是菜单触发复查次数。失败分别显示 `H LOST`、`ROOT NEW`、`DATA BAD`、`CODE BAD`，不能都显示同一个 AB。

后续人工验收矩阵为关页重开、其它菜单、P/A/S/M 互切、两条回放进入方式、MY 召回、显示关闭、真正睡眠/恢复、自动关机后重开、USB 连接/退出。必须分别记录操作类型，不能拿显示熄屏代替真正睡眠。每一步读取已有证据，分配次数保持 1；只看到字形没变化不算成功。

恢复边界：任何失配后停用本次开机的堆探针，不反复分配，不 free 来源不明的旧指针。它没有新增 T/S/文件写入；关机后 RAM 状态作废。停止后续 P 加载只能控制下一次启动，不能把删除 P 说成撤销已经刷入的常驻 hook。

## P2：启动、清零与段 0 重载

最小观察点是 `0x20055074` 的启动清零之后、`0x2005BF00` 建堆之前，以及主/替代装载器 `0x20088358/0x20088E5C` 的复制之前。常驻观察桩只写自己的计数、原因位和请求段号，不改原生加载结果。

段 0 root 自己可能被复制覆盖，不能靠 root 里一个 `load0_count` 自证没有重载。已确认的 native loaded byte 同样不是代次。为这一项增加独立见证：P1 已拥有、经 heap epoch 保护的块保存第二份 nonce 和段 0 root nonce；装载桩在复制前向见证记录请求段、次数和校验。进入已知装载器前，把见证指针和 lease 暂存于 native 调用栈；只在确认此次仅重载段 0、堆和该栈未受影响的返回路径重新发布。不能在 root 丢失后扫描主堆猜见证地址。UI 只在见证 lease 仍有效时读它。

如果 root 与见证都丢失，显示 `UNOBSERVED`。如果启动入口经过且 heap lease 不能证明仍成立，也显示 `UNOBSERVED`。禁止重新生成一份相同 nonce 后报“保持”。未知 cold/warm 启动参数与外部 Monitor 重入仍会造成观察盲区。

恢复边界：纯观察不阻止原生复制。存在 heap 代码在途时不进行主动段重载实验。这里只观察日常动作是否自然触发这些入口，不调用 loader、不触发 trap、不模拟休眠命令。段 0 重载可能使后续观察桩不可用；这本身必须记为未观测，不能当作零次。

## P3：SD 初始化通知与卡身份新鲜度

在原生 `0x200A3568` 入口递增 `sd_init_epoch`，返回时记录原返回值。常驻菜单只调用 `0x200A3240(dst)`，把 16 B SD ID 缓存复制到自己的 RAM。显示 ID 的摘要，实际比较保留全部 16 B。拒绝全零或失败结果，记录原生状态和本次成功刷新标志。

未来验收需区分不同卡替换、同卡拔插、休眠前后、原生 I/O 错误恢复和启动初始化。比较是否每次原生重新挂载都先改变计数，以及 ID 是否直到初始化结束才变；本次没有执行其中任何动作。若物理事件不经过这个入口，本探针只能证明其覆盖不足，不能加一个定时读 ID 的循环掩盖。

恢复边界：不创建、更新或删除任何卡/内部文件；不主动 reset SD。对 `/IROM/` 已加载的引擎，仅把 SD 运输事务标为失效，不释放代码或清掉单元恢复记录。原生系统因媒体动作关机时，探针按关机失去 RAM，不承诺保留观察结果。

## P4：单元断开、同单元重连与缓存重填

观察 `0x200935B4` 的 ready 存储、`0x200637E0` 接收入口/出口和 `0x200630F4` 原生电源处理入口。入口只递增计数、关闭探针绑定并记录 ready、缓存标志及当前调用是否在途。接收开始前置 `unit_rx_seq` 为变化中；成功校验后才允许稳定快照。原生负返回保留失败状态，不继承以前的有效标志。

菜单显示 link/rx/电源入口计数与已知单元名、版本是否匹配。50mm、28mm、Mount 分别从新会话开始；同名同版本重连必须改变计数。若原生直接关机或没有回到菜单，结果为 `UNOBSERVED`，不得解释成“没有发生断开”。不靠拍摄或修改配方触发事件。

恢复边界：不向刚连接的单元写旧单元的 stock、T、cursor 或邻接快照。探针不主动发单元 RPC、不调用原生电源处理函数。若原生不支持带电装卸，探针也不新增这种能力；仅观察获后续授权的原生操作流程。

## 接受与失败的含义

P1 只证明被测路径和被测分配大小的保留行为。P2 只证明被观察到的装载入口；P3/P4 只证明实际触发过的媒体/单元通知覆盖。四项通过后仍要另审查 UI 悬空引用、执行中 heap reset 的排空契约、现有 T1 退出恢复和常驻代码容量。任一缺失都不能把日用生命周期标为通过。
