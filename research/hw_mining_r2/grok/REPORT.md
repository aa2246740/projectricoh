# A12 50mm 曲线前没有可改的 3×3

没有。jlaunch3 里，从 demosaic 到 type 23/26 曲线之间，不存在一张可编程的 RGB 3×3（也不带单独的三通道偏置）。能改颜色的九系数只有 type 28 的 `F034C100`，它在曲线的配置入口之后，数值是 RGB↔YCbCr、抽通道或单位阵，不是 GR III 那种曲线前、行和为 1 的 look matrix。按配方去改它，改的是曲线后的矩阵，补不上正片约 1.1、负片约 1.6–1.7 ΔE00 那一项。

证据等级：静态，高。官方 `jlaunch3` SHA-256 `951be1c659c85af58ae3e4ce98707c52f0b4514fc2075256854d59f822671673`，与 `artifacts/firmware/gxr-1.51/jlaunch3` 一致。没上机，也没有门级网表证明像素先后。排除依据是整份已初始化镜像的系数扫描，加上 ISP 打包函数里不存在第二套九系数拷贝。

GR III 的对照只用来定问题：R2Y 里 OFG（白平衡增益）在 CCA0（look，9×s16 Q13，行和 0x2000）之前，GAM 在 CCA0 之后，CSP 才是曲线后的 RGB→YCbCr。GXR 这颗 ISP 对得上的是最后那张 CSP，对不上 CCA0。

## 1. 曲线前的硬件 3×3

扫过 jlaunch3 全部已初始化段。保中性的判据是三个行和（或三个列和）都落在 128、256、512、1024、2048、4096、8192、16384 上，允许再放宽到 ±4，并且非对角项不全是 0。符号-幅值（bit11 为符号、低 11 位为幅度）也按同一标准解了一遍。DNG 的两套 ColorMatrix 按 256 到 16384 以及 10000 的量化去对过，s16 和 s32 分子都没有第二份。

命中的保中性九元组只有 type 28 的单位阵：选择索引 4，ROM 第 3 行（从 0 计），`1024,0,0 / 0,1024,0 / 0,0,1024`。其余“行和恰好是 512”的命中，拆开都是 type 25 那种单独的增益字 `0x00000200` 被半字窗口切出来的，不是 3×3。没有第二张带非对角、行和为 1 的 RGB 矩阵。

唯一被打包进硬件的九系数是 type 28：

| 项 | 值 |
| --- | --- |
| 寄存器 | `F034C100` 起 8 个 word。九个系数占前五个 word 的九个半字，后面三个 word 带着偏置 |
| 镜像 | `H=0x20142AB0`，系数在 `H+0x98`（`0x20142B48`） |
| 写入 | `0x201153DC`，由配置序 `0x2010C248` 经 `0x2010C37C` 调到 `0x20113954` |
| 格式 | u16。YCbCr 这几行按 bit11 符号、低 11 位幅度、Q10（1024 = 1）读，行和是 1024、0、0。打包函数只拼接半字，没有再钳位 |

选择字节是配置结构 `+6`，每次建配置都重读：

- 0：从 `T+0x1400` 拷 14 个 u16。`T = *(u32*)0x200B2CF0`。
- 1..8：从 ROM `0x2012D0C0 + (index-1)*28` 拷，步长 28 字节。
- `>=9`：这段不写。

八行的解码在 `evidence/type28_rows.txt`。选择索引 k（1..8）用 ROM 第 k−1 行：

- 索引 1：RGB→YCbCr，`306,601,117 / -173,-339,512 / 512,-428,-84`，偏置半字 `0,128,128`。
- 索引 2：同一变换，色度行略收，行和 1023、1、1。
- 索引 3：YCbCr→RGB，`1024,0,1435 / 1024,-352,-731 / 1024,1763,0`，即 R = Y + 1.402 Cr，G = Y − 0.344 Cb − 0.714 Cr，B = Y + 1.722 Cb。行和不齐，不是 look。
- 索引 4：单位阵，Q10。不混合通道。
- 索引 5：只留第一行 1024，其余为 0。
- 索引 6：只留后两行 1024。
- 索引 7：色度行放大到 1.5（768/1024），Y 行不变。
- 索引 8：全 0。

这些都是同一张曲线后矩阵的模式变体：色彩空间转换、旁路、抽通道、把色度放大。没有一行是“三个输出都是输入的混合、中性轴仍中性”的胶片 look。

## 2. 这张矩阵的系数从哪来，何时重建

来自模式字节，不是白平衡插值，也不是两套 DNG 光源矩阵。索引 0 走 T 页上那 14 个半字，1..8 走单元镜像里的 ROM 行 `0x2012D0C0`。两条都在 `0x201153DC` 里，而这个函数挂在每次建 ISP 配置的调度器上，不是开机写一次。现有产品改 C100 源行能在下次建配置时生效，和这里的重读路径是同一条。

DNG 的两套 SRATIONAL（分母 10000）在文件里有两份。活的一份在 `0x20225F6C` 和 `+72` 的 `0x20225FB4`。`0x20198E9C` / `0x20198EA8` 只是把这两个地址交回去，供标签使用，不参加乘加，也不写 `F034`。`0x200C5054` 的那一份 144 字节内没有任何 `seth/or3` 或字面指针。两套数都没有量化成 s16/s32 系数表。

## 3. 白平衡增益和矩阵是分开的

分开。type 25 是控制字加四路数，寄存器 `F0348004` 和 `F034800C/8010/8014/8018`。镜像 `0x20142F7C` 起六个 word 是 `0, 512, 512, 512, 512, 1`。硬件 payload 是前五个：`F0348004` 的控制字 0，和四路 512。紧挨着的 `1` 不在这五个 word 里。打包 `0x20118118`，apply `0x20118168`，调用点 `0x2010C304`。配置序里它在 type 26 曲线和 type 28 矩阵之前。没有任何函数把这四个 512 乘进九个系数。

`0x2010EFE4` 还能从外部结构一次盖掉这 5 个 word，源是另一块内存，不是 `0x2012D0C0`。512 作为 Q9 的 1.0 仍是推断，四路对应 R/Gr/Gb/B 还是别的顺序也还没在像素上证实。能确定的是：它不是 3×3，也不是 type 28 的一部分。

AWB 字符串（`Dump AWBCAM`、`CamAwbCreateValue_WDR`、`CamAwbToyCameraGainSet`）在别的子系统里。sec00 和 sec06 里没有 8 个以上 `mul` 挤在 0x60 字节内的循环。sec14 里唯一一处（`0x20267034`）是对结构体字段做标量乘除，不是九个系数。

所以次序是：四路增益和九系数是两个硬件块；配置时先写增益和曲线，再写矩阵。地址也是 `F0348`、`F0349`、`F034C` 这个顺序。这还不是像素流水的门级证明。

## 4. 曲线前还有没有别的跨通道级

type 6、9、11、12、17 都不是 3×3。

type 6 的九个 word 被写成四段：`F0317000` 四个、`F0317014` 一个、`F031701C` 一个、`F0317024` 三个，中间寄存器空着。源表 `0x2012BD54`、`BD78`、`BD9C`、`BDC0`、`BDD2`、`BDE4`、`BDF6` 的九个槽全是 0。唯一的非零默认在 `0x2012BE08`，四个 `0x0032`（50），由 `0x2011292C` 按一个尺寸类或直接常数写进镜像的一个字。请求字节的 bit4 为 1 时，`0x2010D2F8` 才用结构 `+7` 的字节当索引去选这些槽。选来选去都是 0 加一个 50。全 0 的 3×3 会把画面乘黑，而这是出厂数据，所以这些寄存器不是颜色矩阵。

type 9 的 ROM `0x2012B9E4` 是成对的 u16 档位。开头 `0B2E 0036`、`0110 0014`、`031F 0060`，后面同一对 `10CE 0006` 重复多次。不是九个系数。

type 11 是四个打包 word，源在 T 的一小段。type 12 是 16 个配置 word，type 17 是 18 个 word。这三处都没有九系数表，也没有指向这种表的拷贝循环。

曲线前会跨通道、但已经有名字的，是 type 28 自己的另外两块，而且它们和矩阵在同一次配置里、位于曲线入口之后：C040 是 12 个 word（`cfg+4`，`0x2012C0F4` 步长 48），C080 是 24 个 word（`cfg+5`，`0x2012C5D4` 步长 96，或 `T+5196`）。`0x201145FC` 到 `0x2011486C` 用两个权重对 C080 做逐字节混合，混合的是扇区表，不是 3×3。`0x20114890` 对 12 个 word 做同样的事，对象是 C040。

`0x2011E120` 有一段固定的字节 RGB→YCbCr，系数是立即数（655、1285、250 这一组，除以 2550）。它不读表，也不写 `F034`。

type 21 仍是那个大型多表块。`0x2012C058` 的索引是 `0,1,9,0x0E,0x16…` 这种小整数，不是矩阵指针。它没有被扫成一张保中性 3×3。

## 5. 探针

没有可按配方改的曲线前矩阵，所以不做 A→B→A 颜色探针。改 `0x2012D0C0` 或 T+`0x1400` 会动到已经在用的曲线后矩阵，测到的是另一件事。type 6 的源行虽然也在单元 RAM 里，出厂是 0，改出非零值没有“跨通道偏色”的预期，不能拿来当 look 探针。

## 6. 排除了什么，还剩什么

排除了的：

- 已初始化镜像里不存在第二张保中性、带非对角项的 3×3，Q 标度从 128 到 16384，含符号-幅值解法。
- DNG ColorMatrix 没有量化副本，活指针只回到标签 getter。
- type 6 的九个寄存器是分段控制字，源表为 0。
- ISP 配置函数里的乘法簇是 C040/C080 的逐字节混合，或一段固定的字节级 YCbCr。AWB 所在的段里没有九连乘。
- `jlaunch8`（71269 字节）里没有这组 SRATIONAL，也没有 YCbCr 那行或 Q10 单位阵。

还没闭合的：

- `F034C` 一定接在 `F0342`/`F0349` 的 LUT 之后，这是配置顺序和地址顺序，不是门级网表。即便硅片把这张矩阵接到了曲线前面，表里仍然没有 look，只有色彩空间转换和单位阵。单位阵不产生跨通道偏色，YCbCr 行则会把工作域从 RGB 换成 YCbCr，不能当作胶片矩阵来填。
- type 12、17、21 的像素公式仍未知。它们的形状和引用不像九系数，但“不像”不是逐寄存器的语义证明。
- type 25 的 512 是否就是白平衡增益、四路的通道名、以及它相对 LUT 的像素位置，还是推断。
- 只查了 A12 50mm 的 `jlaunch3`。28mm 的 qlaunch 没有扫。
- 没有排除一段完全用移位和加法、不出现 `mul` 的运行时矩阵。这样的循环在配置器和 AWB 段里没看到。

窗口和扫描输出在 `evidence/`。`scan_ccm.py` 做全镜像扫描和交叉引用，`scan_ccm2.py` 解八行并放宽行和，`scan_ccm3.py` 查 DNG 指针和 `jlaunch8`。
