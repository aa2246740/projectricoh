源差异独立检查没有只看实现者的 patch。source-differences.json 记录两棵源码树的哈希差异；缺少的历史构建与检查脚本另列，不误称生产逻辑删除。整份 engine_services/services.c 相同；适配层 view_owned、eng_settings_owned、start_view、core_call、ingress、release_view，以及核心的 freshness、入口锁、deep、make_plan、settings_match、rebind 和 validate_live 等选定函数相同，具体条目在 source-results.json。

新 UvLevels 是十个 int16，20 B。确认赋值复制整个向量，recover_confirmed 取 confirmed_tweak，默认及退回 04 时显式设置 Amount=100；适配层的 values、saved、uv_sync 和返回原条目的比较也使用整个新类型。三单元的重开检查核对恢复后的完整行内容；这不关闭普通预览 I/O 失败的继承项。

另核对十二个归属相关函数。锁定记录、finish、ui_finish、retry_view、deferred_menu 原文相同；六个核心函数只改向量类型名。keep_view 只把旧的连续范围游标公式改成点表定位，归属门槛、标记清理与退出条件相同。检查脚本明确限定这两种变化，证据在 source-results.json。

KvWork 为 2,288 B，目标编译器测得 Engine 内偏移 2,556。它在静态 Engine g 中；最终 ELF 的 g 与 n 均在加载图像 BSS。loader 每个会话分配独立图像并清空其 BSS，因而这里的 static 属于各自会话图像。没有新增堆分配；数学文件没有新的可写静态工作区。旧数学源文件仍作为历史材料存在，最终构建列表和 ELF 中已没有旧数学调用路径，不能表述成“旧文件已删除”。

第七段精确为 1,408 B 旧表、1,984 B GXUI 和 17,384 B GXKV2R2，共 20,776 B。容器 gate 限定 build 129、八个旧参数及精确长度；ig_init 在 eng_init 前同时要求容器校验和 uv_validate 成功。后者核对旧扩展、配置、条目与新整数表；kv_data_open 再核对边界、CRC、项目集合、点序列及保留字段。实际数据块 SHA 与冻结模块相同。36 个主机错误格式检查与源码顺序是两层证据，没有声称它们证明真实调度。

尺寸方面，引擎段为 60,388 B，BSS 为 10,684 B，主请求 107,496 B。相对 gen 127，主请求增加 32,372 B。格式总额仍有 14,696 B 余量，实现报告的专项 108,124 B 预算只剩 628 B；这两项都不是相机剩余连续堆空间。

按 [既有堆报告](../heap_headroom/REPORT.md) 的 262,144 B 池模型，608 B 工作区、主请求和 1,968 B UI 快照算上分配头后共占 110,108 B，连续空池剩 152,036 B。逐个隔离执行的十二处原生分配均成功；它们不代表同时存活。一个条件组合仅剩 7,512 B，再要 32,768 B 会失败；三个保留的 32,768 B 缓冲后再要 77,312 B，新版失败、旧版成功。source-results.json 保留每步数字。真实相机上的共存关系、最大块和其他会话占用仍未知。

真机若在 loader 主请求处失败，配方菜单可能不出现，仍看到原生 Image 项；本次启动的拒绝标记可能使普通重开不再尝试。若加载后才挤压到原生分配，部分原生调用点缺少空值保护，可能表现为菜单无响应、预览异常或异常退出。具体屏幕和恢复动作没有实机证据，不把模型里的分配失败写成已观察到相机死机。
