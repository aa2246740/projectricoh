# 重绑与执行边界

本轮不使用原运行器的整数整体替换。`bindings.py` 只改命名为 generation 的赋值、比较、参数或 DAT 头的 generation 字段；每个字节码常量的使用位置单独处理。共享同一个整数常量的 ASCII 检查仍保留 126。自检同时覆盖嵌套函数和同一函数共用 126 的情况，字符 127 必须被拒绝。最终 UI 帧还有独立的 32…126 断言。

generation 参数、DAT 路径、源码树路径、目标布局和 PIN 分别绑定。PIN 绑定前先断言当前 DAT 就是指定的 `b58396748f1d5bba5ed480c1e7a81bc881a9df08968db2b778086c7c1a9cbf48`、89,308 B、generation 129。旧 helper 缺少的引擎侧 Python 入口从冻结的 gen 127 树按路径载入，不复制历史复审脚本。

`research/g127_fix/run_existing.py` 是本轮读取并在内存中调整的运行器。`research/review_g12x` 与 `research/review_diag` 下的旧 Python 文件只作为路径入口或它们自己的依赖执行。一次汇总生成的错误 JSON 时，终端带出了 traceback 内的旧源码行；后续改为只输出名称、返回码和计数，交付前也清理生成日志中的源码行。没有据此更改旧脚本。

| 本轮参数 | 对原运行器的调用 | 实际含义 |
| --- | --- | --- |
| `--crc-mode host` | 不传原 CRC 参数 | 原模型会在首次装载后的调用中安装经过链式探针核对的主机 CRC 回调。首次装载仍执行目标 CRC。 |
| `--crc-mode native` | 传原 `--fast-crc` | 原模型的布尔位使其不安装上述回调，继续执行目标 CRC 指令。 |

原参数名称与实际语义相反，因此本轮所有命令都明确写模式。菜单专项还明确记录它单独使用的机身 CRC 叶函数。数值专项使用最终 M32R 计算、CRC 和整数辅助指令，且由原解释后端另核样本。

目标布局由原 `layout_only.py` 入口重新编译。22 个核心字段与实现方记录一致；`settings_pending` 按 `recheck+1` 得到 4861。每组有独立输出目录，并使用这份重新测量的布局。数值或文字断言不因此改动。

旧 UI helper 还会重设 staged DAT；它的 DAT、STAGED、STAGED_SHA、ELF 与 ENGINE_ELF 按字段绑定到最终候选。新 state 读取器使用实测的 20 B 向量与八行文本字段，仍要求 ASCII 32…126。r2 数学参考来自独立的原始 C 源码，会话提供 unit 与 slot，保留传入参考缓冲和原完整字节断言。旧范围、控制项与数学期望的差别逐项列在 EXPECTATIONS.md。

GXUI 转换另建只改变数据段与相关 CRC 的合成对象，代码段与最终 DAT 逐字节相同。此类对象记录自己的 SHA，并标明合成输入；不把它的整文件 SHA 写成最终 DAT 身份。目标会话读取全部 32 个已转换的 20 B 向量，另记 ig_init 的实际访问次数。

只有一个 `schedule.py` 调度器。它持有非阻塞文件锁，最多分配三个工作槽。协调者手工复核专项时，通过 `capacity.json` 预留工作槽，总数仍为三个。旧套件中等待子进程的父进程不执行模型计算。每组配置 4200 秒；全局时间盒更早结束时标 TIMEBOX，不当作产品失败。

最初几次准备运行在 PIN 或布局文件处停止，未进入相关产品断言。主机输出重定向还遇到 Python 3.9 的 Path opener 保留原路径问题，被 OS 写入围栏拒绝。修正后重跑；初次返回码仍在执行记录和 attempts 目录中保留。

OS 围栏只允许写入 `research/review_g129` 和 `/dev/null`，拒绝网络。缓存、派生二进制和模拟输入均位于本目录已忽略的 `local/`。本轮不使用用户允许的 `research/g129_knobs/local/` 写入例外。
