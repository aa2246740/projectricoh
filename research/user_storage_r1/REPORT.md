推荐 B：卡上预建文件，容量由文件长度决定并由电脑扩容；当前保留只读，待定位错误、A/B 缓冲隔离和原厂并发门禁验证后再开放保存。

# “我的配方”与“记住上次配方”持久保存研究

本轮没有找到可批准占用的 S 空闲字节。B 比 A、C 更适合做用户可备份、可重建的配方库，但“文件已经建好”不等于“原位写入不动 FAT”，A/B 加 CRC 也不是断电安全证明。固定 16 KB 文件有明确容量，不能满足字面上的无限新增。

权限方面可以只改 DAT。gen117 不写文件是 DAT 的选择，固定 v3.6 resident 会接受写位。实现新的固定文件对象、定位、格式和错误隔离仍需改 DAT 服务代码，单改一个能力位不够。若要求开机后首次拍摄前自动恢复，或需要新的拍摄/格式化互斥 hook，则涉及常驻层；这两项不在现有 0 B 余量内得到实现证明。

## 3. gen117 写权限与只改 DAT 的边界

### 3.1 写位由 DAT 选择

`ig_init()` 两个成功路径返回 `CAP_UI|CAP_S|CAP_W = 0xE0000`。[初始化源码](../../firmware/engine_v38_b36/candidate/containers/product/adapter.c#L390) 没有返回 bit16 `CAP_FILE_WRITE`。

固定 v3.6 [loader.c:153](../../firmware/resident_v36/resident/loader.c#L153) 的发布表达式为：

```c
s->capabilities = RV_READ_CAPS
    | (reply->capabilities & (CAP_FILE_WRITE | CAP_UI | CAP_S | CAP_W));
```

所以 gen117 会话能力是 `0xE7FFF`。若 DAT 明确返回写位，这条相同常驻代码允许 `0xF7FFF`。常驻并没有永久屏蔽 bit16。

存储的路径、token、写门禁和原厂 create/write/rename/delete 桥属于 DAT 内的服务库。构建源清单和 `RV_ENGINE_SERVICES` 重命名宏证明共享逻辑编进两处，DAT 服务库有自己的原厂地址桥，并非每次都进入常驻中一套不可更改的文件策略。见 [源码摘录](local/source-excerpts.txt)、[服务桥](../../firmware/engine_v38_b36/candidate/engine_services/bridges.S#L28)。

本轮对实际 storage 源码的主机调用得到：

| 主机输入 | 结果 |
|---|---|
| 会话 `0xE7FFF`，create / rename / delete。 | 各返回 `-12`，对应 native 调用均为 0。 |
| 只读 token 调 write。 | 返回 `-10`，native write 为 0。 |
| 相同函数、相同 resident ABI，会话改为 `0xF7FFF`。 | create 成功走到 native 替身一次。不是向真实 IROM 创建文件。 |
| 开写位后传新的 user object kind。 | 仍返回参数错误；当前路径表不认识它。 |

证据是 [host_service.c](host_service.c)、[源码提取身份](local/service-source.json) 和 [主机原始输出](local/host-service.stdout)。会话、上下文、范围和 native I/O 是替身；没有把手工设置主机会话能力冒充机身运行结果。

### 3.2 实现还缺什么

当前 object 2 限定三单元各 16 个 GXTS 槽，普通记录上限 256 B；object 1 使用固定 DAT/OK 路径，不能借它存用户库。没有已有的 seek 操作。要在 DAT 服务中新增固定用户对象、精确长度检查、已有文件写 token、经验证的定位和独立只读锁存。保持旧 IROM 安装、GXTS、黑盒的写入关闭，不能为用户库顺手重开全部旧写路径。

不需要为这些功能修改常驻 root、ABI 布局或再占常驻代码。新增状态放在 DAT 私有工作区，文件按页读取；不要扩展已由 resident 编译定长的 `RvSession`。文件可以大于单个 lease，但必须串流校验和分页，不一次分配整库。实际堆/栈余量未测。

另有两个边界。

- 固定 [hooks.c:72](../../firmware/resident_v36/resident/hooks.c#L72) 只在 H01 菜单构造路径调用 `rv_load`。DAT 未加载前无法替用户读取上次状态。只改 DAT 能做菜单首次进入时的完整恢复；它不能新增开机后首次拍摄前的加载时机。若产品把“开机即恢复”定为硬要求，需要新的、堆和单元已就绪的启动入口及首次拍摄门禁。
- DAT 的 `RF_OWNER` 只阻止自己重入，不能证明与原厂拍照、格式化、USB 或更新任务互斥。原生单次调用里的锁也不等于整个 open/定位/write/close 事务排他，不能未经核实就在外层重复取得同一把锁。若现有菜单任务上下文不能提供可靠排他，需要常驻层接收这些生命周期事件、撤销存储 token，并在安全点调度文件事务。当前常驻 200 B 保留区已刚好用到链接门槛，新增余量为 0 B；不能把这类 hook 写成“只加几行就够”。

后两项需要重排/缩减常驻并重新验收的设计，本轮未实施，也未给出能放得下的尺寸承诺。

### 4.2 全部读写路径没有得到证明

[settings_census.py](settings_census.py) 扫描官方全部 16 段线性反汇编，逐行核对 3,858,192 B 指令/数据行，得到 5419 条直接 S 指针访问候选、4645 条 S 偏移访问候选，其中读 2329、写 2316，显式触及 530 个不同字节。另保留 205 条传 S 指针给调用者的候选。

### 4.3 原厂恢复默认并非私有区擦除保证

说明书的 Restore Defaults 恢复拍摄菜单设置，见 [保留的说明书摘录](local/source-excerpts.txt)。没有说明它擦除全部 4096 B。静态找到的 `0x200674B8` 是按字段地址从原厂默认区取值的 helper，并不是整块清零；`0x2035CAF4` 一段还临时默认某字段再恢复原字节。该片段只能算默认处理候选，未闭合到拍摄菜单 Restore Defaults 的完整分派，见 [候选窗口](local/restore-default-candidate.asm.txt)。

所以原厂菜单可以作为已知拍摄设置的用户恢复途径，不能保证移除未知偏移里的私有 magic、CRC 和自动恢复标志。校验失败后的整块初始化也不是用户可选择、无副作用的私有配方清理入口。

容量即使乐观地把前 4092 B 全当私有，也只有有限记录，还要扣除原厂字段、头、CRC 和双份。不能以“单条只有 16–32 B”推出无限槽。

两个定位包装都有主机反例。在真实低层定位代码运行、`fd_select` 边界返回 34 的情况下，请求 32768 后包装仍返回 32768，底层文件位置未移动。`4F40` 虽检查 `-1`，低层错误出口可返回 0，仍会漏过。见 [host-native-results.json](local/host-native-results.json) 中 `seek_reports_target_after_real_lower_fd_error`。因此定位可达已证，可靠的“定位失败后绝不写错位置”尚未闭合。

### 5.2 16 KB 文件内的 A/B 不一定隔离

原厂 fd geometry 返回的扇区数控制 native 缓冲长度 `Q = sectors * 512`。`0x200A5080` 向 Q 边界对齐并可能预读；close 按逻辑位置对 Q 取余提交缓冲。实际 Q 取决于媒体和 native geometry，本轮没有测相机值。

在有界官方指令重放里，B 位于 8192，写 32 B 后 close 的低层写请求为：

| 注入的 Q | 低层写请求 | 对 A/B 的含义 |
|---:|---:|---|
| 4096 或 8192 B。 | 32 B。 | 该例中 B 位于新缓冲边界。 |
| 16384、32768 或 65536 B。 | 8224 B。 | 对齐到 0 的同一缓冲覆盖 A/B，不能假设低层只提交 B 的 32 B。 |

这里运行的是官方包装指令，geometry、磁盘、锁和低层媒体操作是替身。它证明传给低层的请求扩大及 A/B 共用缓冲，实际媒体覆盖范围仍须追踪，未证明物理卡已损坏 A。它也说明 [storage_model.py](storage_model.py) 的“只撕裂非选中 bank”假设不能直接套用到 16 KB 实物。

候选布局应让两份 bank 分别从 Q 边界开始，长度为 Q 的整数倍，并证明每次实际写回都留在非选中 bank。Q 未知或大于布局所支持的粒度时保持只读。若 Q=32768，两个 bank 至少占 64 KB；若 Q=65536，至少 128 KB。不能写死“16 KB 足够安全”。更大的间隔仍不能证明 SD 内部 NAND 映射或 FAT 元数据隔离。

### 5.3 截断、目录项与 FAT

原厂已有项 open 在 `file+7` 保留 `0x80` 标志。正常 `0x82` 状态的有界 write/close 用例在写 32/512 B 后保留 16384 B 目录长度。不是“open 之后必然截断”。见 [已有项打开](local/file-open-low.asm.txt) 和主机结果。

低层 `0x200AB02C` 的小写入会清 `file+156`，close 对 `0x80` 的处理决定后续行为。相同探针若改成标志已清的 `0x02` 状态，32 B 写后目录长度会变成 32 或 8224 B。**这只是条件状态反例，本轮未证明新的固定文件正常路径会进入该状态，不能登记为已复现的正常截断缺陷。** adapter 必须保留原厂内部状态，不能自行改 fd mode、位置或长度来绕过接口。

即使长度保持不变，`0x82`、512 B 的用例仍进入目录扇区写、目录 flush、卷 flush 分支；对应 32 B 用例没有进入这些分支。close 路径包括更新时间、编码目录长度、写目录和 FAT/卷收尾。见 [低层写](local/write-close-low.asm.txt)、[关闭核心](local/file-close-core.asm.txt)。不能把固定长度覆写概括为目录项永不变化。

原位覆写不走新建目录项是已证；“不分配/不释放任何簇”“满卡仍必定成功”“不会波及照片”未证。`0x200B0240` 等簇链处理和实际媒体驱动仍是重放边界，主机 memcpy 不能替代它们。

### 5.4 A/B、序号和 CRC 的可兑现范围

建议一份 bank 表示完整配方库与一条独立的 last snapshot。last 必须含底子及全部微调，不能仅存一个指向可变/可删除槽的编号。这样库和“上次”可以用同一代次发布。另一种分开存储的设计也可以，但每个 last 仍须自包含，不能拼接不同代次的数值。

每份包含格式版本、精确长度、模块身份、配方语义兼容摘要、store UUID、64 位序号、记录数、头和负载 CRC。单条模型记录为 32 B，保存 base/name/uid、10 个有符号值、revision 和记录 CRC。实际值域应由当前配方 schema 决定；模型里的 16 种 base、-5..5 是合成测试域，不是产品上限。

开机读两份，先验证格式/边界/绑定/全部数值，再比较序号。单份无效则选另一有效份；同序号内容冲突、两份无效、格式不兼容则纯原厂 04。序号不得回绕。CRC 不防任意错误恰好形成合法记录，也不提供媒体原子性。

模型的 16 KB 布局为两个 8192 B bank，各有 128 B 头、1 条 last 和最多 251 条用户配方。一般容量公式为：

```text
N = floor((bank_bytes - header_bytes) / record_bytes) - 1
file_bytes = 2 * bank_bytes
bank_bytes 必须满足已核实的 native 缓冲对齐条件
```

本轮模型通过 8193 个前缀撕裂位置、8192 个单字节位置的单 bit 损坏、逐扇区旧数据混入、CRC 合法但值越界、绑定过期、同代冲突、计数越界和序号耗尽。结果见 [host-model-results.json](local/host-model-results.json)。其前提是选中 bank 和文件元数据保持可读；现实中两份同时不可读时只能回 04。

## 6. 异常、并发与用户恢复

| 情况 | 引擎应有的行为 | 用户恢复路径与仍未知项 |
|---|---|---|
| 断电或写入中拔卡。 | 下次只接受完整有效 bank；否则回 04。写/close/读回结果不明立即锁只读，不追加修复动作。 | 关机后用电脑保留卡映像与照片，再恢复备份的配方文件。A/B 不能保证照片/FAT 零损伤，物理断电验证未做。 |
| 卡满、物理写保护、短写、I/O 失败。 | 保存失败，保留已经完整应用的 RAM 配方并显示未保存；不删除照片或另一 bank 腾空间。dirty close 失败后不再尝试存储，提示正常重启。 | 电脑备份后处理空间/卡状态，修复或换卡并放回已验证文件。是否完全不需要空闲簇仍未知。 |
| 正在存照片或连拍。 | 返回 BUSY，不启动 open/seek/write；在明确原厂安全点再允许用户保存。仅看“当前在菜单”或自己的 busy 位不算互斥证明。 | 不要求用户通过错开操作来代替产品门禁。RTOS 排他与 I/O 阻塞上限目前未知。 |
| 格式化卡。 | 当次 RAM 引擎仍存在时撤销旧 token/卡代次，拒绝写入，显示“配方文件不可用，仅本次使用；请用电脑恢复配方文件”。 | 格式化也会删除卡 DAT；下次没有可用引擎源时直接原厂路径，不能承诺不存在的引擎仍显示自定义提示。电脑重新放入受理的卡包和配方文件。 |
| 文件 open=-1、长度不符或不可读。 | 统一当不可用/错误，不能判断成“确认不存在”；不 create、不 rename、不 delete。会话只读。 | 用户在电脑上检查唯一目录项、文件长度和备份内容。不要因换一个文件名就忽略既有 FAT 异常。 |
| 模块切换、USB、休眠/唤醒、媒体代次变化。 | 旧 token 失效；重新验证身份与文件。未证明生命周期门禁前不开放写入。 | 正常关机后重开并重新进入配方页；USB 只读属性不作为内部写保护证明。 |
| 配方库绑定过期。 | 保留文件，拒绝不兼容记录并回 04或上一完整有效快照；显示需电脑迁移。升级不能触发删除/改名清理。 | 电脑用受支持工具迁移或从备份还原。不要绑定整个 DAT build-id，避免无关代码更新让全部用户配方失效；兼容性必须落到实际配方语义/schema。 |

GXTS R4-01 的既有证据是：旧绑定被当成缺失，之后选中实际仍存在的目标，rename 失败并把扩展停用；并非旧绑定本身要求停用引擎。[review_full_r4](../review_full_r4/REPORT.md#L11) 还记录停用后预览值未恢复。新用户库的存储失败应局限于存储只读状态，不能单独用 `RV_FAULT` 把有效图像会话停用。若画面应用本身已部分改变，仍必须按图像事务合同恢复并验证纯 04。

同名黑盒问题的规则也保留：无论重试几次，open=-1 都没有变成可靠的不存在证明。B 不从相机创建文件，因此不包含这个失败后的 create 路径。既有重复项应先在电脑保留证据和备份，不能靠按路径重开证明自己拿到了唯一同一目录项。

## 7. 画面状态必须完整，存储不能代替应用事务

采用用户给定的当前合同：彩色配方只使用 Standard S，selector=1、WB 中性；微调和值保存在 DAT 私有状态和用户文件，不借 S 图像字段跨关机保存。原厂 04 是产品中的完整原厂配方身份，不要把它误写成旧设计中的 S selector=4。

应用顺序应是完整读入和校验快照，重建底子与全部微调的期望原生行/T/W状态，再按已有受理的应用合同提交、读回校验，最后一起发布 active recipe、数值和高亮。失败则完整恢复 04；不能出现“高亮上次、底子04、微调来自另一条”的组合。

S 可能在意外时机整块保存，所以“关机时再把临时 WB/图像数值清掉”不足以满足规则。若某个新微调仍依赖临时写有画面影响的 S 字节，必须先改成不污染 S 的实现或明确证明原厂快照被遮罩；后者不在本轮被证明可只改 DAT。

固定 resident 未执行 DAT 之前，能保留的退路是原厂状态，不能承诺上次库已经读取。即使文件恢复模型通过，纯 04 的首次拍摄、失败恢复后 T/W、S 和预览一致性仍需真实相机验收。

## 8. C：IROM 的额外问题

`/IROM` 是原厂文件系统卷，可通过同一文件服务在相机内写入；USB 只读不等于相机代码不能写。路径与挂载的既有静态研究见 [irom_storage](../irom_storage/REPORT.md)。

本轮重新提取固定 v3.6 中未改变的更新分支：`0x2010D70C` 对 DUMMY.BIN 处理失败后，在 `0x2010D780..0x2010D7B8` 进入卸载/准备/格式化/重挂载链；其中 `0x2009951C` 经 `0x2009997C`、`0x200A3E64` 调通用格式化 `0x200AA7E8`。见 [更新分支](local/irom-update-format.asm.txt)、[IROM 包装](local/irom-format-wrapper.asm.txt)、[IROM 核心](local/irom-format-core.asm.txt) 和 [通用包装](local/format-wrapper.asm.txt)。换成自有文件名不能避免全卷格式化。

与 B 相比，C 失去电脑直接替换文件的简单回退。若坚持“相机也永不新建”，USB 又只读，就缺少预置及丢失后的重建方式。若由 DAT 从卡导入，则必须另解首次不存在证明、重复项、断电、满卷和备份恢复，不能复用旧的 open=-1 后 create。原厂格式化内置存储会删除该卷照片及所有文件，不是只清用户配方的恢复按钮。

只改 DAT 可提供相机内读写/导入逻辑，不需要解锁 USB 或修改常驻文件服务；这不消除上述风险。当前建议 C 不作为主存储，也不作为“文件消失就自动重建”的后台退路。

## 9. 给引擎的最小接口建议

以下是建议合同，不是已实现接口。

| 接口 | 合同 |
|---|---|
| `user_store_probe()`。 | 只读打开固定名，校验精确长度/EOF、格式、store UUID、模块/schema、bank 范围；返回容量、代次和只读原因。检查失败不改变文件。 |
| `user_store_read(index, out)` / `user_store_last(out)`。 | 分页或串流读取，验证记录 CRC、值域、底子身份和整份快照的一致性。last 返回自包含值，禁止借当前槽值拼接。 |
| `user_store_save(expected_generation, snapshot)`。 | 只接受用户确认后的完整状态；检查原厂安全点、文件未替换、现有长度和 Q。只打开已有项，只写非选中 bank 的允许范围，禁扩长、禁创建/改名/删除。定位假成功尚未解决时返回只读。 |
| `user_store_verify(bank, expected)`。 | write 及 close 均需检查；重新只读打开，验证完整 bank、位置、精确文件长度及预期代次/内容。返回 READBACK_VERIFIED，不命名为断电持久提交。 |
| `user_store_invalidate(reason)`。 | 撤销自有 token，锁存只读，记录明确原因。未确认结果的 close 不重复调用，不把原厂 -1 翻译成 ENOENT，不修复/格式化卷。 |

错误至少区分 `SOURCE_UNAVAILABLE`、`READ_ONLY`、`BUSY`、`FORMAT_OR_BINDING_INVALID`、`COMMIT_UNKNOWN`、`SEQUENCE_EXHAUSTED`。下次正常启动或明确修复后重新 probe 才能恢复写资格，不能每按一次 OK 都重试。

空间与名称表由电脑工具在关机取卡后扩容或迁移，再由相机只读核验新容量。当前报告没有实现该工具。名称表/配方目录的额外占用必须计入容量，模型的 251 个配方不包括可变长名称表。

## 10. 最小相机验证方案，未执行

后续只在已有设备授权及受理的探针任务中执行。本轮不生成探针 DAT。使用已备份的空白测试卡，不用工作照片卡；保持机身 v3.6，保留已受理卡包及文件的电脑副本。正常关机换卡，不用拔电试验来证明 FAT 原子性。

| 步骤 | 预期现象与验收值 | 恢复方法 |
|---|---|---|
| 1，电脑预置独立 `USRPROBE.BIN`，含两份已知记录和保护区；先只读。 | 相机读到正确长度、CRC、模块和完整数值；记录 native geometry/Q。create/write/rename/delete 计数均为 0。 | 关机取卡，电脑删除自有测试文件或放回原备份。无写入验收。 |
| 2，先检查定位与生命周期。 | 只读定位到各 bank 和边界，返回内容及位置均正确；主机已有的定位错误分支必须被新版受限适配器识别，不能只看返回偏移。未证明原厂排他时停止在只读阶段。 | 退出页面、正常重启，恢复只读卡包。 |
| 3，允许一次非选中 bank 保存。 | 对齐和实际提交跨度满足 Q；close、重开读回通过。电脑比较前后文件及卡映像，确认选中 bank、保护区、目录唯一性、文件长度、首簇/簇链与照片内容；记录实际目录时间字段变化。 | 任一异常停止后续写入，关机保留原卡映像，再恢复备份文件或更换测试卡。不要自动修复 FAT。 |
| 4，正常关机后重开，覆盖三个单元。 | 进入 DAT 后恢复同一底子和全部值，active/highlight 与实际状态一致；用户状态文件不可用、两份 CRC 坏或绑定不符时为完整04。首次菜单前的照片单独核验，不能以菜单恢复替代开机恢复。 | 关机移走测试 DAT，放回受理卡包；单独移走卡 DAT 不能排除 resident 从有效 IROM 引擎回退。必要时按原厂拍摄菜单恢复默认，不能声称该菜单已清理未知 S 私有区。 |
| 5，只读退路。 | 缺文件/长度错/写保护/卡满分别拒绝保存。原厂格式化测试卡后，当次若引擎仍运行则只读并提示；下次无 DAT 则原厂。不得 create 同名文件。 | 电脑恢复测试文件和受理卡包，正常重启。格式化只针对已备份空测试卡。 |
| 6，拍照存储并发。 | 相机正在写照片时保存请求为 BUSY，native 用户文件写调用为 0；照片落卡且哈希/目录正常。只有在原厂写完成的明确安全点才允许后续保存。 | 取消保存、正常关机；保存卡映像及拍摄结果，不靠反复 OK 或反复 close 自救。 |

A 暂不做未知字节写入探针。可对原厂 Restore Defaults 前后只读采集 S，确认具体字段及保留项；它只能补充候选，不能证明所有其它路径不读目标字节。C 暂不做 IROM 写入/格式化探针。

这套正常路径验证也不能关闭任意瞬间掉电、控制器写重排、卡故障或不可返回的 native I/O。上述媒体可靠性仍为 UNKNOWN，若产品要求这些条件下照片绝对不受影响，当前三个方案都没有满足该承诺的证据。

