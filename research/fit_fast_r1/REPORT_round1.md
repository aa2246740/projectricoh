# fit-fast r1 技术报告

## 范围与测量口径

机器为 Apple M1 Pro，10 核（8 性能核、2 能效核）。使用已有 Python 3.14.7、NumPy 2.4.3、SciPy 1.17.1、Pillow 12.2.0、MLX 0.31.1、Clang 21 和 Rust 1.93.1；没有安装依赖。NumPy 和 SciPy 均链接系统 Accelerate。环境回执为 `environment.json`。

入口保留原命令行参数及 JSON/NPZ 结构。为遵守原目录只读边界，默认输出根目录是 artifacts/downloads/fit-fast-r1/runs/default；后续若有硬编码原 LOCAL 的读取器，也必须改指新根目录。不能声称整个下游只改脚本名就完全透明。

当前数据和入口定义的 51 个目标，包含原报告 27 项和 8 个内置目标 × 3 单元。每目标有 L0、L1 及 28 个完整码域组合，共 1,530 次主拟合。51 已经包含内置目标的三个单元，没有再乘三。本报告没有执行、也不外推 4,590 项墙钟；固定向量检查另覆盖全部三个单元。

每轮使用新输出目录，实际求解 L0/L1 和其余 28 项。仅只读复制原研究声明的常规码域控制起点，不复制完整码域最终解，不续算，不用照片留出来选择参数。旧完整轮次分为 0:12、12:27、27:39、39:51 四段，整轮墙钟为四段活动墙钟之和，不计段间等待，不以累计 solver 秒数冒充墙钟。每个目标超时 1,500 秒；最终精确重测另按至多 20 分钟的批次执行。

参考版用冻结的原 Problem、SciPy 优化器及保存流程。默认快速版保留该优化器，替换前向中的等价计算节点。参考全轮三个单线程数值进程，快速全轮四个，因此全轮倍数包含并行度变化。原计时两边子进程实际 nice=20。恢复后的首次常驻探测实际 nice=19，逐进程记录在回执；随后改为 setpriority，最终精确重测实际 nice=20。首次探测不作为相同优先级的因果比较。

每段记录启动负载、进程表、源码 SHA、迭代数、全部主结果和预测归档。后台应用与其他项目持续运行，未排空机器，未调整其他任务优先级。完整轮次每版本一次，不声称已测五轮稳定吞吐。所有速度均为所列负载下的观察值。

## 剖析与实现

真实 948 点、319 参数的原短求解显示：约束差分约 38%、扇区核约 26%、SVD 约 27%。精确前向优化后，另一个短求解的 SVD 占 1.682 / 2.501 秒，约 67%。两次 profiler 的迭代范围不同，不能作为总耗时前后比较。在后一个样本中，保留 SVD 而删除其余全部工作最多再快约 1.49 倍。

默认路径有以下改动。

- C 扇区核调用同一 SciPy ndtr，禁用 fast-math 和隐式 FMA 合并，保留原张量收缩和归一化顺序。
- 原模型已有解析颜色雅可比；本实现只将约束差分按独立参数块批量计算，保留步长和表达式顺序。
- 同次评估复用重复扇区，拒绝步只算残差，接受步再构造雅可比；不初始化当前拟合从未读取的 Legacy Safety 网格。
- 缓存不变的 Fourier 系数；所有谐波在 binary64 精确下溢为零时复用 DC 结果，不截断非零项。
- 缓存目标 Lab 和基线 ΔE00，以完整类型、形状、步幅和字节为键；每个预测重新评分。17 个输入修改、数组视图和淘汰的行为检查通过。
- 常驻 worker 复用导入和依赖，每个新目标前重验该进程已读输入的 SHA；依赖解包、原生编译加锁并原子替换。输出按请求顺序收集。

主公式从冻结源码 AST 生成，仅替换核对过的节点；源码结构不符合预期时拒绝加载。默认保留原 SVD、边界、迭代上限、停止阈值、训练分区和整数候选选择。

算法实验采用有界 LM，复用雅可比、缩放正规矩阵及相同阻尼/活动边界下的 Cholesky 分解，以训练整数目标稳定为停止依据。cached_lm2 从 L2 起使用 LM，cached_lm 从 L3 起使用；cached_lm_end 把 LM 终点交回原整数候选选择流程。它们不读旧完整码域答案或照片留出评分。

最终常驻探测的 LM2 有 3,537 次雅可比构造、13,626 次复用、9,878 次 Cholesky 构造、6,291 次复用。全轮残差迭代从 69,974 降至 25,905。这是算法收益；失败点是量化后的结果等价。

## 后端和求解方案的实测选择

948 点完整归一化扇区权重，七次交替计时，负载均值为 5.90 / 8.01 / 11.27：

| 实现 | 中位耗时 | 最小—最大 | 等价 |
| --- | ---: | ---: | --- |
| NumPy | 3.585 ms | 3.046—3.802 ms | 参考 |
| C | 0.931 ms | 0.908—1.033 ms | 原始权重逐位相同 |
| Rust | 0.858 ms | 0.829—0.925 ms | 原始权重逐位相同 |

原生实现的范围重叠。默认选通过完整模型与拟合验收的 C；不能据此断言 Rust 整轮更快。见 bench_backends.json。

MLX GPU 实际执行 float64 返回 `float64 is not supported on the GPU`。已测 float32 原始高斯核有 14,038 项超过逐项相对误差 1e-12，最大绝对差 3.05e-5，不能采用。GPU 探测的驻留方式和未归一化工作量不同，未与 CPU 完整核混报；没有实现多字浮点 Metal 引擎。

真实 TRF 矩阵 4,464 × 319，非零占 12.57%。五次交替分解中位数：SVD 106.236 ms、稠密 QR 加小 SVD 49.514 ms、系统 Accelerate 稀疏 QR 加小 SVD 57.734 ms；负载为 66.12 / 84.22 / 56.95。稀疏 QR 未优于稠密 QR。见 bench_factors.json。

正规矩阵特征分解的原 27 项 × 30 组合有 16 项整数状态不同、5 项训练整数目标变差；QR 有 14 项整数预测不同、7 项目标变差。分解改变了浮点运算顺序，完整优化路径随后出现不同整数结果；首次分叉尚未定位，不能证明差异只来自舍入，故未替换默认 SVD。物理坐标、择优起点、提前停止、滞后雅可比、稀疏矩阵和 Broyden 更新也有探测回执，没有作为合格结果。

## 剩余瓶颈和下一步

精确路径仍受 SVD 和迭代数限制，前向优化后短求解约 67% 在 SVD。最终常驻整轮累计 worker 时间中，LM2 为 54.2% 求解器、45.8% 其他工作；终点 LM 为 61.5% / 38.5%。最终精确入口的求解器占累计 worker 墙钟 94.52%，其余 5.48%。这些是累计 worker 时间组成，不是墙钟的可相加阶段。带 profiler 的终点单目标还显示扇区/前向、评分、质量检查和导入成为可见成本；调用有包含关系，不能把其比例相加。最终 LM2 的目标 0 完整 30 组合剖析共 9.736 秒，其中 solve 累计 3.794 秒、扇区 2.993 秒、权重核 2.501 秒、评分 0.962 秒、runtime 导入 1.188 秒；这些行也包含嵌套调用，不能相加。剖析用于定位，不能代替未插桩计时，见 profile_round_final-lm2-round.json。

下一步先记录 QR/正规分解首次分叉的接受步、活动边界与病态方向，建立由矩阵条件触发的 SVD 回退，禁止按目标编号硬编码或读取旧最终答案。再试曲线/偏移线性块消元和原生批量 TRF，保留原整数候选选择。在 27 项预测和质量全部通过后，再以相同核数、负载相近的五轮交替全量测吞吐。照片批量评分可减少 LM 的非求解部分，不能修复当前等价缺陷。

缺陷关闭须同时满足：指定整数预测与质量一致、逐照片留出对照通过、保存重建与码域通过、串并行一致，以及新鲜完整轮次至少 20 倍。目前没有此路径，实验求解器必须加 --experimental-solvers。
