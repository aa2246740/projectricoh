当前提供的 [reference-profile.json](r4/reference-profile.json) 明确为 `synthetic_fixture`，只服务主机用例，不是已批准的真实原生映射。它不能与 `device_capture` 混用。真实探测交付前，必须从最终原生指令独立取得映射并复审、封存；该步骤尚未执行。齐全结果只允许进入离线复核，ER 归属和最终 H42 时间仍保留独立关口。

### R4.4 同步复审 P2 和实现注意事项

1. SLOT 必须区分 `0x201BC3CC` 的 11 个有效描述与原生物理数组的 99 项循环上界。32 只是旧记录容量预算。实际映射必须说明哪些项有效、其余项如何逐项核对；使用完整覆盖、非活动及异常位图时，未覆盖或状态不符均不通过。不能凭两份相同的短列表省掉其余项。
2. 字段名按原生指令确定。`0x2057828C` 是每类跨度数组，`0x2057841C` 是数量数组，槽地址矩阵从 `0x205785AC` 起、每类 76 B。`P+0xEC` 是池起点，`P+0xF0` 是含末字节的池终点；主机半开末端为它加 1，并与 `P+0xF8` 核对，`P+0xF4=P+0xF8−0x40000`。跨度值不能被当作槽基址。
3. 当前主机 JSON 是交换合同，不能直接等同于目标 BSS。新增元数据、完整扫描、紧凑编码、UI 文字和解码工作区都须进 G0。若仍按旧 64 B 记录两种画质的全部 99 项，BSS 由 77,824 增为 86,400 B，主请求估算为 114,508 B，超出两道上限，必须重设计记录方式或腾空间。不能沿用旧 1,680 B 余量称为完整新诊断程序已放下。
4. 刷回矩阵增加恢复目标维度：官方 1.51 和日用 v3.8 分别封存恢复文件集及 SHA，记录有无 DAT/CTL、卡与 IROM 来源、版本检查、拒绝/退出分支和真正终点。每种启动镜像、故障夹具和三个单元按对应目标补证，不能以一个“官方基线相同”覆盖两种恢复包。
5. 用户步骤仍只采 50mm。本轮三单元正例是不同参考身份的合成数据，不能转成 28mm、MOUNT 的容量、框线、时间或照片验收。S10 新增回放前基线；BW 仍不要求用户额外凑按键，未收齐时整次采集不通过。
6. 保留完整 SHA、首次执行前缓存同步、高层文件 API 与保存活动交接、前一文件关闭后再开下一文件、H09 到 K 的唯一映射、H42 拒绝零像素变化及完整提交、H41 独立备份先恢复、H43 真实替换字和局部快照、8 行/13 字符、完整 552 B 输出及效果事务合同。上述最终程序和真实设备层仍按各自关口执行。

本轮只写设计目录和 `/Volumes/Workspace/Scratch/tmp/projectricoh/v4-r4/`。当前输入与写入范围见 [input-receipt.json](r4/input-receipt.json)，清理见 [cleanup.json](r4/cleanup.json)。不改产品代码，不上卡，不刷机，不联网、不做 Git 写操作、不开子代理；各检查前台串行执行。

本轮只写 `research/body_v4_design/` 和 `/Volumes/Workspace/Scratch/tmp/projectricoh/v4-r4/`。检查使用 [offline.sb](r4/offline.sb) 限制网络与写入，四个指定旧文件保持未读。开始时的 r3 清单 62 项中核验 58 项，旧四项沿用原哈希并核对元信息；本次复审清单 21 项全部匹配。当前只读输入冻结 142 项，见 [input-receipt.json](r4/input-receipt.json)。R3 原始回执和清单另存，不改写历史记录。

推荐结构仍是固定窗口、SHA-256 绑定的扩展、可替换 DAT、只放数据的 ER。变化在于扩展和 DAT 共用一个原生父块，ER 归属、H43 时机、主图修改与时间验收分别设门。

| 部件 | 所在位置与职责 |
| --- | --- |
| 窗口 | 固定区间 `[0x2005276C,0x20054800)`，8,340 B。保存全部原厂续接、扩展身份与装载、入口检查、受保护状态、H41 恢复和已获准的 H43 小件。 |
| 扩展 | 父块内固定子区。迁入会话、DAT 装载和菜单分派，执行有界拍摄计划。文件 `GXRCE.EXT` 的完整 SHA-256 固定在窗口；换扩展需重建机身。 |

本文证据分层使用“静态已证、主机已证、估算、未知”。既有模型结果另标出处，不能算成本轮重跑。相机、RTOS、实际照片与物理更新没有在本轮验收。

## 2. 小堆只申请一个父块

### 2.1 分配次数、顺序和失败合同

在原生的首次合格 H01 装载路径，先保留一块共享装载工作区，再保留一个长期父块。扩展、DAT、会话、UI 快照和工作结构只在父块内划分，不能各自调用原生申请。内部区间按冻结大小计算，不写出原生子块头，不把内部地址交给原生释放函数。

父块内从低地址起为控制区、对齐后的扩展、16 B 保护间隔、DAT 会话及状态、DAT 映像与 BSS。各区采用半开区间；顺序一旦封存，装载期间和运行期均不移动。共享工作区按 EXT、DAT、GXRFX 的文件顺序复用，不并存三份副本。GXRFX 写入 ER 前另过 §3 的首次写入门。

通常低层块跨度为 `align4(request)+12`。原生 28 B 分裂门槛允许每块吞掉最多 24 B 短尾，工作区和父块都要先计入这项预算：

```text
父块实际跨度 + 工作区实际跨度 + 其他自有原生跨度 ≤ 108744
通常父请求上限 = 108744 − 620 − 12 = 108112
默认父请求上限 = 108112 − 24 − 24 = 108064
默认合法最坏跨度 = (608+12+24) + (108064+12+24) = 108744
```

108,744 B 是保守设计上限，不能因 r2 基线漏计 12 B 而扩大。108,112 B 只用于无短尾算术和对照，不是默认可发出的父请求。默认先留 48 B，不能等返回超限才停止，因为占用已经发生。若要取回这 48 B，须证明分配时两个块都必然分裂，包含检查到申请之间的并发条件，并重新复审。G0 保留逐块头、地址和跨度回执。通过核头之前不得把候选地址作为自有区域访问。UI 必须位于父块中已有状态区，不再申请新块。

单父块只修复新增拆分造成的形状变化，不能证明所有堆历史都安全。最终真实父请求和所有新增内部占用还要重放既有原生申请、碎片及失败历史；不能把一个正例扩展成全机保证。

装载状态为“未尝试、前提未就绪、正在装载、已验收、已发布、停用到重启”。前提未就绪包括单元尚未发布或高层文件交接未满足，不消耗一次性装载机会；开始实际装载后，任何失败都在本次开机内停止重试。

| 失败点 | 必须发生的结果 |
| --- | --- |
| 工作区返回 0、块头不合法、边界或堆代次不符。 | 在清零或读文件到该地址之前停止。没有父块、扩展入口或 DAT 入口发布。 |
| 父块返回 0，或真实跨度不足、越界、内部布局溢出、短尾使总账超限。 | 在父块清零、EXT/DAT 复制和入口登记之前停止。仅工作区的保留占用也写入回执。 |
| EXT/DAT 头、长度、重定位、身份、短读、EOF、SHA 或关闭失败。 | 清除所有可调用入口和未完成计划，关闭已开句柄；关闭失败则本次开机自有 I/O 停止，不开下一文件。 |
| 归属、堆代次或卡身份在高层调用后改变。 | 旧地址不再访问，不尝试对新堆释放旧块。记录保留跨度；无新发布、无重复申请。 |
| 未发布块清理。 | 默认保留到重启并计账。只有原分配归属、堆代次和无引用都成立时才允许释放，记录实际结果；不得仅凭数值地址相同释放。 |
| READY 后停用。 | 发布历史保留给固定关闭通路；先恢复原厂视图归属，再回原厂 7 行。正在执行的像素提交按 §4 完成后才退役。 |

上述每条失败后，H01/H02/H05–H10/H40–H43 都须按各自合同执行原厂续程。照片保存、缩略图和编码不能因为扩展不可用而少调用一次。未发布地址不进入入口表，停止标志也不能留下旧指针可用。

### 2.2 父块预算与当前 DAT 的差距

暂以真实 v3.9 的 `1,228+6,144+256=7,628 B` 作为 DAT 会话、状态和 UI 容量账。v4 改动后的真实值必须重测。父块控制区暂留 64 B，内部保护间隔 16 B；重定位的持久和临时存储都包含在各自槽内。

```text
P = align4(64 + align16(EXT文件+BSS+另需存储)
               + 16 + v4会话及状态开销 + align4(DAT文件+BSS))
默认 P ≤108064，实际所有原生跨度仍须满足 §2.1
```

| 扩展槽 | 无短尾的算术预算 | 默认含两份短尾预算 | 再留 512 B 计划余量 |
| ---: | ---: | ---: | ---: |
| 8,192 B | 92,212 B | 92,164 B | 91,652 B |
| 10,240 B | 90,164 B | 90,116 B | 89,604 B |
| 12,288 B | 88,116 B | 88,068 B | 87,556 B |
| 16,384 B | 84,020 B | 83,972 B | 83,460 B |

当前 g151 的真实布局为文件 88,596 B、BSS 9,180 B，合计 97,776 B。按 12 KiB 扩展槽，无短尾预算超出 9,660 B；默认含短尾预算超出 9,708 B。只减去压缩设计的 9,480 B 数据，默认仍差 228 B；再假设原型代码少 12 B，仍差 216 B。删除颗粒和统计能省多少尚未编译，不计为已腾出的空间。当前 g151 没有尚未新增的 8 KiB 效果池，不能再从它身上减一次。

因此 G0 必须同时构建真实缩小 DAT。可选措施是按 §8 修正 R3 压缩，删去 v4 不需要的拍摄 DAT 代码，并减少内置表或容量；每一项都以最终完整链接结果为准。不能增大父块来保住效果数，也不能在 ER 归属未成立时靠移动数据段补账。

### 2.3 扩展身份和文件交接

窗口固化 EXT 的完整 SHA-256、精确长度、头布局和允许重定位边界。先检查固化长度与头，再整读、校验、执行重定位、同步缓存，最后发布。运行期 16 点检查只是抽样，不能承诺任意损坏都能发现；它不替代首次完整 SHA，默认不改成 CRC 放行。

EXT、DAT、GXRFX 依次使用已审高层 open/read/close，前一文件成功关闭后才开下一文件。设计实现前必须补一份高层 API 合同：调用任务、内部锁与交接条件、是否可能提交原厂其他文件的脏缓存、卡身份来源、允许的保存活动状态、返回值及关闭失败后句柄状态。不能把同一调用路径等同于与其他文件活动独立，也不能照搬低层锁用法。

初次 H01 若发生在拍照后，须正面确认原厂文件活动交接满足该合同；不满足就暂不读 EXT/DAT/GXRFX。本轮不为此新增信号量 47 操作。不能证明 API 合同就保持该文件功能关闭。

库读入前核对卡身份和依赖的 DAT 身份，过程中和关闭后复查。拔卡、替换、短读、超限、EOF 不符或关闭失败，均不发布半个库。open 返回 −1 仅表示不可用或未知，不能据此新建、改名或删除文件。GXRFX 整体校验通过才发布；运行期失效时停止新效果应用，已有完整配方保持原状态，不能留下半套行。

回执逐个记录生产者、消费者、地址计算指令、区间公式、CPU 或 DMA、创建和失效事件、首个 H01 时是否仍活动。任何未解析间接来源或活动引用不能填“无”。未覆盖模式不进入该 ER 构建的支持范围；若无法阻止进入该模式前原生读取 ER，则整个 ER 档不发布。

首次写入门为“审计齐全、适用当前档和单元、无旧活动引用、运行期代次和边界一致”。任一未知，ER 状态为关闭，库、帧、哨兵和测试图样全部零写入。只读 MEM、HEAP、CRC 或哨兵不变均不能使这道门成立。

### 3.3 归属成立后的运行核对

之后才能写可重复生成的图样，并在每个已审场景后核对整个 ER：4 KiB 头、完整 256 KiB 库区、完整 60 KiB 小数据区、整帧和全部尾部，记录检查字节数、首个差异、代次和场景。单靠首尾哨兵不能通过。载入真实库和半格帧后，使用前完整验证对应内容及身份。

这项运行核对只支持已经审过的范围与生命周期，不扩展为所有使用者证明。只读消费者可以读取错误内容而不改变图样；两次检查之间使用后恢复原值也不可见。E02 必须保留这一反例：归属未成立时先写图样，再由原生只读消费者读取，哨兵不变但数据已经改错，判定器必须拒绝。

任何归属、布局、内容或代次异常都锁存关闭 ER 新操作。本张尚未开始修改时零写入拒绝；正在提交时按 §4 完整结束后再关。重启或换单元不是自动通过，须重新满足首次写入门。

## 4. 拍摄入口按整张照片执行

### 4.1 冻结计划、身份与跨任务同步

DAT 只在菜单提交不可变的配置版本。H09 在任务 6 将该配置与本张原生拍摄身份冻结；H42/H40 在任务 26 只消费同一张的记录。保存任务不进入 DAT，也不与菜单共用可变请求缓冲。

父块保留 18 个 96 B 槽，覆盖 K 槽数，记录开机、堆、单元、设置代次、原生源标识、拍摄序号、K 地址和 K 生命周期、配置版本、尺寸、跨度、动作、CRC 与状态。用短 IRQ 区间完成槽认领和发布，复制完成才写有效序号。读取者先复制到固定局部结构，再复查序号，此后只用快照。

必须从原生指令建立 H09 源标识到 K 生命周期的唯一对应。H09 本身没有可直接假定的 K 参数，不能靠“最近一条”或 FIFO 顺序猜配对。找不到唯一对应时本张整项拒绝，TIME 也不计算。满槽、漏 H09、重复 H42/H40、K 被复用、计划过期、单元变化均不能覆盖仍活动的旧槽。

H42 的预检与提交状态为“未认领、已预检、正在提交、完整完成、已释放或拒绝”。原生保存对本张 K 和像素的独占时段必须由原生调用链及缓冲生命周期证明，不以手工设状态 5 的夹具代替。未能证明该时段或 H42→H40 身份关系，主图修改保持关闭。

### 4.2 受支持尺寸与整张动作

全部动作只支持冻结白名单单元和调用来源，L 尺寸、宽 4,288、行跨度 8,576 B、YCC 基址 32 B 对齐。K 在 `[0x205757A4,+18×588)` 的有效槽内。源像素完整区间在本张获准缓冲内，且不得与 ER、窗口或父块相交。

H40 现有获准外层返回地址为 `0x201558A8` 和 `0x2015EAA4`。H42 所在函数有 8 处间接调用来源，必须分别追到是否执行普通 JPEG 主图路径，再封存自己的白名单；不能把 H40 的地址直接当成 H42 的白名单。来源未确认就零像素变化地拒绝。

### 4.3 拒绝零修改，提交没有正常中途退出

H42 的实际替换字为 `0x20171FD0` 的 `14881EC0`，原厂 K 来自 r8。全部拒绝路径和完整完成路径最终都恢复原厂现场，执行 `r4=r8`，调用原厂缩略图 `0x2015DF5C` 恰好一次，继续 `0x20171FD4`。后续原厂编码和文件保存照常。

首笔像素写入之前完成：窗口与父块检查、扩展 pin、计划唯一匹配、完整尺寸和范围、原生缓冲归属、代次复查、独立 H41 备份准备、整项操作的指令与调用链验收。访问 ER 的动作另须 ER 归属和布局检查；首帧完整 CRC 只用于半格第 2 张，第 1 张在复制完整后生成 CRC 并发布记录。XPan 不访问 ER，不以 ER 已开启为前提。任一拒绝都须逐字节比较整个主图，变化为 0，而非只比较 CRC。

进入提交后只执行已验证的有界复制或填充内核。循环不调文件、RPC、DAT、分配、释放或可失败服务，不逐行重新调用退役检查，也不在某行返回原厂。扩展执行 pin、父块和本张源目标在提交期间不得释放、移动或重建。异步 STOP、菜单设置变化、库异常和退役请求只锁存到下一张；本张完成后再处理。IRQ 不在整帧操作期间关闭。

r2 的“可能只拼了一半但文件完整”出口删除。实现若仍存在从提交中途跳回保存的正常分支，或者不能保证本项完成且没有完整原图副本可恢复，就不启用该主图功能。不能靠关闭编码、跳过保存或有 DNG 来弥补部分 JPEG。

H42 的 XPan 提交前，还须在窗口受保护状态中认领 32 B 的独立裁切记录，保存 K 生命周期、拍摄身份、原始指针与尺寸及裁切量。H42 完整填黑后只发布本张完成标记。H40 由窗口优先消费这份记录，不依赖扩展、DAT 或已排队的退役检查，按同一预检计划裁切；H41 恢复后才释放本张记录。STOP 和配置变更只影响下一张。原生调用链必须保证 H42 到 H41 的本张 K 和源缓冲不复用、不换归属，且本入口确实到达一次 H40；若不能证明，XPan 主图功能不开。不得把“黑边已做、裁切没做”列为可交付出口。

半格第 1 张始终照常保存。关机、换单元、改尺寸、超时或首帧无效时，第 2 张整张走原厂，下一张重新开始。第 2 张拼好后按原厂保存结果收尾，不能承诺它另有一份未拼的 JPEG。DNG 没有本设计新增写入；JPEG-only 必须按相同像素合同验收。

### 4.4 H40/H41 独立恢复

H40 包装器在改描述前建立独立备份，包含 28 B 的 `K+0x14C..0x15B`、`K+0x190..0x19B`，K 身份、拍摄序号与有效标记。48 B 布局已测；正式选择窗口受保护状态或当前包装调用栈，不能放在扩展或 DAT 会话中。r3 根区已为窗口方案保留 48 B。

编码返回后，无论成功失败、扩展已退役、库失效、STOP 或代次异常，第一件事都是恢复这 28 B，再清除有效标记，然后才做任何可失败检查或 H41 记录。保留原厂编码返回值，编码器仅调用一次。退役不能先清备份，嵌套入口不能覆盖活动备份。

v4 对主图的合法提交只在 H42 完成，DAT 不获像素写权限。原厂编码错误后的取消保存、归还槽和复用仍须追完两个白名单调用者，分别覆盖 JPEG 与 RAW+JPEG。没有追完不能把“编码器正常返回过”当成照片保护证明。v3.9 的只读范围不因本设计自动扩大。

### 4.5 H43：坐标与显示时机都要确定

候选 A 的函数入口是 `0x201F7E2C`，r2 所指原厂尾部实际字是 `0x201F813C`；正式构建须再次按冻结官方指令核对原字。候选 B 是 `0x201D7120`，在 `0x201BE250` 复制所需矩形之前画。两者互斥选择，不把 A 入口断点当尾部证据。矩形原语 `0x201D709C` 不设正式钩子，既有升级记录调用它 91 次。

DAT 提交最多 4 个矩形、颜色、层、当前缓冲身份和几何版本。窗口先复制到固定局部快照，再复查偶数序号，之后只读快照。所有负坐标、加法溢出、无效颜色、层宽不是预期的 640 或 320、缓冲换代、当前层无归属或提交矩形不覆盖目标，均不画本帧。用已证层宽和高度检查，不能只写死 640×480 后夹紧。

保存原厂寄存器、返回值、LR、SP 和 IRQ 状态。画线不得调用扩展或 DAT。§5 的受控差分可提供坐标，仍须静态和最终机器码证明 A 返回后尚未提交，或 B 的矩形确实覆盖所需线条。颜色号 0 不能直接解释为透明或空闲。任一事实未定，H43 关闭，可延期，不猜空层。

光标缓存修复也受当前视图归属约束：只在原厂 Image 状态或自有视图仍为当前时恢复 `0x205A2944`，并核对 `0x2022F726`。不能在其他视图上写旧游标。

### 5.3 OSD 的差分必须能解释

每个受控场景记录全部 5 层身份与前后缓冲。先按颜色表、透明规则和原厂颜色号 0 的用法解释内容，再提取实际坐标。每层最多保留 16 个完整 `x,y,w,h,color,flags` 结果，宽或高为 1 的细线也不能隔行漏掉。

读取分固定小片，保留片号和完成数；只在状态、设置、层表和缓冲身份一致时组合。片间变化或记录不足即本场景未定。两次相同摘要只说明可重复观察，不证明整层无人使用。若原生仅在按键事件时提供不足的采集机会，保留未定，不增加隐藏定时器或要求用户反复试到看似通过。

网格和信息框两对必须分别得到稳定、可解释的坐标差分。候选提取溢出、黑色与透明不明、缓冲翻转无法归一、仅有行数或众数时，不输出框线层结论。只读数据无法决定显示提交时机时，H43 未定，交 §4.5 静态时机核对或延期。

### 5.4 SLOT 计算按原生池规则，不相加各类张数

分别采集 S06 与 S07，记录大区表、`P=0x2057AC98` 及 `P+0xEC/F0/F4/F8`、单/双 YCC 选择、实际 P 池起止、尾部长度、类别总数、每类全部地址或范围、个数、间距及间距来源。地址字段来自对应画质的同一冻结记录。

实现前须从原生类别计算指令列出“质量字段与 ID、类别 ID、JPEG 槽、RAW 槽、一组照片的资源需求”的完整映射，绑定官方指令哈希，封存在采集文件之外的独立参考文件。记录不能自己提供期望集合；物理 99 项的完整覆盖口径及原生字段地址按 §R4.4 核对。若原生类别表能静态推导全部模式，仍要用 S06、S07 运行时池边界核对。未知 ID 不猜含义。

容量计算器用同一输入参数重放原生顺序、对齐、头部、封顶与共享池规则，先复现未缩短时的全部类别、基址、个数和尾部，再只改长度字，计算 12.25 MiB、12 MiB、512 KiB 三档。每类 18 个封顶时，池长不能退化成“个数×间距”；只有一个槽时，必须从原生公式或描述字段确定间距，不能由相邻项猜。共用同一 P 池的类别不是可同时排队的独立容量。

输出是“指定单元、画质、单/双 YCC 和场景前提下的容量预测”，不是所有拍摄时的连拍张数保证。RAW+JPEG 必须按一组资源重放；不能把两类各自个数当成可拍组数相加。最终 v4 还须实测连拍到忙与释放复用。

选择顺序为先比较 12.25 MiB 与 12 MiB 的 JPEG-only 和 RAW+JPEG 损失，再由用户选择。r2 的“少一两张”只是候选取舍，不是未经确认的硬门槛；不能只因一档还剩 1 组就替用户接受损失。资料不完整时三档均未定，不自动选最小档。

### 5.5 MEM、HEAP、IMG 和栈的边界

MEM 只显示采样区在两次有效采样间是否出现可见变化。没变化、写回原值、漏采样、未观察到的读者都不产生排他性结论，也不产生分配峰值。HEAP 只报当前物理块及空闲链的一致快照；遍历失败、布局改变、出现未计 UI 块或自有范围不合法时读数无效。

IMG 必须完整保留 K、K 生命周期、外层来源、质量与画幅字段、主图基址、宽、高、跨度及区间。MET 可列出候选尺寸偏移，但候选匹配不授予元数据写权限。

STK6 先核对 RTOS 记录、栈界与标记，再报告观察到的水位；不可读时显示 n/a。零填充水位会漏掉后来写零的栈，不单独证明剩余可用栈。T6、T26 和 IRQ 最终仍按 G0 的完整调用账验收。

### 5.6 用户操作，按画面提示完成一轮

以下是以后诊断包通过独立复审后的步骤，本轮不执行。编排者事先核对机身、诊断身份和测试卡文件，并准备按编号排序的页面目录。

1. 先拍下原来的画质、画幅、网格和拍摄信息框设置。装 50mm，开机后先按 ADJ；还没出现诊断页就再开一次，直到 SUM 显示身份正确和 READY。
2. 半按退出菜单，回到拍摄画面。依次按 Fn1、Fn2，再半按快门一次，不拍照。
3. 先设为 JPEG-only L、3:2，再照提示分别采集“网格关、网格开”和“拍摄信息框关、拍摄信息框开”。每次只改提示的那一项，回拍摄画面后半按一次。收不齐就记“资料不完整、不通过”，保留已有资料，不反复尝试。
4. 换成 JPEG-only L、3:2，开一次 ADJ 记下设置页，退出后拍 1 张。换成 RAW+L、3:2，同样记一次并拍 1 张。再改 16:9 拍 1 张，改回 3:2 后连续拍 3 张。用手机连着拍到相机写卡结束、能再拍和能回放的画面。
5. 先开 ADJ，看到 S10 回放前基线已记下，再半按退出。按播放键看最后一张，放大一下，再回拍摄画面；下次开 ADJ 记录回放后的同场景快照。
6. 开 ADJ，按提示冻结结果。正常操作没有收齐的只读测量保留未定。用手机按编号录完所有子页，SUM 中缺的项目照实保留。另记下你愿意为半格第 1 张和第 2 张各多等几秒。
7. 按第 1 步的照片恢复手动改过的设置，关机，换回日常卡。

诊断本身不写文件，但用户拍照后原厂仍会保存 JPEG/DNG；手动改的画质和显示设置可能保留，必须手动还原。若操作异常就结束当次，换回日常卡并按既有冷启动方法核对，不以再次未复现抹掉首次异常。页数取决于完整字段和类别数，不承诺 5 分钟做完。

## 6. 时间只按测到的范围解释

### 6.1 BW 保留量化误差

只读 ER 的 `0x8` 别名，以及 DAT 自己确实已分配的 64 KiB 对照区。前者是旧图像大区的只读观察，不表示 v4 已获得 ER。输出名称为“读吞吐区间”和“校验样本耗时”，不写读写速度，不据此判定缓存属性或 H42 总时间。

候选固定工作量为 32 个有效片，每片读 ER 256 KiB，循环读 64 KiB 对照区 4 遍，另测固定 64 KiB 的 CRC 样本。总量与次数不受运行 tick 控制。可以把三个内核分到不同回调，但每类仍固定 32 片；收不齐则未定。只利用正常必测操作产生的既有回调，冻结时不足就保留未定，不为凑片数增加用户按键。G0 若整回调超 2.0 M 条，缩小每片工作并重新编译计数，不在设备上按时间不断延长。

读内核保留实际 load 与可见的自有累加结果，对照区在自有 BSS 中初始化；在最终机器码核对没有被编译器消去。读发生在开中断状态，不把整回调的 IRQ 区间或其他任务等待从证据中省略。

记录每片开始/结束 tick、字节数、重复数、来源与校验结果。以已确认的 1 ms 时基，N 个分开计时片的累计有效 tick 为 Q，则保守计时区间为 `[max(0,Q−N), Q+N] ms`。对应吞吐区间为 `[总字节/时间上界, 总字节/时间下界]`，下界为 0 时速率上界不定。Q 不足 128 tick、溢出、零时差、来源变动或缺片均显示未定，不假定误差会随重复数自动抵消。

64 KiB 的旧单次测量必须保留为反例：真实 40 MB/s 可读 1 或 2 tick，算成 65.536 或 32.768 MB/s；真实 15 MB/s 可读 4 或 5 tick，算成 16.384 或 13.107 MB/s。区间跨某个研究阈值只能记未定，本版不再使用 40/15 MB/s 放行半格。

CRC 样本可以给出同读法和内核下校验 256 KiB 的估计区间，不能给整帧最坏界。读 ER 不约束写 ER、重叠移动、填充、CRC、缓存同步及任务等待的合计时间；旧程序窗口和自有缓冲的带宽也不能替代。

### 6.2 TIME 只到编码返回

每张使用 `开机/单元代次 + 原生源标识 + 拍摄序号 + K生命周期` 绑定 H09、H40、H41。只有唯一对应、顺序有效且三项齐全时，计算 H09→H40 和 H40→H41。字段名分别为“到编码入口”和“编码调用到返回”，不能称为保存完成。

前一张未到 H40 而后一张 H09 已到、单通道忙导致回调漏失、K 复用、重复或乱序，均作废相应配对并累计漏项。禁止最近两个 tick 相减。快速连续三张作为独立场景，不能混入单张基线。

手机视频另记快门动作、原厂写卡指示结束、再次接受拍摄、可回放的时点，以及帧率与读数误差。这些是原厂基线，不是 H42 的新增时间。

### 6.3 半格时间放行留到最终 v4

用户给出的额外秒数 `B_first`、`B_second` 是需求输入，不是测量结果，没有默认 1 秒通过值。未填写或改变需求须保留未定。

最终 v4 用封存的复制、重叠移动、填充和 CRC 内核，在实际图像/ER 窗口和 T26 环境分别测 H42 全程，包括预检、pin、同步及等待。同时用相同设置的基线比较实际写卡结束、可重拍和可回放延迟。按每个获准单元与 JPEG-only、RAW+JPEG 记录样本数、最大值及 tick/视频误差，不把电脑模型的耗时当相机数据。

在已声明测量场景内，最大额外等待的上界不超过用户对应预算，像素和原厂续程验收也全通过，才可开启半格。跨预算、漏项、配对不明或未覆盖内存环境就关闭该功能。样本最大值只支持所测条件，不宣称全机最坏值。若实现前就必须决定时间是否能接受，暂缓半格，不能用只读 BW 提前给肯定结论。

## 7. 刷回独立性必须补最终镜像证据

### 7.1 现有证据只能这样说

r2 的两份保存记录是官方镜像仅改长度字和校验字，分别减 12.5、12.25 MiB。推荐尺寸镜像 SHA-256 为 `2d0de3c8b4adf1b2bbb341b71b0b4540bbb77f5ee11b4641ff15bd7d284cacff`，不包含尚未实现的 v4 窗口或扩展。

复审独立重比：第 65,975,242 步到确认，之后按输入 18、24；到 5 亿步以 budget 停止。99 个里程碑、46 次文件打开和 NAND 命令计数与官方相同。NAND 命令计数相同没有区分更新阶段，不能说实际更新已完成。

既有 H42 位置和 H43 函数入口未命中，支持继续选点；H43 A 的实际尾字未在原记录单独覆盖。原生分配器在开机共用路径执行，矩形原语被调用 91 次，因此不在这些位置增设正式钩子。

### 7.3 尚不能用夹具替代的刷机门槛

模拟器若仍到不了实际机身 NAND 更新、单元检查或更新、完成画面，就保留未通过。补模型时必须执行原厂对应状态机并验证更新目标、数据、完成状态与重启后身份；将返回值固定成成功不算补证。有限记录只批准其实际到达的路径段。

物理按键电平、电源控制器、真实卡时序和更新完成仍需后续专门验收。它们与全部最终电脑端恢复证据是刷机前门槛，不把第一次真实刷机当成已有证明。实现中不修改单元固件。

用户恢复说明统一为：装 50mm，开机时按住“+ 与播放键”。刷机前说明改动和恢复方法，取得用户明确同意。正式阶段沿用已核对的三单元流程，不能自行声称其他顺序等价。默认故障步骤不包含格式化；刷回不会找回格式化删除的照片。

## 8. 效果格式与其他 P2 必须一并保留

本轮不替效果扩容或 g150/g151 发布审查放行。v4 依赖以下格式和事务条件：

1. R3 的物理块长与有效点尾分别定义。当前正常数据有效点尾为 7,902 B，有效点区为 `[3664,7902)`，物理块长 7,904 B，最后 2 B 为零填充。要求 `logical_end=POINT_OFFSET+2×POINTS`、最大引用尾等于 logical_end、引用覆盖有效点区且无空洞、`block_length=align4(logical_end)`、尾填充全零。正常 R3 能被正式解析器接受，版本按合同处理 R2；非零填充、未引用点、越界和错误对齐均整体拒收。
2. 逐个单控制遍历全部 65,536 个 int16 输入，覆盖 3 单元、8 基底、10 控制及隐藏项，比较成功/拒绝、52 B 请求与失败时输出不变。结合完整档位和剂量序列、独立查表与组合逻辑相同给出组合性证明，保留两两端点。非法单位、基底、空指针和点索引另测。
3. 从最终打包 DAT 回读 R3 和基底，比较完整 552 B 输出，包括九行、T、14 行及 CRC；新增效果用最终编码的相同基底建立参考。保留“请求相同但 C080 最终字节不同”的对照，比较器必须检出。失败在 W 前拒绝、零写入，不能只比较请求或 CRC。
4. 文件、代码和主请求三项按最终链接同步定容量 K。完整效果身份进入构造、当前态、确认态、快照、补偿及重算。保留内置→效果、效果→同基底另一效果、效果→内置的锁忙回归，比较九行、T、S 和实际计划全部字节，不能只看模式已相同。
5. 定长 12 B 名字复制到有 NUL 的缓冲；两套持久文本数组都扩为 14 B，并检查局部数组和固定复制。所有自有页面、空页与过渡页恰好 8 行。颜色行、黑白、ISO100 的 14=5、MOUNT 原厂 04/pin 和 T1 掩码按最终整数编码字节检查。
6. GXRFX v2 不仅扩大行索引，还要同步容量、行数、索引上限、精确区长和整体 CRC 规则。256 KiB 约千条只是估算，按每个条目、独立行池和元数据实算。格式不合法时整库不发布，不给已应用配方留下部分更新。

数据格式、主体服务与三个代数条件须来自独立放行并封存的基线。当前报告首行或一次对象编译不能代替发布复审。若最终 DAT、BSS、代码或 ABI 变化，全部尺寸和身份回执重算。

## 给用户的大白话

这轮修的是资料判定：少一份快照、场景混了、记录被覆盖，或单元、序号和时间对不上，都算“资料不完整、不通过”，不能据此判断缓存大小、框线或保存时间。资料齐全也只代表可以交给电脑复核。

v4 想做的仍是宽幅照片、两张竖拍拼成一张，以及更大的效果库。现在这版把会伤照片的出口改掉了：条件不对就在改照片前停下；开始改以后必须做完整，不能交给你一张只拼了一半的照片。

下一步先在电脑上确认代码和数据真正放得下。然后才做一张只读诊断卡，先开出诊断页，再按键、换两种画质拍照，最后录完结果。它能告诉我们连拍缓存可能少多少、框线位置能否确定，也能记录原来的保存时间；它不能证明那块内存没人用，更不能提前保证半格只多等一秒。

半格要拿走约 12 MB 图像缓存。现有模型里，单份 YCC 的输出池少约 22%，双份 YCC 少约 38%；具体少几张和你能否接受，要等对应画质的数据。若代价太大，可以只留 0.5 MB 做效果库，半格先不开。框线时机没有证据时也先不开。

你的相机本轮仍是 v3.8，v3.9 和 v4 都没有刷。现有电脑记录只证明“+ 与播放键”能走到确认并继续读取更新文件的一段，没有证明最终 v4 能实际完成刷回。以后真要更新，先补最终镜像和坏窗口、坏扩展的电脑证据，再说明改了什么、怎样恢复，等你明确同意。恢复说明用 50mm，开机时按住“+ 与播放键”；默认步骤不包含格式化。
