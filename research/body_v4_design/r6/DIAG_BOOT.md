# diag-v4p 的 R6 只读增补

本文件是未来实现的规格，不是已经可运行的诊断包。主设计 §R5 的严格记录合同及 §5 的 11 个场景全部保留；本增补不能以“齐全”代替 ER 归属、参数事务、持久保存、真实首张颜色或恢复完成证据。

## 1. 两种能力和只读边界

| 能力 | 能证明的范围 |
| --- | --- |
| `BOOT_CURRENT`。 | 使用经过独立放行、身份封存的 v3.9 机身，在 H01 之后读取当时的状态、MY、S、锁、单元与完整九行/T。没有装载前资料就明确显示 `Early n/a`。当前值不是首次状态 5，也不是未发生来源动作的证据。 |
| `BOOT_EARLY`。 | 需要新的只读观察机身。DAT 装载前在独立自有固定 RAM 保存原始启动与来源事件，DAT 后来只读并显示。观察版本不自动套配方，不修改键码或拍摄参数。必须先有新的机身/build/ABI/DAT 身份和独立复审。 |

新增读取仅限已确认对象和范围；不扩大地址扫描或试发未知单元查询。诊断只申请 READ、UI、BODY，不申请 S/W 或文件能力，不分配/释放原生块，不用信号量 47。S 与尾部通过新版本有界纯读状态接口取得，不调用需要 CAP_S 的旧 op 4。单元仅发已审核的 X/V 读取，不发 W，不改 T，不提交存储。观察结果只写已证明自有的 832 B 固定存储和诊断 BSS；UI 沿用已审核的受限发布例外。

新增机身不能靠不明 RAM 开始记录。G0 必须证明该区冷启动、保留 RAM、升级与正常路径的初始化和归属，全部原厂续接及寄存器现场正确。采样不持原厂锁、不增加等待；原生字段无法在当前任务/IRQ 安全读取时记录缺项，不在错误上下文补 RPC。

## 2. 来源与观察点

首先静态列出原生启动类别、MY/复位/来源的全部生产者、分派者、最后参数复制、完成与保存提交点，以及全部首次成像参数消费者；逐点封存机器码、调用来源、字段含义和时基。没有完整清单时，“事件数为零”只表示未观察，不能证明没发生。候选地址不能替代真正完成点。

| 点 | 必须保存的原始事实 |
| --- | --- |
| P00 启动分类。 | 最早观察点 PC 与原始分支值、普通/播放/升级/维护/复位恢复/保留 RAM 类别、开始位置是否早于全部来源动作、boot 身份和对象初始化阶段。分类不明保留未知，不由最终状态推断。 |
| P01 参数来源与单元完成。 | 每个生产者/完成点 ID、原始来源值、MY 分派与恢复完成、S 指针/长度/版本和来源、单元链接及初始化状态、实际完成 tick 和原厂去向。迟到来源也必须记录，不能在第一次 5 就停止观察来源。 |
| P02 首次进入 5。 | 本次首次原生状态转移的前值/后值、tick、任务、IRQ、锁 ID/count、MY 与 pending 原值及其初始化事实。以后回到 5 不覆盖首次项；如需返回次数，从逐条事件重算，不能只累计计数又丢弃条目。 |
| P03 首个成像参数消费者之前。 | 实际请求身份、半按/直接全按/其他触发、PC/来源 ID、tick、任务和原厂下一目标。须早于任何为该照片读取/下发成像参数的命令；单元初始化读取和拍摄参数消费者在独立映射中区分。H10 和 H09 不能顶替本点。 |
| P04 首个 H01 与装载。 | H01、装载开始/结束和 READY 的真实先后、同一 boot/来源/单元/S 身份；在合法任务只读完整 S 白名单/40 B 尾部、503 B 九行、T、唯一 ID 原始长度和全部字节，并在前后复查对象。读到当前快照只标为当前，不填入 P01/P02 的空位。 |
| P05 首张与后续照片。 | 复用逐张 H09/H40/H41 的来源、序号、K 生命周期和 tick，明确首张是否在 H01 前发生。没有唯一 P03→照片映射就保持未定，不能用“最近一张”猜。 |
| P06 来源失效及原厂保存。 | MY、Restore Defaults、Start Settings Readout、Setting1/Setting2、Body/Camera Unit、单元/版本及维护恢复各自开始、最后复制、完成和保存边界；记录已识别 40 B 尾部前后原值及 S 对象。只观察，不清尾部或触发保存。跨开机持久性另由独立场景及存储证据证明。 |

已知只读字段包括状态 `0x205D9C00`、MY `0x205D9AA3`、pending `0x205DA00B`、S 指针/长度 `0x200C0DAC/0x200C0DB0`、S 的 `+8/+0x36E/+0x6DD/+0x6DE/+0xFD4`、锁 `0x204104F0/+4` 和既有单元名字/版本源。先核对 S 对象合法区间、长度 `0x1000`、扩展版本，再读并复查身份。MY `0x202E43D4` 仅为候选分派入口，来源候选 `0x200677AC` 仍需实际完成证据。唯一 ID 须另有厂商字段、长度、读取方法和对象寿命依据，名字或版本不能充当它。

## 3. 早期原始存储与诊断内存

固定存储 `[0x200542C0,0x20054600)` 共 832 B：64 B 头，加 32 个 24 B 原始记录槽。每条预算为六个 uint32：连续物理序号、原始 tick、来源/事件类型号、上下文索引、两个原始参数。类型号和上下文索引必须来自独立冻结目录，并有完整原始定义。多字事实用明确的分片事件，不把大对象的摘要算作原始快照；序号按物理分片计，按组验证全部分片后才算一个成功的语义事件。

64 B 头预算包含格式与开机标识、采集范围/状态、覆盖情况、阶段引用以及必须在 DAT 停用后保留的 dirty/错误状态。头中的冻结事实与运行控制字段须明确区分，不能为清运行状态改写已冻结事实。`layout_probe.c` 只测预留槽大小，尚未给出实际字段布局；最终字段若放不下，扩大区间并重做窗口 G0，不能丢字段。

32 条是待验证的容量，不是来源全集的上界。实现者必须列出每个支持场景从 P00 到该场景封存的生产者次数、各事件最大分片数、状态返回事件和并发保留项，证明所需物理槽数 ≤32。超出时新增记录停止并锁存溢出，已有记录不覆盖；该场景不完整。不得用位图、总计、首次/末次摘要替代中间原始事件，不得只记录“感兴趣”的来源却声称没有其他来源。功能版本在首次事务之后仍持续撤销来源许可；运行控制序号不能冒充可证明记录齐全的采集计数，溢出或不明来源须撤销资格。

DAT 通过有界只读接口读取固定记录，冻结后不再复制完整事件链。诊断新增 BSS 上限 768 B：128 B 读取/控制/冻结元数据、512 B 九行/T/校验快照、128 B S 相关原值/40 B 尾部/完整单元身份。超过八字节的未知 ID 仍要报告实际长度和缺口，不能截短后放行。需要保存不同阶段的完整九行时必须分别预留空间或分开冻结采集；一份当前快照不能覆盖早期快照。

新增代码上限 1,024 B，共享读取/格式化净减目标 640 B。历史起点为文件 20,480、BSS 77,824、固定 7,628，加入增量和净减后目标请求为 107,084 B。64 KiB 自有对照区完整保留，额外原生块为 0。主请求硬限 107,612 B，亦须满足用户上限 108,124 B；目标不是实际放下。R5 原始来源的最终紧凑编码、完整 99 项覆盖和导出 UI 尚需真实链接。若仍用原 64 B 方式多存两组物理项，另增 8,576 B，达到 115,660 B，失败。

BOOT 在首次 H01 后独立冻结并录完。随后显式建立 S01–S11 的新冻结集，早期固定槽仍只读；它们关联同一 boot，但不是把已经冻结的主记录继续补字段。MY/复位等需覆盖动作当次的场景，使用独立 boot/场景编排，使 P06 完成和必要原厂保存事件落在该次封存之前。若动作发生在封存后，它不属于已封存范围，不能算已覆盖。并存的封存描述和新采集元数据也要进入真实 BSS 账。

所有新服务、快照、冻结接口和 UI 的整回调仍 ≤2.0 M 指令，开 IRQ 扫描；只读单元调用的原生等待、真实 T6/T26/IRQ 栈另有上界。缺任何上界不安装该观察版本，不以短布局编译或 PC 采样当作证明。

## 4. 固定记录合同与判读

保留 R5 的底层条目重算、独立参考、准确字节冻结和公共非零拒绝。BOOT 新格式使用新的固定版本：字段集合、类型、枚举、范围、分片规则和上下文关系全部写死；新来源、新字段或旧格式不得默认接受。不能向旧 version 4 追加未知成员后仍称兼容，也不能把只有旧 11 场景的齐全结果称为 R6 已通过。

每条物理事件记录它被采集时的 boot、单元/链接/S 代次、来源序号和阶段上下文。若采用索引压缩，对应上下文必须在当时先锁存，完整保留建立事件；不得在 H01 从父记录事后复制身份。全部原始字段的 PC/对象来源须有独立目录，源点未启用、开始过晚、丢中间事件或未知来源均不完整。

| 派生字段族 | 必须由底层重算 |
| --- | --- |
| 头、阶段的有效/丢失/覆盖/溢出数、完成与覆盖位图。 | 逐条物理序号、重复身份、必需生产者/阶段/分片集合和独立场景预期；头声称的零丢失、全覆盖不能自证。观察能力不足或停止原因不明时不宣称完整。 |
| 物理记录数、语义事件数、起止序号与阶段引用。 | 数实际条目，验证相邻序号及分片组，再数完整语义事件；P02 必须是从 P00 开始所保存的第一次 5，P03 为该范围第一个对应消费者。 |
| 各段长度、偏移、ID 长度、S/行对象长度和校验。 | 从保存的完整字节串、片段及独立结构尺寸重算，核对范围、无洞无重叠、CRC/SHA 与冻结回执。真实 ID 不明即未定，不用摘要替代。 |
| MY/复位/来源计数、是否未发生及来源最终完成。 | 按完整生产者目录逐项核对开始/完成/保存事件和顺序。没有事件只有在从早于全部来源的记录开始、来源目录齐全且无缺失时才可表示“未发生”。 |
| 时间与启动耗时。 | 从原始 tick 和独立时基计算有界差值，允许有证据的 uint32 回卷；当前 H01 时刻不补首个 5，编码返回不算保存完成。 |
| 跨开机场景结论。 | 从独立场景清单关联动作当次和随后的新 boot，分别核对记录/快照/来源与持久存储身份。不能把两个 boot 的事件拼成一份连续链。 |

凡缺快照、场景混用、覆盖、来源/类别不明、单槽间距未知、无效时间、单元不符、序号不连续，整次输出“不完整、不通过”。早期信息齐全时仅可显示“早期记录齐全，可复核”；不显示自动套用已通过。缺失 P04 时允许研究 P00–P03 的原始资料，但总状态仍不通过。

新判定器交付前，从每份完整正例逐字段删除、增减、换类型、复制/交换/截短及两点组合变异；另覆盖完整场景少一种来源、缺片、晚启动、32 槽溢出、两边计数一起改错、同值 MY/复位、跨 boot/单元与旧窗口资料。更新记录摘要后也要检测原始来源关系。每个负例公共命令行必须非 0，完整独立封存正例全部接受。R5 全部原例作为兼容独立测试，不能以新版本拒绝旧版代替旧格式自身的正确判读。本轮没有实现或运行这份 BOOT 判定器。

## 5. 用户步骤的增补

以下仅用于未来获得单独批准的只读观察包，本轮不执行。操作前由编排者准备每次启动的编号与待录页目录；相机自有页始终 8 行、每行最多 13 个可见字符，32 位地址完整拆页显示。记录不写文件，用手机按编号录完；每次关机前冻结并录完自己的结果，不能指望下次 RAM 仍在。

1. 先拍下现有设置。装 50mm，在普通拍摄模式关机再开机，先不要推 ADJ。按平常方式拍第一张，再开 ADJ，按页面提示冻结、录下这次开机的记录。这张是早期场景，不算装载 READY 后的 S06。
2. 再关机开机一次，先不推 ADJ，直接把快门按到底拍第一张；之后才开 ADJ、冻结并录完这一份。两次记录分别编号。后续再按主设计 §5.6 做 Fn、网格/信息框、JPEG/RAW、连拍与回放，不增加凑 BW 片数的按键。
3. 另按编号检查 MY1、MY2、MY3 的启动、调用和退出，包含一组“MY 参数恰好和 04 相同”的设置。每个需要判断下次启动的动作，都先录动作当次，再关机开机录下一份；不能把三种 MY 合成一次已覆盖。
4. Restore Defaults 和 Body/Camera Unit 来源切换会改变设置，留到另行获准的设置验收，事先记录并按原约定恢复；观察包自己不执行这些动作。分别录动作完成当次和下一次普通开机，同值复位也保留。流程不含格式化。
5. 三单元既有验收时复用关机换单元的步骤。现场只有不同型号时，只能覆盖不同型号；同型号两颗单元的 ID 区分须有对应实物或明确标为夹具证据。播放开机、保留 RAM、更新与维护分支先用模拟器和独立 CPU/存储夹具补齐，不能为了采集要求用户反复更新相机。

一个观察包可复用原定拍摄和菜单操作，但多个来源场景仍需要各自的启动，不能承诺一次开机全测。没有可靠 ID、早期源点或完整页就保留未定，结束当次并导出现有资料，不要求反复开 ADJ 直到看似正常。诊断不写文件；用户试拍由原厂保存 JPEG/DNG，手动设置也可能保留。

## 6. 留给功能版本的证据

本增补只帮助建立候选时机和普通启动资格。下列事项仍须独立验证：参数写者与消费者的整个事务时段、锁忙及逐步补偿、S 来源失效和保存的断电一致性、DAT 退役后的固定拒绝、数据资源区的 ER 归属、最终真实首张颜色、实际新增等待和全部恢复目标。新的更新/维护排除也必须进入主设计 §7 的真实入口及坏窗口矩阵。只读原值相同不能替代其中任何一项。
