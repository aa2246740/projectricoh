### 斜坡是有结构的点对，通道含义仍未定

`0x201179A0..0x20117AF4` 将 `F+0x25` 展开到镜像 `0x20142D70..0x20142D90`，完整 writer 送往 `0xF03532F0..0xF0353310`。选择号 0 读 `T+0x2400`，1 到 10 读 `0x2012EF68 + 16×(选择号−1)`。255 会改用 10，超出范围则保留既有镜像。

首、尾 word 只有低位值。中间七个 word 为 `(源[2i−1] << 16) | 源[2i]`。原厂非恒等行 4、5、7、8 的高半字基本固定为七个递增控制点，中心为 127；低半字随行改变。恒等行中心为 128。因此“默认两个半字相等”并非完整结构。点对曲线是更强的解释，半字的硬件含义仍未知。

模型把 `T+0x2408` 的响应值从 128 改为 96，两模式都只改变 `F0353300`，得到 `0x00800060`，另一半保留 128。快速路径不写这九项；完整打包会重建镜像，完整应用会重写硬件。不能把 Off 后再次 On 当作必然恢复斜坡。[斜坡源与打包](local/r3/evidence/ramp-source.txt)、[单变量重建](local/r3/scalar_studies.json)

### 48 word 是八个记录，后半段的 T 地址不连续

前半块由 `F+0x29` 选择，后半块由 `F+0x2A` 选择。每半块 24 word，分成四个 24 B 记录，writer 在 `0x20257A20..44` 连续写 48 word。

| 块 | 选择号为 0 时的四个 T 源 | 选择号 1 到 16 的库 | 目标 |
| --- | --- | --- | --- |
| 前半 | `0x0B4C / 0x0B64 / 0x0B7C / 0x0B94` | `0x2012D58C`，每行 96 B | `F0353340..F035339C` |
| 后半 | `0x0BAC / 0x0C00 / 0x0C18 / 0x0C30` | `0x2012DB8C`，每行 96 B | `F03533A0..F03533FC` |

出厂 T 的前四记录相同，尾部响应多为 `0x80`；后四记录也相同，相应响应多为 `0x40`。前部含递增的 16-bit 数值，整体形状支持曲线或增益记录的解释。它没有显示常见 RGB 三元组、逐像素 mask 或颜色索引。相同记录和固定尾值也不能排除硬件中的多路或混合用途。

在选择号为 0 的模型中，`T+0x0B5C` 的一个字节改变只落到 `F0353350`；后半对应尾字节 `T+0x0BBC` 只落到 `F03533B0`。这与 r2 改 `T+0x0BAC` 的结果不同，后者改变记录开头，不是尾部响应。两者不能混称同一个试验。

P2 直接测试前半第一个记录的尾字节，不更改来源选择号。快速路径不触及本块，完整重建会覆盖它。后半块暂不追加第二个探针，先用一个受控变化确定现象。[八记录取源](local/r3/evidence/block-source.txt)、[完整 writer](local/evidence/type32-writer.txt)、[T 与行库](local/r3/sources.json)

### 可达的 F035 页没有给出新的颜色定义

X 的普通页分支把 `0xF035` 形成基址 `0xF0350000`。该地址区使用 32-bit 访问：V 读取对齐 word，再取所需半字；W 读取完整 word，替换一半后写回完整 word。它不是原子 16-bit MMIO store。[页选择](local/r3/evidence/address-page.txt)、[实际读写宽度](local/r3/evidence/word-half-write.txt)

有界扫描在单元中找到 271 处 F035 或 F036 高半字构造，在机身中找到 261 处；两个映像各有 72 个四字节对齐的 F035 地址常量。它们含以下已知描述组，数量不能当作寄存器数量或写入点数量。

- type 29 是 `F0350008/002C/0030/0034/0038`。writer 另操作 `F0350004`。
- type 30 指向 `F0351000`。
- type 32 包含上述候选，也包含 `F0354000`、`F0355000` 附近的控制和表。
- type 33 指向 `F0356000..6014`。

本轮没有把这些字段连到独立边缘颜色、叠加层或 alpha。`F0353000` 来自 F 的首个 halfword，已见普通参数位控制关系；模型中的零不是相机现场值。对它枚举位值会同时改变多个未知条件，不适合作为本轮单组探针。描述组可对照 [既有 ISP 清单](../isp_pipeline/REPORT.md)，新增地址证据见 [单元扫描](local/r3/scans/jlaunch3-f035.txt) 和 [对齐常量](local/r3/scans/jlaunch3-words.json)。

原生 type 32 部分 writer 会保存访问状态，并经 `0x20258324` 设置 `FF70006F/0070/0074` 的若干位后写入。普通 W 没有等价协议。P2、P3 因此不能被描述成已经验证的原生配置替代品。[原生部分写入](local/r3/evidence/native-partial-write.txt)、[type 32 访问控制](local/evidence/type32-access.txt)

### OSD 有颜色，但尚未连到描边

机身链 `200E1610 → 203D04C8 → 203D0554` 将 RGB 转为 Y、Cb、Cr，色度加 128 并限到 0..255，保留输入高字节。两个调色板基址按代码算式分别为 `F0218000` 和 `F0218400`，每项四字节；写入前检查 `F0218804` 的 bit 15。

机身有 256 项初始化和更新循环。另一条链 `201D709C → 201BE074 → 201D7EC0 → 20062750` 按 320 或 640 的行宽，以一个 8-bit 值填矩形；它提供了图形使用索引颜色的正向证据。该行宽仍不能替代完整显示缓冲契约。[机身调色板](local/evidence/body-three-tables.txt)、[更新循环](local/evidence/body-palette-updates.txt)、[缓冲选择](local/r3/evidence/body-buffer-choice.txt)、[矩形填色](local/r3/evidence/body-pixel-colour.txt)、[字节填充](local/r3/evidence/body-byte-fill.txt)

单元也有同构例程 `20105020 → 2025D5F0 → 2025D67C`，目标同样是 F021 调色板。现有直接地址构造扫描仅找到包装器调用低层例程，未找到包装器的上层直接引用或对齐函数指针。间接调用和计算出的地址未穷尽，不能宣布它从不运行。[单元颜色例程](local/evidence/unit-osd-colours.txt)、[引用范围](local/r3/references/detail.json)

本轮尚未分别把直方图、电子水平仪、对焦框绑定到单元侧的调用者、颜色索引和缓冲生产者。直方图相关字符串只能证明统计或诊断代码存在。没有证据表明这些可见图形由单元绘制，更没有证据表明峰值白边消费 F021 调色板。因此不设计“替换公共白色”的试验。

### MODE 1、MODE 2 剩余字的去向

每模式为五字节 A 加五字节 B。以下是静态展开关系，完整与快速配置的消费范围不同，不能把所有字段都当作快速路径的即时控制。

| 字段 | 展开与下游 | 对本轮的意义 |
| --- | --- | --- |
| A[0] 两半字节 | 进入辅助结构 `20383F64` 的前两字节，经 type 27 镜像 `201430B4` 处理，相关描述组以 `F034A000` 开始。 | 旧的 type 32 算术模型不覆盖这个结构。不能用 A[0] 的模型差异为空来证明该字节无效。 |
| A[1] 两半字节 | `F+2/+5`，选择固定目标的其他系数或响应组。 | 没有可识别的颜色路由位。 |
| A[2] 两半字节 | `F+8/+9/+0E/+0F`，到 `30E8..3118`、`3130..3150` 等。 | 系数与标量选择已知，颜色通道语义未知。 |
| A[3]、A[4] 高半字节 | `F+26/+27/+28`，到 `F0353324`。 | 已有真机排除，不再设计。 |
| A[4] 低半字节 | 所查两条展开路径没有消费它。 | 没有给它指定新枚举值的依据。 |
| B[0] 两半字节 | `F+4/+7`，响应表到 `3044..3054`、`308C..309C`。 | 改响应仍不等于改颜色。 |

| B[2] | `F+0C/+0D`，到 `F0353120`。 | 缺独立颜色或边缘输出的定义。 |

## 三项探针设计

优先级是 P1、P2、P3。没有制作这些文件，表中的 P、A、R 名称是未来模块的逻辑名称，不是本轮交付的二进制文件。所有步骤都以未来已有对应模块并通过其主机检查为前提。

### 共用框架和恢复边界

沿用现有菜单 08 的单文件 `P` 加载方式、入口 +16、436 B 文件和 CRC32=0。P 模块再次触发时切换回原值，另有一个只含自身目标的 R 模块。更换卡上 `P` 文件沿用既有流程，不要求在运行中更换存储卡。

现有 `pk_io` 的低偏移选择 T 页 `12C0`，高偏移选择 D 页 `2012`。P1 直接复用。P2、P3 及各自的只读 A、复原 R，需将低偏移分支的页常量改为 `F035`。指令宽度不变，但这已经改变模块的访问范围，必须另改地址白名单并验证，不能沿用旧校验结果。[现有辅助代码](../../firmware/peaking_probe/pk_core.S)、[现有 B 模块](../../firmware/peaking_probe/module_b.S)

每次 W 前核对旧值，W 后重新 V 读回。只接受原值或该探针的唯一改值，其他值显示 `ER` 并停止。R 对原值重复执行不写，对改值执行一次恢复，对未知值不写。旧 R-all 不覆盖 `EBE0`、`3350`、`3302`，不能声称它会恢复这三项。

X/V/W 还有一项共用前提。`202429C8` 在四个待处理计数非零时会修改 `T+3F0C/+3F10`，V 也会走它。映像中 `2024615C..6168` 的四个初值为零；本方案只接受完整冷启动后未运行调整事务的会话，模块自身只用 V/W/X，不设置这些计数。已有框架不能为一个任意旧会话证明它们为零，不能把任意会话的 A 读取称为零副作用。[记账路径](local/r3/evidence/address-reader-state.txt)、[启动数据](local/r3/initial_state.json)

P1 的目标是映像中的运行时 D 数据。其原始文件不变，完整断电并重新加载映像后恢复原值，这是本方案避开 T 源的理由。P2、P3 按 ISP 临时配置寄存器设计，没有非易失写命令；但缺少芯片复位定义和这两个地址的冷启动实测，无法把它们的断电恢复写成保证。按用户的硬条件，它们保持备选，不进入可执行文件制作。

观察期间固定曝光和场景，同时保留合焦细线、失焦平坦区、真实白物体和 UI 参照。不半按、不拍摄、不切其他处理模式。参数可能与照片处理共享，当前没有照片隔离证明。异常时停止当前组，按该组的恢复或完整断电流程退出。

### P1：MODE 1 的成对输出量，首选设计

改什么：D 页 `2012` 的 halfword `EBE0`，即 `0x2012EBE0`，从 `FFFF` 改为 `7FFF`。保留第二个字节，只把第一路 255 降为 127。原始文件位置为 `jlaunch3+0x0E3DE0`，不修改该文件。

在 MODE 1 的出厂 B[1]=129 条件下，完整和快速模型都仅将 `F035311C` 从 `0x00FF00FF` 改为 `0x007F00FF`，镜像为 `20142C50`。MODE 2 使用相邻行 `EBE2`，寄存器不变。MODE 1 的系数加一条件不会改变这两个 B[1] 展开字段。[成对量打包](local/r3/evidence/mode-limits.txt)、[P1 重建](local/r3/probe_studies.json)

启用前守卫为 `X12C0 V3B06 = 8100`、`X2012 VEBE2 = FFFF`，目标自身必须为 `FFFF`。只读 A 可沿用五项布局，读取 `EBE0/EBE2/3B06/3B10/3B00`。不修改任何 T 选择器。

预期现象是 MODE 1 白边强度、白色饱和区域或处理响应变化。该半字是不是上下限、正负响应或其他量仍未知，不能将“255”命名为已证实的白色 RGB。若出现仅沿合焦轮廓的颜色变化，它才成为颜色线索。

成功标准为改值、原生消费和复原都成立，并且只有合焦轮廓稳定变色，平坦区、真实白物体与 UI 保持参照。只有白边强度变化，算机制线索，不算改色成功。只有整幅变化，判本组不适合独立描边改色。若没有确认原生消费，画面不变记 `INCONCLUSIVE`。

R-P1 的唯一表项为 `{EBE0, FFFF, 7FFF, 7FFF}`。恢复 D 后再次走 Off 到 MODE 1 On，让原生快速配置消费原值。断电恢复依赖未修改的 D 映像重载，不依赖 T 提交行为。

未来操作不超过五步。

1. 按既有流程准备 P1 的 `P`，完整冷启动，关闭其他配方和调整功能。使用固定场景，将辅助对焦设为 Off。模块在下一步自动检查前置值。
2. 选菜单 08 一次，只有显示本组 `ON` 才继续。退出菜单后打开 MODE 1，让原生路径消费 D 表。
3. 记录描边、背景、白物体及 UI 的变化。若需核对消费，可用另行审核的只读配置观察镜像 `20142C50`；镜像本身不证明像素效果。
4. 再选 08，确认显示本组 `OFF`，重新执行 Off 到 MODE 1 On 并检查画面。若显示 `ON` 或 `ER`，停止触发 08 并完整断电，备用 R-P1 按既有换 P 流程使用。
5. 取下电池后重新冷启动，在未启用探针时核对 D 原值及原始画面，再结束该组。

### P2：48 word 块的第一个尾字节，条件设计

改什么：`X F035`，目标 halfword 偏移 `3350`，从 `8080` 改为 `4080`。实际 W 是对 `F0353350` 的完整 32-bit 更新，预期为 `0x80808080 → 0x40808080`。另外三个字节保留，不更改 T、行选择号或同块其他记录。

启用前要求目标为 `8080`，另核对 `3352=8080`、`3354=8080`。五项只读布局可取 `3350/3352/3354/3358/335A`，后两项在所述默认源条件下为 `0370/06E0`。现场不匹配就停止，不能用模型值覆盖未知配置。

预期现象是某一区间的描边响应或整幅细节响应变化，尚无根据指定红色或绿色。若只在合焦轮廓出现稳定颜色而背景与白物体不变，支持独立颜色控制。只有细节强度变化，不算改色成功。只有整幅改变，判本组不适合独立描边改色。若观察后寄存器已被重写，或 W 未在当前访问状态生效，记 `INCONCLUSIVE`。

R-P2 的唯一表项为 `{3350, 8080, 4080, 4080}`，使用 F035 页。Pn 自身的反向切换执行同一恢复。完整 writer 也能从未改的源重新覆盖它，但没有追到保证在每次菜单退出时发生的事件，不能只靠菜单切换恢复。

本组只涉及一个已定位的处理配置 word，不涉及存储提交。仍缺普通 W 与原生访问协议等价、寄存器可可靠读回、完整断电后恢复的硬件证据，当前不满足“断电一定复原”的制作条件。

仅在上述条件另行关闭后，未来操作才是以下五步。

1. 按既有流程准备 P2 的 `P`，完整冷启动，辅助对焦 Off，固定场景。模块在下一步检查目标半字及两个守卫值。
2. 选菜单 08，只有本组 `ON` 才继续。退出菜单后打开 MODE 1。
3. 观察轮廓、背景、白物体和 UI。下一步的 `OFF` 只说明恢复前读到了本组改值，不证明整个观察期间持续生效。
4. 再选 08，确认显示本组 `OFF` 并检查画面。若显示 `ON` 或 `ER`，记 `INCONCLUSIVE`，不再触发 08，直接完整断电。备用 R-P2 按既有换 P 流程使用。
5. 取下电池后重新冷启动，核对目标的原值与原始画面，再结束该组。

### P3：斜坡中心低半字，条件设计

改什么：`X F035`，halfword 偏移 `3302`，从 `0080` 改为 `0060`。完整 word 为 `F0353300: 0x00800080 → 0x00800060`。高半字和其他八个斜坡 word 不改。

启用前除目标为 `0080` 外，还核对 `3300=0080`、`32FE=0060`、`3306=00A0`。五项只读布局可取 `3302/3300/32FE/3306/32F0`，最后一项预期为零。非恒等斜坡或不同现场值不使用这组固定常量。

预期首先是中段亮度、对比度或白边强度变化，这会支持点对响应解释。只有某一颜色分量沿合焦轮廓变化，才支持进一步研究独立颜色通路。整幅曲线变化或白边仅变强弱，都不算改色成功。未确认改值在观察期间保持时，画面不变仍记 `INCONCLUSIVE`。

R-P3 的唯一表项为 `{3302, 0080, 0060, 0060}`，使用 F035 页。它只恢复低半字，完整 32-bit 写回保留当时的高半字。P3 与 P2 有相同的访问协议和断电恢复缺口，因此同样保持备选。

仅在前置条件另行关闭后，未来操作不超过五步。

1. 按既有流程准备 P3 的 `P`，完整冷启动，辅助对焦 Off，固定场景。模块在下一步检查目标半字及三个守卫值。
2. 选菜单 08，只有本组 `ON` 才继续。退出菜单后打开 MODE 1。
3. 记录轮廓与中间调变化。下一步的 `OFF` 只确认恢复前低半字仍为改值；高半字和整个观察期间的值仍需独立只读证据。
4. 再选 08，确认显示本组 `OFF` 并检查画面。若显示 `ON` 或 `ER`，记 `INCONCLUSIVE`，不再触发 08，直接完整断电。备用 R-P3 按既有换 P 流程使用。
5. 取下电池后重新冷启动，核对原始斜坡和画面，再结束该组。

### 436 B 预算和当前未证明的部分

本轮重新读取现有 A、B、R、R-all 成品，四者均为 436 B，整文件 CRC32 为零。没有调用汇编器、链接器、模块生成脚本或卡包脚本。

| 未来模块 | 按现有源码计算的预算 | 仍需验证 |
| --- | --- | --- |
| P1 | B 原始 432 B，常量编码增加 12 B，四项守卫表缩为两项减 8 B，估计 436 B。 | 对 `FFFF` 使用无符号 `ld24`，不能用会符号扩展的负值；复查分支与最终文件。 |
| P2 | 同上，估计 436 B；低偏移页常量改为 F035 不增加指令宽度。 | F035 地址白名单、访问协议、读回及恢复。 |
| P3 | B 原始 432 B，常量编码增加 6 B，守卫表少一项减 4 B，估计 434 B，补齐至 436 B。 | 最终布局、F035 白名单与恢复。 |
| 各自 R | R 原始 436 B，五条恢复记录缩为一条减 32 B，估计 404 B，再补齐。 | 每组只允许自身原值和唯一改值，不恢复未知现场状态。 |
| 各组 A | 仍用现有五项只读布局，目标为 436 B。 | 页常量、五项期待值和读取副作用前提。 |

这些是源码宽度预算，不是新模块已通过链接或设备验收。P1 的 D 源变化在两种打包模型中验证；P2、P3 只验证了真实 W 辅助例程的 32-bit 更新与反向恢复算式，没有模拟 ISP。详细结果见 [探针算术与旧框架身份](local/r3/probe_studies.json)。
