# 紧凑记录来源表

本文件解释候选实际记录的字节。它不是已封存的原生语义参考；未列全的类别、颜色、生命周期与时间不据此判通过。

全部多字节数为大端。最终 M32R 结构偏移来自编译器对象，见 `evidence/layout.json`，不使用主机 `sizeof` 猜测。

## 转录

- BOO 是实际 DAT 头 256 B 加 DgCurrent 768 B，共 1,024 B、37 页。编号和总数使用十六进制，因此末页为 `BOO 0024/0025`。末页只有前四行是数据，后面是结束提示。
- REC 是 DgRecord 11,500 B 加 DgAux 3,776 B，共 15,276 B、546 页；编号从 0 到 `0221`，页数为 `0222`。每页七个 32 位字，最后页的不足部分按头内字节数截断。
- REC 头为 12 个 uint32，依次是 magic、版本、代数、总字节、全记录 CRC、标志、boot、unit_epoch、link_epoch、s_epoch、set、初始化 tick，随后是 12 B 单元身份。CRC 用全记录且将偏移 16 的四字节置零后重算。
- C 结构将最后一个头字段命名为 `ready_tick`，但它实际在纯初始化中采样，早于 resident 发布 READY。解码器按真实来源输出 `init_tick`，`ready_tick` 明确为未定。装载前的 H01/装载起点和完整 READY 时序没有在此候选中采到。
- `decode.py` 读取冻结 REC 并核对完整 CRC、实际 DAT 头、主请求和当前来源。它目前只输出可解释的原始部分，总结论始终不完整，退出 2。它还不能生成齐全的实采 R5 输入。

## DgCurrent，768 B

| 相对偏移 | 内容／实际来源 |
| --- | --- |
| 0–127 | 32 个 uint32 元数据，见下表。 |
| 128–632 | 九行 503 B 和 T 两字节；每行的来源地址及长度在 `gate.py` 的 ADDRESSES/SIZES 中固定。 |
| 633–639 | 七个保留零字节。 |
| 640–767 | DgNative，见下表。 |

| 元数据下标 | 含义 |
| --- | --- |
| 0、1、2 | 已走过的固定行数、成功位图、状态位。状态 READY=1、FROZEN=2、INVALID=4、OVERFLOW=8、CHANGED=16、MISSING=32。 |
| 3、4、5 | 第一行前和最后一行后的 tick、错误返回。 |
| 6、7、29、30 | 采第一行时的 boot、unit、link、S 代次。 |
| 8–17、18–27 | 十行各自开始、结束 tick。 |
| 28 | 每行 3 位状态；1 表示本次读取成功，2 表示失败，高两位必须为零。 |
| 31 | 偏移 128 到 767 的 CRC32。 |

| DgNative 偏移 | 内容／实际来源 |
| --- | --- |
| 0–7 | 版本 1、长度 128、零标志。 |
| 8、12 | S 指针和长度，来自 `0x200C0DAC/DB0`。 |
| 16、20、21、22 | 状态 `0x205D9C00`、MY `0x205D9AA3`、pending `0x205DA00B`、链接 `0x2040F804!=0`。 |
| 24、28 | 锁 count/id，来自 `0x204104F0/F4`。 |
| 32–43 | 经 resident 身份检查的单元名字、main/cmp 版本。 |
| 44–68 | S 的 25 个白名单字节，按 `observe.c:offsets` 的顺序。 |
| 69–71 | 保留零。 |
| 72–111 | S+0xFD4 的完整 40 B。 |
| 112、116 | 采样后的 S 指针和长度。 |
| 120–127 | 保留零。 |

九行只发 X/V 读取，不发单元写命令。每次读取后重查 resident 身份、链接和 RPC 可读状态；首尾完整 DgNative 必须相等。失败锁存，不重试覆盖已有行。没有 P00–P03 或唯一 ID 来源。

## 其他来源和剩余缺口

| 结构 | 实际保存内容 | 未关闭的语义 |
| --- | --- | --- |
| DgKey | 连续物理序号、tick、实际状态、视图、原始码、游标、缓存、固定槽和 set。 | 关闭到状态 5 之间的完整原厂事件链。 |
| DgLayer | 前后缓冲身份、尺寸、四片 tick 与读结果、最多 16 个矩形。 | setting 尚为零；颜色/透明度参考和原生绘制消费者时序未封存。 |
| DgSlots | 两套各 99 项覆盖和非零位图；最多 11 个非零类别的物理 ID、count、stride、base、18 地址；原始池字段。 | 完整画质/类别/资源映射和独立原生顺序重放未封存；超 11 类锁存缺项。 |
| DgSource.requests | H09 每次的 144 B 原始参数块，最多 8 次。 | 真实照片身份及其到 K 的唯一映射。 |
| DgSource.k_sources | H40 的 K 前 128 B，最多 8 次；尾部 16 B 未用。 | 这不是完整 588 B K 快照，不能凭此复算全部尺寸和生命周期字段。 |
| DgImage | 白名单 H40 处 K+0x14C、154、156、158、70、0D 的直接观察和前 64 B。 | 独立来源映射、K 复用和先后关系；不能拿这些观察值自证全部派生值正确。 |
| DgTime | 独立 H09、H40、H41 原始时刻、K、状态、调用来源。 | 生命周期一直带 MISSING；不输出最近两次相减的配对。 |
| DgMem | 池尾部前后各 16 个字，间隔 256 B。 | ER 归属和无使用证明。 |
| DgBw | 三类各 32 条固定工作量、源地址、起止 tick、结果；ER 每片的 16 B 图样。 | ER 若不满足整片周期图样，就无法从该压缩来源复算，标 MISSING；真实时基未封存。 |
| heap/stacks | 有界堆链摘要及 RTOS 栈记录、标记、零水位观察。 | 完整调用栈和 IRQ 上界；零水位不等于真实最坏占用。 |

JSON 版本 6 的 `gate.py` 接收独立封存的 profile/capture 和它们各自的 SHA。它沿用原 R5 对合成完整记录的复算，加上 BOOT_CURRENT 原始 768 B 的复算；这条合成验证链与上表尚未闭合的实采链分开报告。
