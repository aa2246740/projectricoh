# g157 第二轮：MOUNT 有监督现场步骤

执行资格以本轮 [复审结论](REVIEW.md) 第一行为准。若结论为“修改后再上卡”，本文件暂停执行；若仅放行 MOUNT test，只用下面的 test SHA。默认先做 test，只有报告明确放行 test 和 release 时才单独安排 release。一次只装一个包，不在同一轮中途换包。

先拍开机后的首张照片，再打开 ADJ。首次诊断最有价值，不要先手动套一次配方再判断 BOOT 是否成功。

本流程用于 2026-11-05 的有监督 MOUNT 试拍。使用现有 v3.10 机身，机身身份为 `a04f1ed4`，不刷写机身。只核对下表中的完整 SHA，不使用上一轮旧 g157 或历史 control 包。

| 包 | 完整 SHA-256 | 文件大小 | 本轮用途 |
| --- | --- | ---: | --- |
| test | `2b8904592ce56ab03649ced52c8479b0bbac4e45bf9a47505d220795bb3ec56c` | 94,868 B | BOOT 开、读回和诊断开；默认按本主线验证开机恢复。 |
| release | `3ebc261cf290a376d59ffc24b4d5b6f9ab1dd5b9d5a8cd7242561d45707107b6` | 92,400 B | BOOT 关、读回和诊断开；预期 B02，记住 03 不表示开机已套用 03。 |

从仓库交付文件取包：[test DAT](../../firmware/package_v310_g157_test/local/SD_ROOT/GXRCE.DAT)、[release DAT](../../firmware/package_v310_g157/local/SD_ROOT/GXRCE.DAT)。两者文件名相同，必须用完整 SHA 区分。

release 若获放行，另起一轮重复装卡和拍照主线。在第 24 步，正常预期是 BOOT 没有自动套用、首拍保留开机实际颜色；第 25 步出现 B02 属于策略关闭。保留首拍和完整诊断后，再从第 27 步手动套用；不能把 release 首拍彩色记成 test 的 BOOT 回归。

release 首拍仍是黑白，也不能算它自动恢复成功，单元原有状态的持久化仍未查清。只保留这次照片，并记录 B02 与随后显式套用的结果。

新包的手动事务失败会尝试完整补偿为纯 04；补偿失败时保留 DIRTY/GUARD，并由 H52 拦半按与全按。即使菜单已经关闭，也不能据此认定故障解除。B 码锁存的是 BOOT 首次原因，手动故障后可能仍显示旧 B20、B11 或 B02，不能靠 B 码判断刚才的手动事务成功。

相机已经装好 MOUNT，电量充足，照片采用 RAW+JPEG。使用固定、有彩色物体的场景，保持 M 档及曝光设置。开始前由监督者确认原厂 Image Settings 为 Standard、WB 补偿为 0,0。不能确认时，先收集下文的 B20 诊断，不把它当作自动恢复失败。

表内的 P 是用手机拍的证据，J 是用 GXR 拍的 RAW+JPEG。一个编号只做一个动作。涉及移动游标的步骤，每按一次键拍一张手机照片；没有到指定条目时只重复该步骤，不长按。

## 诊断码查表

| B 码 | 含义 |
| --- | --- |
| B00 | 没有锁存跳过原因。自动成功通常直接进入正常列表，不会自动弹 B00 页。 |
| B01 | DAT 没看到合格的 BOOT 派发。 |
| B02 | 当前包关闭 BOOT 策略。release 正常会这样；本次指定 test 不应如此。 |
| B10 | 启动 activity 不合格。 |
| B11 | 内部模式或原厂选择组合未确认。 |
| B12 | MY 激活。 |
| B13 | 原厂模式切换尚未结束。 |
| B14 | 设置来源、指针、长度或 BOOT 调用参数不可用。 |
| B15 | 启动 state 不在允许窗口。 |
| B20 | 原厂图像设定或 WB 阻止自动套用。 |
| B21 | 记忆缺失、来自另一 DAT，或记录不合法。 |
| B22 | 完整原厂九行或 T 与所需基线不符。 |
| B23 | 原厂参数锁忙。 |
| B30 | epoch、对象、单元或事务身份发生变化。 |
| B31 | 颜色事务或补偿失败。一次补偿成功也会保留这个首次故障码。 |

第一行 `G157B11R03` 的 `R03` 是记忆的基础配方 03。`R00` 是没有可用记忆，`R80` 至 `R82` 是三个用户项，其他高值可能是全局 Look 编码，不能当作列表中的第几行。第二行的 `A03`、`A04` 是实际确认的配方，`A--` 是尚未确认，不能把它写成纯 04。

V/T/R 行末尾的单字符 R 是另一种值，表示锁存时的记忆读取结果。R1 有效，R2 没记录，R3 属于别的 DAT 或版本，R4 单元不符，R5 结构/CRC/索引不合法，R6 参数不合法，R7 设置源暂不可用。第一行的记忆编码可能在 H01 读回后更新，行末的 R 仍保留 BOOT 原因。不要把两者混在一起。B01 页中的问号表示未采到启动原值。

F 行是所有已检查失败条件的集合，不只有 B 码所指的一个原因。M/U 是内部模式与子模式，Y 是 MY，P 是 pending，A 是启动 activity，H 是已观察入口的位集。H 中 H50 的一位来自现有 pending 合同推断。V 是启动 state，T 是事务阶段，N 是原厂选择，L 是来源。L03 是卡，L01/L02 是内部副本。S 行保留设置对象与长度供本地分析，不要手抄地址到公开 issue。I 行是原厂图像选择与 WB 的编码，`01` 为 Standard，`09` 为 Vivid，WB 两轴 `09/09` 为中性。Q 是 resident 状态。D/G 是入口快照中的 DIRTY/GUARD，不代表后来所有操作都成功。

Unsaved 的 M00 表示有待保存的记忆、没有细分错误码；M01 是忙锁，下一次用户操作边界才允许再试一次；M02 是外来尾部，不能覆盖；M03 是结构、参数或其他服务拒绝。都先拍照并停止本轮，由监督者读证据，不反复按 OK 试着消掉它。

## 画面与停止条件

| 画面 | 代表什么 | 只做的下一件事 |
| --- | --- | --- |
| 八行配方列表，有名称、游标及 `>` / `~`。 | 列表已发布；`>` 是当前项，`~` 是读回的记忆，游标仅表示将操作哪一行。 | 拍完整屏幕，再按主线下一步。 |
| 配方卡片、参数项或数值页。 | 处于配方编辑界面，不能仅凭页名认定颜色或保存成功。 | 拍整页；不在首拍前进入这些页面。 |
| `G157B..R..` 八行诊断。 | DAT 已运行到诊断入口，B 码为启动原因，R 与 A 分别表示记忆和实际确认。 | 拍全八行，保留问号，不裁掉 S/I 行。 |
| `>M00` 至 `>M03 Unsaved`。 | 记忆还未成功存入逻辑 S，不代表已经写入 NAND。 | 拍整页并停止本轮。 |
| `n Error`，其中 n 是配方号。 | 该项遇到非预期的 T 控制，当前项不能当作成功套用。 | 拍整页并停止，不换一项继续试。 |
| `ERR` 加四个字母或数字。 | 手动事务记录了故障；后缀是入口、阶段、状态与 RPC 序号的组合，不能单凭后缀判断已恢复。 | 拍完整错误页，记下刚才唯一一次动作，然后停止。 |
| 选择 HC BW 后回取景，仍是完整彩色。 | 可能已经安全补偿到 04；目标 HC BW 没有成功，关菜单不表示可继续试拍。 | 拍取景屏并停止。 |
| 快门半按或全按被拦，或按键不响应。 | 可能保留了 DIRTY/GUARD，也可能是其他故障；不能把无响应等同死机或没电。 | 手机拍屏幕和指示灯，停止按键，交监督者。 |
| 只有原厂条目，没有 g157 名称。 | DAT 未装载、已退役或首表发布失败；DAT 自己的诊断可能完全看不到。 | 拍完整页面，转下面的掉表收证流程。 |

若遇到 ERR、Error、Unsaved、异常颜色或快门保护，先停止现场流程。不要拔电池、强制断电、拔卡、反复开关机或用换包试着清错。先由监督者收齐照片、时间和上一动作；有写卡活动时保留供电。恢复或降级另行判断，不在失败状态下执行下面的正常降级动作。

## 整张列表消失与回退

若 ADJ 只剩原厂项目、没有 g157 标题，也没有任何配方名称，先拍完整页面。再拍机身版本页，记录它发生在第一次开机还是第二次开机，以及两次之间有没有动卡。版本页仍可能显示 1.51，单凭它不能确认已经刷入修改后的 v3.10。当前 v3.10 resident 未改，DAT 未加载、DAT 被退役或首次菜单发布失败时，g157 的诊断也可能完全看不到。没有 B 码不能排除故障，也不能说明文件坏了。

停止继续拍摄，由监督者先保留卡上 DAT 的 SHA、目录截图和已有 P/J 文件。不要先格式化、重复制或刷机，否则会丢掉区分现场原因的条件。

正常降级到 g156 前，先在没有 ERR、Unsaved 或护栏、仍能工作的 g157 列表中保存纯 04。否则高索引 g157 Look 的记忆可能让 g156 一直显示 Unsaved，下一次换回 g157 还可能重新恢复旧的 Look。

| 步骤 | 只做这个动作 | 要拍什么，以及画面代表什么 |
| --- | --- | --- |
| R0 | 若当前已经是 `4 Std`，按一次上或下离开它。 | PR0，拍离开后的那一行；本步让随后返回 04 成为一次显式选择和保存。若原本不在 04，跳过。 |
| R1 | 在 g157 列表里按一次上或下，向 `4 Std` 移动一行。 | PR1-序号，拍当页。未到目标则重复本步。 |
| R2 | 按一次 OK。 | PR2，拍纯 04 卡片或取景画面。 |
| R3 | 若仍在卡片，按一次 OK。 | PR3，拍取景画面。 |
| R4 | 按一次 ADJ。 | PR4，拍 `>4 Std`，确认没有 M00 至 M03 Unsaved、ERR 或 Error。否则停止，不能进入 R5。 |
| R5 | 按一次 ADJ。 | PR5，拍退出菜单后的画面。 |
| R6 | 按电源关机。 | PR6，拍关机后的黑屏。 |
| R7 | 等写卡指示灯熄灭。 | PR7，拍熄灭的指示灯。 |
| R8 | 取出 SD 卡。 | PR8，拍取出的卡。 |
| R9 | 将卡接到电脑。 | PR9，拍卡根目录。 |
| R10 | 用第 5 步的备份替换卡根目录的 DAT。 | PR10，拍替换后的文件。 |
| R11 | 核对回退 DAT 的完整 SHA。 | PR11，拍完整输出，并与备份 SHA 比较。 |
| R12 | 正常弹出 SD 卡。 | PR12，拍已弹出状态。 |
| R13 | 把卡插回相机。 | PR13，拍卡槽盖。下一轮由监督者单独决定。g156 本身仍有手动事务 P1，这次换回不是安全修复。 |

## 还在用 g156 test 时的临时注意事项

上 g157 之前保留已经确认正常的那套设置，暂停在 ADJ 内切换或试套新配方，尤其不要从 Vivid 或非中性 WB 进入手动套用。g156 test 的同类失败可以留下半套颜色而没有快门保护；还能按快门不能证明颜色完整。这不等于此前所有正常照片都受影响。

若出现 ERR、Error、Unsaved、异常颜色、无响应或掉表，手机拍完整屏幕，记下上一动作，停止试拍与重试，交监督者处理。不要把 g156 release、旧 g157 或反复复制相同 DAT 当作已验证的规避办法。逻辑 S 重放也不能证明真实关机已经把记忆写进 NAND。
