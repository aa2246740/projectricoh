## 最终表与调用契约

- [C 整数表](tables/knobs_v2_r2_tables.h) 与 [JSON 整数表](tables/final.json) 内容一致，已经编译 C 头文件并逐字段回读比较。
- [C 菜单入口](src/menu.h) 与 [Python 菜单入口](src/menu.py) 按表内顺序接收档位；未列出的百分比、越过到顶档的请求返回错误，不静默钳到同一档。
- [C 整数核心](src/knobs.c) 与 [Python 整数核心](src/knobs.py) 每次从不可变的原厂 04 和原始配方重新计算，不累加上一次结果。
- 普通剂量采用 Q12，4096 表示 1。Cont、High、Shad、Sat 的搜索域扩至 ±16384；Fade 为 0..4096，其余为 ±4096。UI 标称仍是 ±9，Fade 是 0..+9。
- 表中的 `cap_lower`、`cap_upper` 为 1 时，仅在对应端点加 `!`。`min_level`、`max_level` 和 `points` 是实际可选范围。Amount 的 `level`、`dose` 均为整数百分比。
- 原有有理曲线和饱和度公式不变。曲线数学表扩到 2^16 增益，以测到实际 8 位量化平台；不会把旧的 16 倍增益边界直接当作到顶理由。

默认档为 Amount=100%，其他项=0。全部默认档逐字节保留原始 552 B。Amount=0% 且其他项为 0 时逐字节得到本单元原厂 04；这只覆盖深层条目，不证明完整原厂 JPEG 外观。

## Warmth、Tint、Split 与黑白边界

Warmth 与 Tint 的最终路径是矩阵色度行和，保留 Y 权重，并按各半组实际 Y 和分配整数增量。Split 的最终路径是 T1。T1 Warmth、Tint 仅作为对照，菜单入口不会选择这条路径；03 Tone 不在最终 JSON、C 表或预览中。

保留的 T1 对照有 798 个 C 与 Python 一致状态，黑白 Tone 的两种算法有 114 个一致状态，见 [comparisons.json](local/comparisons.json)。这些比较只证明实现一致，不证明 Tone 在相机可见。03 的颜色行全零，矩阵色度仍可能被清零。算法和 [PROBE.md](PROBE.md) 保留，待另行授权上机确认。

## 复跑与封存

在仓库根运行，Python、编译临时文件、日志和产物均限制在本任务目录；不安装依赖，不访问网络，不启动子代理。
