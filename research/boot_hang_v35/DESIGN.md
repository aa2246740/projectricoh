# v3.5 条件设计，尚未通过机制门槛

当前决定是 `STOP_AFTER_DESIGN`。没有 v3.5 resident、映像或暂存包。本文件是后续实现的约束，不是已经验证的补丁。

## 开工条件

现有现场证据足以排除“必须有我们的 resident/loader/engine 才会挂”，但不足以证明 H05 零详情表单独足以修复。须先补齐 [next-experiment.json](local/next-experiment.json) 的单变量现场结果，或闭合等强的原生开机调用与故障证据。不能以强制进入的主机重放替代该条件。

## 拟保留的结构

- 以冻结 v3.4c 为底，在新的 `firmware/resident_v35`、`firmware/image_v35` 中改。官方目录、zip、Stage2l 和 v3.4c 不覆盖。
- RV_BASE=`0x2005276C`，RV_LIMIT=`0x20054800`，RV_ROOT=`0x20054700`，容量 8,340 B，root 256 B，三个 pins 与 ADJ names/count 描述符保持冻结值。payload 中的 H05/H09 桩必须修改，原因是冷路径现在必经 shared/C；其它 payload 修改须逐项解释。
- 优先完整复用 generation 113、64,816 B 的 `GXRCE.DAT`，SHA `6cb63aa47c18086f5ade681ffe4dc97378394ff7a65c0688d19b3880d804c707`。不改引擎算法、配方、容器容量或 IROM 行为。
- 必须处理真实的容器绑定：DAT 的 `+80..111` 是 resident build ID，`+212..227` 是 ABI ID；`rv_header()` 两者都比对。现有 `resident/build.py` 会因源码或自身脚本变化生成新 build ID。因此“ABI 不变”本身不能保证旧 DAT 可加载。实现前须明确兼容 ID 策略并记录新代码的独立 SHA，或按获准的绑定/ABI变更重封装并重验；不得直接复制目录后假称容器兼容，或把新代码称作旧源码构建。

## 冷路径和暖路径

H05 在尚无正面 READY/user-entry 见证时，只用短汇编路径保持原生寄存器、LR、PSW 和 SP，提供已验证的零详情表后返回 `0x201FEBEC`。不得调用 `rv_hook_shared`、`rv_hook_observe`、loader、文件/RPC/分配器。表须覆盖与 Stage2l 相同的 16×12 B 范围，或证明更小的范围能覆盖所有实际索引；不能读 flash-FF 区假充零表，也不能借未知 RAM。

暖 H05 在已证 owner 会话中保留现有 cursor/details 恢复逻辑。50mm/Mount 的八行仍使用完整真实配方和已有微调面板。28mm 在正面用户入口后继续原生行和原生详情行为；不能因冷态抑制而永久取消其正常原生编辑入口。没有 owner 会话不等于损坏，不得由此锁死日常功能。

H09 冷路径仅做保留现场的短汇编门禁，然后重放 `push lr || nop` 并返回 `0x20170990`；不提前下压 shared/C 的 104 B 临时栈。门禁必须先读并核对 root magic/version/READY、会话见证及必要停止标志。暖路径保留当前 grain 条件及四字节包改写，不能用还原原生 H09 永久取消 grain。

READY/user-entry 见证不能仅由状态56、ADJ项8、tag32父视图或 `open=-1` 推出。H01 的构造器调用仍未证明只由用户操作触发。必须在真实原生输入分派边界追到正面来源，或另证初始化阶段不能签发该见证；不得用 H05/H09 自身签发许可。该入口证明是当前设计尚未闭合的一部分。

H09 已有拍摄初始化调用证据，应先纳入静态验收。H01/H02/H06/H07/H08 若另证开机可达且有 Stage2l 行为差异，须在同一版解释和对齐；目前不能宣称它们均不在开机执行，也不能盲目复制其 Stage2l 实现。

## 功能不可退让

| 功能 | 必须维持的行为 |
|---|---|
| GR IV Posi 01 / Nega 02、04、05–08、ISO100 行和已有 look | 保留全部 entry552/record64/深表数据和处理。零详情不等于清零深层配方。 |
| 可见列表 | 50mm/Mount 恰好八个真实配方，28mm 原生列表；不显示空槽或重复行。 |
| remember-last 与高亮 | 仅恢复光标；高亮必须对应 live recipe。一次断电后是完整上一配方或纯04，原生 S 保持04，look只存深行；不得接受混合状态。 |
| Fn2 和每配方微调 | 仍能开面板、草稿编辑、OK保存、MENU丢弃；格式化、无卡或只有OK的日常状态不被抑制。 |
| 安全隔离 | 保留正面无效DAT、明确 I/O 错误/冲突的隔离；不因含混 `open=-1`、尚未 READY 或重开菜单而新增日常锁死。 |
| grain、CTL、日志及恢复 | 暖 grain、现有 CTL 语义和黑盒能力不删减；不依赖黑盒捕获 loader 之前的启动失败。 |

这些是继承的产品验收要求。本轮未重新证明相机行为。

## 尺寸与审计

冻结 resident payload 7,868 B，root 256 B，余量216 B，现有审计门槛200 B。直接再加192 B零表只剩24 B，还未计汇编门禁；即使只加84 B也只剩132 B。两种直接追加方案都不合格，不能扩大窗口、挪root或降低门槛解围。须在实现阶段证明现有不可变零数据可复用，或以不删功能的代码缩减偿还空间。当前没有给未经证明的表地址。

引擎容器余量720 B。若绑定允许复用，最终 DAT 必须逐字节相同；若有必要重封装，完整深行数据、执行逻辑和新身份须分别验证，不能仅看生成成功。

后续构建须走复制后的原 harness，检查真实 ELF/映像中的冷路径无 C 调用、临时栈边界、暖 H05/高亮、H09 包行为、28mm 原生回退、所有继承产品矩阵、官方28个兄弟文件、checksum 和尺寸。最终包需29个固件文件加DAT、全文件 SHA256SUMS，并且先通过新一轮独立对抗审查。本轮没有为未通过机制门槛的设计生成该包。
