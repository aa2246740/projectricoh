# 明暗分色（Classic Neg.）：没有按亮度变化的色度表，只能靠三通道各自的曲线

2026-10-20。静态分析由 Opus worker 完成，它没有写文件的权限，本文由主代理落盘。没有修改仓库、没有动 SD 卡、没有刷机。worker 的草稿在 `/tmp/lumchroma/`。

主代理复核了以下几点：
- T 提交函数 `0x20065DB0` 在交叉引用表里只有两个调用点：`0x2006683C`（文件导入）和 `0x20241E50`（UEE00）；
- 在 `jlaunch3` 里没有找到这个地址作为字面量出现；
- C/D 的 66 B 全零。

但 T 写入是不是易失的，worker 的结论和既有研究不一致，见第 2 节「T 写入的风险」。

## 结论

1. **GXR 里没有哪一级会给灰阶加上随亮度变化的色偏。** 能做分色的，只有放在 RGB→YCbCr 矩阵之前、三个通道各用一条的曲线。具备这种形状的只有 type 23（Ricoh 内部名 RLUT）和 type 26（LUT），都是 31 节点输入表加 3 张 33 项输出表。
2. **P/A/S/M 配方里，只写数据的唯一路线是让 type-26 按通道各用一条曲线。**
   - 辅助表 C/D（`0x2013024E`，66 B）很可能就是第 2、3 通道的输出表。
   - 控制字是 2 时，C/D 被忽略，三个通道共用主表。
   - 把控制字 T+0x2445 改成 0，再按配方写 C/D，应该就能得到三条独立曲线。这是推断，拍一张就能证实。
3. **type 23 不能靠写数据为普通静帧打开。** 静帧的控制值 1 是写死在代码里的立即数，推断为「关」。它只在 SCENE → Cross Process（场景 28 → 效果 23）里按通道工作。
4. **退路：用矩阵做线性近似，不用写 T。** 见 `research/channel_mixing/REPORT.md`：让 Cb/Cr 两行的系数和略偏离 0，再调偏置，就能得到从暗部到亮部线性变化的色偏。它只能做线性部分，残差要用富士 LUT 的灰轴来算。

## Ricoh 内部的模块名（已验证）

调试转储函数 `0x20105A00..0x20105E20` 打印每个模块的 RAM 副本和名字。

| type | 名字 | 寄存器基址 |
|---|---|---|
| 21 | WDR | F0340000 |
| 23 | RLUT | F0342000 |
| 24 | EXIP | F0343000 |
| 25 | AWBIP | F0348000 |
| 26 | LUT | F0349000 |
| 27 | INP（插值，即去马赛克） | F034A000 |
| 28 | MCM | F034C000 |
| 32 | FLT | F0353000 |

- 推断的流水线顺序：WDR → RLUT → EXIP → AWBIP → LUT → 去马赛克 → MCM → FLT。所以 type-26 很可能在去马赛克之前，作用在 CFA 通道上。
- 时钟门控 `0x20252E80..0x202530A0` 会关掉控制字为「关」的模块：
  - LUT 的关闭位是 bit 3；
  - WDR、EXIP 的关闭位是 bit 0。

## 1. type 23（RLUT）

- **格式**（已验证）：
  - RAM 副本在 `0x20143118`，共 68 字：1 个控制字、31 个 u16 输入节点、3 组各 33 个 u16 输出（0..4095）。
  - 源表：输入在 `0x20130290 + 62·k`，三组输出在 `0x20130404 / 0x20130590 / 0x2013071C + 66·k`，k = 0..5。
  - row 2 是恒等，row 3/4/5 是 Cross Process 用的三行。
- **配置函数 `0x2010E544` 写入的值**（已验证）：
  - 静帧：控制 1、输入 row 2，输出不重装（`0x2010E55C`）；
  - 取景：控制 2（`0x2010E7A8`）；
  - 不选曲线的请求：控制 1，三组都是恒等（`0x2010EBC0`）；
  - 效果 23：控制 0，用 row 3/4/5（`0x2010EC98`），由 Q+0xC5 = 1/2/3 选行。
- **打包函数 `0x20119BC8`**：控制位 1 置位时，把第 0 组复制到第 1、2 组。
- **普通静帧旁路 type 23**（推断，证据较强）：
  - 相邻的 WDR、EXIP 都以 bit 0 = 1 表示关，配置函数一开始就把 WDR 和 RLUT 都设成 1；只有 Cross Process 用 0。
  - GR DIGITAL IV 2.30（同系引擎）里，不选曲线的情况会在控制 1 下装一组互相对不上的表：第 0 组是 8 位曲线，第 1、2 组是恒等。这样的表要是真用上，画面必然坏掉，所以控制 1 只能是「关」。
- **域与位置**（推断）：12 位进、12 位出，线性光，在 LUT 和 MCM 之前。三组的顺序是 R、G、B：Cross Process 的 row 3 在暗部抬高、亮部压低第 2 组，即暗部偏蓝、亮部偏黄。
- **能否按配方写**：这几行能用现有 W 循环写，但普通静帧用不上，因为没有数据通路能改到控制字。要改代码（`0x2010E55C`、`0x2010EBC0`），不推荐。

## 2. type 26（LUT）的辅助表 C/D 和控制字

- **布局**（已验证）：
  - C = `0x2013024E`，D = `0x2013026F`，各 33 B，夹在 22 行主输出和 type-23 输入行之间。
  - 打包函数 `0x20118468` 在配置字节 C[3] / C[4] 为 1 时装载它们，写入 RAM 副本 +0x68 / +0x8C，以及寄存器 F0349068 / F034908C。
  - 所有选曲线的请求都把这两个字节设成 1，静帧和取景都一样。
- **C/D 在所有版本里全为零**（已验证）：GXR 的各单元固件（jlaunch3、klaunch3、l06firm3、l08firm3、nlaunch3、qlaunch3）和 GR DIGITAL IV 2.30 都一样。
- **控制字**（已验证）：取自 T+0x2445，只在 `0x2010EB30`、`0x2010EB94` 读取，原样写进 F0349000，出厂值为 2。
- **开机默认**（已验证）：RAM 副本里控制字为 0，C、D、主表是同一条恒等曲线。
- **C/D 的含义**（推断）：是第 1、2 通道的绝对输出表。理由：
  - 寄存器布局和写入函数与 type 23 一致；
  - 开机默认用控制 0 配三份完整曲线；
  - 全零的 C/D 只有在控制 2 下被忽略，画面才会正常。

  通道顺序未知。
- **要写的东西**：
  - C/D 是一次 66 B 的写入。
  - 控制字是 T+0x2444 处的一个半字，经 X12C0 + V 0x2444 + W 写入。
  - 邻字节 T+0x2444（出厂 0）会被 INP 打包函数 `0x20118F5C` 读取，要先快照。

### T 写入的风险（主代理补充，必须先解决）

worker 判断 T 是易失的：T 提交 `0x20065DB0` 只有两个直接调用者，关机重开就会恢复成 2。但既有研究记录了不同的情况：
- `research/color_injection/REPORT.md`：T 是从存储描述符 4 读入的 0x4000 字节参数块，带校验和 0xAA 标志。UEE00 会算好校验，把整个 T 写回存储，是持久写入。
- `research/body_rpc8_probe/REPORT.md`：固件内部的校准流程也会自己发 UEE00（`0x2022F140`、`0x20230180`）。「T 只在外部明确发 UEE00/UEE53 时才保存」证据不足，审计记录为 `zero_persistence_proven=false`。

如果 T+0x2445 = 0 被意外保存，开机后原厂 04 就会用 C/D = 0 的逐通道模式。按推断，画面会只剩一个原色。而且 T 存在单独的存储区，官方 1.51 重刷很可能不会重置它，这就越出了已经验证过的恢复边界。

所以逐通道 type-26：
- 上机前要用户明确同意，并讲清这个风险；
- 设计上要缩小暴露窗口：只在分色配方生效期间改，离开时立刻写回 2；打开菜单时先盲写一次 2，作为自愈；
- 或者先用矩阵线性近似。

## 3. GLUT（`0x2010EC08` / `0x2010EC14`）不是色度机制

- Q+0x60（来自 AE 结果，推断为增益或 ISO）与 T+0x1FF0..0x1FF8 = 16/24/40/56/72 比较，大于等于 40 时启用。但出厂 T+0xAEB 是 0xA5，所以实际关闭。
- 启用时从 `0x2012F960` 和 `0x2012FC6C` 各拷 65 个 u16，送到辅助引擎寄存器 F0380024 / F03800A4。
- 推断是高 ISO 下压暗部用的单条 12 位曲线，做不了分色。

## 4. 其余模块

- **WDR（type 21）**：表是恒等，静帧调用 `0x2026782C(0)` 时为关，不改色调也不改饱和。
- **EXIP（type 24）**：按白平衡增益算各通道的高光截断，外加一个拐点。只管高光，没有偏置。
- **MCM（type 28）**：
  - 24 扇区表与亮度无关。
  - 尾表 F034C120..C13C 有 7 个 u16 节点和 9 个 u8 增益（64 = 1.0），出厂全是 1.0。推断是色度增益，自变量是什么未知。它最多能随亮度降低饱和，给不了中性色偏色。
- **AWBIP（type 25）**：四个增益都是 512，只能整体偏色。
- **type 14**：按通道的空间增益平面，用于整体偏色和暗角。
- **type 33/34/37/38**：滤波、GLUT 和辅助表，与颜色无关，或者不在图像请求路径上。
- **CPU 代码**：没有按亮度计算色度的软件。

## 5. 最小上机实验（需要新构建和用户同意；涉及 T 写入，见上面的风险）

另用一套表文件，把 07、08 替换掉，不和色相环那一套冲突：
- **07**：只把 T+0x2445 写成 0，T+0x2444 保留原字节，C/D 仍为零。
- **08**：T+0x2445 = 0；C = stock row 5 的输出（B5）；D = B5 在第 4..28 项上加 24 码，截断后保持非递减。

M 档，固定日光白平衡，拍 stage2d 色卡和灰阶，按 04、07、04、08、04 的顺序各一张。记下取景画面，量六块灰的 R/G/B。

| 07 | 08 | 结论 |
|---|---|---|
| 画面只剩一个原色 | 04 加上某个通道在暗部、中间调被抬高 | C/D 是绝对通道表；08 偏向哪个通道，D 就对应哪个通道 |
| 和 04 一样 | 某个通道约翻倍或削顶 | C/D 是有符号的增量，逐通道仍然可用 |
| 和 04 一样 | 和 04 一样 | bit 1 不是开关 |

通过的条件：08 按预测给灰阶带上色偏，重新选 04 后回到 ±2 码以内。恢复办法：重新选 04，或关机重开。但若 T 已被意外保存，这两种办法都不够，见第 2 节。

## 6. 并入表文件（worker 原案）

- flags bit 1 表示「LUT 逐通道」，bit 0 仍留给 type 23。
- 条目从 212 B 增加到 284 B，新增：C/D 的 CRC32、C（33 B）、D（33 B）和 2 B 填充。
- 文件变为 16 + 7×284 = 2004 B，RAM 约 2216 B。
- 校验：C、D 都非递减，末值足够高、不会把某个通道写死，CRC 正确。
- 写入顺序：
  - 切到逐通道配方时，先写表，最后写控制字；
  - 回到 stock 时，先把控制字写回 2，再把 C/D 清零。
- 拟合顺序：三条曲线 → 去马赛克 → BT.601 矩阵 → 24 扇区表。
- payload 只剩 116 B，可能要动用 `rfw_defaults` 里 392 B 的空槽。
