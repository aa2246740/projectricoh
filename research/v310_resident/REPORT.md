中性基线加入本轮 resident BOOT 原型后，真实 M32R 严格链接缺 640 B。单机内副本缺 460 B，仅卡变体缺 124 B，三种均拒绝链接。按任务的停止条件，本轮在尺寸门槛停止，没有删减保护、放宽窗口或继续功能测试。代码仅为未通过链接的研究原型，不能用于相机。

固定窗口仍为 `[0x2005276C, 0x20054800)`，8,340 B。root 244 B、pins 12 B，链接脚本另保留 24 B，因此代码上限为 8,060 B。原 `resident.ld` 逐字节未改。下表代码数来自失败链接生成的 map，表示实际排布需求，不表示已有可用二进制。

工具链为 GCC 13.4.0、GNU ld 2.43。沿用中性基线的 `-flto -fno-guess-branch-probability` 和真实链接脚本；仅 `boot_policy.c` 不使用 LTO，使返回 0 的关闭策略不会让编译器删除被测事务代码。单机内副本、仅卡只在 scratch 中换入原型选项的 `loader.c`，默认源码仍保留两个机内副本。三个 map、全部编译和链接命令、日志、身份和目标布局保存在 [evidence](evidence)。可复算数值见 [measurements.json](evidence/measurements.json)。

## 已写入的机身侧原型

源码位于 `firmware/resident_v310_boot/resident/`，从默认中性原型复制。原 v3.9、中性原型及其他工作区没有改写。

- H50 在 T02 已证的普通拍摄 state 32 后处理调用处，先执行原厂 setter，再锁存首次真实 state 5。它不执行 DAT 事务。
- H51 在 C03 已证的 task 6 after 返回点调用一次 `boot_step`。后续进入 5 不再尝试。装载、父块、纯初始化握手及 READY 与 H01 共用，不构造菜单或自动按键。
- H52 在 C01 已证的键解析器序言之前检查原始快门请求，早于 C02 的设置读取。错误时撤销本次请求，保留固定保护。该点不证明持键、连拍、自定时的全路径覆盖。
- 固定状态复用 `reserved_lane` 的 4 B，偏移 236，地址 `0x200547EC`。目标编译通过 256 B 总长及偏移断言。旧 resident、服务层及 g153 产品源没有该字段的读写者；旧生产代码仅在冷 `rv_reset` 时清 root，退役不清它。本轮把 root 的全 FF 检查抽为 H01 和 H50 共用的 `rv_root_acquire`。
- 固定字保存 seen、pending、attempted、busy、dirty、guard、cancel、permit、result 和 error。resident 在第一笔可写 DAT 调用之前先置 dirty。退役保留 dirty 与 guard；未确认完整结果时不能放行受保护的快门请求。
- resident 的 DAT 代码限制改为 69,632 B。通用和对齐校验器、装载及代码抽检共用该常数。完整 DAT、服务库、打包器和其他读者的一致性仍由 DAT 后续工作关闭，本轮没有宣称完整 68 KiB 链路可用。

这些是源代码与编译证据。跳板的运行现场、一次性模型和实际错误收尾尚未执行验收。

## ABI 摘要

完整合同见 [ABI.md](ABI.md)。显式 BOOT 复用已校验的 `entries.panel_event`，操作号 `args[8]=0x100`，阶段 `args[9]=0 PREPARE / 1 APPLY / 2 CANCEL`。`args[12]=0 / 1 / 2` 分别表示只读、当前目标事务、只允许恢复实际 04；`args[13]` 指向只读固定 BOOT 字。原 lease、epoch 和 private context 参数保持现有位置，请求和回复仍为 64/32 B。

PREPARE 在 READY 后单独执行，只读验证同型号有效记录、实际模式排除 MY、精确纯 04 双读。PREPARED 回复必须回显 lease 和 UNIT epoch，资格位等于 7。resident 核对后才为 APPLY 设置 dirty 与许可。目标写只限 S 白名单、当前行 map 和已审 T，不授予文件、菜单、MY 或意愿记录写入。

TARGET 2、PURE04 3 是完整最终结果。有效回复要求 `RV_CONSUMED`、`status=RV_OK` 及正确 lease/epoch。应用错误或快门取消只允许一次 CANCEL；CANCEL 只能返回完整 PURE04，否则锁存 ERROR 5 并退役。DAT 缺失或退役不能解除固定保护。新的 build/ABI 身份由构建脚本生成，交叉组合的实际拒绝测试未运行。

`rv_boot_proven()` 当前返回 0，实际自动写许可关闭。B04/B05 的类别仍为候选，C07–C11、C14/C15 的完整消费者及原生等待上界没有闭合；不能从 MY=0、模式号、当前空闲或测试准备的状态推定资格。MY、更新/维护、未知类别、非可信 root 和 dirty root 均不能得到本轮 BOOT 目标许可。更新路径零新入口执行仍待实际恢复检查，本轮不把静态隔离写成运行通过。

## 快门保护选择与上界

选择取消当前快门请求并将事务补偿到完整 04，机主随后重新按快门。H52 在 busy、dirty 或 guard 时返回事件 0，事务中锁存 CANCEL；不缓存请求、不重复发送全按码、不递归调用 DAT。第一笔颜色写前收到请求，确认只读准备的完整 04 后结束；已经授予写许可时最多一次完整补偿。补偿失败或 DAT 退役则保留错误与禁止拍摄。

保护函数等待次数为 0、DAT 调用次数为 0。每次 BOOT 最多 PREPARE、APPLY、CANCEL 各一次。原生 RPC、文件和预览的时间上界未证，因此不能给出“最多多少毫秒恢复 04”的承诺。没有已证明的事务时间上界，实际自动写入保持关闭。这也避免把 H10 之后的保护误当成 C02 之前的保护。
