# Stage 2g：深槽表放到 SD 卡上

包在 `artifacts/stage2g-packages/stage2g/`，整个 `artifacts/stage2g-packages/` 被那里的 `.gitignore`（内容 `*`）挡住。没有上机，没有动 `/Volumes` 和 SD 卡，没有 git commit。源在 `firmware/stage2g/`，从 stage2e 复制而来，stage2e 的三个目录没有改动。

（本报告由构建 worker 写成，因为它没有写文件的权限，由主代理落盘并删减。主代理用自己的脚本独立复核过这些：
- 包内 `shasum`。
- 和 2e 相比只有 `ilaunch3` 不同，差异全落在校验和与 payload 窗口内。
- 八个 hook 位置与 2e 逐字节相同。
- 校验和 `0x6A75CA8F`。
- DAT 与恢复树和 2e 相同。
- 按本文的格式独立解析两套表文件：头常数、文件 CRC、行 CRC、单调性都对；等价表逐行等于 2e 固件里的表，新表逐行等于 2f 固件里的表。
- 重跑 verify：宿主和 ASan/UBSan 各 133 项，等价性与 2e 逐字节相同，payload SHA-256 可复现。）

这一版把所有非 stock 的深槽表从 payload 挪到卡上的 `DEEPTBL0.DAT` / `DEEPTBL1.DAT`。菜单在 stock（deep id 0）时打开，表就被读进一块单独 `gxr_alloc` 的内存。payload 只留 stock 的 A5、B5、colour row 1，用来恢复 04。以后改颜色只需重新生成这两个文件，不必重建固件。

## 没变的

- 八行的名字、银行、DAT 与 2e 相同。RV1 格式仍是 16 槽。四份 DAT 仍是 `9b04ab6b…`，count 字节仍是 `0x08`。
- 深槽仍是 `{1,2,3,5,6,7,8}`，写入目标不变：A5 `0x2012F504`、B5 `0x2012FFFC`、colour `0x2012C5D4`。
- 八个 hook（七个站点加 count 字节）与 2e 逐字节相同，包括两个指针型 hook：`adj_name_table` 是 `20053f6c`，`adj_empty_details` 是 `d2c0200582e23e6c`。做到这一点，靠的是把 ui.o 的 rodata 钉在 2e 的地址 `0x20053E6C`。
- 分派器 `0x26F8FC` 仍是 `d2 c0 20 5e`，跳表等于原厂，探针尾 `0x20054700..0x20054800` 仍是 `0xFF`。
- 类别门 {0, 4}。`rfw_acquire`、`rfw_cursor_commit`、`rfw_select`、`rfw_apply_action`、`rfw_close`、`rfw_is_open`、`rfw_is_active` 的目标码与 2e 逐字节相同。RPC-8 仍只接受 V/W/X。
- 失败语义不变：W 之前失败就发布 S；W 开始之后失败就粘住并失败关闭。
- `jlaunch3` 和其余 28 个组件等于官方，恢复树 29 个文件等于官方。

## 表文件格式（DEEPTBL v1，大端，1500 字节）

`/ATA1/DEEPTBL0.DAT` 和 `/ATA1/DEEPTBL1.DAT` 两份，内容相同。

| 偏移 | 字节 | 字段 |
|---|---:|---|
| 0 | 4 | magic `GXDT` |
| 4 | 1 | 版本 `1` |
| 5 | 1 | 条目数 `7` |
| 6 | 2 | flags `0`。bit 0 留给 type-23 行，v1 见到就拒绝 |
| 8 | 2 | 条目长度 `212` |
| 10 | 2 | 预留 `0` |
| 12 | 4 | 文件 CRC32，覆盖 16..末尾。存 0 视为无效 |
| 16 | 7×212 | 条目，按深槽 1、2、3、5、6、7、8 排列 |

头 12 字节不逐字节比较，而是要求 `CRC32(bytes 0..11) == 0xC631B02D`，这样省代码。

每个条目 212 字节：

| 偏移 | 字节 | 字段 |
|---|---:|---|
| 0 | 1 | 槽号，必须等于该位置的深槽号 |
| 1 | 1 | 扩展字节，写 0（v1 不用） |
| 2 | 2 | 预留 |
| 4 | 4 | 绑定配方的 CRC32，即 `rfw_defaults[slot-1]` 那 49 字节 |
| 8 / 12 / 16 | 4 各 | A5、B5、colour 各自的 CRC32 |
| 20 | 62 | A5：31 个 u16 输入 |
| 82 | 33 | B5：33 个 u8 输出 |
| 115 | 96 | colour row 1 |
| 211 | 1 | 填充 |

## 加载与失败关闭

- **时机**：在 `rfw_open` 里，银行装好之后、算高亮之前，调用 `rfw_deep_refresh`。只在 `deep.active == 0` 且 `uncertain == 0` 时读。已经生效的深槽，RAM 里那套表不动，所以回到 04 时不依赖卡。
- **两路读取**，仿照现有 DAT：先读 DEEPTBL1，再读 DEEPTBL0。
  - 两份都有效但内容不同，视为冲突，失败关闭。
  - 只有一份有效时用它；若只有 DEEPTBL1 有效，要读两次且一致才用。
- **RAM**：单独一次 `gxr_alloc(1712)`。申请失败只把 `tables_ok` 置 0。缓存从 3540 B 变成 3548 B。原生分配器 `0x2005BF5C` 失败时返回 0。
- **校验**：
  1. 长度恰为 1500。
  2. 头常数对。
  3. 文件 CRC 非 0 且对得上。
  4. 槽号对得上。
  5. 绑定配方的 CRC 对得上。
  6. 三行各自的 CRC 都对。
  7. A5 严格递增，且在 1..4094 内。
  8. B5 不递减。
- **失败关闭**：`tables_ok = 0` 时，所有配方的目标 id 都当作 0，所以不发 RPC，ISP 保持 stock，S、预览、列表、名字和 04 都照常。机身上能看到的现象：选过 01、02、05..08 后重开菜单，高亮落在 04；选过 03 后重开，落在第 1 行。

宿主和 ASan/UBSan 都覆盖了下面这些失败路径，每一条都检查 A5/B5/colour 仍是 stock、RPC 调用为 0：
- 两份文件都缺；
- 长度不对：1499 B、只有头、空文件、多 1 字节、填满整块；
- magic 错、版本错，条目数、flags、条目长度错；
- 文件 CRC 错，或存成 0；
- 三行任一行的 CRC 错；
- 曲线问题：重复、递减、出现 0 或 4095、输出下降；
- 条目和配方对不上：槽号错、两行对调、配方 CRC 错、名字改过；
- 两份文件冲突；
- `gxr_alloc` 返回 NULL；
- 读错误；
- 没卡；
- W 开始后才失败。

正向路径也测了：缺一份或坏一份时用另一份；01 生效后拔卡，04 仍能恢复；生效期间换表，要等回到 04 才换；开 100 次菜单只申请一次内存。

## 空间

payload 从 8060 B 降到 **7968 B**，结束地址从 `0x200546E8` 变为 `0x2005468C`。探针尾前余量从 24 B 增到 **116 B**。payload SHA-256 是 `d5fdd8d5429f4d66aae98cbe57dc6462c205c8db33df43deddaf7b9549729f18`。

| 项 | 字节 |
|---|---:|
| 移出非 stock 表、缩小 `rfw_deep_rows`、去掉对齐填充 | −648 |
| 新函数（校验、刷新、加载、CRC 等）、拆读文件函数、两条路径字符串 | +648 |
| deep_isp.c 的调用改用 `bl` | −104 |
| 钉住 ui.o rodata 前的填充 | +12 |
| **净** | **−92** |

腾出的空间比设计估计的少，原因有两个：2e 已经做过去重，非 stock 的表本来只有 543 B；读文件和校验的代码大约 608 B。最大的剩余空间是 `rfw_defaults` 里 392 B 的空槽，这一版没动。以后的色表都放在表文件里，不再占 payload，所以空间已经不是瓶颈。

## 测试

- 宿主和 ASan/UBSan 各 133 项：2e 的 86 项按原名、原顺序保留，另加 47 项。
- 工具测试 21 项，ABI 模型 36 项，镜像审计 7 项，分派器 25/25，保护窗口 30 个与原厂相同，拒绝用例全部通过。
- 等价性测试：`tests/equiv_driver.c` 分别链接真实的 2e 源和 2g（读等价表），按 04→01→02→05→06→07→08→04→03→04 切换。两边的运行记录逐字节相同，SHA-256 为 `a1996ecd…`，共 920 次 RPC，其中 864 次 W。换成新表后，只有 04→03 和 03→04 两步不同。

## 上机验证计划（worker 原案）

0. 刷入 `candidate/SD_ROOT`（29 个固件文件加四份 DAT，不含表文件）。恢复用 `recovery-official-1.51/SD_ROOT`。换表的步骤是：选 04 → 关机 → 换文件 → 开机 → 开菜单。
1. **没有表文件（失败关闭）**：八个名字都在；01、02、05..08 和 04 一样；03 是原生黑白配 stock 曲线；高亮按上面说的规则落；不卡死。
2. **等价表**：高亮回到刚选的那一行，八行中性块与 2e 照片相差在 ±2 码以内。
3. **新表**：03 中性块约 3/15/67/210/243/249，至少 D4 在 54–84、D3 在 189–218；04、01 与验证 2 相差在 ±2 码以内。
4. 可选：表已生效时拔掉表文件，04 仍能恢复。
5. 可选：两份表文件内容不同，表现应与验证 1 相同。

## 需要特别注意

1. 第二次 `gxr_alloc(1712)` 在机身上能不能成功，还不知道。若失败，所有深槽失败关闭，表现和「没有表文件」一样。
2. 代码第一次在 `0x20053E6C` 以上执行（`.text.late` 在 `0x20053FEC..0x200541F0`），仍在段 0（`0x2004B000..0x20054F24`）里，在 payload 预留区之内。
3. C 代码第一次使用 `bl`。38 条 PC 相对重定位都做了距离检查和目标核对。
4. 失败关闭时 03 是原生黑白配 stock 曲线，不是高对比。
5. 换了表文件，要先回到 04 再开菜单才会生效。
