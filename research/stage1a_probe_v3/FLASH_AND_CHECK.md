# 电脑端完成、真机未验

这是 v3 的用户操作草案，待主代理复核及用户确认后执行。全部相机和卡操作由用户完成。Agent 不连接相机，不写 SD 卡或 `/Volumes`。电脑端通过不能替代本页的真机结果。

候选包：[stage1a-probe-v3-sentinel](../../artifacts/stage1a-probe/packages/stage1a-probe-v3-sentinel/)。电脑验收：[verification.json](verification.json)。

```text
probe ilaunch3:
75b4aa1e80e43ea374630d264557f29c490ab5ac4cf6a610e8807bf02fa19ca5
official recovery ilaunch3:
da1980e9d6f3996ede4953b8311cf0ce2abeb4bb300b6ee60a38f38e29a3cdf7
```

## 准备既有照片和卡

1. 选两张明显不同 ISO 的已有回放照片，例如 ISO 200 的 A 和 ISO 3200 的 B。记下文件编号和照片内容，在官方固件回放信息页核对两个数字 ISO。两张都应避免 `ISO-LO`。
2. 备份卡内照片和设置，确认机身/模块版本适用官方 GXR 1.51 包，并按已有 Phase 0 操作使用满电电池。
3. 用户将 `probe/SD_ROOT/` 的 29 个升级文件复制到实验卡根，逐一核对与 `probe/SHA256SUMS` 相符。只准备这一套升级文件。保留照片，不合并 recovery 树。
4. 用户另准备 `recovery-official-1.51/SD_ROOT/` 的 29 个官方文件及对应清单，供正常更新器恢复。换包、重新复制或文件可能变化时，重新读回校验。

以下命令仅供用户手动执行。`CARD` 由用户填写，命令读取卡上的 29 个文件，不负责复制。

```sh
CARD="/Volumes/用户填写实际卡名"
V3_PKG="/Users/wu/.t3/projects/projectricoh/artifacts/stage1a-probe/packages/stage1a-probe-v3-sentinel"
(cd "$CARD" && shasum -a 256 -c "$V3_PKG/probe/SHA256SUMS")
```

必须得到 29/29 `OK`。卡根的升级文件名、AppleDouble `._*` 升级副本或另一套升级文件也由用户核对。未满足时不进入更新步骤。

## 更新和首次回放

1. 用户安全弹出卡，断开 USB，关机，将实验卡插入相机。
2. 沿用已经验证的 Phase 0 操作，按住 `+` 并按回放按钮 `2-3 秒` 进入更新确认页。核对机身、模块和版本，用 Fn2 选择 Yes，再按 MENU/OK。
3. 写入期间保持供电与卡/模块连接，等待更新自动完成并重启。更新中不拔卡或断电。
4. 打开 A 的回放信息页，记录文件编号、整屏照片和标签。
5. 切到 B，再切回 A，按 `A -> B -> A -> B -> A` 连续来回切换。每次都记录文件编号、照片内容和新显示的标签，确认实际换了照片且画面可正常更新。

全部哨兵为 FF 时，A、B 都显示 `OK 8`。数字 `8` 是全干净的约定序号；`NG 0..7` 是首个非 FF 的哨兵序号，映射见 [REPORT.md](REPORT.md)。该数字不表示照片 ISO，不应期待 `OK 200` 或 `OK 3200`。

每次切换都要求触发新的生产函数调用并重新判定。电脑端已用同一实例的 `OK 8 -> NG 0 -> OK 8 -> NG 7` 检查无缓存路径；真机测试仍需按上述两张既有照片来回触发。两张照片上相同的 `OK 8` 画面本身不能证明内部读取次数，记录应保留这项证据边界。

## 每个状态变化后重复两张照片

以下项目当前全部 `NOT_RUN`。完成每项后都执行 `A -> B -> A -> B -> A`，记录每次文件编号、标签、画面和异常。停留在同一张照片重复拍旧 `OK 8` 不满足该步骤。

- 更新后的首次回放。
- 正常关机再开机。
- 回放切到拍摄再回放。
- 正常待机后唤醒。
- 实际可用的另一种回放布局。

两个公开入口输出相同。没有独立入口调用证据时，normal/alt 的真机覆盖分别记 `NOT_PROVEN`，不能根据相同标签或布局名称填 PASS。

如果已有显示 `ISO-LO` 的照片，单独检查其标签保持原样。LOW 非零时第二次原厂 formatter 可覆盖首次 `NG`，**`ISO-LO` 不作为哨兵通过证据**；没有这种照片则将该项记 `NOT_RUN`。

遇到 `NG`、乱码、不能切换照片、卡住或基本拍摄异常时，记录文件编号、标签、此前操作与 probe 哈希，停止后续实验。更新未结束时保持供电，不将更新中的等待当作回放卡住处理。

## 官方恢复和记录

1. 相机仍能启动、读卡并进入正常更新器时，用户使用官方恢复卡；需重新复制时，只使用 `recovery-official-1.51/SD_ROOT/` 的 29 个文件。
2. 用户手动读回清单，必须 29/29 `OK`。

```sh
(cd "$CARD" && shasum -a 256 -c "$V3_PKG/recovery-official-1.51/SHA256SUMS")
```

3. 用户沿用相同更新操作刷回官方，等待完成并重启。
4. 再次回放 A、B，确认恢复原厂各自的 `ISO %d` 数字，关机再开机后重新核对。

恢复树在电脑端已与官方逐字节一致。本流程依赖能启动并进入正常更新器，没有给出坏 MAIN、Monitor 或 USB 救援保证。本轮实际恢复为 `NOT_RUN`。

用户记录每项的 `PASS/FAIL/NOT_RUN/NOT_PROVEN`、机身/模块版本、文件编号、照片 ISO、实际标签、整屏照片、操作顺序和两个 ilaunch3 哈希。`OK 8` 只能记录为“本次 8 个哨兵读值为 FF”，不能记录为“8340 字节全部干净”或“代码区生命周期安全”。
