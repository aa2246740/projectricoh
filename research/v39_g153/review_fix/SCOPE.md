# g152 复审修复的 g153 差量范围

本轮只把正式交付的 `eng_core.c` 修复移入 g153，另缩减空闲 B 行池以满足原空间门槛。服务库、resident、机身镜像、v3.9 适配器、代次和有效效果数据均未改。

| 组 | 本轮安排及理由 |
|---|---|
| 原复审跨退出用例 | 复制原脚本及 `after-refusal-*` 证据；50mm/MOUNT、退出后实际槽 04/08 四项。仅把已失效资格的内部断言从 1 改为 0，完整九行/T、完整 S 在按键和重开后均须等于实际此前状态。 |
| 锁忙缩减矩阵 | 最终测试 DAT 上完整重跑 48 项，四种切换、三种时序、OK/半按、两个单元。逐条复核服务操作顺序、S 零写及退出/重开的九行/T、完整 S、56 B 引用。 |
| 未建基线回归 | 原 g150 非原厂首轮晚遇忙两单元、T=0 两单元、九行变化、T 变化、无效捕获和补偿失败，共八项。失败捕获和补偿须进入 ERR 并保持 uncertainty。 |
| 效果应用 | 三单元各十个效果，验证有效池未因缩容改变、首次捕获/提交、确认、退出重开、完整 552 B 与完整 S。 |
| 状态入口回归 | 50mm 的冷启动/确认/启动 T/首次读回；MOUNT 的确认/启动 T/双包记录互换；28mm 冷启动。另测错误页和失归属，覆盖新增资格失效边界。 |
| 同类事务变体 | MOUNT 退出后实际状态为效果、50mm 多次拒绝后成功、MOUNT 原生半按退出和模型恢复实际行后重开。模型输入不代表真实拍摄。 |
| 机身身份和恢复路径 | 重新核对完整输入与镜像摘要、正常重算源码 build id/ABI、原字节门与两包 28 个官方同伴文件。机身机器码逐字节未变，保留上一轮最终机身的三组恢复、H09/H10/H40/H41 和颗粒回执，不计成本轮运行。 |
| R3 和效果格式 | 最终包重新解析并比较全部有效数据和用户扩展。解析器和编码行未改；全格式拒收、数学全值域和其余容量组合留给发布复审。 |
| 其他 | 完整 144 项锁忙、99 条旧回归全组合、空/49 行及全部名字夹具、实机 LCD/RPC/RTOS/画质留给发布复审；本轮限于引擎快照有效期及缩容的受影响范围。 |

所有相机指令模型使用 Python 后端。测试通过 `job.py` 在 `nice -n 10` 下以前台方式运行，每批最多两项，两项均退出后才开始下一批。每进程独立 Scratch 子目录，单次超时至少取相应历史耗时三倍。旧回执保存在 `prior/evidence`，不计为新 DAT 的执行结果。
