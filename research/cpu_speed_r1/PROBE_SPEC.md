# v3.6 最小 CPU / LUT 测速探针规格

状态：仅规格，没有实现、构建或上卡资格。旧 P0 不能直接使用。目标是用菜单上的原始读数和手机秒表，测出 `s/tick` 与 `tick/像素对`；物理 MHz 仍需时钟树或更强运行证据。

## 1. 固定对象与最小范围

| 项目 | 必须满足的值或行为 |
| --- | --- |
| resident | v3.6，build id `b779cc756a740506415ca5df8eb5c8f08e1b04ea9d8c4c614f7ae971e92b94f7`。 |
| ABI | `d7387c3670059c325186de3af1b3d5c6`，全部 16 B 比较。 |
| 尺寸上限 | 沿用 v3.6 的 file 98,304 B、code 65,536 B、image 114,688 B、单 lease 65,536 B、state 6,144 B；最终产物逐项检查。 |
| 输入树 | 只参考 `firmware/resident_v36`、`firmware/engine_v38_b36` 和旧 P0 的纯内核、计时包装。另建探针源树，不改 frozen resident。 |
| 安装物 | 只有一份新的 `GXRCE.DAT`。不提供或替换 ilaunch、resident、刷机文件；不写 IROM。 |
| 权限 | 仅探针所需 UI、只读查询和私有 RAM lease；不授予 `CAP_FILE_WRITE`、设置写或拍摄处理权限。 |
| 处理对象 | 私有合成像素对和私有 LUT。没有主图 hook、照片文件读取、JPEG 编解码、拍摄、回放缓冲写入或 RPC。 |
| 结果 | RAM 中保存，八行分页菜单显示；掉电丢失，由用户用手机拍屏或抄录。 |

新 DAT 必须按 v3.6 loader 的真实格式绑定、验签和校验长度。独立验证 loader 会在当前 gen117 / IROM 状态下选择这份 SD DAT；不能把旧 P0 的代数常量改掉就假定可以加载。发布页显示唯一探针版本和短哈希，避免把旧读数认作新探针。

运行时绑定或校验失败就拒绝进入探针；不兼容 v3.4c 的旧 build id/ABI，不用未知入口地址继续运行。以上绑定来自本轮只读 ELF 检查，不是对相机当前内存的一次读回。

最小版本只测完整 17³ Q8.8 表。33³ 的完整表为 215,622 B，超过现有单 lease 和内嵌映像容量；菜单明确显示 `33 NOT FIT`。不把重复访问一个 17³ 小片段的时间称为 33³ 测速。33³ 以后另作内存方案及实机测试。

## 2. 零文件写入是最终产物属性

不链接或调用旧 P0 的 `flush`、日志写入和产品 blackbox。省去 install、remember/store、日志、备份、标记文件，以及 DAT→OK 的 rename。创建、写、删除、rename、truncate、同步落盘和 IROM 写入口均不可达。

探针专用 engine service 分发表直接拒绝整个 `RV_STORAGE` 类。resident 为装载 DAT 做的只读打开、读取和关闭可以保留；探针本身不打开文件。`CAP_FILE_WRITE` 关闭只是第一层，不能替代最终 ELF/DAT 的可达调用审计。gen117 源码中仍有通用 blackbox 定义，不能用某个源文件名称或 grep 结果证明最终包没有写入。

之后构建时，须用准确的最终 DAT 做以下检查：反汇编及重定位没有到写入 API 的可达边；所有正常、取消、错误和重入测试中，文件变更调用计数为零；强制调用 storage 服务也被拒绝。测试不向真实卡写“验证日志”。

## 3. P1 修法：先原子拒绝，后捕获和发布

现有 v3.6 `resident/shared.c:rv_ui_capture` 仍把越界游标改记为 1，`rv_ui_abort` 又只接受原表 `0x2022D610`、七行。旧 P0 若覆盖十三行原表，保存和恢复不对称。不能用“最终画面正常”替代逐字节恢复证明。

保持 resident build id 不变。在探针自己的 engine service 副本中，为 `ui_list`、`ui_view` 中每个 `rv_ui_capture` 调用加入同一发布前条件；不能只在 adapter 的外层检查一次。预检查可提前拒绝；权威检查必须放在现有 `rv_irq_save()` 之后、第一次 capture 与任何原生 UI 发布写之前，避免分配、文字转换和其它回调之间改变原状态。

第一次捕获的必要条件：

1. 原生表指针 `*(u32*)0x2022F5A8 == 0x2022D610`，行数 `*(u8*)0x2022F5AC == 7`。
2. `0x2022F725`、`0x2022F726` 的两个原始 byte 都在 1..7；不钳制、不归一化、不先写成 1。
3. native view 数组、数量、tag-32/tag-33 及 state 符合 v3.6 所支持的菜单上下文；没有其它 owner、未知 restore 记录或失配 epoch。现有 `owned()` 的约束继续适用。
4. 上述条件全部成立，才调用 capture，保存四个原值并继续发布。否则返回可识别的 `P1 REJECT`，不写四个原生 UI 字段或 tag-33 state；未取得所有权时不调用可能恢复他人状态的 abort。

已经拥有本探针八行视图时，更新页只验证自己的 owner、epoch、原始七行快照和租约，不再按“原表必须七行”检查当前八行视图，也不覆盖原快照。发现其它视图抢占则停止，不能再次 capture 把本探针的八行表当作原表。

原生 UI 发布写白名单如下。私有 RAM、分配器和现有 resident 的关闭动作另按原契约审计，不混称“全机零内存写入”。

| 地址 | 宽度 | 恢复要求 |
| --- | ---: | --- |
| `0x2022F5A8` | 4 B | 精确恢复保存的原表指针。 |
| `0x2022F5AC` | 1 B | 精确恢复为保存的七行。 |
| `0x2022F725` | 1 B | 精确恢复原始游标，不钳制。 |
| `0x2022F726` | 1 B | 精确恢复原始游标，不钳制。 |
| 经过验证的 tag-33 view state 槽 | 4 B | 只替换自己的槽，并按 v3.6 `rv_ui_abort` 所支持的 stock state 撤回。 |

用原生 MENU、OK 退出、H06、错误和 resident retire 路径验证恢复；包括初次 glyph 转换失败、分配失败、部分发布、epoch 改变、语言改变和嵌套 H08。不得把 kernel、分配器或文字转换放进关中断区；关中断只包住原有的短捕获、状态验证与发布。

P1 的必要回归用例是：原游标 1..7 的全部 49 个组合均精确恢复；0、8..13、255 任一出现时拒绝；十三行原表、未知表和错误 view 必须拒绝且原生 UI 发布写计数为零。逐步注入失败，核对四个字段和 view 槽，不能只核对行数。P1 修复须在准确的最终 DAT 上通过才可另行申请实机执行。

## 4. 菜单和状态机

固定八行，可分页，不沿用旧 P0 的十六行发布。v3.6 的 H06/H08 错误退路明确以八行为条件，行数变化须另审。最少三类页：参考时间、当前样本、样本历史。所有 `T` 值按十进制显示，明确 `RAW TICK`，不在机上先换成假定毫秒。

建议每页八行分别显示：版本/阶段、run 序号、样本类型、N、start、end、delta、页号/错误或控制提示。一个字段放不下就分页，不能截掉高位。当前 run 序号只区分同一次上电内的试验；重启清零，不能冒充全局唯一 ID。

状态为 `NEW → REF RUN → REF DONE → ADMISSION → BENCH → DONE`，任何异常转 `INVALID/ERROR`。菜单第一次成功发布之后才取 reference start；OK 被确认时先取 reference end，再撤回视图。若在首次发布前失败，不开始计时。

OK 仅在已核实的 H07 调用者和请求组合中作为确认；沿用现有 P0 已区分的 `0x202C2D74/0x202C2D84` 与 reason `0x23`，但须重新核对 v3.6 的 frame 字段。遵守 v3.6 `keep==0` 的关闭行为，不靠返回 CONSUMED 强留菜单。确认后可退出并重开，展示 RAM 里的本次参考结果。MENU 取消、其它事件、模式变化、休眠、未知重入使参考作废；重新开始必须重取 start，不能沿用旧起点。

基准由明确的 DOWN/菜单事件每次推进一个短样本，完成后把控制权交回原生 UI；H01、H02、H05、重绘和 H09 不自动重复 kernel。已经完成的 run 不因重绘重新测量。所有结果区以有效标记最后提交，部分更新不显示为成功样本。

## 5. 三种计时内容

所有样本使用已确认的原生 tick `0x2005F164`。计时包装必须保持调用约定、栈对齐、r8..r13 与 lr；以现有 `timing.S` 为参考，最终反汇编复核。IRQ 和调度始终开启，计时前后检查 PSW 的中断允许位；tick API 在中断关闭时返回 0，不可把它误认成零耗时。

| 类型 | 内容 | 用途 |
| --- | --- | --- |
| E | 完全相同包装，空调用，不做像素变换。 | 估计读时和调用的固定成本。 |
| D | 与 10-22 相同的 `addi r8,#-1; bnez r8` 序列。 | 复核墙钟有效循环速率及长短比例，不宣称测到物理 MHz。 |
| L17 | 已计数的 `p0_kernel`，完整 17³ Q8.8 三通道表、坐标表、私有 scratch。 | 直接测 tick/像素对。 |

L17 使用固定种子、覆盖六个四面体、端点及相等分量的向量。完整表 29,478 B、坐标 1,024 B。先做小量输出正确性检查；样本后在计时区外计算输出校验，保证没有被优化成空循环或漏处理。CRC、初始化、生成数据、UI 更新和结果格式化不在计时区内。

私有源/目标须与 kernel 的原位接口一致，每对 4 B；缓冲头尾 guard，确认合法 lease 范围，绝不别名原生主图或 UI。每次样本用确定的输入，初始化成本单独列出。首次调用与后续调用分别保留，但不把首次自动称为“物理冷缓存”。输入分布、表 hash、编译选项和样本顺序写进之后的探针规格/构建报告。

逐次准入：L17 从 N=4、64、512、4096 开始，每次一个 callback。只有前一步耗时不超过软预算的一半，才允许下一步扩大。默认软预算为参考 `30 s` 区间 tick 数的 1/600，按本轮单位推断约 50 ms；这只是设计目标，回调结束后才能检查，不能宣传成硬超时保护。

若内存及准入通过，可选 8192，最多 16384 对；最多 65,536 B scratch，不超过单 lease 限额，并审计与 UI、表、state 和 resident 同时存活的实际堆余量。内存不足就使用较小 N，不能挤占未授权 RAM。D 从 `2^14`、`2^16`、`2^18` 渐增，至多 `2^20` 且同样受准入限制；不直接在菜单 callback 重放 `2^24` 的长阻塞。

每种 E/D/L17 至少重复三次，轮换 E→L 与 L→E 的顺序，保存每次原始 start/end/delta。至少两个 N。若净差只有几 tick，标 `LOW RES`；目标净差至少 16 tick，优先 32 tick。达到预算仍不够时，如实交付低分辨率结果，不无限加长。可只读记录样本前后的 `0xFF000074`，标出档位寄存器变化；不写时钟、不扫描未确认 MMIO。

## 6. 用户操作步骤（将来探针通过审查以后）

1. 在电脑备份当前卡上的 `GXRCE.DAT`，记录哈希。相机关机；仅把已验收的新 DAT 替换到原位置，卡上的其它文件原样保留。此次研究没有执行这些操作。
2. 普通开机，不执行固件更新组合键。进入现有 ADJ / 图像设置入口，核对菜单中的 `B36 CPU P0`、版本和短哈希。看不到正确版本就停止，不靠反复安装修复。
3. 进入 `REF RUN` 页。看见计时已开始时启动手机秒表；大约 30 秒后，在按 OK 的同时停止手机秒表。抄下实际秒表秒数 S，不强行记成 30.000 秒。重开菜单，记录该 run 的 reference start/end/delta。
4. 重复参考测量至少两次；时间充裕做三次。可追加一次约 10 秒的试验观察按键/视觉固定误差，但不以短试验替代长试验。若期间退出、休眠、报错或模式变化，此次作废。
5. 在 BENCH 页按提示用 DOWN 推进，每次只执行一个样本。抄下 E/D/L17 的类型、N、三个 tick 字段、序号、校验状态和寄存器档位。手机可拍菜单屏幕；不按相机快门，不需要拍摄任何新照片。
6. 到 DONE 后拍全所有结果页。任何 `P1 REJECT`、`INVALID`、`LOW RES`、校验错误或预算退出原样记录；不能只选最短一次作为结论。
7. 相机关机；在电脑恢复原 DAT 或仅移除本探针 DAT，再普通冷启动回到原状态。没有探针卸载写入、日志清理、rename 或 resident 更新动作。

参考计时的开始取样早于用户看到屏幕，停止取样晚于按键动作，包含人手与 UI 延迟。把约 ±0.3 s 当作 30 s 参考的初步误差预算只是设计假设，不能说已经校准。多次参考差异若超过合理人手误差，先报告 tick/墙钟不一致，暂停换算。

## 7. 从读数计算

所有相减先做 unsigned 32-bit 回绕差，拒绝零、跨半圈或被作废的测量。手机时间与同 run 的 reference 配对：

```text
ΔTref_i = (ref_end_i − ref_start_i) mod 2^32
τ_i     = 手机实记秒数 S_i / ΔTref_i                 # 秒/tick
```

若约 30 s 的测量给约 30,000 tick，τ 约 0.001 s，才是外部时钟对本轮“1 ms”静态结论的支持。保存各次 τ 和分散程度，不能先将它舍入为 1 ms 再计算。

对相同 N 的 L 与 E 扣除固定成本，并以两个长度检查斜率：

```text
b_N  = median(ΔL_N − ΔE_N) / N                    # tick/像素对
b    = [(ΔL_hi−ΔL_lo) − (ΔE_hi−ΔE_lo)] / (Nhi−Nlo)
T17_main    = 6,106,112 × b × τ                    # 秒，当前内核外推
T17_640x480 =   153,600 × b × τ                    # 秒，假设显示图尺寸
```

差分与各长度的 `b_N` 明显不一致时，保留分歧并报告调度/缓存敏感性；不用直线硬拟合。对起止 tick 量化、E 扣除和长度差分分别传播误差。若净差不足或为负，不给高精度秒数。最终同时给重复样本的最小、中位、最大值，注明调度开启；不把最小值当作整机上限。

D 的条件有效速率可以另算：

```text
F_eff_MHz = Cloop × (Nhi−Nlo) / [(ΔD_hi−ΔD_lo) × τ] / 10^6
Cloop = 4，另列 5、6 的情景
```

它仍含 IRQ、调度、取指等待和可能的变频。即使手机确认 1 ms，也不能只凭这个数确定物理主频。L17 的直接 tick/像素对不依赖 MHz 假设，因此是本探针的主要交付。外推全图没有覆盖真实主图的 cache、DMA、并发和缓冲所有权；33³、JPEG 和完整用户路径均另验。
