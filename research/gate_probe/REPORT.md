钩子改挂 `0x202871C4` / 文件 `0x23C3C4`。它在 `0x201C092C` 返回后的第一条指令上采样，屏幕显示这五个门控输入：活动字 `*(u32*)0x205D9BF8`、类型字节 `*(u8*)0x2022F71C`、part 字节 `*(u8*)0x205A280F`、count `*(u8*)0x205A27D4`、part2 栈顶 `entries[count-1]` 的 tag 和 state。第 7 行是同一套判据当时的返回值，`01` 或 `00`。

本轮只做设计，没有编译、链接、打包，也没有改官方镜像和 stage2b 候选。

## 为什么不能用现有的 `0x2028709C`

`init_recipe_cache` 现在挂在 Image Settings 初始化 `0x20287080` 的前段。那一条 `jl` 返回之后，类型、count、tag、state、part 字节都还没写成门控要看的值。

静态确认，S09:42536 起，文件 `0x23C280`：

```
2028709c  d0c02027 80e01fec   seth/or3 → 0x20271fec，随后 jl     文件 0x23c29c
20287118  6405f000            ldi r4,#5                          文件 0x23c318
20287124  81e1f71c            r1 = 0x2022f71c
2028712c  24011ec0            stb r4,@r1 → jl 0x2028579c         文件 0x23c32c
202871a0  80e007e0            r0 = 0x201c07e0
202871a4  67001ec0            ldi r7,#0 → jl                     文件 0x23c3a4
202871bc  80e0092c            r0 = 0x201c092c
202871c0  66001ec0            ldi r6,#0 → jl                     文件 0x23c3c0
202871c4  d0c02033 80e01d14   seth/or3 → 0x20331d14              文件 0x23c3c4
202871cc  1ec0f000            jl r0
```

`0x20331D14` 和 `0x20331D18` 都是 `1f ce f0 00`（`jmp lr`，S09:217421）。原来这条调用没有副作用。

类型 5 要到 `0x2028712C` 才写入。part2 的 tag、state、count 在 `0x201C07E0` 里面写。part 字节要等 `0x201C092C` 末尾才写。所以 `0x2028709C` 读到的是开页之前的栈。stage2b 的 `rfw_open` 本身也不调用 `rfw_ui_active`，选择失败发生在页已经打开之后。探针如果在 `0x2028709C` 采样，会把“还没写完”当成“门控看到的值”。

列表绘制同样太早。tag 33 的绘制在 `0x201FFF38`（`or3 r0,#0xd360`，文件 `0x1B5138`）调用 `0x201FD360`。这条调用从 `0x201C07E0` 内部的 `0x201D82FC` 进来，发生在 `0x201C092C` 之前。开页那一帧看到的 part 字节，是 `0x201C06F4` 处理过、但 layer action 还没回写的值。`0x201C07D4`（文件 `0x1759D4`）在原值已经是 2 时会把它清成 0：`60 00 20 01`（`ldi r0,#0 → stb r0,@r1`）。只钩绘制函数，很容易把 `P=00` 报成门控失败的原因，而按键时门控看到的已经是后面写进去的 2。

## 采样点

静态确认。`0x202871C4` 是 `0x201C092C(r4=2, r5=0, r6=0)` 返回后的第一条指令，仍在只被活动号 8 调用的 `0x20287080` 里。分派器不改。

S09:95175，文件 `0x26F8FC`，本设计保持原字节：

```
202ba6fc  d2c0205e            seth r2,#0x205e
202ba700  a1c29bf8            ld r1,@(-25608,r2)    ; *(u32*)0x205d9bf8
202ba704  41fff000            addi r1,#-1
202ba708  80510016            cmpui r1,#22
202ba764  d0c02028 80e07080   活动号 8 → jl 0x20287080    文件 0x26f964
```

跳转表 `0x20377434` / 文件 `0x32C634` 的 44 字节保持原样。下标 `(8-1)*2` 的半字是 `0x0038`，落到 `0x202BA72C+0x38 = 0x202BA764`。表的原文：

```
00fc0118 007002bc 01540000 001c0038 005402bc 00e0008c
00a800c4 01bc01d8 02bc0250 026c02bc 028802a4
```

五个值在这条指令之前的写入点：

| 值 | 写入 | 证据 |
| --- | --- | --- |
| 类型 `0x2022F71C = 5` | `0x2028712C` | 上表。并行 `jl 0x2028579C` 在写入之后运行，那个函数是否再改这个字节，本轮没有逐条追完，标未知。探针读采样点上的字节，不假定它仍是 5 |
| count、tag、state | `0x201C0890`、`0x201C0878`、`0x201C0888` | 见下一节。push 被跳过时这些写不发生 |
| part 字节 | `0x201C0CE0` | S08:3136，文件 `0x175EE0`：`28 0a f0 00`（`stb r8,@r10`），`r10 = 0x205A280F` |
| 活动字 | 分派器读过之后，初始化函数本体没有对 `0x205D9BF8` 的 store | 本体静态确认。`0x201C06F4` / `0x201C07E0` / `0x201C092C` 是否改它，没有逐条追完，标未知。探针在 `0x202871C4` 重新读这个字 |

part2 记录的地址是静态的。`0x201C0840` 起：`base = 0x205A27BC + (part<<4) - 16`。part = 2 时 base = `0x205A27CC`，count 在 `+8` = `0x205A27D4`，entries 在 `+12` = `0x205A27D8`。启动时 S08:2693，文件 `0x1757F4`，`st` 把 `0x205A279C` 写到 `0x205A27D8`。条目 8 字节，tag 在 `+0`，state 在 `+4`。这和 stage2b `foreign.h` 的 `RfwUiEntry` 一致。

`0x201C06F4(2, …)` 在 push 之前把 count 清 0，并把 `0x205A280E` 的 bit1 置上。push 在 `(byte_280E & 2) == 0` 或 `count >= 2` 时整段跳过。正常走过时 count 变成 1，`entries[0].tag = 33`，`entries[0].state = 0x2022F71C`。这是这条初始化路径的静态形状。`0x201C092C` 中途还会调用 `0x201C3D08`，它会不会再压栈，标未知。所以 count 的预期不能写成“一定是 1”，屏幕上的 `C` 才算数。

part 字节的最终值也不是静态能定死的。`0x201C092C` 的 part2 分支在 `0x201C0A18` 把 `r8` 设成 2，但 `0x205A2815 == 0` 的那条路会在 `0x201C0BA0` 把 `r8` 改成 4，再在函数出口存下去。`0x205A2813`、`0x205A2815` 的运行时值本轮看不到。推断：`P=02` 和 `P=04` 都有静态路径能走到，`P=00` 则对应“清掉之后没有再写成 2”。这只是采样之前的地图，不是对真机的判断。

## 屏幕上的九行

每屏 9 行、选择 1..8 时窗口起点为 0，这是 stage1_ui 已核对过的绘制规则。本设计不挂钩 `0x202870A8`，七模式 switch 仍把光标设成 1..7（`0x202870FC..0x20287114` 的 `ldi r8,#1..#7`）。因此开页后前 9 行都在画面上。

大端。活动字 8 的内存是 `00 00 00 08`，地址 `0x205D9BF8` 上的那个字节是高字节 0。stage2b 的门控比较的是整个字：payload `0x20052A58` 是 `addi r5,#-8`，然后 `bnez` 失败。第 1 行的 `A` 打印这个字的低 8 位，也就是地址 `0x205D9BFB` 上的字节。第 8 行的 `W` 打印整个字。只看 `*(u8*)0x205D9BF8` 会在活动号其实是 8 时显示 `00`。

| 行 | 文字 | 读什么 |
| --- | --- | --- |
| 1 | `A=%02X` | 活动字的低 8 位 |
| 2 | `T=%02X` | `*(u8*)0x2022F71C` |
| 3 | `P=%02X` | `*(u8*)0x205A280F` |
| 4 | `C=%02X` | `*(u8*)0x205A27D4` |
| 5 | `G0=%02X` 或 `G0=--` | 栈顶 tag。33 十进制是 `21` |
| 6 | `S=%08X` 或 `S=--------` | 栈顶 state |
| 7 | `V=%02X` | 下面的判据，`01` 通过，`00` 失败 |
| 8 | `W=%08X` | 活动字全文 |
| 9 | `E=%08X` | `*(u32*)0x205A27D8`，entries 指针本身，不解引用 |
| 10..16 | `........` | 占位，说明这是 16 行的 type 5 页 |

`E` 是固定地址上的一次加载。`G0` 和 `S` 只有在 `1 <= C <= 2`、`E` 四字节对齐、并且 `E` 落在 `[0x205A0000, 0x205C0000)` 时才解引用。否则写 `--`，`V` 为 0。启动写入的 `0x205A279C` 在这个区间里。这个范围检查比门控多一道，避免诊断包因为野指针死机。门控本身只判断 NULL。真机上次没有在选择时死机，所以当时的指针要么是 NULL，要么是可读的。若 `E` 不在这个区间，把 `E` 那一行报回来，不要把它当成 tag 失败。

判据与 stage2b `platform.c` 的 `rfw_ui_active` 相同，按 payload 里已经生成的指令理解：

```
word = *(u32 *)0x205D9BF8
if (word != 8) return 0
if (*(u8 *)0x205A280F != 2) return 0
if (count == 0 || count > 2) return 0
if (*(u8 *)0x2022F71C != 5) return 0
if (entries == NULL) return 0
if (entries[count - 1].tag != 33) return 0
if (entries[count - 1].state != 0x2022F71C) return 0
return 1
```

`V=01` 表示这一拍五个条件都成立。它不是按键当时的值。本设计不挂钩 Fn2、live commit、确认函数的原逻辑，所以看不到开页之后又被改掉的字。若屏幕上已经是 `V=01` 而选择仍然不进配方，下一步才是在按键路径上再采一次。那一次不在本包里。

## 画到哪，以及不写什么

type 5 描述符 `0x2022F5A8` / 文件 `0x1E47A8` 原文：

```
20 22 d6 10   07   ff ff ff   00 00 00 00
```

`+0` 改成探针的指针表，`+4` 从 7 改成 16。`+5..+11` 的 `ff ff ff 00 00 00 00` 不动。主菜单描述符 `0x2022DB60` 不动，所以主菜单仍指向 `0x2022D610`。

绘制在 `0x201FE410` 做两级加载：`ld r1,@r3 → ld r2,@r1`。这和 stage2b 的 `table[i] = &labels[i]`、`labels[i] = glyphs[i]` 是同一种形状。指针表做进镜像，运行时不改它们。运行时只往 glyph 缓冲区写。

glyph 用现成的 `gxr_ascii`（`0x201D73E0`，stage2b `abi.S` 的 `TO_NATIVE`）。参数顺序是 GCC `r0..r3` 转到原生 `r4..r7`：名字指针、不含 NUL 的长度、输出缓冲、`gxr_language`（`0x201DC180`）的返回值。每格 96 字节，和卡槽菜单的转换缓冲一样大。`A=08` 这种字符串远小于 96。`gxr_ascii` 返回后若首字节仍是 0，把同一条 ASCII（含 NUL）直接抄进该格。绘制器 `0x201D2054` 会自己把 ASCII 转成 `01 xx`。两条路都只写我们的 glyph 格。

开页过程里，push 内部已经画过一次。那时 glyph 还是镜像里的 0，画面是空的。采样和 `gxr_ascii` 完成之后，再调用一次原厂画家 `0x201FD360(r4=2, r5=0x2022F71C, r6=0)`，让这九行画出来。`r6=0` 走 `0x201FD418` 的 `bnez r9` 不成立的那条，也就是完整几何路径。推断这和 push 在 flag 为 0 时的开页绘制是同一种调用。

画家本体 `0x201FD360..0x201FDE90`（文件 `0x1B2560`，长度 `0xB30`）里，没有 `0x205A280F`、`0x205D9BF8`、`0x200C0DAC`、`0x202D6F38`、`0x2009005C`、`0x20287080` 的 seth/or3 立即数。静态确认的是这个范围里的立即数扫描，子调用没有展开，标为范围限制。type 5 描述符 `+8` 的过滤指针保持 0，画家开头把它存到 `0x205D4F64` 后走 `beqz`，不会写 state 的 `+9/+10`。

探针函数先把五个值拷进寄存器或栈，格式化完成，再调用 `gxr_ascii` 和画家。画家即使改了 RAM，屏幕上的文字已经是采样结果。

运行时写入只允许落在 `probe_glyphs[16][96]`，以及重入字节 `0x200546FF`。不写 `S`（`*0x200C0DAC` 指向的设置块），不写 `0x205D9BF8`，不写 `0x2022F71C`，不写 `0x205A280F`，不写 `0x205A27D4`，不调用 `rv1_apply`、`rfw_select`、`gxr_preview`（`0x202D6F38`）、`gxr_layer_action`（`0x201C092C`）、RPC-8（`0x2009005C`）。不恢复 `force_adj_image`。不改活动号，不强制类型 5。

重入字节在尾保留区之前的最后一字节。进入时若已是 1，只返回，不再次绘制。画家是否会重入 `0x20287080`，本体扫描没看到，子调用未知。这个字节是为了防止那种重入变成递归。它不是门控状态。

## 镜像布局

段 0 的文件偏移是 `VMA - 0x2004AE00`。`0x2005276C` 的文件偏移 `0x796C` 已用容器头核对。官方这一段 8000 字节和尾部 `0x20054700..0x20054800`（文件 `0x9900`，256 字节）都是 `FF`。

| 符号 | VMA | 文件偏移 | 大小 | 镜像内容 |
| --- | --- | --- | --- | --- |
| `probe_glyphs` | `0x2005276C` | `0x796C` | `0x600` | 16×96，初值 0 |
| `probe_labels` | `0x20052D6C` | `0x7F6C` | `0x40` | 16 个大端指针 |
| `probe_table` | `0x20052DAC` | `0x7FAC` | `0x40` | 16 个大端指针 |
| `probe_no_details` | `0x20052DEC` | `0x7FEC` | `0xC0` | 192 个 0 |
| `gate_probe_render` | `0x20052EAC` | `0x80AC` | 到 `0x200546FF` 之前 | 代码 |
| 重入字节 | `0x200546FF` | `0x98FF` | 1 | 初值 0 |
| 探针尾 | `0x20054700` | `0x9900` | 256 | 保持 `FF` |

`labels[i] = 0x2005276C + 96*i`，`table[i] = 0x20052D6C + 4*i`。第 0 项：`probe_labels` 处的字节是 `20 05 27 6C`，`probe_table` 处是 `20 05 2D 6C`。第 15 项：glyph 在 `0x20052D0C`，label 槽 `0x20052DA8` 的字节是 `20 05 2D 0C`，table 槽 `0x20052DE8` 的字节是 `20 05 2D A8`。其余 14 项按同一公式填。

代码必须在 `0x200546FF` 之前结束。链接脚本把 `gate_probe_render` 钉在 `0x20052EAC`，这样钩子字节不随函数长短变化。容量大约 6228 字节。stage2b 那份 8000 字节的配方 payload 不要整段搬过来。

## 钩子字节

五处替换。没有第九个钩子。`0x2028709C` 从“调用配方打开”改回原厂取模式，采样挪到写完 part 字节的地方。

| 位点 | VMA | 文件 | 原字节 | 新字节 |
| --- | --- | --- | --- | --- |
| 采样并绘制 | `0x202871C4` | `0x23C3C4` | `d0c02033 80e01d14` | `d0c02005 80e02eac` |
| 确认函数改为立刻返回 | `0x202871D8` | `0x23C3D8` | `2e7ff000` | `1fcef000` |
| type5 名字表 | `0x2022F5A8` | `0x1E47A8` | `2022d610` | `20052dac` |
| 行数 | `0x2022F5AC` | `0x1E47AC` | `07` | `10` |
| type5 附加表 | `0x201FEBE4` | `0x1B3DE4` | `d2c02023 82e2fd38` | `d2c02005 82e22dec` |

采样钩子是 `seth r0,#0x2005` / `or3 r0,r0,#0x2eac`，后面原有的 `jl r0`（`0x202871CC`）进入 `gate_probe_render`。函数按被调用者保存 `r8..r13/lr`，返回到 `0x202871D0` 的 `pop lr → pop r8`。`r8` 在那之后被弹出，不再使用。

附加表钩子用 `r2`：`seth r2,#0x2005` / `or3 r2,r2,#0x2dec`。只替换 type 5 的指针。type 9 在 `0x201FEBE0` 就分到 `0x2023FD8C`，不受这 8 个字节影响。16×12 的全零表避免光标落到第 8 行以后时读出原厂 7 行附加表的相邻数据。开页时光标是 1..7，这张表是防拨盘，不是采样所必需。

确认函数的五个调用点在 `jl` 之后都不读 `r0`，直接分支离开：`0x202B8D9C`、`0x202BD890`、`0x202BEA54`、`0x202C2D74`、`0x202C2D84`。`1f ce f0 00` 是 `jmp lr`，不会 push。因此不会进入 `0x202871E0` 的 `0x201C092C(2,1,0)`，也不会进入后面的模式 setter `0x20268768`。原函数里 `r4==0` 才会关层并可能写图像模式。探针安装期间，确定和关闭不再做这件事。调用者仍会走到自己的后继，其中 `0x202C2D70` / `0x202C2D80` 的后继是 `0x202C31CC`。那一段会不会另写设置，本轮没有追完，标未知。

明确保持原字节的位置：

| 位点 | 字节 | 原因 |
| --- | --- | --- |
| `0x2028709C` | `d0c02027 80e01fec` | 仍调用原厂 `0x20271FEC`，让光标 switch 得到真实图像模式 |
| `0x202870A8` | `12806005` | 不跳过七模式 switch |
| `0x202BA6FC` | `d2c0205e` | 分派器保持原厂 |
| `0x20377434` 起 44 字节 | 上表 | 跳转表保持原厂 |
| `0x202BB968` | `dbc02022` | 不挂钩 live commit |
| `0x202BE24C` | `d0c02026` | 不挂钩 Fn2 |
| `jlaunch3` | 整文件 | 只改机身 `ilaunch3` |

`0x202BB968` 和 `0x202BE24C` 保持原厂，意味着拨盘和 Fn2 仍会走进原来的图像模式逻辑。操作时不要碰它们。

校验：文件 `0x16C` 的大端 u32，相位 0。对 `image[0x200:]` 计算 `sum(byte * (i % 6 + 2))` 的低 32 位，写回 `0x16C`。官方镜像的存储值和按这个式子重算的值都是 `0x6ACDB212`。头部 `[0,0x16C)` 和 `[0x170,0x200)` 不动。探针镜像的新校验值要等代码链接之后才能算，本轮没有数。`jlaunch3`、升级窗口、启动窗口沿用 stage2b `build_candidate.py` 的原厂比对，本设计的五个位点和 payload 都不在分派器、跳转表、探针尾里面。

## 函数在做什么

链接时只放这三个原生入口：`gxr_ascii`、`gxr_language`、`gxr_list_paint = 0x201FD360`。不要放 preview、layer action、RPC、文件和 `rv1_apply`。

```
uint32_t gate_probe_render(void)
{
    uint32_t word, entries, state, verdict;
    uint8_t type, part, count, tag;
    char text[16];
    unsigned i;

    if (*(uint8_t *)0x200546ff) return 0;
    *(uint8_t *)0x200546ff = 1;

    word = *(uint32_t *)0x205d9bf8;
    type = *(uint8_t *)0x2022f71c;
    part = *(uint8_t *)0x205a280f;
    count = *(uint8_t *)0x205a27d4;
    entries = *(uint32_t *)0x205a27d8;

    verdict = 0;
    tag = 0;
    state = 0;
    if (word == 8 && part == 2 && count >= 1 && count <= 2 && type == 5 &&
        entries != 0 && (entries & 3) == 0 &&
        entries >= 0x205a0000 && entries < 0x205c0000) {
        uint32_t ent = entries + (count - 1) * 8;
        tag = *(uint8_t *)ent;
        state = *(uint32_t *)(ent + 4);
        if (tag == 33 && state == 0x2022f71c) verdict = 1;
    }

    /* 先格式化进栈，再 gxr_ascii 到 probe_glyphs[i]。
       首字节仍为 0 时，把含 NUL 的 ASCII 抄进同一格。
       行 10..16 写 "........"。然后： */
    gxr_list_paint(2, 0x2022f71c, 0);
    *(uint8_t *)0x200546ff = 0;
    return 0;
}
```
