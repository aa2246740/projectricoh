# spektrafilm 全部 20 种胶片导出成 LUT：一致性、相机相似度、推荐

2026-11-01。本轮在本机沙箱里运行了 spektrafilm 的 LUT 导出器，把 20 个胶片档案导出成 `.cube`，再用真实照片核对"LUT 和 spektrafilm 本身出图"是否一致，最后算了两种相机相似度（都是**电脑预测**）。

本轮没有碰相机、存储卡或 `/Volumes/RICOHDCX`，没有生成上卡文件，没有 git 写操作，也没开子代理。spektrafilm 的代码（GPLv3）没有复制进任何仓库，只在 Scratch 里运行，结束后已删除。

---

## 0. 结论（给用户看的大白话）

1. **一致性：LUT 和 spektrafilm 本身出图，肉眼看不出差别。**
   - 检验照片：6 张 GXR 街拍 JPEG 和 6 张 DNG，各约 114 万像素。
   - 给 JPEG 用的两种 LUT：20/20 全部达标。色差中位 0.03–0.08，p99 0.22–0.95。目标是中位 <0.5、p99 <2。
   - 给 RAW 用的 V-Log LUT：
     - 33³ 有 17/20 达标。Velvia 100、Superia X-TRA 400、Portra 800 推两档在最暗的部分插值不够细，p99 到 1.6–2.7。
     - 所以另外导出了 **65³**，20/20 达标：中位 0.06–0.18，p99 0.23–0.72。电脑工作室从 RAW 出片请用 65³。
   - LUT 里只有颜色，没有空间效果：每种胶片都做了"格点打乱"检验，打乱前后逐像素完全相同（0/65535）。
   - 在格点上，导出器写出的值和 spektrafilm 直接渲染只差 ≤4.7/65535，也就是浮点精度。
2. **spektrafilm 导出器有两个坑，作者默认设置也有一个要注意。**
   - **反转片**（Provia、Velvia、Ektachrome、Kodachrome）用命令行导出会被"印到相纸上"，结果是负像：输入 0.05 的暗灰输出 0.86。
     - 它自己的图形界面对反转片是直接扫描胶片。本轮照界面的做法，只改这一个开关。
   - 命令行的 `--stops-above-gray` 参数被悄悄忽略了（程序内部参数名对不上），所以改用它自带的 `--from 配置文件` 传这个设置。
   - **作者默认的 sRGB LUT 会把照片提亮约 1.5 档**：中灰 0.466 输出 0.74，GXR 照片中位亮度从 L* 49 变成 72–78。
     - 这是作者有意的设计，为了用上胶片的高光肩部。
     - 第三方 NicePhoto 在 LUT 前加了 −1.5 档增益把它压回去；我们的"中灰不提亮"版做的是同一件事。
3. **每种胶片能像到什么程度（电脑预测，接在 GXR 04 JPEG 后面，用"中灰不提亮"版）。**
   - **相机现在就能做的相机表近似：余差 2.1–4.8**。
     - 余差的意思：≤1 看不出，1–2 要并排细看，2–3 仔细看能分辨，>3 一眼看出。
     - 所以相机表只能做到"像个大概"。最好的是 Ektachrome 2.1、Provia 2.3、Kodachrome 2.3、Velvia 2.4；最差的是 Portra 800 推两档 4.8、Superia 3.9。
   - **机内 17³ 真 LUT（还没上机）：全部 96–98%，余差 0.22–0.33**，基本一样。
   - **电脑工作室**：
     - 套 sRGB LUT 就是 spektrafilm 本身，色差 <0.1；
     - 从 RAW 套 V-Log 65³，色差约 0.1。
   - 机身上只能"像个大概"、电脑上可以"完全一样"，这个结论和 fotufilm 那一轮一致。
4. **推荐先进相机 5 种（风格分得开）：Portra 400、Kodachrome 64、Velvia 100、Vision3 500T、Pro 400H。**
   - 只放电脑工作室的：Portra 800 推一档、推两档，Superia X-TRA 400，C200，Ektar 100。
5. **和 fotufilm 重叠的片种：两家是明显不同的两种"味道"，同名片之间差 3–7 个色差单位**，不是同一个东西换了名字。
   - 柯达负片：spektrafilm 的更容易做进相机。
   - 反转片和电影卷：fotufilm 的相机表余差更小，颜色更浓；spektrafilm 的更淡、更中性。
   - 详见第 4 节。

## 1. 怎么做的

### 1.1 源码与环境

- **源码**：官方仓库 `https://github.com/andreavolpato/spektrafilm`，最新标签 `v0.3.3`，commit `500bc429b7e93450ef228305c319dc03d8e185d1`（2026-05-31）。
  - 克隆到 `Scratch/.../spektrafilm/src`，按不可信数据处理。我们的脚本都在本目录，用 `python -I` 运行，路径作为参数传入。
- **环境**：仓库没有锁文件。用 uv 按它的 `pyproject.toml` 解析依赖，生成带哈希的锁定文件，再 `--require-hashes --only-binary :all:` 安装（只用预编译包，不在本机编译任何下载的代码）。
  - Python 3.13.7：uv 装在 Scratch，作者要求 3.13。
  - 主要版本：numpy 2.5.4、scipy 1.18.1、colour-science 0.4.7、numba 0.68.1、scikit-image 0.26.0、OpenImageIO 3.1.19.0、pyFFTW 0.15.1、rawpy 0.26.1。
    - 都在它 pyproject 允许的范围内，但比作者开发时新。
  - 锁文件存档：`sandbox/requirements.lock`（SHA-256 `76bbc04b…682b`）、`sandbox/build-req.lock`（`e04fd3d3…ec53`，setuptools 和 wheel）。
  - spektrafilm 包本身在沙箱里断网安装，用 `--offline --no-deps --no-build-isolation`。
- **联网只有三次**：克隆源码、下载 Python、下载锁定的依赖包。之后全部断网。

- **网络**：除本地 unix socket 外全禁。实测 `curl https://1.1.1.1` 不通。
- **写入**：只允许 `Scratch/tmp/projectricoh/spektrafilm/` 和 `/dev` 节点。实测写本目录被拒。
- **读取**：
  - 禁止 `/Volumes` 下其他卷，`/Volumes/RICOHDCX` 单独再禁一次；也禁止 `~/Documents`、`~/Pictures`。
  - 例外只有：Scratch、本目录的 `render.py` 这一个文件、`captures/street-g137-20261031/{jpg,dng}`（只读）。
  - 实测 `ls ~/Documents`、`ls /Volumes/RICOHDCX`、`ls research/fotufilm_bake` 都被拒。
- **其他**：`HOME`、`TMPDIR`、numba 和 matplotlib 缓存都在 Scratch；`nice -n 10`；每个进程最多 4 线程；全程最多 2 个计算进程。

### 1.3 导出设置

- **工具**：全部用 spektrafilm 自带的 LUT 导出器（1-LUT 拓扑，sRGB 输出）。
- **导出器的 `lut_mode`** 会关掉颗粒、光晕、散射、耦合剂扩散、眩光、镜头和扫描模糊、锐化、自动曝光、扫描黑白点校正。曝光是固定线性增益，不逐张自动。
- **相纸**：用每个胶片档案自己的 `target_print`。
  - 富士负片：Crystal Archive Type II；
  - 柯达负片：Portra Endura；
  - 电影卷：Vision 2383；
  - 4 种反转片：没有相纸，直接扫描胶片（`io.scan_film = True`，和它的图形界面规则相同）。
    - 命令行没有这个选项，所以这 4 种用导出器的 `BundleBuilder` 导出，只改了这一处；其余 16 种直接调用它的命令行。
- **每种胶片 4 个文件**：

| 文件 | 输入 | 曝光 | 用途 |
|---|---|---|---|
| `spektrafilm_<id>_srgb.cube` | sRGB | 作者默认 `auto`：白点放在中灰上 4 档，增益 2.88，中灰提亮约 1.5 档 | 原汁原味的作者默认 |
| `spektrafilm_<id>_srgbmid.cube` | sRGB | 增益 1.0，中灰不提亮；用 `--from` 配置文件传 `stops_above_midgray = 2.4739` | **接在 GXR JPEG 后面、拟合相机表用这个** |
| `spektrafilm_<id>_vlog.cube` | Panasonic V-Log / V-Gamut（场景线性） | 作者默认 `auto`：本身的 8 档余量，增益 1.0 | RAW，33³ |
| `spektrafilm_<id>_vlog65.cube` | 同上，65³ | 同上 | **电脑工作室从 RAW 出片用这个** |

- **为什么选 V-Log**：导出器没有开放线性输入（作者注明"等 log 整形器"），只能选 log。
  - 选 V-Log 是因为 README 的示例和作者论坛发的测试 LUT 都用它，我们的工具也早就支持。
  - 工作室使用方法：把 DNG 的场景线性光（中灰约 0.18）转到 V-Gamut，再编成 V-Log，然后套 LUT。

### 1.4 一致性验证

- **"spektrafilm 直接渲染"的定义**：不经过 LUT 导出器，直接用它的运行时 `SimulationPipeline`。
  - 设置：空间效果和随机效果关掉（`deactivate_spatial_effects` / `deactivate_stochastic_effects`），自动曝光关掉，但**没有**开 `lut_mode`。
  - 输入用 colour-science 自己解码，乘上和导出器相同的固定增益，输出由运行时自己编码。
- **格点打乱**：33³（或 65³）恒等格点和打乱顺序的格点放在同一张图里渲染，还原顺序后逐像素比较。
- **照片**：
  - JPEG：R8051530、554、570、586、594、610，缩到 1/8，共 114 万像素，8 位码值，两边吃同一份像素。
  - DNG：R8051530、533、562、577、644、685，宽 536，用的方法同相似度工具：2×2 CFA 平均、按每张 DNG 的白平衡矩阵、固定的 50mm 测光锚点；结果转成 V-Log。
  - 本仓库的 DNG 读取器遇到 LensInfo 标签（50736）里分母为 0 的有理数会报错。本轮在进程内把它读成 0，不影响颜色数据，原文件没改。
- **比较方式**：LUT 用四面体插值，在 CIELAB（D65）里算 ΔE00。另外记了三线性插值和 8 位输出的数字，见 `local/bake_*.json`。
- **整幅副表**：R8051530、586 按 1/4 尺寸，分别用作者默认的自动曝光，以及作者默认的空间效果（只关颗粒）渲染，再和 LUT 比；附带 8×8 低通。

### 1.5 相似度

- **工具**：`camera.py`、`ceiling.py`、`convert.py`、`cube.py`、`fit.py`、`spaces.py`、`guard.py` 复制自 `research/fotufilm_bake`。
  - 只改了 `guard.py` 的写入围栏，以及 `ceiling.py` 第一行的来源说明。
  - 驱动脚本 `similarity.py` 和 fotufilm 那轮同口径：50mm 的 04 模型、同样 4 张 DNG 场景、同一套留出合成色（种子 20261023）、第 4 张整图留出、λ=0.1。
- **百分比** = `1 − 中位色差(结果→目标) / 中位色差(04→目标)`。
- **注意**：作者默认版的"04→目标"有 15–20，因为提亮 1.5 档本身就是很大的差别，而相机曲线能学会提亮，所以百分比显得高（76–86%）。**看余差更直观**，"中灰不提亮"版的余差比默认版小 0.3–1.1。
- **三种用法**：
  - 接 04 JPEG · 默认（`srgb`）；
  - 接 04 JPEG · 中灰不提亮（`srgbmid`）；
  - RAW 场景光（`vlog65`，DNG 场景光编成 V-Log）。

  - 同为 33³ 时，Apple Log 略好（Velvia p99 1.56），F-Log2、S-Log3 和 V-Log 差不多。所以根本办法是加密格点，不是换编码。

  - 这部分是边缘、纹理和高光光晕，不是颜色，放不进 LUT。

## 4. 推荐

### 4.1 先进相机的 5 种（相机表近似现在就能做；用"中灰不提亮"版）

| 胶片 | 余差 | 机内 17³ | 理由 |
|---|---:|---:|---|
| **Portra 400** | 2.65 | 96.8% | 柯达负片代表。Portra 160 和 800、Gold、UltraMax、Ektar 都在 0.3–1.3 以内，一支代表即可。如果允许按 RAW 场景光拟合，Portra 160 余差 2.43 更好 |
| **Kodachrome 64** | 2.33（RAW 场景光 2.33） | 97.7% | 暖调、低彩度的老反转片，和其他片都差 2.3 以上 |
| **Velvia 100** | 2.39 | 96.6% | 反差最大的风景反转片，和 Provia 差 2.3 |
| **Vision3 500T** | 2.74 | 97.4% | 电影卷代表（拷贝片 2383 的低饱和、中性高光）。200T、250D、50D、Verita 都在 0.65–1.25 以内 |
| **Pro 400H** | 3.00 | 96.7% | 富士负片里余差最小、偏冷偏淡，和柯达组差 2.4 以上 |

- **可替换**：
  - Ektachrome 100：余差 2.13，全场最小，但和 Provia、Vision3 50D 只差 1.8–2.1；
  - Provia 100F：余差 2.31，标准反转片。
- **相机表都只能"像个大概"**：余差 2.3–3.0，并排能分辨。机内真 LUT 通了以后，这 5 种都能到 96–98%（余差 ≤0.25）。

### 4.2 只放电脑工作室的

| 胶片 | 原因 |
|---|---|
| Portra 800 推两档、推一档 | 相机表余差 4.8 和 3.7。V-Log 33³ 本身也不够细，要用 65³ |
| Superia X-TRA 400 | 余差 3.9；默认空间效果的影响在 20 种里最大（低通 p99 2.2–2.6） |

| Ektar 100 | 余差 3.16；和 Portra 400 差 1.2，进相机意义不大 |

其余（Gold、UltraMax、Portra 160/800、Provia、Ektachrome、Vision3 50D/200T/250D、Verita）工作室全部可用；上机等机内真 LUT，或者以后从同组里替换。

### 4.3 工作室里怎么用

- **GXR JPEG**：套 `_srgbmid.cube`，亮度和原片接近。想要作者原本那种明亮版，套 `_srgb.cube`。
- **RAW**：DNG 场景线性光（中灰约 0.18）→ V-Gamut → V-Log，然后套 `_vlog65.cube`，和 spektrafilm 本身中位差约 0.1。
- **颗粒、光晕、局部对比**：另外做，见 `film_engines_eval` 第 3.4 节。它们在 spektrafilm 里也是按胶片物理尺寸算的，可以参考思路，但不抄 GPL 代码。

### 4.4 默认相纸以外值得做的组合（只列建议，本轮没导出）

| 富士负片（Pro 400H、Superia）× **Portra Endura**，或柯达负片 × **Crystal Archive** | "换相纸"能把冷暖倾向互换，比换胶片更细的变化 |

## 6. 和第三方 NicePhoto 重烘版的对比

数据：`research/film_engines_eval/local/downloads/hf-opensourceluts/` 下的 8 个 `.lut16`，只读，SHA-256 见 `local/nicephoto.json`。

| 代号 | 胶片 | vs 我们默认 | vs 我们中灰不提亮 | vs 我们默认 + 拟合前置增益 | 拟合增益 |

| P09 | Portra 400 | 15.48 / 28.76 | 0.41 / 0.68 | 0.06 / 0.51 | −1.50 EV |
| P06 | Portra 160 | 15.29 / 28.94 | 0.36 / 0.54 | 0.07 / 0.41 | −1.50 EV |
| D17 | Gold 200 | 15.31 / 29.14 | 0.38 / 0.61 | 0.08 / 0.51 | −1.50 EV |
| D18 | UltraMax 400 | 15.26 / 28.20 | 0.39 / 0.59 | 0.07 / 0.41 | −1.50 EV |
| P05 | Ektar 100 | 15.41 / 29.93 | 0.49 / 0.78 | 0.08 / 0.60 | −1.49 EV |
| P03 | Pro 400H | 16.35 / 30.62 | 0.19 / 0.53 | 0.09 / 0.46 | −1.52 EV |
| D12 | Superia X-TRA 400 | 16.79 / 36.50 | 0.24 / 0.84 | 0.09 / 0.58 | −1.51 EV |
| C13 | Vision3 500T | 16.23 / 27.11 | 0.70 / 0.99 | 0.06 / 0.37 | −1.47 EV |

（ΔE00 中位 / p99，6 张验证照片）

差异来自哪里：

1. **几乎全部来自曝光增益。**
   - NicePhoto 在作者默认 LUT 前面加了约 −1.5 档的线性增益，让中灰 0.466 进、0.466 出；我们默认版把 0.466 变成 0.71–0.77。
   - 我们在默认 LUT 前拟合同样的增益后，和 NicePhoto 只差中位 0.06–0.09。
2. **剩下 0.06–0.09 来自版本和取整**：他们用 spektrafilm-lut 0.3.4，我们用 v0.3.3 标签，还有 16 位取整和插值，属于看不出的量级。
3. **"中灰不提亮"版和 NicePhoto 差 0.2–0.7。**
   - 两者不是完全同一种做法：我们是在导出器里把增益设为 1；他们是按中灰拟合的增益（约 0.35 = 1/2.88，相当于增益 1.0 再微调）。
   - 结果中灰比他们暗 0.002–0.009，电影卷差得最多。
4. NicePhoto 没收反转片，理由是"经过负片相纸，结果是负像"，和本轮第 0 节第 2 点的发现一致。本轮按图形界面的规则直接扫描，4 种反转片都正常。
5. 上一轮 `film_engines_eval` 用 NicePhoto 版算的相似度和本轮"中灰不提亮"版接近。
   - 例如 Portra 400 相机表余差：上一轮 2.63，本轮 2.65。
   - 本轮改用"中灰不提亮"版作推荐依据，这样不依赖第三方文件。

## 8. 偏离、限制、清理

- **偏离**：
  - 反转片用导出器的 Python 接口并打开 `scan_film`，没有走命令行；
  - "中灰不提亮"版的负片用 `--from` 配置文件传参，原因是 `--stops-above-gray` 无效；
  - 新增 `vlog65`（65³），原因见第 2 节；
  - DNG 读取器的分母为 0 问题，在进程内处理（第 1.4 节）。
- **限制**：
  - 相似度全部是电脑预测，见第 3 节开头。
  - 依赖版本比作者开发时新（numpy 2.5、numba 0.68 等），但都在 pyproject 允许范围内；和 NicePhoto 的 0.3.4 只差 0.06–0.09，说明影响很小。
  - 整幅副表只用 1/4 尺寸。spektrafilm 的空间效果按胶片毫米换算，性质不随分辨率变。
  - V-Log 用法假定 DNG 中灰约 0.18。工作室要用同样的定标（本轮用固定的 50mm 测光锚点）。
- **清理**：
  - `Scratch/tmp/projectricoh/spektrafilm/` 整个已删除，包括源码、Python、虚拟环境、uv 缓存、中间图。
  - 留下的只有本目录：脚本、沙箱配置、锁文件、报告，以及被 git 忽略的 `local/`。
