# 合同请求（前端 → 编排者 / 后端）

状态：第一阶段（设计师，2026-10-30）。这些是 PRD 第 7 节没有写清楚、或者写法之间互相冲突的地方。前端没有改接口，只在下面写了「暂定做法」，编排者裁定后再更新 PRD 和本文件。

每条格式：**问题** → **依据** → **前端需要** → **前端暂定** → **谁裁定**。
标「阻塞」的条目，第二阶段对应的面板不能完成；其它条目只影响细节。

## 1. 【阻塞】`flip` 一词两义

- **问题**：PRD 7.1 的 `geometry.flip` 是左右镜像（布尔）。现在的 `/api/photos/{id}/crop` 里的 `flip` 是**横竖切换**：`crop.js` 的 `recomputeDefault(view, preset, angle, flip)` 把它发给后端，含义是「这次和照片本身的方向反过来」。同一个名字，两个意思。
- **依据**：`studio/web/assets/crop.js` 的 `flipFor`、`recomputeDefault`；PRD 第 2 节「左右翻转」和 7.1 的 `geometry.flip`。
- **前端需要**：横竖切换用新名字 `orientation`（`'landscape'` / `'portrait'`），`geometry.flip` 只表示镜像。
- **前端暂定**：横竖改发 `orientation`。在后端还没改之前，发旧的 `flip` 字段（这样旧版本的后端照常工作）。
- **谁裁定**：编排者（定名字），后端（改 `/crop` 的入参）。

## 2. 【阻塞】实时预览用 `POST`，PRD 写的是 `GET`

- **问题**：PRD 7.2 写 `GET /api/photos/{id}/render?size=preview&stage=final`。但现在的前端在拖动滑块时，把**还没保存的草稿**（`recipe`、`adjust`、`curve`）放进 `POST` 的 body 里请求预览。如果改成 `GET`，只能看到已经保存的 sidecar：拖动时画面不变，松手保存后才变。这正是 PRD 第 1 节要修的「看不到效果」。
- **依据**：`studio/web/assets/preview.js` 的 `runPreview` 和 `studio/web/assets/api.js` 的 `apiBlob`（默认 `POST`）。
- **前端需要**：
  - 保留 `POST`。body 接受草稿键：`recipe`、`adjust`、`curve`、`geometry`、`crop`、`frame`、`stamp`；只带有的键。
  - 参数：`stage=final|uncropped`（PRD 的名字）；`size=preview|full`（PRD 的 `size=preview`；现在的 `max_edge=800` 请同时兼容，或定一个）。
  - 不带 body 的 `GET` 也保留（读已保存的状态）。
- **前端暂定**：`POST` + body，`size=preview` / 不带 `size`（即 full）。
- **谁裁定**：编排者（改 PRD 7.2），后端（实现）。

## 3. 【阻塞】未裁切画面的有效区域

- **问题**：`stage=uncropped` 的画面在拉直、透视、畸变之后，边缘会留下空白角。PRD 第 2 节要求「裁切框自动收进有效画面内，不出现空白角」。前端自己算不了透视的有效区域，只能算拉直。
- **依据**：PRD 第 2 节「规则」；DESIGN 2.8 第 2、3 条。
- **前端需要**：响应头 `X-GXR-Valid-Rect: x,y,w,h`（归一化到未裁切画布；画布是旋转、翻转之后、裁切之前的坐标）。每次 `uncropped` 请求都带。
  - 同时请定空白角的填充：平色（建议 `#1b1c1f`，和界面底色一致）还是透明（要求 PNG，文件大，建议平色）。
  - `stage=uncropped` 的范围：颜色 + 畸变 + 透视 + 拉直 + 旋转翻转；**不含**裁切、边框、时间戳。
- **前端暂定**：没有这个头时，用前端的拉直近似（`geom.js` 的 `fitRect`，只算拉直）。透视不算。
- **谁裁定**：后端（实现头）；编排者（确认填充颜色）。

## 4. `/api/frames` 要列出可调的项；「不加边框」怎么表示

- **问题**：PRD 7.2 说 `/api/frames` 列出「样式、默认值，以及每个样式可调的项」，但没有写结构。时间戳的格式、字体、颜色、大小、位置也需要一个可选值列表，否则前端要写死，后端改了前端就对不上。另外，PRD 的 6 种样式里没有「不加边框」，但用户必须能关掉边框；PRD 7.1 也没说关掉时 `frame` 写什么。
- **依据**：DESIGN 5.1、5.2、6.2；PRD 第 4、5、7 节。
- **前端需要**：
  - 每个样式：`id`、中文名、`options`（列表，取值见 DESIGN 5.2 的表：`color`、`weight`、`text`、`show_logo`、`show_params`、`show_date`、`show_frame_no`、`canvas_ratio`）、默认值。
  - 时间戳：`formats`（`id`、中文名、示例字符串，如 `'26 10 30`）、`fonts`（`id`、中文名）、`colors`（`id`、中文名、`hex`）、`sizes`（`id`、中文名）、`corners`（`id`、中文名）、`text_max_length`（24）。
  - 「不加边框」：`frame.style` 取 `'none'`，还是缺省 / `null`？请定一个。
- **前端暂定**：`style: 'none'`；选项和默认全部从 `/api/frames` 读。接口没有时见 `IMPLEMENTATION_PLAN.md` 第 4 节（面板显示「还没准备好」，不写假选项）。
- **谁裁定**：编排者（定 `'none'` 还是 `null`），后端（实现接口结构）。

## 5. 默认值的结构和优先级

- **问题**：PRD 7.2 有 `GET/PUT /api/defaults/finish`，但没写结构。另外 PRD 4.5 说「『设为默认』，新照片和批量导出都会用上」，没说清楚：
  - 照片自己已经有 `frame` 或 `stamp` 键时，用哪个？
  - 照片没有这些键时，是后端在渲染和导出时用默认，还是前端在第一次编辑时把默认复制进 sidecar？
  - 出厂默认是什么（DESIGN 12 第 1、2 条）。
- **依据**：PRD 4.5、5、7.1、7.2；DESIGN 5.4、6.3、12。
- **前端需要**：
  - 结构：建议 `{"frame": {...}, "stamp": {...}}`，键名和 sidecar 一样。
  - 优先级：照片自己有键 → 用照片的；没有键 → **后端渲染和导出时解析为默认**（前端不复制）。这样「不加边框」必须是显式的 `'none'`（见第 4 条）。
  - 出厂默认：`frame.style = 'none'`，`stamp.enabled = false`（DESIGN 12 第 1、2 条，待定）。
- **前端暂定**：按上面的结构和优先级写；出厂默认按 DESIGN 写。
- **谁裁定**：编排者（优先级、出厂默认）；后端（实现解析）。

## 9. 数值的方向和范围

- **问题**：PRD 没有写正负号的含义。DESIGN 里前端已经按下面的约定写了界面文字；需要后端确认，否则文字和效果可能相反。
- **依据**：PRD 第 2、3 节；DESIGN 2.4、2.5、3.1。
- **前端约定**（请后端确认或改）：

| 项 | 范围 | 正数 | 负数 | 界面说明 |
|---|---|---|---|---|
| 拉直 | −45 … +45 | 顺时针 | 逆时针 | 数值显示「+1.2°」 |
| 垂直 | −100 … +100 | 楼顶变宽（摆正仰拍的楼） | 楼顶变窄 | 「往右拉：楼顶变宽」 |
| 水平 | −100 … +100 | 右边变宽 | 左边变宽 | 「往右拉：右边变宽」 |
| 镜头畸变 | −100 … +100 | 修正桶形（线条往外鼓） | 修正枕形（线条往里凹） | 「往外鼓 / 往里凹」 |
| 黑点 | −100 … +100 | 压黑 | 发灰 | 「发灰 ↔ 压黑」 |
| 饱和度、自然饱和度 | −100 … +100 | 更艳 | 更淡 | 「淡 ↔ 艳」 |
| 暗角 | −100 … +100 | 提亮四角 | 压暗四角（PRD 已定） | 「压暗四角 ↔ 提亮四角」 |
| 曝光 | −5 … +5 挡，步长 0.1 | 变亮 | 变暗 | 「挡」（不写 EV） |

- **谁裁定**：后端（确认符号）；编排者（确认界面文字）。

  - 坐标：`rect` 归一化到「旋转翻转之后、拉直之后、裁切之前」的画布。`GET /crop` 的 `frame` 要反映 `rot90` 之后的宽高。
