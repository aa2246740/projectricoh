# GXR Studio v2：产品需求与分工

编排者（产品设计、总指挥）写于 2026-10-30 16:5x。这份文档是前端和后端唯一共同遵守的合同。合同里的任何改动都要经过编排者，并在本文件末尾的「变更记录」里登记。

## 0. 产品原则（用户原话的归纳）

- 考验的是摄影基本功。后期只做一点点：裁切、纠正、边框装饰、时间戳，外加相机配方和少量调节。**功能要最小，但做到的每一项都要好用、好看。**
- 用户是 GXR 玩家，不是修图师。默认值要好看，一键就能出图，不懂参数也能用。
- **所见即所得**：页面上看到的就是导出的结果。看不到效果的功能等于坏了。
- 原图永远不动，所有编辑写在 sidecar 里，随时可以还原。
- 中文界面，用大白话。

## 1. 修复：配方和调整"看不到效果"（P0）

用户的反馈是：应用配方、调整图片，很多时候页面上看不到变化。

已知线索（编排者看到的，待后端诊断确认）：
- 用户图库在 `~/Pictures/GXR Studio`，共 35 张 DNG 和 75 张 JPG，也就是说大约 40 张只有 JPG。
- 后端有 `NoRaw`：配方要从 RAW 算。只有 JPG 的照片上，配方大概没有任何效果，界面也没有说明原因。
- `web/assets/crop.js:177` 的注释说，配方和调整的预览是整张画面，不带裁切和拉直，于是两种预览之间来回跳。
- 还可能有：预览没有刷新、缓存命中了旧图、调整幅度太小、滑块松手后没有重新渲染。

验收：
1. 对有 DNG 的照片，8 个内置配方中每个都要让预览明显变化。用画面平均色差衡量：相对原厂标准，彩色配方 ≥ 2，黑白配方要变成黑白。滑块松手后 1.5 秒内看到新图。
2. 每个调整滑块拉到两端时，预览像素都要变化（自动测试衡量），两端的方向也要正确。
3. **只有 JPG 的照片**：
   - 调整、曲线、裁切、纠正、边框、时间戳全部要能用（这些都是普通图像运算，不需要 RAW）。
   - 配方：如果后端能用现有引擎或 LUT 在 JPG 上做出近似效果，就提供，并明确标注"近似（这张没有 RAW）"。做不到的话，配方面板里写清楚"这张只有 JPG，配方需要 RAW（DNG）。拍的时候把画质设成 RAW+JPEG"，并把配方按钮置灰。**不能点了没反应。**
4. 预览统一成一个"成片预览"：配方 + 调整 + 纠正 + 裁切 + 时间戳 + 边框。只有进入裁切/纠正标签时，才临时显示未裁切的整幅画面和裁切框。

## 2. 新功能：纠正（对齐苹果相册的"裁剪"页，P0）

现在只有 ±10° 的拉直。要改成和苹果相册一样的一组纠正工具，放在"裁切"标签里：

| 控件 | 范围 | 说明 |
| --- | --- | --- |
| 拉直 | −45°..+45°，步长 0.1° | 方向键 ↑/↓ 每次 0.5°，保留现有快捷键 |
| 垂直 | −100..+100 | 纠正"楼往后倒"的透视（梯形）。0 = 不动。效果相当于虚拟俯仰约 ±30° |
| 水平 | −100..+100 | 左右方向的透视纠正 |
| 镜头畸变 | −100..+100 | 一个径向系数，纠正桶形/枕形。主要给 MOUNT 卡口转接老镜头用。A12 镜头默认 0 |
| 旋转 90° | 按钮 | 逆时针转 90° |
| 左右翻转 | 按钮 | 镜像 |
| 自动 | 按钮 | 检测地平线和竖直线，给出拉直和垂直的建议值。没有把握就不改，并提示"没找到明显的水平线" |
| 还原 | 按钮 | 全部纠正和裁切回到原图 |

规则：
- 处理顺序：畸变 → 透视（垂直/水平）→ 拉直 → 旋转/翻转 → 裁切。
- 纠正之后，裁切框自动收进有效画面内，不出现空白角（和苹果一样）。用户手动拖的框如果越界，就自动缩回。
- 现有的比例预设（XPan 65:24、社交媒体比例）、横竖切换和构图辅助线都保留。
- 拉直的范围从 ±10° 放宽到 ±45°。旧 sidecar 里的 `angle_deg` 继续有效。

## 3. 新功能：调节（P1，最小增补）

在现有的曝光、色温、色调、对比、高光、阴影和曲线之外，只再加四个，对齐苹果相册的同名项：
- **黑点**（−100..+100）
- **饱和度**（−100..+100）
- **自然饱和度**（−100..+100）
- **暗角**（−100..+100，负值是压暗四角）

不加锐化、降噪、清晰度这些项。

## 4. 新功能：边框（P0）

目标是像哈苏、徕卡出片那样：**无论怎么裁切，边框都整齐、比例一致，看着舒服。**

### 4.1 样式（第一版 6 个）

| ID | 名称 | 样子 |
| --- | --- | --- |
| `gallery` | 画廊白边 | 四边等宽的白边。宽度按成片长边的比例算（细 2% / 中 4% / 粗 7%），所以不同裁切的照片放在一起是整齐的 |
| `leica` | 信息条 | 照片下方一条白色信息条，高度约为短边的 9%。左边是 RICOH 标志 + "GXR"，右边两行：第一行是镜头和曝光（如 `A12 50mm F2.5 MACRO`），第二行是 `f/2.5  1/250s  ISO 200`，中间一道细竖线 |
| `hasselblad` | 哈苏留白 | 左右和上边是细白边，下边是宽白边，下方正中一行小号 "RICOH GXR"，下面再一行灰色参数 |
| `film` | 胶片黑边 | 黑色边框，边上用胶片边缘那种小字写 `RICOH GXR · A12 50mm`，颜色偏橙或米黄，可以带帧号（文件名里的数字） |
| `instant` | 拍立得 | 白边，下边特别宽，下面可以写一行自定义文字，提供手写风字体 |
| `canvas` | 等比画布 | 把任意裁切放进固定比例的画布（1:1 / 4:5 / 9:16 / 3:2），照片居中，四周补白或补黑。给小红书和 Instagram 用 |

### 4.2 每个样式可调的项（尽量少）

- 底色：白 / 黑 / 米白
- 粗细：细 / 中 / 粗
- 开关：显示标志、显示参数、显示日期
- 一行自定义文字，可留空

### 4.3 文字来源

- 机身固定写 RICOH GXR。
- 镜头：从 EXIF 读单元型号，A12 50mm / A12 28mm / MOUNT A12。MOUNT 镜头的焦距如果 EXIF 里没有就不显示。
- 光圈、快门、ISO、拍摄时间：从 EXIF 读。
- 缺哪个字段就隐藏哪个，不显示空值或 "None"。

### 4.4 素材

- RICOH 标志用 Wikimedia Commons 的 `File:Ricoh_logo_2005.svg`。它标注为 PD-textlogo（不受版权保护），但仍然是理光的注册商标。放进仓库时附上来源和"商标归理光所有，仅供个人照片装饰"的说明。
- "GXR" 字样用开源字体排出来，不去找机身铭牌图片。
- 字体只用 SIL OFL 或 Apache 许可证的字体，连同许可证文件一起放进仓库，总大小不超过 3 MB。

### 4.5 规则

- 边框在成片外面另加，不吃掉照片内容。导出尺寸 = 照片尺寸 + 边框。
- 边框的设置跟着每张照片保存。另外有一个"设为默认"，新照片和批量导出都会用上。

## 5. 新功能：时间戳（P0）

复古胶片相机那种日期戳。

- **默认样子**：七段数码管字体（DSEG7 Classic，OFL 许可），橙红色，带一点发光，位于照片内部右下角，不放在边框上。
- **日期格式**（可选）：`'26 10 30`（默认）、`26 10 30`、`2026.10.30`、`10 30 '26`，可以另外加上时间 `14:05`。
- **日期来源**：EXIF 的拍摄时间。没有拍摄时间就用文件时间，并提示一句。用户也可以手动改日期，比如为了"穿越"效果。
- **自定义文字**：可以换成任意一行字，例如 `TOKYO` 或 `GXR`，也可以和日期并存。
- **可调项**：
  - 字体：数码管 / 打字机 / 简洁无衬线，三种
  - 颜色：橙 / 红 / 黄 / 白
  - 大小：小 / 中 / 大
  - 位置：四个角
  - 发光：开 / 关

## 6. 渲染与导出顺序（前后端必须一致）

配方 → 调节和曲线 → 畸变 → 透视 → 拉直 → 旋转/翻转 → 裁切 → 时间戳（画在照片内）→ 边框（加在照片外）→ 输出 sRGB JPEG。

预览走同一条管线，只是分辨率低一些，所以预览看到的就是导出的结果。

## 7. sidecar 新键与 API 合同

### 7.1 新增和变更的 sidecar 键

所有键都是可选的，缺省就表示不启用。

```json
{
  "geometry": {"straighten": 0.0, "vertical": 0, "horizontal": 0, "distortion": 0, "rotate90": 0, "flip": false},
  "adjust": {"...现有...": 0, "black_point": 0, "saturation": 0, "vibrance": 0, "vignette": 0},
  "frame": {"style": "leica", "color": "white", "weight": "medium", "show_logo": true, "show_params": true, "show_date": false, "text": "", "canvas_ratio": "4:5"},
  "stamp": {"enabled": true, "content": "date", "date_format": "'yy mm dd", "show_time": false, "date_override": null, "text": "", "font": "seg7", "color": "orange", "size": "medium", "corner": "br", "glow": true}
}
```

- `rotate90` ∈ {0, 1, 2, 3}，表示逆时针转了几次 90°。
- `crop.angle_deg` 与 `geometry.straighten` 是同一个量：旧照片读出 `crop.angle_deg`，写入时两边都写，迁移逻辑由后端负责。
- `stamp.content` ∈ {`date`, `text`, `date+text`}。

### 7.2 接口

旧接口保持兼容，新增的只有：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| PUT | `/api/photos/{id}/edit` | 现有接口。请求体允许带 `geometry`、`frame`、`stamp` 和新的 `adjust` 键，带 `expected_rev` |
| GET | `/api/photos/{id}/render?size=preview&stage=final` | `stage=final` 返回成片预览（含边框和时间戳）。`stage=uncropped` 给裁切标签用，只应用颜色和纠正，不裁切、不加边框 |
| POST | `/api/photos/{id}/geometry/auto` | 返回 `{"straighten": x, "vertical": y, "confident": true/false}` |
| GET | `/api/frames` | 列出样式、默认值，以及每个样式可调的项 |
| GET | `/api/photos/{id}/meta` | 返回边框和时间戳要用的 EXIF 字段：镜头、光圈、快门、ISO、拍摄时间，没有的字段为 null |
| GET/PUT | `/api/defaults/finish` | 默认的边框和时间戳设置 |
| GET | `/api/photos/{id}/capabilities` | 返回 `{"raw": bool, "recipe": "full"/"approx"/"none", "reason": "..."}`，前端据此决定配方面板显示什么 |

错误格式沿用现有的 `api/errors.py`。

## 10. 合同修订 1：对前端 14 条问题的裁定（2026-10-30 18:0x）

逐条回应 `research/studio_v2/ui/CONTRACT_REQUESTS.md`。本节和第 7 节冲突时，以本节为准。

1. **flip 的两种含义。**
   - `geometry.flip` 只表示左右镜像。
   - `/crop` 的横竖切换改名为 `orientation`，取值 `landscape` 或 `portrait`。
   - 后端在这一版里仍接受旧的 `flip` 字段，按横竖切换处理，并在响应里返回 `orientation`。
2. **预览接口。**
   - `POST /api/photos/{id}/render?stage=final|uncropped&size=thumb|preview|full`。请求体可以带草稿键，只带出现了的：`recipe`、`adjust`、`curve`、`geometry`、`crop`、`frame`、`stamp`。
   - 不带请求体的 `GET` 读取已保存的状态。
   - 尺寸：`size=thumb` 长边 240，`preview` 长边 1600，`full` 为原尺寸。旧参数 `max_edge` 继续兼容。
   - 拖动滑块时的预览就走这个接口，必须在 1.5 秒内返回。
3. **未裁切画面的有效区域。**
   - `stage=uncropped` 包含：颜色、畸变、透视、拉直、旋转、翻转。不包含：裁切、时间戳、边框。
   - 每次都带响应头 `X-GXR-Valid-Rect: x,y,w,h`，归一化到这张未裁切画面。
   - 空白角填平色 `#1b1c1f`，图片格式用 JPEG。
   - 导出时永远不会出现空白角，因为后端在保存裁切时会强制把框收进有效区域。
4. **不加边框写作 `frame.style = "none"`。** `/api/frames` 的结构按前端第 4 条的建议执行，并在其中的 `stamp` 对象里给出格式、字体、颜色、大小、位置等可选值，以及 `text_max_length = 24`。
5. **默认值。**
   - 结构是 `{"frame": {...}, "stamp": {...}}`。
   - 优先级：照片自己的键优先；照片没有这个键时，由后端在渲染和导出时套用默认值，前端不往 sidecar 里复制。
   - **出厂默认：边框 `none`，时间戳关闭。** 理由是：用户没有选择时，导出的照片不能被悄悄加上东西。
   - "默认要好看"体现在别处：第一次打开边框标签时，6 张样式卡片都用当前照片实时渲染，点一下就生效；"设为默认"之后，新照片自动套用。
6. **`reason` 文字**：中文大白话，可以直接显示给用户，不含内部代码。
7. **"近似"的标注。** 导出响应里 `render_label` 的取值是 `prediction`（电脑预测）、`approx`（近似）、`original`（照片本身）。近似效果的导出文件名加后缀 `_近似`。
8. **样式缩略图**：不新增接口。直接用第 2 条的 `POST render?stage=final&size=thumb`，请求体里带 `frame` 草稿，用当前照片实时渲染。后端对缩略图做缓存。
9. **数值方向**：按前端第 9 条的表执行。后端实现时以这张表为准，测试也要覆盖方向。曝光沿用现有的范围和步长。
10. **几何的写入路径和坐标系。**
    - 几何参数统一走 `PUT /edit {geometry}`。`PUT /crop` 只写 `preset`、`rect`、`orientation`。
    - `straighten` 和 `crop.angle_deg` 由后端保持同步。两个入口共用同一个 `rev`。
    - **`rect` 的坐标系就是 `stage=uncropped` 返回的那张图**：用户在裁切页看到什么，框就画在什么上面。`GET /crop` 的 `frame` 宽高同样指这张图。
11. **`/meta`**：按前端第 11 条执行。显示用的字符串由后端格式化好。`date_override` 的格式是 `YYYY-MM-DD`，`null` 表示用拍摄时间。
12. **自动纠正**：请求体可以为空。`confident=false` 时返回当前值，另带可选的中文 `message`。
13. **前端测试**：允许前端新增 `studio/tests/test_web_*.py`，用 node 跑纯函数测试。前端只能新增这类文件，不能修改已有的测试。
14. **小项**：全部同意。错误信息由后端写成中文大白话；`X-GXR-Label` 只在 `stage=final` 时带；时间戳文字上限 24 个字。

## 11. 合同修订 2（回应验收 research/review_studio_v2/REVIEW.md，2026-10-31）

1. **底图怎么选（预览、缩略图、导出都按这一条）**
   - 选了配方：用 RAW 渲染。只有 JPG 时配方不可用，见 3.3。
   - 没选配方，有相机 JPG：用相机 JPG 作底图。
   - 没选配方，只有 RAW：用 RAW 的 04 标准渲染。
   - 然后统一依次做：调整/曲线 → 畸变 → 透视 → 拉直 → 旋转/翻转 → 裁剪 → 时间戳 → 边框 → 编码。
   - **没有任何编辑、也没有生效的默认装饰时**，预览和导出都直接给相机 JPG 原样（只有 RAW 时给 04 标准渲染）。
   - 预览和导出只能有这一条流水线，旧的导出分支删掉。
2. **导出分辨率**：`size=full` 和导出一律用完整分辨率解码，RAW 是传感器全尺寸，不能借用半尺寸的预览渲染。`long_edge` 按加上边框和画布之后的最终尺寸计算。
3. **原图比较**：新增 `GET /api/photos/{id}/render?stage=original&size=preview`。
   - 有相机 JPG 就给相机 JPG；只有 RAW 就给 04 标准渲染。
   - 永远不带编辑，也不带默认装饰。
   - 按住空格查看原图时用这个接口。
4. **裁剪坐标系**：`GET/PUT /crop` 的 `frame` 宽高、比例和横向/纵向，都按几何变换（旋转 90°、畸变、透视、拉直）之后的有效画布计算。sidecar 里继续保存原始尺寸。
5. **有效区域**：只要做了拉直、垂直、水平或畸变，最终画面就必须落在有效区域内，不能露出 #1b1c1f 的填充角。没有裁剪框或裁剪框是整幅时，也要自动收进有效区域，并且把实际用到的裁剪框写回 sidecar。
6. **复原和默认装饰**：复原写 `frame.style="none"`、`stamp.enabled=false`，明确关掉装饰，不再继承默认值。只有从来没设过装饰的照片才继承默认值。
7. **缓存**：缩略图和预览的缓存键要包含解析后的默认值版本。默认值一改，列表 URL 和图像缓存要一起失效。
8. **EXIF**：新流水线导出时，从源照片复制可迁移的 EXIF（日期、相机、镜头、曝光参数），更新方向和尺寸，再写 ImageDescription。
