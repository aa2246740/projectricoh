# GXR 配方专属微调面板：静态逆向与 hook 设计

建议复用现有 Fn2 hook `0x202BE24C` 打开面板，继续使用原生 part 2 / tag 33 列表绘制，以“保存并替换栈顶视图”切换子面板。面板的行文字、光标、微调值和配方身份都由卡上引擎持有。新增按键前置分派及 UI 重建、隐藏观察点，避免面板行号进入原厂七项 Image Settings setter。

打开面板后不能沿用当前 Fn2 桩的返回值 2。分派器会把 2 转成事件 1，重新初始化 ADJ 页，覆盖刚建立的面板。新入口应保留状态 56，通过原 epilogue 返回 0；面板内已消费的事件直接走 `0x202B1344`，继续收下一事件。

静态证据支持这个设计，但还不足以把它作为“一次刷完”的最终 hook 合同。两个重要缺口是：物理方向键、ADJ 拨杆与 Detail 事件之间的全部别名没有闭环；休眠、所有 MY 召回入口的提前失效通知没有闭环。`0x202D6F38(0)` 能请求预览，不能据此承诺每次深层行写入都会立即出现在下一帧。

本任务只读官方固件、既有研究和源码；未构建、链接、打包、执行相机固件，未访问相机或存储卡，未生成上卡文件，未 commit/push，未启动子代理。全部写入限于本目录。分析日期为 2026-10-23。目标是机身 1.51，主力 GR LENS A12 50mm 1.51；28mm 和 MOUNT 的具体深层写入由其它研究负责。

## 2. 按键分派与“现在按右会怎样”

### 2.1 先分清物理键与逻辑事件

已核实，本地 GXR 手册文本的机背说明把 Fn1 标为左、Fn2 标为右；MENU/OK 是同一个按键。手册还允许用 ADJ 拨杆左右代替 Fn1/Fn2 导航。Image Settings 的 B&W、TE、Setting1/2 用 Fn2 进入细调。出处为 [手册文本](../phase0_drill/evidence/gxr-manual-extracted.txt) 的 447–455、507–525、3054–3057、5318–5338 行，对应印刷页 3、5、71、135。

固件同时有横向导航族 `0x21/0x22` 和既有研究称为 Fn2/Detail 的 `0x25`。这三者不能仅靠按钮名称合并。下面的逻辑事件到 handler 已闭环；从硬件扫描、按下/释放/长按到这些逻辑事件的所有物理别名没有闭环。因此本报告不会把 `0x25` 写成“Fn2 的每一种物理按法都必然生成它”。

### 2.2 状态 56 的可复查路由

已核实，ADJ 状态表为 `0x203764C8`。`0x202B1100` 是 shooting 分派循环，`0x202B1298..12A4` 调每行 `+4` handler；若前一 handler 返回 0 且状态检查允许，`0x202B1308..130C` 再调 `+8` handler。事件号在 `r11`，第一列原生参数是 `r4=event, r5=消息块`。事件 1 是状态进入/初始化，不应直接当作 ADJ 物理按键号。

| 操作或事件族 | 逻辑事件 | 第一列 / 第二列 handler | 活动 8 / type 5 的静态行为 |
|---|---|---|---|
| 向上导航族。 | `0x1F, 0x59, 0x2D`。 | `0x202C2880` / `0x202B84F4`。 | 调 `0x202897AC` 更新 UI，再在 `0x202C2AA4` 调 `0x202BB4BC`。`0x2D` 被转成 `0x1F`。 |
| 向下导航族。 | `0x20, 0x5A, 0x2C`。 | `0x202C25B8` / `0x202B84F4`。 | 同类路径在 `0x202C27DC` 提交。`0x2C` 被转成 `0x20`。 |
| 横向左族，包含拨杆/通用横向导航。 | `0x21, 0x30`。 | `0x202B848C` / `0x202BAD14`。 | 第一列有原生条件分支；第二列走前一 ADJ 槽查找 `0x202C1F68`，可改 `S+0x39F`。 |
| 横向右族，包含拨杆/通用横向导航。 | `0x22, 0x2F`。 | `0x202B848C` / `0x202BAB34`。 | 第二列走后一 ADJ 槽查找 `0x202C1FD4`，可改 `S+0x39F`，然后重新分派。 |
| Fn2 / Detail 逻辑动作。 | `0x25`。 | `0x202B6014` / `0x202BE220`。 | 第一列直接返回 0。第二列在 `0x202BE248` 检查活动 8，`0x202BE24C` 为现有 hook。 |
| MENU/OK 确认族。 | `0x23`。 | `0x202C2ABC` / `0x202B76EC`。 | 活动 8 跳到 `0x202C2D54`，在 `0x202C2D70/80` 调 `0x202871D8(1/0)`。 |
| ADJ 压入 / 确认族。 | `0x2B`。 | `0x202C2ABC` / `0x202B76EC`。 | 同一个活动分派进入确认/关闭路径。长按和所有释放事件仍须物理核对。 |
| 另一原生关闭族。 | `0x33`。 | `0x202C2ABC` / `0x202B76EC`。 | 含额外原生条件，不把它猜成独立 MENU 键。面板先撤下，再放行。 |
| 半按候选族 / 全按候选族。 | `0x29,0x63` / `0x2A`。 | `0x2029FDC4`、`0x202BD724` / `0x202A00E4`、`0x202B8C14`。 | 已有正向调用经 `0x202BE978` 或直接到 `0x202871D8`。物理半按与固件确认选项的组合仍需上机。 |

“上下、MENU/OK、ADJ 压入、半/全按”的物理命名采用原生行为与手册对应，是推断；表内事件值、handler、调用和分支是已核实。`0x59/0x5A` 等别名不应一概称为长按。键转换函数 `0x20289A9C` 把 `0x1F/0x20` 映射到 UI 事件 19/20，把 `0x21/0x22` 映射到 12/14，把 `0x25` 映射到 10。原始键消息处理 `0x202AFE98` 对不同按键阶段另加 29、58、87，并有原生特例，这也是必须区分事件层次的原因。

证据为 [state56_decoded.json](local/state56_decoded.json)、[shooting_dispatch](local/shooting_dispatch.disasm.txt)、[dispatch_tail](local/dispatch_tail.disasm.txt)、[adj_keys](local/adj_keys.disasm.txt)、[adj_horizontal](local/adj_horizontal.disasm.txt)、[adj_slot_forward](local/adj_slot_forward.disasm.txt)、[adj_close](local/adj_close.disasm.txt)、[event_remap](local/event_remap.disasm.txt)、[event_remap_tail](local/event_remap_tail.disasm.txt)、[physical_key_map](local/physical_key_map.disasm.txt)。

### 2.3 当前右操作有两条不同结果

已核实，在 Fn2/Detail 的 `0x25` 路径上，官方代码读取 `S+0x36E`，4、5、3、6 分别打开 Setting1、Setting2、B&W、TE 编辑页。Setting1 的调用点是 `0x202BE2C8`，目标 `0x2028A04C(1,0)`；随后切原生状态 60。

当前 Stage2l 在 `0x202BE24C` 跳到 `recipe_fn2_guard`。配方页门成立时，桩把原生保存的 `r8` 改成 2，再跳 `0x202BE6A8` 返回，跳过编辑页及原状态切换。随后 `0x202B1314` 把返回值 2 分派到 `0x202B1340`，置 `r11=1`，再次运行当前状态的初始化；状态 56 的事件 1 会到 `0x202BA5C8`。因此这条右/Detail 动作不会打开细调面板，而会要求原生重新进入该 ADJ 状态。[fn2_editor](local/fn2_editor.disasm.txt)、[fn2_tail](local/fn2_tail.disasm.txt)、[dispatch_tail](local/dispatch_tail.disasm.txt)、[当前 ABI 桩](../../firmware/stage2l_switch/abi.S)。

在横向 `0x22` 路径上，现有九个 hook 没有改 `0x202BAB34`，它仍会尝试切到后一 ADJ 功能槽。不能说“所有右操作现在都无效”。

设计上先让卡上策略明确接收 `0x25`。为覆盖尚未归一的右操作，建议同时允许配方列表中的 `0x22` 打开面板。这样 ADJ 向右也进入微调，向左仍可离开该配方槽。若产品要求 ADJ 向右继续切槽，则先做物理事件记录，按消息来源分开，不能仅凭事件名保留这个差异。该选择只影响有效配方页，原厂页沿用原路径。

## 3. 面板显示：复用列表，避免调用原厂编辑器

### 3.1 采用栈顶视图替换

已核实，`0x201FD360(r4=part, r5=state, r6=绘制参数)` 从传入 state 的类型和 `+4` 描述符表取行，标签并不强制来自固定的原厂全局。type 5 描述符为每项 12 B，行文字采用两层指针，`0x201FE410` 连续解引用。原生绘制支持 9 行及滚动。证据为 [draw_list](local/draw_list.disasm.txt)、[row_text_indirection](local/row_text_indirection.disasm.txt) 及既有 [列表研究](../stage1_ui/lever-FINDINGS.md)。

已核实，`0x201C07E0` 对 part 2 和 part 3 的栈深度都限制为 2；每条记录 8 B，tag 在 `+0`，state 指针在 `+4`。part 2 计数是 `0x205A27D4`，记录数组指针是 `0x205A27D8`。返回值是实际压入序号，容量不足时不应按“成功”继续。`0x201C06F4` 会清空该 part 的计数。`0x201C092C(...,1,...)` 处理隐藏/切换使能位，不能把它当作已证明的通用“弹出一条记录”API。[ui_push_pop](local/ui_push_pop.disasm.txt)、[ui_exit_tail](local/ui_exit_tail.disasm.txt)。

推断 / 设计，打开面板时：

1. 同时验证引擎 READY、原生状态 56、活动 8、part 2 活动、type 5、原栈顶 tag 33 / state `0x2022F71C`、外层配方序号 1..16、模块和页面代次。不能只看活动号或 S 的值。
2. 将原栈顶的完整 8 B 记录、计数、数组地址和原配方光标记入常驻层拥有的恢复记录。面板固定绑定这一次的模块、槽号和配方内容身份。
3. 引擎准备私有列表 state、描述符、稳定的标签引用和字符串。保留 type 5 样式，以私有 `+4` 表覆盖该类型的标签和 7–8 行计数，私有 `+9/+10` 保存初始/当前面板行。为 state 预留 32 B；这个数是预算，实际复制字段范围仍应随完整 renderer 消费者审计确定，不能据邻接对象地址猜 sizeof。
4. 只替换原栈顶的 state 指针，保留 tag 33、计数和数组地址。然后沿原生 `0x201C092C(2,0,0)` 激活/重绘。不开原厂状态 60，也不动 `0x2022FC18` 编辑缓冲。
5. 面板内部按键全部由前置 hook 消费，不能再调用原 `0x202BB4BC` 提交面板光标。打开动作本身的释放/重复事件不得立刻给第一项参数加值；按消息来源和阶段区分新按压，首版在物理映射验收前先禁用参数长按重复，不用固定延时猜按键已经释放。
6. 关闭时先停用面板输入；确认数组、计数、栈顶和代次仍属于本面板后，恢复保存的 8 B 记录，重绘配方列表。若页面已被原厂重建，只撤销面板所有权，不向旧数组地址写回。

这会在外层深度为 1 或 2 时使用同一方案。直接再压一个 tag 33 只适用于深度 1，且还缺少可靠的逐条 pop 合同；不推荐作为首版。Setting1 编辑页在 part 3 使用 tag 41，Recall 使用 tag 83，各有自己的状态、复制和保存逻辑，也不能当作一个无副作用的通用 push API。[editor_open_tail](local/editor_open_tail.disasm.txt)、[既有地址簿](../stage1_ui/ADDRESS_BOOK.md)。

### 3.2 行内容、字符集和宽度

设计示例为标题行 `R01 Posi`，接着 `Cont  +1`、`Satur +0`、`HiLt  -2`、`Shad  +2`、`Default`、`Back`。标题不可选，另四行可编辑，最后两行为动作。加锐度仍不超过 8 行，无需给小面板新增分页。初始光标放第一项参数，`+/-` 选行，Fn1/Fn2 改档；普通参数行上 MENU/OK 返回配方列表，选中 Default 时 MENU/OK 恢复该配方的默认微调。左右只改数值，返回用 Back 或 MENU/OK，避免左键同时承担减值和返回。

已核实，原生文字并非只能画 ASCII。它同时支持资源字形串和动态 ASCII。`0x201D2054` 会检测并转换 ASCII，使用全局临时缓冲 `0x205C34F8`，扫描上限 256；`0x201D73E0` 是有界名字转换包装，最后使用 `0x201D7170` 的菜单文字类型 8。ASCII 之外的 UTF-8 不能直接当原生资源字形串。证据为 [text_ascii](local/text_ascii.disasm.txt)、[text_ascii_tail](local/text_ascii_tail.disasm.txt)、[text_wrapper](local/text_wrapper.disasm.txt) 及 [文字研究](../stage1_ui/text-FINDINGS.md)。

设计上只使用可打印 ASCII，值符号使用 ASCII `+` / `-`。每行先限制为 8 字符并保证 NUL；若转字形，8 字符普通路径需至少 17 B 输出空间。标签指针与转换输出持有到引擎关闭，不能保存共享临时缓冲地址，也不能把栈上字符串交给异步重绘。若需双缓冲，切换发布必须与绘制串行。

已核实，当前 type 5 的该文字分支左缘为 219，右缘由 `*0x205D444C` 决定为 320 或 640，宽度分别为 101 或 421 个原生坐标单位。[row_geometry](local/row_geometry.disasm.txt)。这不是“固定能放 N 个字”的证明；字号、坐标缩放、字形宽度和语言都会影响结果。8 字符是复用既有短配方名策略的设计上限，`Cont  +1` 恰为 8 字符，仍须真机检查裁切。可复用 `0x201D74A8` 测宽，但 [既有深选择研究](../deep_select_fix/REPORT.md) 已指出转换结果与字形宽度的解释未完全对齐，不能拿未核实的单位计算一套像素保证。

不推荐用原厂 details 区排整个面板。它按高亮行取一个 12 B 提示记录，只画补充文字/图标，没有独立的多参数光标或保存语义；原表只有 7 项，16 项越界问题仍要处理。可以另做“右键编辑”提示，但它不替代子面板。[list_details](local/list_details.disasm.txt)、[既有列表研究](../stage1_ui/lever-FINDINGS.md)。

## 4. 实时预览：能证明什么，不能证明什么

已核实，原生编辑保存事件 `0x202BE118` 先调用 `0x2028A420` 写 S，再在 `0x202BE148` 调 `0x202D6F38(0)`；普通 Image Settings 提交 `0x202BC868` 也用这个预览入口。这提供了可靠的“改参数后请求刷新”接入点。[fn2_editor](local/fn2_editor.disasm.txt)、[preview_commit](local/preview_commit.disasm.txt)。

`0x202D6F38` 构造参数块，在 `0x202D6FB8` 调 `0x201709CC`，后者写命令 `0x2F03`、长度 144、flags `0x8000`，提交到队列 15，返回 0 或 -1。外层函数返回的是 sender 的结果，没有等待一帧被显示的证明。[preview](local/preview.disasm.txt)、[preview_sender](local/preview_sender.disasm.txt)。

它还会调用 `0x202AF8EC(1)` 增加 `0x2037F814` 的计数，完成发送后把 `0x205D9A8B` 设为 2。前者是可增减的计数，后者是状态字节；本轮没有找到能把任一值当成“可写深层行的独占锁”或“显示已完成”信号的闭环。不能自行清零它们来强行解 busy。[preview_flags](local/preview_flags.disasm.txt)、[preview_flag2](local/preview_flag2.disasm.txt)。

已核实，现有引擎 `cache->busy` 只防自身重入。深层 RPC 的 preflight 条件是 `gxr_thread_context()==0`、`gxr_rpc_ready()!=0`、`gxr_rpc_limit()>8`，再查模块身份；这些判断不等于持有原厂图像处理锁，也不独自证明当前是某个指定任务号。[platform.c](../../firmware/stage2l_switch/platform.c)、[deep_isp.c](../../firmware/stage2l_switch/deep_isp.c)。

推断 / 设计，每次微调按以下事务执行：

1. 从“原配方＋该配方的微调向量”重算完整候选行，钳位微调至 −2..+2；不要在上一次量化结果上反复累加。对比度、高光、阴影由引擎重算深层行，不能放开原厂对比度滑块去选别的行。
2. 在已有配方应用 owner 和允许 RPC 的任务上下文中串行写入、核验整组深层数据。绘制函数、IRQ、拍摄 sender hook 中都不做这些工作，也不写 `/IROM/`。若异步应用，完成回调必须重查页面、S、模块代次。
3. 完整写入成功后才发布相关 S 字段，并请求一次 `0x202D6F38(0)`。半写、RPC 失败、模块失效时不继续预览或假报新值成功；保留实际已写范围，按引擎恢复合同回到上一完整版本，恢复不了则保留故障状态。
4. 同一时刻最多一个应用事务。短按按档处理；重按/长按在 busy 时最多保留一个最新目标值，不积累无限请求，也不让重绘触发应用。不在未测量前承诺 5 Hz、10 Hz 或逐帧响应。
5. S、深层行和请求入队都成功后，更新面板的已应用值并标记该配方脏；持久化交给存储服务。入队失败发生在深层写入之后，应明确区分“数据已应用、预览请求失败”和“事务从未应用”，不能仅把显示值减回去就算回滚。

已有 [曲线研究](../contrast_curve/REPORT.md) 证明 A12 50mm 的 `0x20118468` 从所选深层行取 A/B 数据并打包，后续有写硬件出口。它支持“下次重新取用这些行会得到新数据”的推断。它没有闭合 `0x2F03` 每次都重读当前修改的第 5/20 行、使缓存失效并在下一帧提交的整条链。本轮也没有补出这条链。因此画面立即变化、实际延迟、busy 完成通知、长按可承受频率、快门抢占期间的时序，全部未知。

## 5. 退出、原厂字段和保存边界

| 边界 | 要求的设计行为 | 本轮证据与限制 |
|---|---|---|
| MENU/OK 返回。 | 正常参数行关闭面板并返回原配方行；Default 行执行恢复默认；Back 行返回。只消费这一事件，不让原厂把面板行号当配方序号。 | `0x23` 的原确认路径已核实，按键前置分派可拦截。MENU 与 OK 无法当成两个独立物理键设计。 |
| ADJ 压入、原生关闭族。 | 先撤下面板、取消未开始的微调请求，再放行原事件，由原生关 ADJ 页。 | `0x2B/0x33` 到关闭路径已核实；不吞掉后续原事件。 |
| 半按 / 全按快门。 | 先撤下面板，再放行原事件和快门确认设置。正在写行时由应用 owner 中止/收尾；不能直接释放数据或提交半组行。 | 相关逻辑族到 `0x202871D8` 的调用已定位。输入 hook 是分派前，不是硬件中断前，不能据此声称能抢占任意正在进行的 RPC。 |
| 其它菜单盖住或重建 UI。 | 观察 `0x201C06F4`，以及 `0x201C092C` 的隐藏操作。仅当栈顶仍属本面板时恢复记录；之后关闭所有权。 | 两个通用入口的原指令可核对。原厂直接写 UI 全局的其它路径未穷尽，不能只靠这两个点保证全部退出。 |
| MY 召回。 | 在 S 被替换/重写前关闭面板，撤销旧配方绑定；不把旧 S 快照写到新的 MY。已有微调留在自己的配方记录，下一次显式选择该配方再应用。 | 已有 `0x2036B6C0`、当前设置导入 `0x2011F580` 可作通知候选；不覆盖全部模式盘与 MY 路径。必须接入常驻层统一的 S/模块代次通知。 |
| 休眠、关机、模块断连。 | resident 先阻止新卡代码调用，使面板失效，并在有效页面上撤回 native 指针；应用 owner 负责深层行收尾。唤醒重新校验，默认不恢复正在编辑的面板。 | 本轮没有证明统一的 pre-sleep hook。仅在唤醒后检查 stale 指针太晚，不能作为“干净退出”的实现。精确入口由生命周期研究闭合。 |

面板关闭只结束视图，已成功应用的微调继续作用于当前配方；切换到其它配方时，引擎用那一配方自己的微调向量重新计算。完整停用扩展、MY 或模块代次变化时，按常驻层通用恢复合同处理深层行，不能把“返回上层列表”与“恢复原厂 ISP”混为一个动作。

S 的原厂 Image selector 在 `S+0x36E`，Setting1 的三个原始全局字段在 `S+0x36F/+0x370/+0x371`，五色数组在 `S+0x8AC/+0x8B1`。面板保存 −2..+2 的逻辑微调，不把它直接写进这些原厂 raw 编码。饱和度如何映射到 S 或深层色彩行由 recipe_tweak 引擎合同决定，UI 不自行选择另一种编码。[既有数据研究](../stage1_data/REPORT.md)。

不调用 `0x2028A420` 保存本面板。它依赖原厂临时编辑对象，会把旧索引重新写入 S，可能覆盖刚应用的配方；`0x2028A04C` 也不是无副作用的通用建页函数。面板保留配方原来的 base mode，禁止原厂 `0x202BB960` 的七项 setter 接触面板行号。原厂 Setting1 编辑页若在面板之外开放，须先结束配方会话，再按新的 S 重新建立映射。

每模块 16 个槽的微调至少绑定“模块身份＋槽号＋配方内容身份/版本”。同一槽更换配方时不能套上旧配方的微调；模块之间不共用一个向量。Default 将本配方逻辑向量恢复为 0，再经同一应用事务重算，不能从当前深层曲线反推默认值。`/IROM/` 的文件格式、原子更新、写放大、失败提示由存储研究决定，本任务没有写入或模拟这些文件，也不承诺每次按键已落盘。

## 6. Hook 清单与默认回原厂路径

以下全是未安装的替换语义。官方原字节与当前 Stage2l 字节逐项在 [local/HOOKS.md](local/HOOKS.md)，共 9 个既有 hook、3 个新增 UI 候选、2 个 MY 通知候选。休眠入口尚无候选，不伪造地址。原厂续接必须重放全部被覆盖指令并保持 native/GCC ABI、PSW 和栈平衡。

| 类别 / 地址 | 替换语义 | 默认回原厂路径 |
|---|---|---|
| 打开面板，既有 `0x202BE24C`，文件 `0x27344C`，4 B。 | 原活动 8 比较保留。有效配方页时调用卡上 `panel_open(module,slot,recipe_identity)`，成功后保持 `r8=0`，通过原 epilogue 返回 0；不切状态 60，也不返回会重建 ADJ 页的 2。 | 重放 `seth r0,0x2026`，续 `0x202BE250`。加载失败后须先恢复完整原厂页，不能让 16 项配方页直接进入七项原 setter。成功接管用 `0x202BE6A8` 原 epilogue。 |
| 面板按键及横向右别名，新增 `0x202B120C`，文件 `0x26640C`，4 B。 | 在状态表查找前接收 `r11=逻辑事件` 和原生 SP+28 消息块。面板开着时消费上下、左右、Default/Back/确认；关闭外部事件则先撤下面板再放行。配方列表的 `0x22` 可在这里打开面板。 | 重放 `ldi r0,1; nop`，续 `0x202B1210`。消费事件时恢复全部现场，转 `0x202B1344`，它设置 `r11=0` 并进入下一轮；不要从 shooting 大函数直接 jmp lr。 |
| 关闭保护，新增 `0x201C06F4`，文件 `0x1758F4`，4 B。 | 在 part 重建/清计数前通知 resident；只有拥有的面板才撤回栈顶记录，清除调用资格。part 3 覆盖也可触发关闭。 | 重放 `push r8; push lr`，续 `0x201C06F8`，原参数和状态继续。这个入口不发 RPC、不做存储。 |
| 关闭保护，新增 `0x201C092C`，文件 `0x175B2C`，4 B。 | 对拥有面板的 hide 操作做同样处理。用 UI 更新 API 自身重绘时要有抑制位，防止自身递归退出。 | 重放 `push r8; push r9`，续 `0x201C0930`；普通 activate/redraw 不改变原行为。 |
| 既有初始化 `0x2028709C`，8 B；光标旁路 `0x202870A8`，4 B。 | READY 才发布配方列表并绕过原枚举；引擎载入后才能打开微调。 | 前者回 `0x20271FEC` 原 getter；后者重放原光标/枚举入口并续 `0x202870AC`，不能继续无条件跳 `0x20287118`。 |
| 既有名字 `0x2022F5A8`，4 B；计数 `0x2022F5AC`，1 B。 | 外层列表是当前模块的 16 配方；面板用自己的描述符和计数，避免改全局表制造两页竞争。 | 默认保留原表 `0x2022D610` 和计数 7。当前 Stage2l 计数实际上是 8，不能因为 hook 名叫 count_16 就把现状写成 16。 |
| 既有 details `0x201FEBE4`，8 B。 | 有效配方列表和面板选稳定的空 details；可在卡引擎后续版本补提示。 | 原 `r2=0x2023FD38`，续 `0x201FEBEC`。原厂页应保留其 details。 |
| 既有确认/关闭 `0x202871D8`，4 B。 | 识别配方所有权。面板若尚未退出，先走统一 close；外层才按 keep/close 处理。不能用旧 `rfw_ui_active()` 仅认固定 state 的逻辑来判面板。 | 原 `push lr; nop`，续 `0x202871DC`。自有页面失败时先恢复整套原厂 descriptor/cursor，再放行。 |
| 既有实时选择 `0x202BB968`，4 B。 | 只处理外层配方光标。面板行号由按键 gate 消费，即使经其它路径到这里也禁止进入原七项映射。 | 重放 `seth r11,0x2022`，续 `0x202BB96C`；完整接管后用原 `0x202BCF58` epilogue。 |
| 既有拍摄 sender `0x2017098C`，4 B。 | 保留原来的已提交快照检查；不在这里打开面板、重算曲线、分配或写文件。 | 重放 `push lr; nop`，续 `0x20170990`。 |
| MY 通知候选 `0x2036B6C0`，文件 `0x3208C0`，4 B。 | 在该召回流程通知视图失效。原入口同时包含保存参数到 `r8` 的指令，须完整重放。 | 续 `0x2036B6C4`。只覆盖该入口，不作为 MY 总闸。 |
| 当前设置导入候选 `0x2011F580`，文件 `0xD4780`，4 B。 | 在该入口写 S 之前关闭面板、撤销旧身份；仍执行整个原厂导入。 | 重放原生栈帧分配，续 `0x2011F584`。其它 MY/模式切换仍依赖生命周期合同。 |

`0x202B120C` 是很宽的共享路径，必须以 resident root 的状态和页面所有权先门控；缺文件、坏容器、错误模块、非配方页均重放原指令。不能把卡代码直接写成该入口的无条件目标。新跳转约跨 2.5 MiB，在 M32R BRA24 的已知范围内；精确编码、指令槽、入口和所有续接还需实现后的静态审计，本轮没有组装新跳转。

正常返回列表与故障回原厂是不同恢复操作。前者要求引擎和所有标签内存仍有效；后者由 resident 自有记录恢复原厂标签、计数、details、合法 cursor 和所有权，不能再调用已失效引擎。深层行是否已恢复成功另有独立状态，不能由 UI 恢复推定。

## 7. 常驻层、卡上引擎分工与预算

| 常驻层必须具备 | 卡上引擎负责 |
|---|---|
| 条件 hook、寄存器/PSW/native ABI 桥、默认原厂续接。 | 行标签、数值格式化、光标、范围和 Default/Back 的交互。 |
| panel owner、页面/S/模块代次、保存的 native 栈顶记录、失败时撤回自有 UI 指针。 | 模块内 16 配方位及各自微调向量、配方身份校验。 |
| 统一 `ui_before_reset`、`ui_abort(reason)`、生命周期撤销通知。 | 从基础配方重算曲线，写入/核验深层行，发布 S，请求预览。 |
| 对有效入口和已分配块的校验，停止调用失效卡代码；故障时能独立恢复 native UI。 | 串行应用、busy 合并、存储脏状态，调用 `/IROM/` 存储服务。 |

设计 ABI 至少包含 `panel_open`、`panel_event(event,msg)`、`panel_abort(reason)`、`apply_step(identity,param,value)`；返回值区分 PASS、CONSUMED、CLOSE_AND_PASS、FAULT。不能只用 bool 把“已经改数据但预览失败”压成没有变化。`ui_abort` 的 resident 部分必须在卡入口失效后仍可运行，不能仅保留一个指向卡上 abort 函数的指针。

估计新增 UI 常驻职责需额外约 512–896 B，包含入口调整、完整现场保存的事件桥、两处退出观察、所有权/恢复逻辑和约 64–96 B 状态。这是未编译预算，不是链接尺寸；共用现有生命周期桥可减少重复。按原常驻设计上限 5632 B 加 896 B，约 6528 B，距 8340 B 窗口尚有 1812 B，不能据此承诺一定装得下。最终须把所有新增生命周期 hook 放入同一次链接预算。

卡上面板代码预算约 1.5–3 KiB，私有 UI 数据约 320–512 B；不含曲线算法、RPC 状态机、文件读写和存储服务。双缓冲字符串、对齐和更完整身份记录可能增加占用。没有测得运行延迟或最坏栈深。

主要风险是物理别名误分流、通用 hook 在其它 shooting 状态误触发、原生异步绘制留存指针、两套视图共用全局绘制缓存、RPC 期间快门或生命周期抢占、原厂路径重新覆盖深层行、回原厂 UI 后深层恢复尚未完成。关闭根状态、恢复 UI、恢复图像数据需要分别记录结果。当前 Stage2l 的 `rfw_ui_active()` 固定认 `state==0x2022F71C`，不能原样用于面板。

## 8. 最小上机验证顺序与交付复核

以下是未来获准上机后的顺序，本轮没有执行，也没有为这些步骤构建文件。

1. 先只记录按键事件、来源消息、活动号、part/tag/state、栈深度，逐个按 Fn1、Fn2、+/−、拨杆左右/压入、MENU/OK、半按/全按。关闭物理别名缺口，确认现有右操作走 `0x22`、`0x25` 或其它路径。
2. 只做空面板视图替换，不改 S 或深层行。检查 7–8 行、数字正负、选中颜色、语言、101/421 坐标两种布局；关开反复验证外层原配方行和 16 项滚动。全程读回栈顶、计数和指针，不能只看截图。
3. 空面板期间分别测试 MENU/OK、ADJ 压入、半按、其它菜单、MY、回放、休眠/唤醒、关机和模块断连。先证明在原厂 UI 重建前已撤回自有指针，再允许加入深层写入。
4. 单独测试参数写入与 `0x2F03` 请求。对一档已知变化记录候选值、实际深层读回、S、sender 结果、模块完成证据和取景视频，区分“请求已入队”与“画面已变化”。先证明深层行被重新取用，再加入其它参数。
5. 测快速短按、长按、busy 中快门、应用失败和回滚。确认无面板行号进入原七项 setter，无半写配置拍摄；测量响应时间后再决定重复键节流策略。
6. 最后接入每配方保存与 Default。验证 16 槽、不同模块、换配方内容、存储失败、断电重启和原厂回退。持久化成功、画面成功与照片成功分别留证。
